# CONTEXT.md · 术语表

一词一句定义的项目术语速查；不带实现细节，随批次追加。

| 术语 | 定义 |
|---|---|
| 参考标尺 | 随插件分发的结构数值基准（`skills/novel-design/references/参考标尺.md`），含节奏、反派、比例、衰减、题材修正等分档与其打破条件。 |
| 对手梯队 | 故事骨架「核心冲突与对抗力量」内的反派分层子表（层级｜存活周期｜代表对手｜出牌与去向），数值经取数算式引自参考标尺。 |
| 压力升级检查 | 卷纲第五段五核对项：本卷激活层级对齐分卷行／对手出牌至少一手／卷末去向写明／终局暗手留痕／本卷升级位（主角位阶/实力本卷至少推进一处，对照 世界书/力量体系/ 条目台阶）。 |
| 取数算式 | 消费视图引用参考标尺数值时的呈报行，格式「取数：参考标尺·固定层＋比例层×衰减×题材」。 |
| 打破条件 | 参考标尺每行附带的合法偏离说明——命中打破条件或本书自报值的偏离不记为发现项。 |
| 单源资产 | 数值或判据的唯一数据源文件——技能文档与底本只引用不内联，校准升版只改源文件。 |
| 记忆文风条目 | 文风建档门产物类名（作者层与本书记忆两通道）；条目名固定「文风画像·{书名}」。 |

## 首章旅程术语（0.0.31 产品体验批补全——按旅程阶段排序；新手教程用人话，系统术语在此查）

### 安装与配置

| 术语 | 定义 |
|---|---|
| DSH（DeepSeek Harness） | 运行工作台的宿主程序：先装 DSH 再装 Abzu 插件，会话、模型连接、凭据与文件权限都由它负责，版本要与 Abzu 要求的一致。 |
| profile | DSH 里的一份插件组装（例如 `abzu`）：不同 profile 的插件与设置互不影响，装插件或核对配置时用 `--profile abzu` 指定。 |
| 工作区 | 本会话处理作品的目录：写作前准备一个专门目录并在会话里选中，同一工作区可以放多本书。 |
| 主模型 | 构想、细纲、正文、审读共用的聊天模型：在 设置 → 模型 填协议、地址、密钥与精确模型 ID，发一条短消息试通后再开始建书。 |
| 增强索引 | 检索增强的可选能力合称（嵌入、场景识别、重排序三件）：基础写作可整个留空，配置入口与费用说明见隐私与费用文档。 |

### 建书

| 术语 | 定义 |
|---|---|
| 构想七要素 | 建书前必须确认齐的七项基本盘：缺项时建书被拒，补齐并明确确认后重试。 |
| 建书 | 把确认后的构想落成书仓的动作：由工具完成，成功标准是书房出现书名与文件树，不是对话里的一段文字。 |
| 书仓 | 一本书在磁盘上的目录与版本历史：判断进度一律回书仓文件（定稿、账本、提交历史），不凭模型承诺。 |
| 书房 | 工作台左侧的书库面板：在这里展开文件树、打开定稿与草稿、核对这本书的实际文件。 |

### 作品定调（设计）

| 术语 | 定义 |
|---|---|
| 快速开写（路径 A） | 新手默认的设计路径：说「快速开写，先跑起来再细化」，工作台按构想一次起草全部设计给你过目，同意后逐件写入。 |
| 逐部设计流程（路径 B） | 进阶设计路径：说「使用逐部设计流程」，契约、世界书、骨架、分卷、卷规划逐部细聊逐部确认，轮数更多、控制更细。 |
| 作品契约 | `作品契约/契约.md`，一本书的顶层约定文件：分部更新、绝不整体重写，篇幅约定写在「阅读体验与情绪承诺」分部的「章节篇幅」子节。 |
| 契约六部 | 作品契约的六个分部（题材与读者定位／核心看点与差异化／阅读体验与情绪承诺／主角原则与关系边界／叙事方式与文风基调／创作禁区与不可妥协项）：逐部对谈时每聊定一部更新一部。 |
| 世界书 | 设定条目库（人物档案、世界规则、力量体系等模块）：快速开写至少要有主角一条人物档案加一条世界规则，条目按模板起稿、留白合法。 |
| 故事骨架 | `大纲/故事骨架.md`，故事走向总纲：快速开写只须确认「主角目标与成长轨迹」「核心冲突与对抗力量」两部，其余可留白。 |
| 骨架九部 | 故事骨架的九个分部：不为填栏编造终极真相、最终敌人或结局，想到的记暂定猜想，想不出整行留白。 |
| 分卷布局 | `大纲/分卷布局.md`，八部的卷级节奏表：快速开写只在「故事阶段分配」小节写本卷卷行，其余留白。 |
| 卷纲 | `大纲/卷规划/卷NN/卷纲.md`，一卷的具体计划：叙事结构、弧线、线索推进、卷末兑现四段齐全，加第五段压力升级检查，没想好的段标留白。 |
| 留白 | 设计件里「没想好、不勉强填」的合法状态：确认含留白的整份文档不等于所有分部已确认，后续按需补齐。 |
| 章节篇幅 | 契约「阅读体验与情绪承诺」下的子节（目标／下限／上限三行正整数）：经作者同意写入后，细纲、起草、审读继承此项做篇幅核对。 |

### 章细纲

| 术语 | 定义 |
|---|---|
| 章细纲 | 动笔前的一章计划（核心节七节：视角与焦点、信息边界、情绪与节奏目标、起止边界、前置条件核对结果、冲突与爽点、章末双钩）：确认之后才进入正文。 |
| 近期窗口 | `大纲/卷规划/卷NN/近期窗口.md`，排近期要写章节的清单：第一条条目名必须与第一章章名一致。 |
| 写前十查 | 确认细纲前的十项检查：机器四查自动跑、过目单六查进呈确认件。 |
| 章末双钩 | 章尾并留的两类钩子（期待钩与悬念钩）：设计期排期期待钩（悬模式下占双钩其一），不是写时顺手。 |

### 写稿与审读

| 术语 | 定义 |
|---|---|
| 正文起草 | 按已确认细纲写正文：涉及定稿或改变故事方向时停下来交作者确认。 |
| 草稿区 | 未定稿稿件的存放区（`草稿区/草稿/卷*/稿N.md`）：保存不等于审读，审读不等于定稿。 |
| 审读 | 对整章草稿的检查环节：发现项按处置枚举处理，篇幅超范围走发现项，不自动裁稿。 |
| 待审稿 | 起草与必要修改完成后交作者过目的版本：阅读它确认修改符合意图，再决定是否定稿。 |

### 定稿与恢复

| 术语 | 定义 |
|---|---|
| 定稿 | 作者批准后写入 `定稿/` 并产生版本提交的动作：成功标准是定稿文件加对应提交，不是批准按钮被点过。 |
| 吃书补偿 | 修改已定稿内容的正式流程：已定稿要改设定或事实时走它并留痕，不随手覆盖。 |
| 故事账本／本书记忆 | 获批沉淀事实的落账处：定稿带沉淀时随之变化，核对进度时一并查看。 |
| 版本提交 | Git 历史里的记录：设计提交和作者修改提交都不等于章节定稿，判断章节状态看定稿文件与账本。 |
| 导出合集 | 把指定范围的定稿汇成一份成品文件：确认目标目录与冲突情况之后再保存，合集只含定稿不含草稿。 |
