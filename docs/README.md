# docs

四类文档：**产品**说是什么与怎么走，**技术**说怎么实现，**标准**说必须遵守什么，**设计**说打算改成什么。
前三类描述现状、随实现更新；设计是一次性方案，定稿后取舍结论并入前两类。

| 文档 | 内容 |
| --- | --- |
| [产品/是什么](产品/是什么.md) | 产品定位、三层金字塔、书仓与工件 |
| [产品/怎么走](产品/怎么走.md) | 全流程总览、开书、章节循环、横切流程、作者确认点 |
| [产品/术语](产品/术语.md) | 创作域术语：一个词在本产品里指什么 |
| [技术/现状](技术/现状.md) | 包结构、运行时、安全模型、状态推导、数据层、构建与安装、开发命令、CI 与发版、外部资产 |
| [技术/已知问题](技术/已知问题.md) | 代码与运行时的已知缺口、风险、已定未做的调整 |
| [标准/书仓格式](标准/书仓格式.md) | 书仓文件真源、写入约束、兼容性（修改数据相关代码前必读） |
| [标准/技能编写规范](标准/技能编写规范.md) | 运行时技能、判据件、心智条目、任务包的写法与修改流程 |
| [标准/判据体系](标准/判据体系.md) | 方法论资产的结构、来源与校准，以及从知识库提取进仓的管线 |
| [标准/工程规范](标准/工程规范.md) | 提交、版本、测试、CI 与发版、文档、数据铁律、错误处理分域、导出面纪律、偶发失败诊断 |

协作入口（路由到上述文档）在仓库根的 [AGENTS.md](../AGENTS.md)。工程域术语见 [GLOSSARY.md](../GLOSSARY.md)。
