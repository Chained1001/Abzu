# 维持 core 的汇总导出，不做逐名化

`packages/core/src/index.ts` 有约 40 处 `export *`，最终汇总出约 588 个具名导出。工程规范禁止**新增** `export *`，但这批存量不逐名化。

我们决定**保留汇总导出，只约束增量**。

## 考虑过的替代方案

**逐名写 588 个导出。** 拿到的是显式的导出面：读 `index.ts` 就知道 core 对外提供什么。代价是 588 行纯声明，2–3 天的机械工作，且每次新增符号都要改两处。而它解决的问题——「不知道某个符号是否对外公开」——可以用一次 `grep` 解决。

**按域拆成多个 barrel 文件（`export * from './repo'` 等）。** 中间态，比现状多一层结构但不减少总量。它会让「哪个域导出了什么」更清楚，但不会让导出面变显式。没有解决根本问题，却增加了一层文件。

**混合：新代码逐名，老代码汇总。** 这正是我们现在的做法。约束是「不新增 `export *`」，存量按兵不动。

## 后果

`index.ts` 的导出面依然不显式。判断某符号是否对外公开需要看构建产物或跑一次导入测试。

这条 ADR 存在的意义是：它是一个**已裁决的非目标**。将来有人提议「顺手清理一下 export *」时，先读这里——这不是没人想到，是算过账决定不做。
