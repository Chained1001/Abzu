# 不做判据装载器

技能文本与判据件之间存在**口径漂移**：同一判据在技能流程描述与判据件里各写一份，改一处漏另一处。一个「判据装载器」可以消除这一类问题——把判据抽成结构化数据，由装载器渲染进技能文本。

我们决定**不做判据装载器**，接受这类漂移。

## 考虑过的替代方案

**判据装载器 + 结构化判据源。** 判据从 Markdown 变成数据，技能文本由模板渲染。能根除漂移，但代价是把「写判据」这件事从「写 Markdown」变成「写数据 + 维护模板」。判据件的作者是作者本人，不是程序员——判据的价值在于能直接用中文写清楚判断标准，模板化会逼着每句话去适配字段。

**技能文本引用判据件，不重复内联。** 这是理想状态，也是**正在做的方向**：技能只写流程与停机条件，判断标准一律指向判据件。但它不能完全做到——技能需要在特定步骤提要点，完全不复述会让模型在错误的时机去读整件。

**技能文本协议版本化。** 给技能文本加版本号，判据变更时检查引用方是否跟上。这是装载器的弱化版，成本低得多，但当前判据变更频率还不足以支撑这套机制。

## 后果

技能文本与判据件的部分重复会继续存在。发现漂移时按文档修，不指望机制拦截。

若判据数量或变更频率显著上升，重新评估「技能文本协议版本化」这条弱化路径——它比装载器便宜得多，可能已经够用。
