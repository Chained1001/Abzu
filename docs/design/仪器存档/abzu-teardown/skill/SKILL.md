# 拆书

## 核心流程

**Stage 1 快速通读（必做，产骨架）**——子阶段代号 1a 结构审计→1b 轻扫→1c 深读→1d 合成（拆书进度.md 阶段表与批次 ID 前缀用同款代号）：

1. 要原文路径与书名（用户消息已给则跳过；书名缺省取文件名确认）→ 原文处理二选一：复制为 参考作品/{书名}/原文.txt，或外置登记——绝对路径＋全源 sha 记入 参考作品/{书名}/拆书进度.md 外置登记行，扫描工按登记路径读（不重复入库）
2. 【1a】跑 audit.mjs 出 参考作品/{书名}/结构审计.json，看章数、字数、可用率、宽谱/窄谱、高潮块列表；continuity.numbering 标"卷标不全"的书，分卷起止需与用户人工定界
3. 【1a】按实测字数报成本量级（每 100 万字≈100-150 万输入 token＋深读聚合开销）→ 用户选全本／切片（前 N 章，产物头部声明分析范围）／终止；可用率<80% 或 0 章停问三选一——只拆可用章节并声明范围／换更好的源重来／终止
4. 【1b】建 参考作品/{书名}/拆书进度.md（受管区格式照 references/templates/teardown-products.md），跑 index.mjs generate 建空表 参考作品/{书名}/章节索引.csv；空章/污染章在备注列标 `状态:空章`/`状态:污染`，派工跳过
5. 【1b】派扫描工分批轻扫（每批 5-8 章、≤4 万字符；信息密集章缩至 1-2 章；首批特批只含首 3 章作预演门）。批次单七字段：batch_id（前缀枚举见模板拆书进度节）｜章节号＋行号段（章节号用全局章序；行号取结构审计.json 各章 lineStart-lineEnd）｜原文绝对路径｜模式｜输出缓存全路径 参考作品/{书名}/_teardown_cache/{batch_id}.md｜handoff 指针（并行轮内取该轮开始前最近已提交批次）｜任务书注入（默认"任务书全文随提示词注入"——无头通道下扫描工无法自读文件，行格式与 cache-end 全靠它）。min_要点数＝章字数÷200 四舍五入 clamp 1-10；窄谱书或钩级采集时批次单注明。缓存索引行的 第{N}章 N＝全局章序（协议钉死——卷内编号书勿写章题原文编号）；定稿投影回填三列——摘要段→一句话摘要列、人物段→参与人物列、位置段→位置标记列（值＝`位置:原文L{lineStart}-L{lineEnd}`，行号取结构审计.json）；章类型标签（七类，混合打星号——值域见模板 CSV 节）写备注列 `类型:{值}`。每批定稿（写回产物）前跑 validate.mjs（带 CSV 参数），通过后更新拆书进度.md 批次表行与阶段表
6. 【1b】首 3 章摘要给用户过目定口径；确认后一口气拆完；约每拆一成报一次进度
7. 【1c】机械选 20-30 章关键章：全书首末各 3 章；每卷首末章（audit 的 spectrum=宽谱时换成高潮块峰值章＋块前 1 章）；人名词频峰章（数索引参与人物列，出现次数最多的人物取其密集章）；audit 的 authorNotes 检出章（作者自述章，深读后摘录入 参考作品/{书名}/拆书笔记.md·作者自述节）。机械规则算出超 30 章时裁剪：高潮块每块只留峰值章（去块前 1 章），仍超则按块峰值倍率从低到高砍块；人名词频峰章最多保 3。深读批 handoff 统一取最近已提交轻扫批
8. 【1c】派扫描工深读关键章，每章产 200-400 字深卡；批次单列出高潮候选章时，扫描工在跨章观察节记该章三信号（前 5 章贬损有无/当众场景词有无/旁观反应段数）
9. 【1d】聚合索引＋深卡＋审计，在 参考作品/{书名}/ 下合成骨架五件套（参考作品骨架.md/拆书笔记.md/反面清单.md/人物总表.md/伏笔总表.md），格式照 references/templates/teardown-products.md。类型占比表数据源＝grep 索引备注列 `类型:` 前缀计数；续航引擎清单可初判（定型待 Stage 2 追踪词频曲线）。反面清单三源：用户提供评论数据优先→无则问作者要不要派采风代理抓真实书评→再无才留空写"暂无数据"，不编造骂点
10. 【1d】骨架一页结论给用户过目；确认后可产 参考作品/{书名}/章节速览.md（作者读的投影：章号/章名/一句话摘要三列）＋原文封存

**Stage 2 深度分析（可选，卷纲首次启动时触发）**——先报成本（逐对象追踪读章，量级与 Stage 1 深读相当），给延期选项（暂不拆，卷纲用骨架降级继续）。以 参考作品/{书名}/章节索引.csv 为地图按对象追踪，不线性重读。先载图（读 参考作品/{书名}/人物总表.md＋伏笔总表.md＋章节索引.csv），再走七步：

1. 人物弧线追踪（S/A 级）
2. 伏笔链追踪（埋提收）
3. 关系演变追踪（3-5 条，有向动词，禁"朋友敌人"）
4. 双时间线对照（真实序↔披露序；调度标签六值见 references/templates/teardown-products.md）
5. 爽点循环深拆（选 3 个典型，四段式＋铺放比）
6. 冲突矩阵（利益/信念/情感/身份秘密/方法五类）
7. 合成 参考作品/{书名}/深度分析.md

**Stage 3 分卷细拆（可选，每卷触发）**：

1. 从 参考作品/{书名}/结构审计.json 的 volumeSummary 取该卷起止章；numbering 标"卷标不全"时与用户人工定界
2. 定窗口＝本书当前写作的章位区间（来自卷纲触发方给的章位）等比折算到参考书的章位±10 章；窗口外不拆，产物标"未拆章位：第X-Y章"
3. 派扫描工分卷模式逐批，窗口内每章 1 张 14 字段事实卡
4. 聚合产 参考作品/{书名}/分卷拆解/第N卷.md
5. 对照时命中未拆章位→只增量补拆该章，不整卷重拆；用户明示"全卷拆"才全拆（先报成本）
6. 可选文风定点取样（用户要求才做）：按索引定点读 4-6 段原文锚点（对白密集/战斗/过渡各取样），产文风备注（句长节奏/对白密度/描写习惯；每条标题材词汇｜语感标记）；新书项目已有 故事文风/文风基准.md 则回填其观察区，不重扫全书；置信度 A/B/C

## 首次使用

进场第一件事：要原文在哪（用户消息里已给路径则跳过）＋书名（没说就从文件名取，顺口确认）。然后一次一件：

1. 跑 audit.mjs（本地机械、零 token）→ 按实测字数报成本量级：轻扫要把全书读一遍，每 100 万字约 100-150 万输入 token，另有深读与聚合开销。用户据此选——全本拆／切片档（只拆前 N 章，成本按比例，通常够用）／终止。切片档产物头部声明"分析范围=第X-Y章（占原书约Z%）"；可用率<80% 或 0 章在此停问三选一：只拆可用章节并声明范围／换更好的源重来／终止
2. 补元数据：作者/完结状态/题材标签——文件头部或用户处能取则取，取不到问一句，再没有记"原文未明确"（直填骨架基础信息表）

覆盖率定档（审计后；覆盖率＝可用章数÷原书总章数，原书总章数取用户告知的规模或完本标记，切片档按切片内章数计）：≥95% 完整拆；60-95% 拆＋产物头部声明缺失范围及受限结论；<60% 只做暂定分析不称覆盖全书，Stage 2/3 不触发；切片完整拆＋头部声明分析范围。

进场：书名未指明→列 参考作品/ 下各书进度三态（未开始/进行中/已完成）让用户选。读 参考作品/{书名}/拆书进度.md：有进度→按批次表定位断点，先报"上次到哪、剩多少"再续拆，不重拆已完成（已拆摘要永不覆盖；重拆=删该批摘要及覆盖缓存；整本重拆=换新目录）；无进度文件→从步骤 1 全新开始；旧格式产物（骨架在位、索引缺失）→补跑 1a＋1b 再续。

## 脚本调用

脚本随本技能分发，位于本 SKILL.md 同目录的 `scripts/teardown/` 下——调用时把 `{技能目录}` 替换为你加载本技能时看到的 SKILL.md 所在绝对路径。

```
node {技能目录}/scripts/teardown/audit.mjs 参考作品/{书名}/原文.txt 参考作品/{书名}/结构审计.json
node {技能目录}/scripts/teardown/index.mjs generate 参考作品/{书名}/结构审计.json 参考作品/{书名}/章节索引.csv
node {技能目录}/scripts/teardown/index.mjs verify 参考作品/{书名}/结构审计.json 参考作品/{书名}/章节索引.csv
node {技能目录}/scripts/teardown/index.mjs stats 参考作品/{书名}/章节索引.csv
node {技能目录}/scripts/teardown/validate.mjs 参考作品/{书名}/原文.txt 参考作品/{书名}/_teardown_cache/{批次ID}.md 参考作品/{书名}/结构审计.json 参考作品/{书名}/章节索引.csv
```

外置原文时原文参数换登记的绝对路径。

- audit.mjs：章切分、每章字数/sha/行号（lineStart-lineEnd）、章号连续性（卷内重编号感知）、空章/污染章/(上)(下)分章/作者附注检出（authorNotes）、可用率、宽谱窄谱、分卷统计、高潮块、收口跳点、解析器版本。
- index.mjs：generate 建空索引；verify 查表头/行数/列数/sha/摘要长度（引号感知）；stats 报填充进度与坏行数。
- validate.mjs：定稿门禁三项——缓存四节齐＋末行 cache-end 完整形态、范围 hash（缓存章集合重算 sha 对 audit 与 CSV 双比对——不一致=原文漂移，该批失效）、字数容差（摘要 50-100/深卡 200-400，均±5）。另两项别处承担：字段计数＝扫描工缓存自查节 Grep 计数；CSV 写后校验＝index.mjs verify。

## 纪律

1. 不为填字段虚构：缺失写"原文未明确"；不凭开头数章推断全书大反派或最终主题；关键结论带置信度 A/B/C。
2. 参考作品/{书名}/章节索引.csv 是地图：聚合只复用落盘结果；Stage 2/3 按索引选章派工，不重读全书。
3. 原文 Stage 1 确认后封存：此后只有 Stage 2/3 扫描工按批次单再读指定章，主会话不中转原文。
4. 每批定稿（扫描结果写回产物）前跑 validate.mjs；被拒按分级处理——格式违规原样重派、扫描工 Edit 定点改，结构性缺失（缺节/缺章/范围 hash 不一致）整批重派。本技能永不执行 git 提交/推送——产物落盘即完成，入库由用户决定。
5. 扫描工可并行派发（每轮多批）；批间交接只读该轮开始前最近已提交批次缓存的"跨批状态"节；1c 深读批 handoff 统一取最近已提交轻扫批。
6. 对用户说人话：报告禁脚本名/JSON 字段/hash 值/批次号；机制带人话名（「退婚当众打脸」式）；工程细节至多末尾一行。
7. 保真三约束：硬事实可溯源到章节；摘要没写的不推断补实；跨指代不串（坐骑等级≠骑手等级）。
