# Abzu 增强实施计划（E1-E8）

> v1.0 ｜ 2026-10-09 ｜ 本计划是 fork 产品（本仓）的方法论注入总蓝图——把设计仓（`dev\Abzu`）的方法论资产按批次融入本仓技能层。依据：四路注入设计研究（设计流程/参考标尺单源/写作管线/拆书移植，2026-10-09）＋修正重研究（标尺单源框架）＋三层实测校准（标尺 v0.4，报告 `test2-6\拆书校准\标尺校准报告_v0.4.md`）。
> 实施纪律沿用本仓惯例：一批一提交一版本号；每批过全量门禁（`pnpm test`／`lint`／`test:release`／`--filter abzu pack-check`／`version --check`）。

## 〇、原则与裁定（已定，实施不得重开）

1. **三层分治**：流程层（怎么想）＝设计仓的；标准层（什么是好）＝设计仓为主＋本仓"强制三方向"保留；机械层（文件体系/工具/门禁/derive 状态机）＝本仓的，全部保留。
2. **冻结面（第一年不动）**：`packages/core/src/derive`、`ledger`、`settlement` 数据结构、全部工具 schema。所有注入走**技能文本层**（SKILL.md/底本/工序/references 资产）＋零依赖脚本；需要动冻结面的项一律进二期清单。
3. **参考标尺＝单源量化资产**：反派量化体系（固定层层级/比例层数量/衰减/题材修正）内含于标尺；骨架"对手梯队"表、分卷对手层级行、卷纲"压力升级检查"＝三个**消费视图**，只从标尺取数（算式呈报），数值永不出标尺；校准只改标尺单文件，三视图自动跟随。
4. **六项实施裁定（2026-10-09 作者已批）**：计划落本仓 `docs/design/`（白名单已放宽）；批次顺序 E1→E5→E3、E6-E8 按需；一批一版本号（E1=0.0.6…）；标尺带 v0.4 实测值落地（低置信项照带标注——Q4 由校准先行解决）；验收深度＝大文本批（E5/E3）加真机冒烟、纯资产批机器门禁即可；本仓新建根 `CONTEXT.md` 术语表（首批词条随 E1）。
