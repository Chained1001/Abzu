# Abzu

面向中文网文作者的一组 AI 写作技能（Agent Skills），以 Claude Code 插件形式分发，帮助作者完成从全书规划到章节成稿的连载创作流程。

## 语言与约定（Language）

### 创作域

**网文（网络小说）**:
以连载章节为单位在网络平台发布的长篇通俗小说，通常为百万字级、按卷分章、保持日更节奏。
_Avoid_: 网络小书

**网文作者**:
Abzu 的目标用户：进行中文网文连载创作的写作者。

**大纲**:
全书级规划文档：世界观、主线冲突、人物弧光、分卷规划与既定结局。
_Avoid_: 总纲

**卷纲**:
单卷级规划：本卷目标、关键转折与高潮、对主线的推进。

**章纲**:
单章或连续数章的节拍表：场景、冲突、情绪曲线与章末钩子。
_Avoid_: 细纲

**正文**:
依据章纲写出的章节成稿文字。

**文风基准**:
"像不像他"层的比对文件（叙述者画像+八维选择倾向+锚点区+保留技法）——写手落笔前入口双读定语态、作家席漂移检测的基准。draft 步 0 首章建档门建档（四支：A提取/B书/自带/默认底座），批1 A.0 首单元校准门转 active；此后作者确认即改（轻通道）。
_Avoid_: 文风档案（旧名，2026-10-01 改名）、文风意向（零消费已删的伪概念）

**行文规格**:
"通不通"层的机械运行规范（排版/句级/指称/事实层），跨作者通用、有对错；与文风基准正交。draft 步 0 首章建档门实例化（字数档取段 4B 锁定值）。

**参考标尺**:
预置资产 references/参考标尺.md：衰减系数/节奏基准/题材修正/追读力（结构基准）。全文里单独出现的"标尺"均指它（概念简称）。

**金手指**:
网文术语，指主角获得的超常能力或优势体系（系统、重生、异能等），是主线爽感的引擎。

**创作进度**:
创作项目中的进度文件（项目基准/创作进度.md），记录各卷、各章的规划与完成状态，是技能从任意层级切入时的定位依据。

**本项目速览**:
项目基准/创作进度.md 头部固定的作者人话入口节：这是什么（AI 辅助网文创作的书项目）、各目录一句话、哪些别手改（登记册、评审、参考作品由技能与代理维护）——作者只看这一节即可定位各文件的角色。

**登记册**:
书项目内只追加、不修改的关键状态记录（事实、伏笔、能力进阶、规则、时间线、命名）。事实条目标注"谁知道"，伏笔条目标注应回收的截止章节；是一致性检查与校对评审的依据。

**设定**:
贯穿全部创作阶段的动态叙事资产（人物、世界观、金手指等），由各阶段技能在产出大纲、卷纲、章纲、正文的同时持续产出与迭代，存放于创作项目的总设定文件夹。
_Avoid_: 前置设定阶段、静态设定集

**参考作品拆解（拆书）**:
对作者提供的参考作品原文做三层（表象/机制/意图）、双向（正向可继承 + 反向要避开）的拆解，产出可复用的分析产物，作为新作品大纲与卷纲创作的"二次开发"基础。原文与拆解产物仅存于作者本地创作项目。

**主要参考**:
被完整拆书的 1 本参考书籍，产出参考作品骨架、拆书笔记、反面清单，作为大纲的结构基础，贯穿创作始终。

**次要参考**:
2-3 本按需提取"零件"（人物原型、关系模式、桥段、氛围、能力机制、情感线）的参考作品（书/动漫/影视均可），不拆全书，产出零件索引。

**参考作品骨架**:
主要参考完整拆书后沉淀的结构骨架产物，作为新作品大纲的结构基础。
_Avoid_: 地基点、地基节点

**差异集**:
新书相对参考作品的差异总纲（写什么/不写什么/改什么/避什么/暂存什么五栏），由题材迁移、反面清单修复、换变量候选、作者偏好、灵感库零件五个来源组装并经作者裁决定稿；暂存栏收留观候选，可被后续段捞回、定稿前必须清空；核心画面与一句话故事由骨架乘以差异集推导产生。
_Avoid_: 把差异集当成必须由作者预先提供的"种子"

**反面清单**:
从公开评论中筛选出的雷点、崩点、争议点、缺点，用于全流程避坑；与用户创作红线冲突时以红线为准。

**切片档**:
拆书进场输入覆盖率四档之一：原文.txt 自身完整（100%）但为原书局部切片——照常完整拆解，产物头部统一声明"分析范围=第X-Y章（占原书约Z%），全书级结论受限"，切片外字段（作者全貌/完结状态等）一律"原文未明确"。

**参考标尺**:
100 万至 300 万字通用的网文结构基准：固定层 + 比例层（每 100 万字）+ 衰减系数 + 题材修正，另含追读力节奏量化区（钩子/爽点/微兑现/伏笔债务）。随插件分发的预置资产（非书项目产物），数值经开发期校准采风维护。

**基本规格**:
创作项目的基础声明文件：题材、篇幅、参考作品、创作红线。

**创作红线**:
作者在基本规格中声明的硬约束（类型/剧情/故事设定/风格四类），全流程生效，优先级最高，允许临时解锁。

**现实依据栏**（设定卡元数据）:
每张设定卡（人物卡/世界核心/力量体系/地图/组织）带一行：来源（现实参照一句话）｜转化手法（直接沿用/改名/混搭/反着来）｜禁写（作者裁定）。嫁接日志管借参考作品，本栏管借现实世界；段5 步5 双线终检。_Avoid_: 世界参照档案（独立文件已溶解 2026-10-01——参照是一次性原料：待采走挂账清单、禁止走基本规格红线、沉淀走灵感库）

**创作项目（书项目）**:
一本书对应一个独立文件夹（位置用户自选，如 桌面根 test2-6），根下以 项目基准/基本规格.md、创作进度.md 为标识，内部结构强约定；新书开新文件夹。用户运行技能的文件夹即书项目目录（又称工作目录，区别于技能安装目录与开发目录）。

**归档目录**:
书项目 归档\ 目录，退役文件的去向：差异集（定稿后标"已完成使命"移入）、拆书缓存清理件、定稿后旧轮评审快照（作者可选归档）、执行完毕的变更提案。根目录原则：作者看到的每个文件都是活的。

**灵感库**:
书目录内可建的素材仓库，六类子目录为全项目统一口径（剧情结构/历史事实/人物原型/文化元素/影视动漫/现实生活），配 索引.md；支持双库——书内专属库＋全局灵感库（索引记全局库指针，不复制文件；检索顺序书内→全局，沉淀时跨书通用→全局、书专属→书内，作者裁决）；书项目初始化时询问新建专属/指向全局/双库并存；采风检索先查库后上网，结果抽象化后经用户裁决沉淀回库，永不存原文。

**业务流程**:
技能中"怎么想"的部分——管节奏、顺序、并行、发散、收敛。

**方法论**:
技能中"依据什么做"的部分——管标准、框架、专业度；是流程每一步强制加载的操作手册，不是可选参考书。
_Avoid_: 参考书、按需查阅的资料

## 设计原则

**写前十查**:
章纲卡过门前的自查单（章0 步2）：机器四查（三约束对照/能力越级/伏笔到期/接钩）＋过目单六查（平章/爽点铺垫/动机三问/近五章结构重复/情绪落点/钩承诺）——作家细纲自查的机制化；连写模式下六查转为差异呈报必报行。

**交互五级**（L1-L5）:
全技能交互形式选型标准（见 docs/design/standards/交互统一标准.md）：L1 静默执行＋四态呈报｜L2 会话问答（创作输入专用，禁弹窗）｜L3 ask 弹窗（枚举裁决，≤4 选项带推荐）｜L4 分组菜单（≥3 裁决一次呈报，🔴 除外）｜L5 强制呈报＋宽限生效。文件落地一律相对书项目根路径，分过目级/知悉级两级呈现。

**零消费即删**：
新增任何字段/文件/触点/问句之前，必须先回答——谁消费它？消费后行为有什么不同（Δ行为）？答不出 Δ≠0，不准加。已有产出物按同标准定期复检（先例：观察区零消费问题 2026-10-01 审查发现；"文风意向"字段发明后即删）。
**豁免两类**（须在模板头申报，2026-10-01）：① 条件消费者——保险型字段，事件触发时消费（如 promises"疑似遗忘"态、人物状态列、安全阀注记）；② 脚手架字段——id/type/status 等校验脚本与断点路由的底盘件。

**图纸与砌砖分离**：
大纲管图纸（结构/预算/调性由主情绪承载），砌砖工具（文风基准/行文规格）在砌砖时领——draft 首章建档门。不在大纲阶段预建正文期工具（2026-10-01 裁定）。
**可执行判据**：凡唯一消费者在正文期的产物，初建延至首个消费点的前一门——设定层（他是谁/他要什么）留大纲期，行为层（他怎么说话/句子长什么样）延正文期。先例：文风基准（已修）。反例修正：声线基线原按此判据延后（S6），2026-10-01 复核推翻——声线的推导输入（性格/处境/关系）段5 已齐，属设定层可推导，改为"段5 全建推导版＋出场后校准"（判据 refine：**推导输入已齐的建，只有语料才能校准的延**）。
**原则与修正同步**：原则立法即生效，配套修正在同批次排期清偿——立法日不留 P0 在案（教训：观察区在零消费即删立法日仍零消费）。

## 技能设计

**思维引导器**:
Abzu 对技能的定位：引导作者与 AI 进行网状、并行、逐步收敛的思考（由模糊到清晰），而非按固定步骤执行的流水线。
_Avoid_: 执行器、流水线步骤

**方法论文件**:
作者整理的专业写作方法论文档（如金手指设计方法），技能在对应环节按需加载，用于约束和增强 AI 的思考，防止纯自我推理。

**核心卡**:
方法论节头部的压缩必读块（意图/判据/路径名/错误名/原语/共思），由节自身内容机械抽取生成，永不与正文漂移；核心卡为必读层，节全文为深读扩展。

**共思链接**:
方法论节之间按共享原语标注的交叉思考边（想 X 时应强制同时想到的节），是四轨道交叉追问原则在知识库侧的落点。

**输出契约**:
技能产物的固定结构约定（各段落及其顺序），用于稳定产出形态，并作为校验脚本机械检查的依据。

**三评审**:
以读者（好不好看）、作家（结构逻辑设定节奏）、编辑（市场卖点对标）三种视角审查产物的横切角色，各持一份独立任务书、各出一份报告、不投票，打磨阶段按序运行（作家→读者→编辑）。任务书：docs/design/agents/（作家评审/读者评审/编辑评审）。
_Avoid_: 评委、评审员、投票表决

**校对评审**:
第四位评审：以登记册为底座做语义一致性审计（时间线、地点与行程、角色知识边界、物理状态、命名、伏笔对账、世界规则、章间因果——八区），查"错不错"，与三评审（查"好不好"）分工互补。

**评审台账**:
评审产物的台账层（评审/评审台账.md）：append-only 的唯一真相源——条目 ID（R{轮次}-{席}{序}）、裁决与理由、状态机流转、遗留总账（去向+触发时点）；跨轮/跨阶段消费方先读台账拿状态图，再按指针回快照取全文。

**评审快照**:
每轮每席评审报告的冻结全文（写定即永不修改，摘要冻结铁律的延伸）：校对席→评审/校对评审/{对象类型}_第{N}轮.md，三评审席→评审/三评审报告/{对象类型}_第{N}轮_{席位}.md；问题清单、席位特有产出、修复方向两侧方案、未检查项降级注只存于此层。

**引证验真**:
评审四席共用的纪律：每条意见必须附对象文件逐字引文，脚本核对引文是否真实存在（允许空格标点差异）；编造引证自动降权，累计两条标"可信度存疑"。评审被作者跳过时验真脚本仍常开（它是脚本不属可跳过范畴）。

**根因标注**:
评审报告为每条问题标注的病灶出处，作为修复路由：大纲档三选一（设定根源→改设定+登记册｜主线根源→改大纲结构区块｜规格根源→改基本规格走变更提案）；卷纲/章纲档相应扩展。

**弃书点预测**:
读者评审的席位特有产出：以目标读者画像体验式通读后，指出"预计读者会在第几卷因何弃书"的位置清单，与毒点扫描、追读力检查共同构成读者侧三件产出。

**标尺对照表**:
编辑评审的席位特有产出：对《参考标尺》逐项对照打 ✅达标/⚠️待校准/❌超标/不适用；待校准数值不计入问题计数，禁止作为判据引用。

**行文规格**:书项目独立文件（schema/行文规格模板.md，type: prose-spec）——"通不通"层默认：排版＋句级＋指称判据＋事实层（不可覆盖区）。优先级链：事实层＞文风基准＞行文规格＞通用手法。

**档位细则**:
代理任务书的变量部分：同一角色代理在不同审读对象（故事剧情/卷纲/章纲）下加载的判据与检查清单文件，一档一文件（tiers/{代理名}-{档位}.md），由调用契约的对象类型参数路由。任务书（角色常量：人格/纪律/报告格式）与档位细则（对象变量：方法论加载/清单/特有产出）分离，是"业务流程与方法论分离"在代理侧的同构复刻。

**修复分级**:
评审修复的两级执行纪律：点修复（单值/措辞/计数，同步点核销后直改）与面修复（人物动机/情节因果/设定规则等语义变化——先依登记册 ID 关联反查产出影响面清单，作者过目后逐项改，影响区纳入复评范围）。面修复=段内迷你变更提案，定稿后同类修改走完整变更提案。
_Avoid_: 改哪算哪、只见单点不见网

**修复支持三角**:
修复执行无解时的取材顺序：① 知识库方法论（评审指导意见的指路节）→ ② 本地参考（灵感库+拆书零件+参考作品骨架，永不含原文）→ ③ 采风兜底（researcher 网络检索，结果抽象化沉淀后再用）。评审指导意见可预标【待采风：查询词】，打磨轮内汇总去重、集中派一次。

**四理由测试**:
一个机制做成代理的立项门禁（代理设计规范 §1，九项目调研共识）：上下文隔离、并行、防自我合理化、成本分层——一条不占的降级为 persona 文件或脚本。

**横切机制**:
贯穿多个创作阶段、由宿主技能在自身流程内约定节点载入调用的能力组件（如三评审、采风检索），以参考文件而非独立技能的形式存在。
_Avoid_: 把横切机制做成独立技能（技能无法调用技能）

**采风检索**:
把网络当灵感库的实时检索机制，任务书：docs/design/agents/采风检索.md（researcher，无档位）。三源检索顺序：知识库（已有判据不重采，指路返回）→本地灵感库/挂账清单（去重合并）→网络兜底（**检索范围硬规则：只采国内源**，查询词一律中文，境外源记入"已排除"；通道调度按页面特征×信息量双维度：CDP 浏览器携登录态＞页面抓取＞搜索摘要，摘要路径可信度上限=孤证；联网增强技能如 web-access 为可选增强层非依赖）；触发源四入口（段2 备资料、段4/5 待采风标记盘点、评审修复【待采风】、拆书反面清单取证——第四入口产出直喂反面清单不走灵感库）；结果抽象化为零件卡，只写待裁决暂存，用户裁决后归档；六类（剧情结构/历史事实/人物原型/文化元素/影视动漫/现实生活）。
_Avoid_: 先上网后翻库、检索结果直接入正库

**模型口碑归纳**:
AI 凭训练语料记忆转述的读者社区批评（非实时检索、无 URL 可溯源、可能失真或过时）。允许作为线索记入反面清单，但必须标"待核实"（置信度 C），不得单独作为修复建议依据；经采风检索带来源核实后方可转正。
_Avoid_: 把口碑归纳当事实引用、无出处骂点

**章纲三约束**:
卷纲技能对三期章纲的全部出口，按章组给出的三列约束：节奏锚点（小高潮/铺垫/回血/切线/压放位）、信息预算（该章组读者应知/应疑/应忘＋伏笔操作＋情绪任务落点）、视角约束（POV 人物/知识边界对 known_by/禁入信息）。卷纲定稿时落盘 故事剧情/卷纲/三约束_第N卷.md，章纲每章先读所属章组。
_Avoid_: 卷纲写成可读故事文本（产物是约束不是内容）、绕过三约束直接写章纲

**章纲卡**:
abzu-draft 的章级规划产物（docs/design/draft/主设计.md §3）：大神细纲形态的显式化——核心=编号情节点 1-3 条（动作+目标+冲突结果+决定）+场景表（动机一句话）+信息预算执行+POV+章末双钩+跨章资产；不写对白和叙述；密度 1:5~1:6 只计创作区；章名写完正文再取。三约束的三列引用块在头部（数据源=三约束文件精排档位标记）。
_Avoid_: 散文式细纲、预写对白、按 1:3 密度做卡

**入戏段**:
正文四段式（校对→入戏→写作→回看）的第二段：大神写前仪式的显式化——画面预演（场景表画面化重述到"能看见"）＋情绪圆融两问（情绪链步骤闭合吗/每画面服务情绪吗）＋末读语态（动笔前最后读的必须是正文语态文字——AI 上下文工程件（oh-story 结尾切片的对应物），非大神仪式）。AI 味治本方案的灵魂段。

**轻确认**:
一行式确认（回"对"/"就按推荐"即算过门），可授权跳过（连写/连跑模式一次授权全程生效）；🔴 级问题项仍呈，不因授权跳过而静默。

**单元批评审**:
正文评审的分级裁定：脚本每章（断档/字数/禁入/章末写入，零 LLM）｜章组批=校对+读者（每单元：章级事实对账+毒点抽扫+连续读三章的追读体感）｜卷级批=四席全（卷末复盘前）。细则用现有档裁剪不另立。

**前卷根源**:
卷纲阶段根因标注的扩展值（在故事设定/主线/规格根源之外）：病在已定稿的前卷——修复走变更提案（影响面含前卷产物与登记册），禁止就地改前卷。

**采风站点经验卡**:
researcher 按域名积累的操作性经验（需登录/动态渲染/须辨原发/转载聚合勿引），存书项目 灵感库/_采风站点经验.md，通道调度优先按经验卡走；跨书通用，作者可手动提升到全局灵感库。

**零件卡**:
采风沉淀的最小单元：类别｜一句话｜层级（骨=套路/魂=原理）｜分级（原理级/套路级/经验级）｜反例（何时不可信，必填）｜来源溯源（站点+URL+日期，不存原文）｜可信度（已证实/孤证/推测）｜去向建议。抽象检验：卡内出现原作具体人名/地名/成句=抽象不足打回。

**沉淀**:
采风或拆解所得的抽象化零件，经用户裁决后归档入库的过程：跨书通用的进全局灵感库，书专属的进零件索引或转化进设定卡"现实依据栏"；不自动写入、须去重合并、永不存原文。

**待采风标记**:
并行思考中不中断检索、只插入【待采风】标记，一轮思考结束后汇总去重、集中检索，结果注入下一轮思考的机制。

**落地审查**:
文件落地后自动运行的轻量格式与跑偏检查：报告 + 建议 + 用户裁决，不自动修改；确定性部分（格式、引用、红线、视角）交给校验脚本。

**变更提案**:
下游阶段发现上游需修改时不直接改，先生成含影响面分析和 2-3 个方案的提案，交用户裁决后逐文件回改并重做一致性检查。

**ID 系统**:
跨文件引用实体的唯一标识（{前缀}{三位零填充序号}、无连字符，如 P001 人物、FS003 伏笔——唯一权威见模板统一规范 §二；V=境界/C=铁则/D=差异集候选，卷/章用自然键），分配后永不复用、永不更改；只有会被跨文件引用的实体才需要。

**嫁接改造**:
外部素材（灵感库零件/采风零件/参考骨架条目/作者口述）接入现有剧情的机制，任务书：docs/design/agents/嫁接改造.md（英文 id：fusion，无档位）。与产物"嫁接日志"同根——代理干嫁接、产出即日志。
_Avoid_: 融合（旧名，2026-10-01 改名）、融梗（版权风险词，边界见融合机制调研）五步：抽象素材→意图分析→找锚点→兼容性检查→出 2-3 个方案→用户裁决。意图是魂、机制是骨、表象是皮——魂保留（思想层可借）、骨可换（重设计而非翻译）、皮必换（表达层红线三件套：具体文字表达、独特情节链条、人物关系的独创组合方式）。锚点自足检验（拿走素材锚点仍有功能）防缝合怪；嫁接日志披露来源防"掩盖原作者"。
_Avoid_: 直接搬运、为素材开洞、缝合怪

**章纲三约束**:
节奏锚点（防提前写完）、信息预算（防提前透露）、视角约束（防上帝视角），由卷纲产出、章纲执行，写死在 SKILL.md 中。

**正文四段式**:
正文生产流程：校对（场景/人物/信息/视角/世界细节）→ 入戏（感官/情绪/认知）→ 写作（感官优先/对话代入/引用故事设定/信息控制）→ 回看（对照故事剧情/章纲/故事设定/衔接/节奏/视角）。

### 平台分发域

**技能（Skill）**:
一个含 `SKILL.md` 的目录，教会 agent 一套做事方法；遵循 agentskills 开放规范（目录名与 name 字段仅限小写字母、数字、连字符）。

**插件（Plugin）**:
Claude Code 的分发打包单位，可包含技能、命令、hook 等组件；Abzu 的分发载体。

**市场（Marketplace）**:
托管 `marketplace.json` 的 Git 仓库，用户从中安装与升级插件。

**单核双壳**:
架构原则——核心层（markdown 技能＋零依赖脚本＋纯文件产物）宿主无关，宿主适配层（壳）薄且可替换。现行单壳（Claude Code 插件）。
