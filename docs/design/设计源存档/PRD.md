> 性质：**骨架**。第 1–11 章为已定稿层（本项目多轮设计问答 + DeepSeek 讨论 + 两轮竞品调研的合并共识）；第 13 章为待商讨清单（文件层细节，逐项讨论后填充）。

## 1. 产品定位

- **一句话**：运行在 Claude Code 上的中文网文写作技能组插件——引导 AI 像人类作家一样思考，用确定性手段守住百万字连载的连贯性。
- **目标用户**：中文网文作者（Windows 为主，经 npx / Claude Code 生态进入，不假设装有 Python）。
- **差异化**（竞品调研结论，2026-09-25 补充修正）：同类项目已有三条路线——爆款方法论路线（Oh Story，约 7100 星）、问答体验路线（chinese-novelist-skill，约 3200 星）、**长篇一致性系统路线（webnovel-writer，约 7100 星：动笔前合同 + 写后事实入账 + 多维审查 + RAG 检索 + 可视化面板）**。第三条路线已被验证需求真实，但其写章流程是"一条龙自动跑完"的工程流水线，作者角色偏"监工"。Abzu 的差异化不在"也做一致性"，而在：**创作过程本身是思维引导（模拟作家网状思考，作者全程主导每一步、裁决一切），确定性机制做骨架**；另有方法论体系（业务流程与方法论分离、作者自带方法论）、融合代理、纯文件零依赖（不需要 Python 和检索 API）、跨工具可移植、MIT 协议。
- **解决的痛点**（按社区讨论热度从高到低；"AI 味"话题按需求剔除）：设定与人物前后矛盾、上下文窗口装不下全书、伏笔埋了不收、大纲执行跑偏、节奏失控注水、多角色声线趋同、视角越界（角色说出不该知道的信息）、修订引入新矛盾、作者需要人肉盯盘。

## 2. 核心设计哲学

1. **技能是思维引导器，不是执行器**（ADR-0001）：引导网状、并行、逐步收敛的思考（由模糊到清晰），强制追问元素之间的交叉关系，允许模糊、防止过早收敛，不按预设模板套写。
2. **业务流程与方法论分离**（ADR 待立）：流程管"怎么想"（节奏、顺序、并行、发散、收敛），方法论管"依据什么做"（标准、框架、专业度）。方法论是流程每一步强制加载的操作手册，不是可选参考书。混在一起的结局：要么流水线，要么瞎编。
3. **方法论与流程步骤绑定**：流程走到某一步，绑定它的方法论必须加载；不属于当前阶段、当前步骤的方法论不加载。例如：处于大纲阶段就只加载大纲阶段绑定的方法论，不碰卷纲的；细化到某一步 X，只加载 X 绑定的方法论 Y，且 Y 为必读。长方法论可拆成"必读核心 + 深读扩展"两截以控制 token 消耗。
4. **设定贯穿全程**：设定是持续演化的活内容。大纲=草创、卷纲=生长修正、章纲=细化、正文=精修补全，每个技能都承担设定维护职责；每次修改回写总设定文件夹，输出契约中含"设定变更"环节。
5. **用户手动调用、裁决一切**：技能只能由用户显式输入 `/abzu:技能名` 触发，技能之间不自动串联；"报告 + 建议 + 用户裁决"是所有机制的统一出口（评审、沉淀、变更、融合均如此）。
6. **软件管确定性，AI 管创造性**：格式、引用、红线、视角、字数等一切可机械校验的事交给脚本；语义判断交给 AI，且必须引用原文举证。
7. **明确严谨，杜绝歧义**：文件引用写相对路径、概念用词统一、判断条件写死；禁用"可能/也许/大概/适当/酌情"这类词；把 AI 当成执行力很强但不会猜心思的新人。
8. **意图是魂，机制是骨，表象是皮**：融合与跨题材迁移时，魂保留、骨可换、皮必换；抽象必须深到故事内核，规则层要重新设计而非直接翻译。
9. **物理切断抄袭路径**：参考作品原文只在拆书阶段被读取，此后任何技能不再读原文；本仓库永不分发任何受版权保护的内容。
10. **方法论自带分级与反例**（魔改自狗头军师项目）：每份方法论标注适用等级（如原理级/套路级/个人经验级）与"何时不可信"，防止 AI 滥用方法论。
11. **交互与知识库使用模式以狗头军师项目为母版魔改**：建档问卷、复述纠错、追问限额（全程最多追问 1-3 个"会改变结果"的问题）、强制区分"已定事实/合理推测/完全未知"、创作红线触发即切换提示流程、失败时诚实降级（明确说没找到，不编造补齐）。

### 3.3 技能安装位置与用户数据的边界

- 技能代码（skills/、sources/）随插件或 npx 更新；用户的书项目和灵感库永不被升级触碰。
- 写新书 = 新开一个文件夹；MVP 不做存量作品导入（`abzu-import` 列入远期）。

## 4. 技能设计

| 技能 | 职责 | 期 |
|---|---|---|
| `abzu-outline` | 全书大纲 + 设定草创 | 一 |
| `abzu-teardown` | 拆书：主要参考完整拆解（三层双向）→ 参考作品骨架/拆书笔记/反面清单；次要参考的零件提取【二期】 | 一（精简版） |
| `abzu-volume` | 卷纲 + 设定生长修正 + 产出章纲三约束（节奏锚点、信息预算、视角约束） | 二 |
| `abzu-draft` | 章纲 + 正文一体产出（内部流转，修订走变更提案在技能内一次完成） | 三 |

- 全部技能：只能由用户显式调用（Claude Code 上用 `disable-model-invocation: true` 硬性保证，其他工具靠 description 声明"仅供手动调用"作软性提示）；description 与正文全中文；目录名与 name 字段用英文（小写字母与连字符）。
- SKILL.md 为轻量入口：只放元数据区（frontmatter，即文件开头以 `---` 包住的配置段）、路由、红线、步骤索引和初始指引，详细内容放 references/。
- 流水线为骨架、允许从任意层切入；技能须能容错地使用不完整或格式不符的上游产物。
- 技能启动先读 项目基准/创作进度.md 定位现状（该读什么、该产出什么）。
- **关于"AI 味"**：不设独立的"去 AI 味"机制（替换 AI 常用词句属于治标，判定为浅薄路线，不做）；治本方案 = 正文四段式（校对→入戏→写作→回看）中"入戏"与"写作"环节的作家思维模拟。写后机械扫描（截断、流程词）可作为落地审查的可选规则【是否启用待商讨】。

## 5. 横切机制（由宿主技能在流程内的约定节点派出或执行）

| 机制 | 已定稿的不变量 | 细节归属 |
|---|---|---|
| 三评审 | 读者（好不好看）、作家（结构逻辑设定节奏）、编辑（市场卖点对标）三视角；各出一份报告、不投票；按序运行（作家→读者→编辑）；**任务书（角色常量）+ 档位细则（对象变量，一档一文件）**按审读对象切换，结构见[代理设计规范](./design/standards/代理设计规范.md)；正文是否纳入评审**待定** | 细则→§13 |
| 校对评审 | 第四位评审：以登记册为依据做语义一致性审计，查"对不对"（与三评审查"好不好"分工互补）。审计覆盖八个方面：时间线、地点与行程、角色知识边界（谁知道什么/隐瞒什么）、物理状态（伤势/持有物）、命名一致性、世界规则、伏笔的埋设与回收、章间因果关系。独立上下文运行，避免偏袒 | 清单→§13 |
| 采风检索 | 本地灵感库优先、网络兜底；带上下文检索；结果抽象化后再用；六类检索结果分别沉淀到对应位置；代理的核心设计在于：问什么、带回什么、怎么抽象、怎么判断好坏。**触发点：段2 研究准备、思考流【待采风】标记汇总、评审修复的指导意见【待采风】标记（打磨轮内集中派一次）、拆书反面清单取证（产出直喂反面清单，不走灵感库）** | 任务书→§13 |
| 待采风标记 | 思考过程中只插入【待采风】标记、不打断；一轮思考结束后汇总去重、集中检索；结果注入下一轮思考 | — |
| 融合 | 五步：抽象素材→意图分析→找锚点→兼容性检查→出 2-3 个方案→用户裁决（可能触发变更提案） | — |
| 落地审查 | 文件写入完成后自动运行、轻量；按产物类型分强度：规格类文件（基本规格/创作进度）=格式与完整性基本检查（脚本为主）；故事类产物（故事剧情/卷纲/章纲/正文）=基本检查 + 质量抽查。报告按严重度分级（阻断/警告/提示）。报告 + 建议 + 用户裁决，不自动修改 | 大纲档清单已内联 workflow-6 步2 ✅ |
| 变更提案 | 下游阶段发现上游需要修改时不直接改：生成"触发点 + 建议变更 + 影响面分析（依 ID 关联索引）+ 2-3 个方案"→ 用户裁决 → 逐文件回改 → 重做一致性检查 | 模板→§13 |
| 登记册 | 记录事实（注明谁知道）、伏笔（注明应回收的截止章节）、能力进阶（只进不退，防战力崩坏）、规则、时间线、命名，**只追加不修改**；ID 分配后永不复用；新实体入账前必须先与已有条目做名称与别名匹配（防同一人物多个名字、多个人物同名），匹配不上才新建 | 字段→§13 |
| 摘要冻结 | 各层摘要（章→卷→书）"写定即冻结"，旧摘要不随后续章节漂移 | 层级与文件位置→§13 |
| ID 系统 | 格式 {前缀}{三位零填充序号}、无连字符（P001）——P 人物/F 势力/L 地点/G 金手指/I 道具/E 事件/FS 伏笔/V 境界/C 铁则/D 差异集候选项；卷/章用自然键不拿 ID；一个实体可有多个别名但只有一个 ID；只有会被跨文件引用的实体才需要 | 唯一权威=模板统一规范 §二 ✅ |
| 设定注入 | 设定拆成条目，按关键词扫描当前上下文选择性地只注入被命中的设定（核心设定常驻）；中文没有空格分词，匹配须用包含式而非整词式，否则会漏检 | 挂载点→§13 |
| 相关旧章反查 | 写新章前，按伏笔、角色出场、状态变化、人物关系四个维度查找相关的已写章节（依据登记册中的出处记录做文本检索，不使用向量数据库） | 触发时机→§13 |
| 节奏断档红线 | 主线、感情线、世界观线三线跟踪：主线连续推进不超过 5 章、感情线断档不超过 10 章、世界观线断档不超过 15 章（默认值可调；借鉴 webnovel-writer 的三线节奏框架），由脚本按章统计即可校验 | 三线定义与阈值→§13 |
| 章末写入 | 每章完成后必须写入"下章计划 + 当前状态摘要"，对话记忆不跨章依赖 | — |
| 过程鲁棒性 | 长流程支持断点续跑（从可信断点继续，不重写已可信完成的产物）；关键产物自动备份（借鉴 webnovel-writer） | — |
| 写前门禁 | 没有章纲不许写正文。双层实现：SKILL.md 指令为基线（所有平台生效），Claude Code 的 hook 做机械拦截（增强层） | hook 候选点→§8 |
| 引证验真 | 评审每条意见必须附原文引证；脚本核对引证文字是否真实存在于原文（允许空格标点差异），编造引证自动降权 | — |
| 根因路由 | 评审报告将问题标注为"正文根源/卷纲根源/设定根源"，作为用户手动调用对应修订环节的路标 | — |
| 输出契约 | 每个技能的产物有固定结构（含"设定变更"环节），供校验脚本机械检查 | 各模板→§13 |

## 6. 代理阵容（8 个，单一源在 sources/agents/，分发到各技能）

> 子代理：由技能在流程内派出的专用代理，拥有独立上下文窗口。模型分层：给不同代理指定不同强弱的模型（Claude Code 专有配置，其他工具自动忽略）。

| 代理 | 职责 | 做成子代理的理由 | 模型分层 | 期 |
|---|---|---|---|---|
| 作家评审 | 结构/逻辑/故事设定/节奏（含三份阶段细则） | 独立上下文 | 强 | 一 |
| 读者评审 | 好不好看、想不想追（含三份阶段细则） | 独立上下文 | 强 | 一 |
| 编辑评审 | 卖点/对标/参考标尺匹配（含三份阶段细则） | 独立上下文 | 强 | 一 |
| 校对评审 | 依登记册做八方面一致性审计 | 防止评审偏袒 | 标准 | 一 |
| researcher | 采风检索 + 提炼 + 结构化写入文件 | 检索过程上下文杂乱需隔离 | 标准 | 一 |
| fusion | 素材融合五步出方案 | 重读分析需要聚焦 | 强 | 一 |
| advisor | 诊断现状，输出"当前最小高价值的一个下一步动作" | 思维引导的具体化 | 强 | 二 |
| explorer | 只读查询登记册/故事设定/进度 | 便宜模型跑高频查询、不污染主上下文 | 便宜 | 三 |

- 任务书**双模式**：有子代理能力的运行环境派独立代理；没有的环境由技能将同一份文件作为流程内角色说明载入——功能简化但不中断。**技能内嵌代理**（B 模式，不入横切阵容）：teardown-scanner（拆书扫描工）＋writer（写手，四段式段二三执行者）——均随所属技能分发。advisor 任务书【二期】、explorer【三期】未写（阵容欠账）。
- 评审执行纪律（借鉴 superpowers 与竞品）：写作方不许给自己指派评审；评审意见必须引证；多轮往复设熔断次数，超限由用户逐条裁决并记录存档。

## 7. 交互设计原则

- 书项目初始化 = 建档问卷（题材/篇幅/参考作品/创作红线/灵感库）→ 生成 项目基准/基本规格.md → 复述内容请用户纠错。
- 追问限额：全程最多追问 1-3 个"会改变结果"的问题。
- 思考中允许模糊，显式标记【待定】/【待采风】，防止过早收敛。
- 所有裁决点（评审结论、沉淀、变更、融合）默认不自动执行，一律等用户决定。
- **自治化例外表**（上条的例外边界——**新增例外必须入表**，未入表的"先斩后奏"一律违规）：
  | 例外 | 边界 |
  |---|---|
  | draft 回看 🔴 三类即时回改（禁入泄露/事实错/POV 漂） | 先改后报（🔴 本属"必须修"，回改后仍呈报告） |
  | 超字一次净删 | 净删零新语义（保情节点/事实/因果/情绪兑现/钩），复检仍超才呈作者 |
  | 入账对账幻觉剔除 | 不入册（防污染账本），报告留痕 |
- 每个技能结束输出面向作者的最终报告，固定四态之一：已完成 / 部分完成 / 需要你处理 / 未完成，附产物清单、问题与下一步建议（借鉴 webnovel-writer）。

## 8. Hook 增强层（Claude Code 专有，可选，不阻塞主线）

> hook（钩子）：Claude Code 插件的机制，可在特定时机（会话开始、写文件前等）自动执行脚本。基线功能不依赖 hook。

**终版清单（2026-09-29 裁定——判据：沙盘实证"提示层守不住"或"模型自检盲区"者必须做）**：

| # | Hook | 触发/机制 | 级别 | 依据 |
|---|---|---|---|---|
| M1 | 写前门禁 | PreToolUse·Write 正文文件→验章纲卡在位→拒绝 | **阻断** | 提示层疲劳必失守（27% 违纪实证）+PRD 双层设计 |
