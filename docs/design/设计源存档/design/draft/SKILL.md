> 版本 v1.0 ｜ 2026-09-29 ｜ 设计源：skills/abzu-draft/（三期）｜ 主设计：[主设计.md](主设计.md)（章纲卡 schema/四段式/契约/接口走查——不重复）
> 本文件：入口路由＋全局规则；流程文件=同目录 章0-章循环.md、批1-单元批与修订.md

## 定位

一章一轮回：章纲卡（三约束的兑现）→ 四段式正文（校对→**入戏**→写作→回看）→ 章末写入→登记册入账；单元（章组）边界做批量动作（缓冲检查/批评审/断档统计）。

## 路由表

| 进场状态 | 去向 |
|---|---|
| 创作进度断点=`draft·第{N}章·段{X}`（受控值表——schema/创作进度模板.md；X∈一/二/三/四/写入/入账） | 直入该章该段续跑 |
| 断点=第N卷卷纲定稿 | 章0（第N卷第1章）——首章先读三约束+精排区首组 |

| 精排区余量<3 章 | 单元批提示→引导重入卷纲滚动细化（技能不自动串联） |
| 修订请求（作者指出问题） | 批1 修订通道 |

## 全局规则

继承大纲 SKILL 全部（1-15，含红线触发切换与作者口径契约）＋卷纲 SKILL 13-21b（正典优先/欠账必清/连跑/灵感库入口/暂存/崩卷预案/开卷判定等），另加：

22. **写前门禁**：无章纲卡不写正文——段三启动前校验卡在位（指令层）；脚本层落地审查同查（双层）
23. **不回改文化**：段四是检查台不是改稿台——🔴（禁入泄露/事实错/POV 漂）才即时回改；🟡 记台账走修订通道；"改到满意"是修订通道的事不是回看段的事
24. **末读语态**：段三动笔前，上下文里最后读入的必须是正文语态文字（上章末两段），不是故事剧情/章纲/登记册/方法论
25. **AI 特有件自觉**：信息预算执行/章末写入/相关旧章反查/**动作节点预标注**是补 AI 短板的发明（无大神先例；动作节点预标注——AI 不会自然想起设定，须在场景表预标注该场景动用哪些设定条目）——好用但不神圣，实测碍事就降级（降级时"核心情绪前→后"写回章纲卡作补偿位）
26. **手改正文保护**（wnw 吸收）：断点续跑时若正文与章末写入登记不符（作者手改过），必须停下用有限选项询问（沿用当前正文/重新起草/只看状态）——不得覆盖作者手改
27. **连写轮上限**（oh-story 吸收）：连写模式每轮 ≤3-5 章，到点收尾汇报（含缓冲余量与台账欠账），不因还有细纲续写
0. **交互形式按《交互统一标准》五级选型**（见 references/interaction-protocol.md；2026-10-01）：建档门四支/出带三岔 L3 弹窗带推荐、挑满意段 L2、章纲卡过目轻确认
27b. **作者口径契约**（同大纲 SKILL 规则 15／拆书 SKILL §七）：面向作者说书不说系统——机制编号必须带人话名（「退婚当众打脸」（EM-003）式）、工程细节最多末行一注、裁决选项用人话呈报

## 红线

1. 原文永不读；拆书产物只到分卷拆解层
2. 禁入信息不泄（known_by 对表——校对段建清单、回看段复查）
3. 登记册 formal 行/已发正文的修改走修订通道（变更提案式一次完成）
4. 章纲卡不写对白和叙述（大神边界）；密度 1:5~1:6
