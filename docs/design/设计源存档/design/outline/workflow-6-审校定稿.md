## 步 3 校对评审

**派出**（子代理或 persona，设计源：[docs/design/agents/校对评审.md](../agents/校对评审.md)，遵循[代理设计规范](../standards/代理设计规范.md)）：

- 传入六参数：对象类型=outline、对象文件=故事剧情/大纲/大纲_定稿候选.md、轮次、上轮报告+本席裁决切片（轮次>1）、判据资产路径（本席为空）、细则文件路径
- **台账产生步**：首次落盘前初始化 `评审/评审台账.md`（frontmatter type: review-ledger）；每次快照落盘后由宿主建台账条目（ID 推导 R{轮}-{席}{序}，状态=新发）——打磨轮裁决/修复/复评全部依赖台账条目存在
- 代理自走：读任务书 → 按路由读大纲档细则（八区清单）→ 依登记册审计 → return 报告
- 复评模式见任务书 §0.1（回归表+修复影响区，不全量重跑）
- **引证验真常开**（脚本前置，非可跳过范畴）：报告文本先验真标注再落盘；验真为列感知（引证列↔对象+登记册+规格，判据列↔知识库+标尺）
- 落盘 `评审/校对评审/outline_第{N}轮.md`（每轮必落，零例外）

## 步 5 打磨轮

**裁决批量通道**（裁决权不变，密度可调——作者三选）：🔴全修（🔴 必修照修，🟡 按推荐处置一次过）／🟡全记（全部记台账走后续通道，本轮只修🔴）／逐条过（默认）。批量档下裁决理由仍逐条记台账。

**循环控制**（机械执行）：

```
轮次 = 1
while 作者不满意 and 轮次 ≤ 3:
    if 轮次 == 1:
        执行：全量审查（步 2+3+4 全跑）
        裁决：作者按台账逐条裁决（🔴必修 / 🟡作者裁决 / 🔵记录）——裁决与理由记台账
        修复：先读 §8.1（改稿怎么改）核心卡——从整体到局部，禁上来改句子；
             按台账修复落点执行：点修复直改（同步点逐位核销）；
             面修复（≥2 实体 ID 或设定根源语义变化）先出影响面清单（登记册 ID 关联反查）
             → 作者过目 → 逐项改 → 影响区记入复评范围；
             意见带【待采风】或方法论/本地无解 → 汇总去重，本轮集中派 researcher 一次，
             结果抽象化后注入修复（🔴 必修项不依赖采风）
        台账：状态流转（新发→已裁决→已修）
        保存：大纲_v{轮次}.md（头注版本链+frontmatter 三处版本身份同步）
    else:
        执行：只跑上一轮发现问题的评审（复评传该席上轮报告+裁决切片；复评=回归+修复影响区）
        修复：同上
        保存：大纲_v{轮次}.md（版本身份同步）
    轮次 += 1

if 轮次 > 3:
    熔断 → 逐条人工裁决落档（台账状态=已裁决·人工）
```

## 步 6 定稿
**呈现**：过目级——定稿候选全文入口+80/20 留白项列表；评审快照与台账知悉级。

**机械操作**：
1. `故事剧情/大纲/大纲_定稿.md` 落盘（15 区块+镜像附表+终稿保护声明+审校记录附录）
2. 登记册转正式态（标 formal，只追加）＋**设定件同步翻转**：世界观四件与人物卡 status draft→active（与登记册 formal 同点——设定件 status 至此有消费者，2026-10-01）
2b. **归档三件**（2026-09-29 审查补）：建 `归档/` 目录（首次）→ ①项目基准/差异集.md 标"已完成使命"后移入 归档/ ②定稿前的旧版本文件（故事剧情/大纲/大纲_定稿候选.md、v1…v{N-1}）移入 归档/ ③问作者：旧轮评审快照是否随归档（默认保留在 评审/ 作为审计证据，作者可选归档）——拆书 _teardown_cache 清理归拆书流程自己的收尾选项，此处不动
3. 80/20 留白区过目："这{N}项留给读者反馈后调整——确认？"
4. **终稿保护生效**："从现在起本技能只可建议不可直接改稿。任何修改走变更提案。"
5. 待验证清单移交（→ 正文阶段）
6. `项目基准/创作进度.md` 终更：断点写终态 `outline·完成`（受控值——schema/创作进度模板.md；卷纲技能进场读此断点直入卷0）（打样P1·2026-10-02 修复）

**作者可跳过步 3-5**：明示跳过 → 跳过原因记创作进度 → 直接定稿
