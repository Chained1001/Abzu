# 变更提案模板

> 版本 v1.0 ｜ 2026-09-29 ｜ 来源：全面审查补设计件 C4（终稿保护一生效即被三处引用却无设计——PRD §5 不变量的落地模板）
> 性质：下游阶段发现上游需修改时的**唯一合法通道**——不直接改已冻结产物；报告+建议+作者裁决（全项目统一出口）

## 触发条件

| 场景 | 例 |
|---|---|
| 终稿保护生效后改定稿产物 | 段6 后要改大纲区块/登记册既有行/基本规格终定栏 |
| 锁定参数变动 | 单章字数档变动（登记册 timeline 全列重算） |
| 下游发现上游缺陷 | 故事剧情/卷纲/正文阶段发现大纲级矛盾（评审台账根因=规格/设定/主线根源的跨阶段流转） |

## 文件与编号

- 提案文件 `项目基准/变更提案_{N}.md`：裁决前活跃态在 项目基准/；**执行完毕移入 归档/变更提案/**（终态；2026-10-01 目录重组裁定）
- 编号：`CP{N}`（台账 ID；与文件名 {N} 一致——登记于创作进度·变更历史；不复用）——CP 前缀待并入模板统一规范 §二前缀表（实现期一并）
- 创作进度·变更历史同步记一行：日期｜CP 号｜影响范围｜裁决

## 模板

```markdown
---
id: cp-{顺序号}
title: 变更提案 CP{顺序号}
type: change-proposal
status: draft → executed（执行后）/ rejected（驳回）
version: 1
created: {YYYY-MM-DD}
---

# 变更提案 CP{顺序号}

## 1 触发点
- 发现人/环节：{哪个技能哪一步/哪位评审（台账 ID R{轮}-{席}{序}）}
- 现状引文：「{冻结产物的原文引文 ≤50 字}」＋ 文件与位置
- 问题一句话：{改不了会怎样}

## 2 建议变更（2-3 案，每案独立可执行）
| 案 | 改动内容（逐文件逐条目） | 代价 |
|---|---|---|
| A | {文件 X 的条目 Y 从 … 改为 …} | {字数/结构/伏笔账影响} |
| B | … | … |

## 3 影响面分析（依 ID 关联索引反查——机械，脚本可做）
| 受影响对象 | 类型 | 关联依据 |
|---|---|---|
| {P001/FS003/区块07 第3卷/卷纲·第3卷} | 实体/伏笔/区块/下游产物 | {登记册挂靠关系/引用扫描结果} |

连带义务清单：登记册需追加更正记录 {N} 条｜下游阶段通知 {哪些}｜重算项 {timeline/预算表}｜复评范围 {席位+区块}

## 4 作者裁决
- 选案：{A/B/驳回/搁置}｜裁决理由：{必填——入评审台账/创作进度存档}
- 裁决时间：{YYYY-MM-DD}

## 5 执行清单（裁决"执行"后填写，逐项打钩）
- [ ] 逐文件回改（按选案）
- [ ] 同步点逐位核销（同打磨轮修复纪律）
- [ ] 登记册更正记录追加（触及登记册时：日期｜CP号｜条目｜更正）
- [ ] 一致性重检（影响面清单全项；复评派受影响席位）
- [ ] 版本身份同步（产物改名/晋级时三处同步）
- [ ] 移入 归档/变更提案/，status: executed
```

## 纪律

1. 驳回的提案**不删**（status: rejected 留档——"为什么当初不改"与裁决理由同等值钱）
2. 影响面分析是机械步骤：优先脚本（ID 关联索引扫描），无脚本时按登记册挂靠列人工反查并在提案中注明"人工反查"
3. 一个提案只管一个触发点——多触发点拆多案，不合并执行
