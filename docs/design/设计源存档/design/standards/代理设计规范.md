## 1. 立项门禁：四理由测试

一个机制要不要做成代理，只看四个理由（调研元模式 #4，九项目共识）：

| # | 理由 | 一句话 |
|---|---|---|
| 1 | 上下文隔离 | 过程噪声不进主上下文 |
| 2 | 并行 | 多席同时跑（一期预留未用） |
| 3 | 防自我合理化 | 写作方不许给自己当评审 |
| 4 | 成本分层 | 贵模型只花在语义判断，机械核对给便宜档 |

**一条都不占的，降级为 persona 文件或脚本**（能脚本的绝不给 LLM——story-skills 原则，亦即本项目设计哲学第 6 条）。

8 个代理过门禁记录（对应 PRD §6 阵容）：

| 代理 | 1 隔离 | 3 防自辩 | 4 分层 | 结论 |
|---|---|---|---|---|
| 作家/读者/编辑评审 | ✓ | ✓ | ✓ 强档 | 代理 |
| 校对评审 | ✓ | ✓ | ✓ 标准档 | 代理 |
| researcher | ✓ 检索噪声隔离 | — | ✓ 标准档 | 代理 |
| fusion（嫁接改造） | ✓ 重读聚焦 | — | ✓ 强档 | 代理 |
| advisor | ✓ 诊断隔离 | — | ✓ 强档 | 代理 |
| explorer | ✓ 查询保洁 | — | ✓ 便宜档 | 代理 |

## 2. 文件架构：任务书（常量）+ 档位细则（变量）

**一个代理 = 一个角色 = 一份任务书。角色不随审读对象变——作家评审审大纲与审章纲是同一个作家。**

- 对象差异（故事剧情/卷纲/章纲）全部放档位细则文件，**一档一文件**。
- 这是"业务流程与方法论分离"在代理侧的同构复刻：任务书管**怎么审**（角色、纪律、格式），细则管**审什么**（判据、清单）。
- 反面方案否决记录：
  - ❌ 角色×档位拆成 12 个代理——persona 重复维护、插件膨胀、"四席互不通气"的设计被文件边界打散
  - ❌ 三档细则内联一份任务书——随档位增长文件膨胀（子代理 system prompt 变贵），二三期改细则要动稳定核心

```
sources/agents/
├── proofreader.md            # 任务书（常量）
├── writer-reviewer.md
├── reader-reviewer.md
├── editor-reviewer.md
├── researcher.md  fusion.md（嫁接改造） advisor.md  explorer.md  写手.md  拆书扫描工.md
└── tiers/                    # 档位细则（变量）
    ├── proofreader-outline.md      ← 一期
    ├── proofreader-volume.md       ← 二期
    ├── proofreader-chapter.md      ← 三期
    └── ……（每代理 ×3 档）
```

好处：二三期加档=加文件不动核心；任务书体积恒定；细则独立版本化；分发脚本按技能消费的档位裁剪分发（如 abzu-outline 只带 \*-outline 细则）。

设计期镜像：docs/design/agents/{角色中文名}.md + docs/design/agents/细则/{角色中文名}-{档位}档.md，落仓时按 §6 映射表转英文名。

## 3. 任务书统一骨架（六节）

| 节 | 内容 | 性质 |
|---|---|---|
| 0 调用契约 | 入参表（§4.1）+ 档位路由表（对象类型→细则文件） | 常量（路由表可增行） |
| 1 角色定位 | 一句话人格｜判据来源｜与其他代理的边界 | 常量 |
| 2 输入清单 | 基础输入（各档通用）+ 隔离纪律；档位增量指向细则 | 常量 |
| 3 引证纪律 | 逐字执行条款（评审四席同文） | 常量 |
| 4 报告格式 | 骨架 + 问题清单固定列 + 落盘路径说明；席位特有区形态在细则 | 常量骨架 |
| 5 禁止事项 | 越界/无判据/读他席/改稿/写文件 | 常量 |
| 6 插件落地 | 文件名/description/model/tools/双模式 | 常量 |

## 4. 交互契约（输入/输出标准）

### 4.1 输入：调用契约六参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 对象类型 | outline / volume / chapter | 路由档位细则 |
| 对象文件 | 绝对路径 | 审读对象，一个文件 |
| 轮次 | ≥1 | 1=首评；>1=复评 |
| 上轮报告 | 路径或空 | **轮次>1 必传，只传本席上一轮自己的报告**（复评聚焦回归检查）；传他席报告=违纪 |
| 判据资产路径 | 目录/文件路径 | 知识库目录＋预置标尺路径——由宿主传入，任务书不硬编码（沙盘实测：硬编码路径与版本号均会失准）；节号→KB 文件映射先读 0B_节级索引.yaml |
| 细则文件路径 | 绝对路径 | 当档细则的绝对路径——子代理 cwd=书项目，任务书内的相对路由无法解析，必须由宿主传入（沙盘实测缺口） |

规则：
- 宿主**只传参数，不做对话叙述**——代理的判断全部来自文件与判据，不来自宿主转述（防宿主观点渗漏；沙盘曾出现宿主口述裁决结果的违纪，明令禁止——裁决结果走台账切片）
- 代理拿到参数后自走流程：按路由读本档细则 → 按隔离纪律读输入 → 检查 → 产出报告

### 4.2 输出：唯一产物 = 报告全文

- 代理 return 报告全文（markdown），**不写任何文件**（tools 只读）
- 引证一律用**「」包裹**——这是引证验真脚本的提取锚点；判据引用用 §节号 / 标尺行名 / 登记册条目 ID
- 报告骨架与问题清单列固定（§3），脚本按列解析

### 4.3 宿主管线（验真在落盘前）

```
派出（六参数）→ 代理产出报告文本
→ 引证验真脚本：「」内文字 ↔ 对象文件/登记册 比对（允许空格标点差异）
→ 脚本标注：验过条目标 ✓；引文不存在 → 该条降 🔵 并标「引证不实」；
  同报告累计 2 条 → 报告头标「可信度存疑」
→ 宿主落盘（两目录方案，唯一口径）：校对席→`评审/校对评审/{对象类型}_第{N}轮.md`；三评审席→`评审/三评审报告/{对象类型}_第{N}轮_{席位}.md`
→ 四席汇总表 → 作者逐条裁决（🔴 必修 / 🟡 裁决 / 🔵 记录）
```

**作者永远看不到未验真的报告。**

### 4.4 增益-成本账（这套契约为什么值得）

增益：

1. 独立上下文防自我合理化——long-novel-writer 明言、superpowers 铁律（执行者禁止自建评审）
2. 模型分层——机械核对（校对/查询）不烧强档
3. 主创作上下文不被评审噪声污染——评审对话不进创作会话
4. 报告可存档、可复评、可熔断——打磨轮"只跑有问题的席"完全依赖报告结构化
5. 验真前置——编造引证在作者眼前自动降权（QianBi 机制）

成本与对冲：

| 成本 | 对冲 |
|---|---|
| 每席重读输入（token 重复） | 输入最小化（隔离纪律本身就是 token 纪律）+ 方法论只读核心卡 + 复评只跑有问题的席 |
| 多代理编排复杂度 | 宿主管线固定（4.3 一条道），无自由调度 |
| 细则文件数量多 | 单一源 + 分发脚本按档裁剪 + CI 校验副本一致（PRD §10） |

### 4.5 效能与成本（沙盘实测，2026-09-28）

test2-7 大纲档单次全评实测：校对 20 万 tokens（标准档）｜作家 61 万（15+1 节核心卡逐维加载）｜读者 19 万｜编辑 58 万（含标尺 28 行逐项对照）——四席合计约 158 万 tokens/轮；复评（校对单席回归+全量八区）30 万。结论与规则：

1. **评审是里程碑成本不是日常成本**——大纲档全评只在定稿打磨轮发生（≤3 轮），不是每章开销；预算按里程碑报
2. **席位并行**（已是默认：四席独立上下文同时派出）
3. **复评瘦身**：复评=上轮问题回归 + 修复影响区复查，**不重跑全量清单**（沙盘第2轮全量八区多花约 1/3 tokens，无新发现增量）
4. **模型分层**：校对=标准档（实测判据全在登记册，不需要强档）
5. **方法论装载上限**：单席单档核心卡 ≤18 节（2026-09-29 由 16 上调——作家席实数 17 节）；细则引用的节必须入装载清单（CI 检查，防"判据被引用但不可达"）
6. **章纲档分片**：登记册随章膨胀，章纲档按"相关旧章反查"结果分片审计，禁止全册重读
7. **验真零 LLM**：引证验真是 Node 脚本，无 token 成本

## 5. 隔离纪律标准（全部代理通用）

三条红线：

1. **不读创作过程文件**（创作进度/待改清单/嫁接日志）——过程自述污染判断
2. **不读其他代理的报告**——各席独立出具、互不通气（复评例外仅限本席上轮报告，见 4.1）
3. **不读超出输入清单的文件**——需要什么在任务书申报，没申报就不读

例外申报制：某档确需增量输入（如章纲档校对评审需要相关旧章反查结果），在该档细则 §2 申报并写明用途。

第四条（对象引用文件，沙盘新增）：对象文件直接引用的证据文件（原创性声明、冻结的嫁接日志、拆书三件套）默认**仍不读**——相关断言只做对象内部互证，报告注明"内部互证降级"；确需原文核验的，在细则输入增量中申报为白名单文件。原理：隔离纪律的保护对象是"判断独立性"，白名单文件属证据而非过程自述，但开口必须显式。

## 6. 评审方法论三层（沙盘补立）

评审"用方法论"分三层，缺一层评审就退化：

| 层 | 回答 | 载体 | 现状 |
|---|---|---|---|
| **判据层**（审什么标准） | 依据什么说不好 | KB 各节核心卡（作家 17/读者 9/编辑 5 节）＋标尺＋登记册 | ✅ 已绑各细则 §1 |
| **技法层**（怎么审） | 按什么顺序和方法审 | §8.2 自检四型（作家总纲：从整体到局部）｜§8.5 挨个过+情绪亏损本质（读者）｜标尺逐行对照法（编辑）｜八区序贯+真矛盾vs故意手法（校对：先对照反转清单排除故意手法，再立冲突） | ✅ 内嵌各任务书/细则 |
| **修复层**（怎么改） | 改的时候遵循什么 | §8.1 改稿怎么改（从整体到局部，禁上来改句子）——**绑修复执行步**（workflow-6 步5）；修复分级（点修复直改/面修复先影响面清单）；无解时修复支持三角：方法论→本地灵感库→采风兜底（researcher）。评审报告只指认不代改 | ✅ 本版补立 |

校对评审不绑 KB 判据是**有意设计**：登记册即其判据（这也是它能跑标准档的原因）；其技法层八区序贯写在细则，真矛盾vs故意手法从调研（Claude-Code-Novel-Writer 的 continuity-editor）吸收。

## 7. 命名与模型分层

- 任务书英文小写连字符：proofreader / writer-reviewer / reader-reviewer / editor-reviewer / researcher / fusion / advisor / explorer；description 与正文全中文（PRD §4 约定）
- 细则文件 = `{代理名}-{档位}.md`（proofreader-outline.md；档位词 outline/volume/chapter）
- 模型分层（PRD §6）：作家/读者/编辑评审、fusion、advisor = 强档；校对评审、researcher = 标准档；explorer = 便宜档

## 8. 双模式（ADR-0002）

- 子代理环境：插件 `agents/` 原生派出，任务书即 system prompt
- 无子代理环境：宿主技能将**任务书 + 对应档细则**一并作为流程内 persona 载入（模型分层失效，功能不中断）
- 细则随技能分发至 references/agents/tiers/，与任务书同批次
