## 一、三个正交轴 + 一个字段（核心原则）

全项目的编号收敛为三个互相独立的维度，外加一个元数据字段：

| 轴 | 格式 | 表达什么 | 可否变更 | 示例 |
|---|---|---|---|---|
| **位置轴** | `1` / `1.1` / `1.1.1` | 章节层级、阅读顺序 | ✅ 可重排 | 大纲的区块排序 |
| **身份轴** | `P001` / `FS003` / `L002` | 实体唯一标识 | ❌ 永不变更、永不复用 | 人物、伏笔、地点 |
| **时间轴** | `version: 1.0.0` | 文件版本 | ✅ 递增 | 大纲_草稿 → v1 → 定稿 |
| **状态字段** | `status: draft` | 文件生命周期 | ✅ 流转 | draft → active → retired |

**禁止混用**：位置编号不当 ID 用（重排后失效）；ID 不当位置编号用（不可重排）。

## 二、实体 ID 标准（身份轴）

### 前缀表

| 前缀 | 物类 | 示例 | 容量 |
|---|---|---|---|
| P | 人物 | P001（顾拾） | 999 |
| F | 势力/门派 | F001（青云宗） | 999 |
| L | 地点/地图 | L001（青云山） | 999 |
| G | 金手指/功法 | G001（长生不灭） | 999 |
| I | 道具/法宝 | I001（扫帚） | 999 |
| FS | 伏笔 | FS001（名字之谜） | 999 |
| E | 事件 | E001（宗门大典） | 999 |
| V | 境界/阶位 | V001（练气） | 999 |
| C | 铁则/规则 | C001（寿元即境界） | 999 |
| D | 差异集候选项（非登记册实体，仅差异集内使用） | D001（辈分碾压） | 999 |

### ID 规则

1. 格式：`{前缀}{三位零填充序号}`，如 `P001`——无连字符、无空格
2. 一经分配**永不变更、永不复用**（ADR 铁律）
3. 新建前**必须先消歧**（与已有条目+别名池匹配）
4. 别名/绰号/字号登记在 naming 册的 aliases 列，不改 ID
5. 废弃条目不删除，改 `status: deprecated`——保证历史引用可解释
6. 同一前缀内位数统一（不用 P01 和 P001 混存）

### 废弃的旧格式

| 旧格式 | 废弃原因 | 替代 |
|---|---|---|
| P01（两位） | 与三位不统一 | 全部升为 P001 |
| F1（伏笔一位） | 与登记册 P001 不统一 | 全部升为 FS001 |
| §1.1 | Markdown 锚点/中文输入不友好 | 直接写 1.1 |
| ①②③ | ⑬ 后字体不稳；不可引用；AI 解析差 | 有序列表 1. 2. 3. 或（1）（2）（3） |
| 一、二、三 | 模板结构层不用中文数字 | 阿拉伯数字 1. 2. 3. |

## 三、YAML Front Matter（文件头标准）

每个书项目模板文件的第一段必须是 YAML front matter（两条 `---` 包围）：

```yaml
---
id: progress                # 文件类型 ID（非实体 ID），全项目唯一
title: 创作进度              # 显示名
type: progress              # 受控词表中的类型
status: active              # 状态机字段
version: 3                  # 整数递增
created: 2026-09-28         # YYYY-MM-DD
updated: 2026-09-28         # 每次实质修改更新
tags: []                    # 一维列表
aliases: []                 # 别名（改名后旧 title 入此）
---
```

### Front matter 规则

1. 必须位于**文件第一行**，两条 `---` 包围
2. 文件保存为 **UTF-8 无 BOM**（Windows 特别注意）
3. 字段名全小写、不重复、不含特殊字符
4. **只用扁平 key:value 或一维列表**，禁止嵌套对象与多行字符串
5. 日期一律 `YYYY-MM-DD`（ISO 格式）
6. `type` 和 `status` 的取值来自受控词表（见下），禁止同义词混用

### type 受控词表

| 值 | 含义 | 示例文件 |
|---|---|---|
| progress | 创作进度 | 项目基准/创作进度.md |

| reference-relation | 关系网与感情线 | 关系网与感情线.md（2026-10-01 补） |
| review | 复盘 | 复盘_第{N}卷.md |

| progress（复用） | 拆书进度／灵感库待裁决与站点经验 | 拆书进度.md／灵感库/_待裁决_*.md 等（轻量件豁免 frontmatter 可选） |

### status 受控词表（文档生命周期五态）

```
draft（草稿）→ review（审校中）→ active（生效，正典）
                                    ↓
                          retired（弃用，保留原文）
                                    ↓
                          superseded（被替代，指向新 id）
```

| 值 | 含义 | 规则 |
|---|---|---|
| draft | 写作中 | 随时可改 |
| review | 审校中 | 打磨轮/评审阶段 |
| active | 生效 | 正典（canon）——写作时以此为准 |
| retired | 弃用 | 保留原文不删，状态改 retired |
| superseded | 被替代 | 必填 `superseded_by` 指向新文件 id |
| candidate | 组装候选 | 大纲类专用：段6 步1 组装产物（评审对象） |
| final | 规格终定 | 基本规格专用：段6 步1 终定复核后——此后变更走变更提案 |
| formal | 账本转正 | 登记册专用：段6 步6 转正——与终稿保护联动，此后只追加 |

> candidate/final/formal（2026-09-29 收编入表）为文件型扩展态，脚本校验按"等价 active/review"处理。

**铁律**：retired/superseded 文件**永不删除**；status: active 的设定即"正典"。

## 五、交叉引用格式

| 引用类型 | 格式 | 示例 |
|---|---|---|
| 文件级 | `文件名.md` | `人物卡·顾拾.md` |
| 锚点级 | `文件名.md##标题文字` | `力量体系.md##境界表` |
| 实体级 | `ID` | `P001`、`FS003`（全局唯一，无需路径） |
| 实体+显示 | `「显示名」` | `「顾拾」` |

### 引用规则

1. **引用绑 ID 不绑标题**——实体改名后引用不断（DOI 思路）
2. 同一文件内不重复引用同一目标（Google 规则）
3. 标题锚点是脆弱的（改标题即断链）——关键锚点用显式 HTML 锚 `<a id="anchor-name"></a>`
4. CI 校验：断链检查脚本扫描全部引用→验证目标存在

## 六、空值约定（表格单元格）

| 写法 | 含义 | 何时用 |
|---|---|---|
| `待补` | 应有而未填 | 数据缺失，等待填充 |
| `不适用` | 该属性对此实体无意义 | 字段不适用于此行 |
| `无` | 明确为空/零 | 有意为之的空值 |

**禁止**：留空白单元格、写 NA/N/A/—。

## 七、表格规范

1. 适用判据：多实体 × 多属性需横向对比 → 表格；层级/短列表 → 列表；术语表 → **加粗术语**+缩进说明
2. **ID 列放最前、状态列放最后**（便于扫描）
3. 单表 ≤30 行；超限拆表（按卷/按章分册）或用 `<details><summary>` 折叠（折叠内首尾各留一空行）
4. 登记册等持续增长的表：数据本体可外置为独立文件，Markdown 表格由脚本从数据文件生成

## 八、中文排版规范

执行《中文文案排版指北》（sparanoid）：

1. **中英文之间加一个半角空格**（盘古之白）："在 Claude Code 上"
2. **中文与数字之间加空格**："花了 5000 元"；数字与单位之间加空格："10 Gbps"（例外：度数/百分比不加）
3. **全角标点与其他字符之间不加空格**："iPhone，好开心！"
4. 中文句内用**全角标点**，数字用**半角**
5. **不重复使用标点**（可"？！"不可"？?！！"）
6. 专有名词大小写正确（GitHub 非 github；TypeScript 非 Ts）
7. 引号统一用中文引号""（简体中文场景）

### 标题层级与中文序号

- Markdown `#`/`##`/`###` 承担结构层级——**#** = 文件名，**##** = 主区块，**###** = 子项，**####** = 最深层（禁止更深层）
- 正文中需要人为分层时按 GB/T 9704 习惯："一、→（一）→ 1. →（1）"——**仅用于有序列表内部**，不与 # 层级混用
- **不跳级**（# 直接到 ###）；**无孤立编号**（只有 1.1 没有 1.2 就不该设 1.1）

## 九、文件命名约定

| 规则 | 正确 | 错误 |
|---|---|---|
| 用中文间隔号·分隔类型与名称 | 人物卡·顾拾.md | 人物卡-顾拾.md / 人物卡_顾拾.md |
| 版本后缀用下划线+阿拉伯 | 故事剧情/大纲/大纲_v1.md / 故事剧情/大纲/大纲_定稿.md | 大纲v1.md / 大纲-定稿.md |
| 编号文件用零填充 | 章纲_第001章.md | 章纲_第1章.md |
| **卷号不补零**（第{N}卷——与现有产物一致；仅章号零填充三位） | 卷纲_第1卷.md / 三约束_第1卷.md | 卷纲_第01卷.md |
| **正文初稿带 `_初稿` 后缀**（章0 步4 入账后去后缀=晋级步） | 正文_第001章_初稿.md → 正文_第001章.md | 第1章_初稿.md |
| 登记册用英文名（机器友好） | facts.md / promises.md | 事实.md / 伏笔.md |
| 预置资产用中文名（人读友好） | 参考标尺.md / 命名规则.md | ruler.md / naming.md |

## 十、列表格式

| 场景 | 用什么 | 不用什么 |
|---|---|---|
| 有序（步骤/阶段） | `1.` `2.` `3.`（Markdown 自动编号） | 手写"步1"、①②③ |
| 无序（并列/要点） | `-`（连字符） | `*` |
| 候选项（选择题） | `A` / `B` / `C` 或 `候选 1/2/3` | 混用 |
| 方法论路径（知识库内） | 保留知识库自身格式 | 不由模板规范管 |

## 十一、模板文件检查清单

新模板创建时逐项检查：

**Front matter**
- [ ] 位于文件第一行，两条 `---` 正确包围
- [ ] UTF-8 无 BOM 编码
- [ ] `id` 全局唯一且承诺永不更改
- [ ] `title` / `type` / `status` / `version` / `created` / `updated` 六必填字段齐全
- [ ] `type` / `status` 取值来自受控词表
- [ ] 日期均为 YYYY-MM-DD
- [ ] tags/aliases 为一维列表，无嵌套/多行/重复键

**实体 ID**
- [ ] 所有实体 ID 为 `{前缀}{三位零填充}` 格式
- [ ] 新建前已做消歧（匹配已有+别名）
- [ ] 无 ID 重复

**交叉引用**
- [ ] 实体引用用 ID 不用裸标题
- [ ] 无断链（目标文件存在）
- [ ] 关键锚点为显式 HTML 锚

**表格**
- [ ] ID 列最前、状态列最后
- [ ] 无空白单元格（用 待补/不适用/无）
- [ ] 单表 ≤30 行或已拆分/折叠

**中文排版**
- [ ] 中英文/中文数字间已加空格（盘古之白）
- [ ] 全角标点、半角数字
- [ ] 专有名词大小写正确
- [ ] 正文分层用 一、→（一）→ 1. →（1），不与 # 混用

**状态标记**
- [ ] 条目级标记均来自【】体系
- [ ] 【待定】项有清空时限标注
- [ ] 严重度标记仅用于评审报告

## 咬合三机制（v1.3 · 2026-10-02——三层咬合总设计的根治层）

1. **宣称消费点反向核验**（治"声称消费者"病）：登记册模板/参考标尺/模板头注的每条"→XX 消费它"，必须在目标流程文件的进场读单或指令行**点名**（grep 可验）；CI 校验"KB 节↔调用点↔读单点名"三方对账，宣称无落点=fail。2026-10-02 前已清偿的先例：反转间隔（批1 A.3 位距行）、rules-T（段5 步6 转译）、标尺三项（改挂单元级）。
2. **读单点名制**（治"意图注释"病）：模板消费方声明的升级形态——每个声称消费方必须落到该步骤**进场读单行**；资源总账消费矩阵逐步补"点名位置"列。设计意图写进字段注释＝没写。
3. **三件套立项门槛**（闭环分级）：新字段/字段升级立项时声明目标等级——**A/B 级须三件齐**（登记册账本列＋审计席判据点名＋机器闸门或脚本对账）；文档侧字段必须读单点名；达不到即标"设计参考件"（明示低期望，不进流程链）。
4. **KB 深度前置**：字段进流程的那一天，其填写指导必须已存在于 KB 节或步骤内嵌判据（"立法日不留 P0"的 KB 版）；KB 节随字段升级同步扩（先例：§2.4 五块随 G 节扩容转交）。

## 轻量件豁免与消费矩阵（v1.2 · 2026-10-01）

- **轻量件豁免**：世界观四件卡、章纲卡等短命/机械件，frontmatter 减为 `id/type/status` 三键（version/created/updated 豁免）；章纲卡 status 于入账后随正文定稿，世界四件于段 6 步 6 与登记册 formal 同点翻 active。其余模板维持六必填。
- **消费矩阵**：新模板必附"字段→消费者→Δ行为"三列表于模板头注释（登记册字段/文风基准已有雏形，存量增量补齐）；年检对表核销——**零消费即删的执行机构**（审查报告无消费动作跟进即白写，四路审查 2026-10-01 教训）。
- **题材扩展档申报**：基调六值之外的题材档（新题材主情绪无档时）走本申报——报{题材}＋{档名}＋{实证书}入模板统一规范备案后生效（F18 配套·2026-10-02 反测——文风基准模板·检索键统一节"走模板统一规范·题材扩展申报"的落点闭链）
