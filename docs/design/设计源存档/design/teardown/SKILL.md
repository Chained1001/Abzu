## 一、定位

**拆书是给 AI 补阅读史**——把一本参考作品的结构、节奏、情绪、意图压缩成下游技能可消费的结构化产物。

**本技能是全项目唯一的流水线技能**（ADR-0001 的声明例外）：步骤机械、产物 schema 固定、不发散；创作思考发生在大纲/卷纲消费拆书产物时，不在拆书过程里。交互模式＝"流水线＋过门确认"：每个 Stage 收尾一个确认门，中途只有计划内的停问点。

## 二、读法总纲（全技能最高纪律，四句）

1. **机械边界只解析一次**（章节切分/hash/审计——之后不再跑）
2. **原文按连续章节块读取一次**（轻扫阶段每块只读一次；1c 深读/追踪对关键章的二次读取是计划内例外）
3. **同次读取产生逐章事实和跨章观察**（一次读两用，不回炉）
4. **聚合阶段复用落盘结果，不重新阅读全文**

## 四、全局红线

1. **原文只在拆书阶段被读取**——原文入库（复制或外置登记路径）后，除扫描工按批次单读取外，任何流程不再读；此后其他技能（故事剧情/卷纲/正文/评审/嫁接改造）**永不读原文**，只消费拆书产物
2. 版权三律：拆书产物**永不存原文**（证据只记"章节+短定位词"）；无 License 参考（analyze-hit-novel 类）只借鉴思想不复制文本；皮必换（拆出的"可迁移"只到手法层）
3. **不为填字段虚构事实**——缺失写"原文未明确"；"不要仅凭开头数章推断全书大反派或最终主题"
4. 用户须声明合法持有原文（进场问询项）

## 五、原文隔离协议（派工七条，扫描工与主会话共同遵守）

1. 主会话**不中转内容**：派发只照抄批次单字段（字段枚举以扫描工任务书 §0 调用契约为准——batch_id／章节范围＋行号／原文绝对路径／任务书／模式／min_要点数／handoff_cache／输出文件；审查修复·2026-10-02 P2-3：两处枚举收敛），不另选不推算
2. 扫描工按行号**自读原文**（原文.txt:L起-L止）
3. 扫描工结果**只写批次缓存文件**，回执一行 `BATCH_WRITTEN`
4. 主会话**不 Read 批次缓存原文部分**——聚合期经摘要/索引取料（digest 纪律：按字段按窗口抽取，不整读）
5. 提交被拒→**按违规分级**：单行可修正的格式违规（字数超限等）→原样再派、扫描工 Edit 定点改；结构性缺失（缺节/缺章/存原文）→整批重派。字数上下限有 ±5 容差，边界值不拒收
6. 原文块每块只读一次——已拆章节的摘要永不因重跑刷新
7. **回执纪律靠通道层强制**：派发方只取回执末行（或以退出码承载）——提示层约束实测 27% 违纪率，不可依赖

## 六、断点续跑与进度

- 单状态文件 `参考作品/{书名}/拆书进度.md`：批次表（批次ID/章节范围/状态/缓存路径/范围hash）＋阶段表（阶段/状态/产物）＋最终态行。**禁止**任何其他 checkpoint/receipt 文件（边界：指书项目内；宿主进程自身日志不在此列）
- **受管区标记格式**（进度文件首尾，标记行逐字恒等）：`<!-- teardown:runtime-state:start -->` … `<!-- teardown:runtime-state:end -->`——受管内容只允许流程写入（meta 行/外置原文登记行/批次表/阶段表/最终态行；文件结构见 [schema/拆书产物模板.md](../schema/拆书产物模板.md)·六）
- **断点三条件**（会话重启逐批次判定，三真=已提交、任一假=按批次表状态处置——审查修复·2026-10-02 P0-3：自 [主设计](主设计.md)·断点续跑规格内联成文，运行时分发件不再外引设计稿）：① **摘要全在**——CSV 摘要列该批各章行全非空（引号感知的 CSV 解析，防摘要内逗号误报）② **缓存完整**——批次缓存四节齐（跨批状态/逐章事实/跨章观察/自查）＋末尾 `<!-- teardown:cache-end:{batch_id} -->` 标记 ③ **范围hash一致**——按该批行号段对原文重算各章 sha256，与 CSV 章 sha 列逐章比对；不一致=原文漂移→该批标失效（只失效覆盖批次，已有摘要不刷新）。digest 三规则（行级节匹配 `^### `／按窗口取 observations·fields·chapters／只读不写、重复幂等）见 workflow-1·批次协议
- 章节索引.csv 含每章 sha256＋全源 sha256＋解析器版本——原文漂移由脚本判断：只失效被覆盖批次，已有摘要不刷新
- 任何会话重启：读拆书进度.md → 重跑计划（脚本扫缓存三条件：摘要全在/缓存完整/范围 hash 一致——判定语义见上"断点三条件"）→ 从缺失批次续拆

## 七、作者口径契约

面向作者**说书不说系统**：报告与问询中禁脚本名/JSON 字段/hash 值/批次号/指标名；机制编号必须带人话名（「退婚当众打脸」（EM-003）式）；工程细节最多末尾一行技术备注。进度汇报节奏：约每拆完一成报告一次，不每批都报。
