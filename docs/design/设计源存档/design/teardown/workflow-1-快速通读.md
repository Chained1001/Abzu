## 1b 章节索引轻扫（分批派扫描工，token 成本主体）

**目标**：每可用章一行索引记录（50-100 字一句话摘要＋**章类型标签**＋参与人物＋位置标记），写入 章节索引.csv——Stage 2/3 的地图、1d 合成的原料、**类型占比统计的数据源**。

**章类型标签七类**（扫描工轻扫时按每章主导内容打一个）：探案／战斗／升级修炼／权谋／**装逼打脸**／日常／感情——边界/混合章打`标签*`（星号，1d 复核）；**感情=恋爱感情线**（亲情归日常）；设定灌输章归升级修炼。1d 据此机械统计占比（实测：无"装逼打脸"类时该类爽点高潮会被日常桶吞噬、日常虚高至 45%+——2026-09-29 切片实测教训）。

**方法论加载**（审查修复·2026-10-02 P1-2）：实证方法论/拆书方法论/结构标记识别（平台噪音剥离——标题清洗/章尾注剥离后字符数才进指标；"钝钩候选"栏；"分隔行数"计数字段——场景汇聚信号）＋节奏量化（窄谱书加报三原始计数：句数/八字内句数/叹号数/引号内字符数；"末 3 句抄录"字段——章末钩三级归级原料）＋伏笔链定位（伏笔候选行——"步骤/数字/专有名词＋当章未使用"写入跨章观察节）＋爽点循环测量（高潮候选章加报"三信号"：前 5 章贬损对话/当众场景词/旁观反应段数）——分发为 references/methods/structure-marker、pacing-metrics、foreshadow-chain、climax-cycle 四件

**脚本调用形**（随技能分发于 `{技能目录}/scripts/teardown/`（＝skills/abzu-teardown/SKILL.md 脚本节同口径），判据仍以本清单为准——审查修复·2026-10-02 P1-4）：

- 索引初表：`node {技能目录}/scripts/teardown/index.mjs generate <结构审计.json> <章节索引.csv>`
- 逐批校验：`node {技能目录}/scripts/teardown/index.mjs verify <结构审计.json> <已填章节索引.csv>`（行数/列数/sha/摘要长度/漏行）
- 填充进度：`node {技能目录}/scripts/teardown/index.mjs stats <章节索引.csv>`
- 定稿 门禁六项机械检查：`node {技能目录}/scripts/teardown/validate.mjs <原文.txt> <批次缓存.md> [结构审计.json]`

**批次协议**：

| 项 | 规则 |
|---|---|
| 批次大小 | 默认 5-8 章／≤40,000 字符（信息密集章缩至 1-2 章/批）；**语义分块（在哪切）与处理批次（一次读多少）是两个轴**，禁止"超 500 章换一套规则"式的双规格 |
| 派工 | 按隔离七条：主会话照抄批次单→扫描工自读原文→写批次缓存→回执一行（通道只取末行）；**预演门批次特批缩小为只含首 3 章** |
| 交接 | handoff_cache 五项：已确认别名/未闭合剧情点/悬念/关系变化/待核事项——扫描工只读**该轮开始前最近已提交批次**缓存的`### 跨批状态`节（并行轮内批间不互指）；隔批不假设接上；1c 深读批的 handoff 统一取最近已提交轻扫批次；非连续行号批次（如第3+22章）批次单行号列写多段 |
| 校验 | 扫描工 Grep count 自查（判据=扫描工任务书 §3b 字段计数表）；主会话 **定稿 门禁六项**（批次协议通用，1c/Stage 2/3 同此清单——**实现以本清单为准，沙盘原型脚本仅供参考**）：① **缓存四节齐**——跨批状态/逐章事实/跨章观察/自查四节标题行俱在＋末尾 cache-end 标记 ② **范围与字段计数**——批内章集合==批次单章集合，字段计数对 §3b 计数表（轻扫=索引行==章数＋要点行≥章数×min；深读=字段行==章数×11；分卷=字段行==章数×14） ③ **原文泄漏检查（版权红线唯一机械检查，第一优先）**——批次缓存逐行对原文做 >30 字连续匹配（滑窗 31 字、忽略空白），命中任一行=🔴 整批拒收重派 ④ **CSV 写后校验三件**——表头与规范表头串恒等｜每行列数恒定（12）｜已提交批次的摘要/行号/sha 列未被改动（沙盘事故：幂等 bug 六次假 PASS——缓存 PASS≠数据地基完好） ⑤ **范围 hash**——按批次行号段对原文重算各章 sha256，与 CSV 章 sha 列逐章比对（不一致=原文漂移→该批失效，只失效覆盖批次） ⑥ **字数容差**——摘要 50-100 字、深卡 200-400 字均带 ±5 容差（边界值不拒收）；要点数按章 min（该章字数÷200 四舍五入 clamp 1-10，**不硬编码**）；拒收分级见 SKILL.md 隔离七条-5 |
| 断点 | 每批 定稿 后更新拆书进度.md；会话中断→重跑计划扫缓存续拆；断点三条件判定（摘要全在/缓存完整/范围hash一致）须用**引号感知的 CSV 解析**——按逗号天真 split 会被摘要列内逗号欺骗产生误报（误报=重拆已拆章，违反永不覆盖） |
| 聚合取料 | digest 抽取用行级节匹配（^### 加空格）——子串 split 会被 #### 深卡头击穿 |
| 要点与索引行两分 | 每章固定 1 条索引行（50-100 字）＋ N 条要点行（min_要点数=字数÷200 四舍五入 clamp 1-10，章均 2000-3000 字时普遍饱和至 10 属预期；深读模式每章 1 张深卡=1 要点） |

**首 3 章预演门**（唯一中途停问）：拆完第 1 批（含首 3 章）后停——给作者看 3 份章摘要样张＋一句话判断＋"这本书值得继续拆吗/摘要口径要调吗"。确认后一口气拆完，进度按约一成一报。

## 1c 关键章节深读（选 20-30 章，扫描工·深读模式）

**选取标准**（从章节索引+审计取，主会话机械选取）：全书首 3＋末 3 章｜每卷首末章｜分卷边界章｜人名频次高频章（高潮密集区）。

每章产出 200-400 字深度卡：六步拆解（情绪事件/欲望目标/阻碍/解决/行动高潮/结局反馈）＋双钩子＋三维打分行（打分|剧情{1-5}·情绪{类型}{1-5}·描写{1-3}，各附≤15字理由——1d 合成与终检"三节奏分开"的依赖项）＋证据定位。逐行格式见扫描工任务书 §3b。同样走批次协议（深读模式：1-2 章/批）。

**方法论加载**（审查修复·2026-10-02 P1-2）：结构标记识别（起飞点定位——首 3 章六步拆解单列"起飞点"行：章号＋计划句短引＋跨界优势首用动作）＋人物弧线提取（出场方式判功能三分——每个新命名人物记"入场两问"：谁带他入场/首章是否完成只有他能完成的事）＋节奏量化（选章替换——宽谱书"每卷首末章"可换为"高潮块峰值章＋块前 1 章"，深读预算压在块接口）

## 1d 骨架合成（主会话·强模型，不重读全书）

**输入**：1b 索引全表＋1c 深读卡＋首尾章深卡＋结构审计。**零原文重读**。

**方法论加载**：§1.14 核心卡（拆的是节奏曲线与情绪拐点）→ §1.15 核心卡（借魂不借形三检验）→ §1.7 核心卡（框架加变量）；实证方法论按产物加载（审查修复·2026-10-02 P1-2）——伏笔总表←伏笔链定位（埋设判据登记候选、词频验证后转正/降级）｜人物总表功能列←人物弧线提取（出场方式判功能三分＋删除测试在激活章跑）｜循环兑现审计小表←爽点循环测量（爽点类型四判按信号组合）｜三幕映射"第一扇门"←结构标记识别（起飞点章号，不用激励事件章号）｜续航引擎清单/底层循环公式←伏笔链定位＋节奏量化（词频四型取材）。

**合成顺序**（对应产物五文件）：

1. 人物总表＋伏笔总表（清单级——从索引"参与人物/悬念未闭合"聚合，机械度高先行）
2. 拆书笔记（表象/机制/意图三层——机制层主要来自 1c 深卡）
3. **参考作品骨架**（最重：一页结论→基础信息→**类型占比表**→阵型结构→情节模式循环→节奏情绪总览→线路→嫁接空位表→读者定位→**引擎/载体/表象三层**）：
   - **引擎判定**（主判定，前置——2026-09-29 沙盘实测裁定：占比表会被切片双向污染且多元素书上"日常"占比第一无信号，唯判据扛住陷阱；故判据坐主位、数据坐证据位）：
     **判据：一级循环（单元事件级，2-10 章一个完整单元；取主角第一 POV 线）的兑现类型＝日常引擎；卷末高潮兑现＝续航引擎**（喂骨架已有"续航引擎清单"字段——双循环各判：诡秘=日常引擎序列晋升+续航引擎世界真相；头部作品双循环是常态不是例外）。兑现三箭头：兑现=台阶/资源/权位→**升级引擎**｜兑现=真相揭晓→**探秘引擎**｜兑现=关系推进/情绪体验→**情感引擎**（言情/日常向）；三箭头皆不中→判据不适用，退回占比+高潮归属直判，置信度 C。**引擎允许复合表述**（"升级引擎·当众打脸释放"）；**口径分工：引擎（兑现型）定续航，爽点循环模板（释放型：装逼/打脸/碾压）定爽点密度，两者都进对标**。执行时附**循环兑现审计小表**（2-3 轮循环实例→兑现物清单→归类——防循环公式写错带偏判据）。
   - **类型占比表**（证据表，降格——判据的数据支撑与漂移判据输入）：1b 章标签统计**前/中/后三段各一列**（切片书＝切片实测＋全书推断双行并排＋采样窗口声明行——"本切片=全书探案最密段/战斗最疏段"式）；各大高潮类型归属。规则：**引擎以后段循环兑现为准**；前段与后段差异标"开局载体"（大奉型）或"疑似换引擎"（赘婿型）；**占比最高≠引擎**（日常是默认桶）。
   - **引擎/载体/表象三层**（替代原"可迁移的魂"一句话）：引擎（真引擎=升级/装逼/战斗之类——不可照搬但**强度必须对标**）｜载体（切入姿势与塑造工具——探案/穿越/职业皆此类，**可搬可放大**）｜表象（题材皮——必换）。放大载体为核心是合法路径，但必须触发下游的**引擎自造检查**。
   - 嫁接空位表=§1.15/1.7 落点：每个空位标"参考填法/可替换方向/建议操作"
4. 反面清单（**三源纪律**）：①作者提供评论/书评数据（最高置信）→按来源筛；②无则问作者要不要派 **researcher 采风取证**（触发源 teardown-negatives，带 URL 与可信度分级）；③**模型口碑归纳**只标"待核实"（置信度 C），不得单独作为修复建议依据。三源全无→"暂无数据"留空表，**不编造骂点**。**"类型漂移"条目特别判据**（2026-09-29 大奉教训：反面清单曾把参考作品的本体展开当毒点，导致新书避开主体）：类型占比前段主导型在后段占比骤降，**仅在有读者流失数据证明时**才判漂移毒点；无数据 → 标"类型占比演变（疑似本体展开——该书引擎可能本就是后段类型，见类型占比表），需读者数据核实"——禁止直接判毒点教新作者避开参考作品的主体

**保真三约束**（合成期专用，防"离原文两跳"漂移）：硬事实必须可溯源到章节｜摘要没写的写"原文未明确"禁推断补实｜跨指代不串（坐骑等级≠骑手等级）。每条关键结论带置信度 A/B/C（A=文本直接说明/B=多处行为一致支持/C=暂定）。

**合并一致性检查**（五文件互查）：姓名别名一致｜时间线不倒｜人物动机前后不打架｜伏笔状态与总表一致｜骨架结论有证据章。
