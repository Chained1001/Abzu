> 版本 v1.6 ｜ 2026-10-01（产物格式块抽取至 [schema/拆书产物模板.md](../schema/拆书产物模板.md)——本设计瘦身为流程＋协议，格式单一源在模板）＋ v1.5 ｜ 2026-09-29（类型机制沙盘实测后修订）（审查修复批：表头串钉死/断点续跑规格成文/总表 schema 对齐实例/冲突矩阵落 schema/三维打分行成文） ｜ 依据：analyze-hit-novel + webnovel-writer + 知识库 §1.14/§1.15 + 沙盘消费侧验证 + 解构梯（原则 19）+ 作者裁定（三阶段+全局维度不可分卷）
> 产物：书项目 参考作品/{书名}/ 下 10+ 文件（分三阶段按需生成）——**产物格式单一源：[schema/拆书产物模板.md](../schema/拆书产物模板.md)**，本文件只留流程与协议

## 设计哲学

**拆书是给 AI 补阅读史**（老鹰"十几年网文阅读"的显式化）——AI 没有作家的阅读积累，teardown 把一本参考作品的结构、节奏、情绪、意图压缩成 AI 可消费的结构化产物。

**三阶段按需供血**：不是一次全拆（token 不可承受），也不是只拆大纲层（故事剧情/卷纲/正文需要更深的参考），而是三个阶段各服务一个下游技能，写到哪拆到哪。

**全局维度不可分卷**：人物弧线、伏笔链条、关系演变、双时间线、主题意图——这些必须看全书才能分析，归入 Stage 2 深度分析，不分卷。

## 产物目录结构

```
参考作品/{书名}/
├── 原文.txt                    ← 复制入或外置登记（见 workflow-0：外置=书项目外路径＋全源 sha256 登记于拆书进度.md；此后仅扫描工按批次单读取）
├── 拆书进度.md                 ← 单状态文件（批次表+阶段表+最终态；断点续跑唯一依据——schema 见 §断点续跑规格）
├── _teardown_cache/            ← 批次缓存（扫描工写；主会话不 Read 原文部分）
│   └── {批次ID}.md             ← 命名前缀见 §断点续跑规格（批次-/批次-1c-/追踪-{对象ID}-/分卷-第N卷-）
├── 结构审计.json               ← Stage 1a（机械检查）
├── 章节索引.csv                ← Stage 1a 建全 12 列（摘要/参与人物留空）→1b 定稿 投影回填
├── 参考作品骨架.md              ← Stage 1d（合成产出）★大纲流程消费
├── 拆书笔记.md                 ← Stage 1d
├── 反面清单.md                 ← Stage 1d
├── 人物总表.md                 ← Stage 1d
├── 伏笔总表.md                 ← Stage 1d
├── 深度分析.md                 ← Stage 2 ★卷纲首次消费
└── 分卷拆解/
    ├── 第1卷.md                ← Stage 3 ★卷纲逐卷消费（卷号不补零——同书项目卷纲命名）
    ├── 第2卷.md
    └── ...
```

> **分析范围声明（全部拆书产物统一）**：位置=frontmatter 后引言块（`> **分析范围＝第X-Y章（占原书约Z%），全书级结论受限**`式）；覆盖率档=大部分/切片时必带并注明受限结论面，全文档可不带。

## Stage 1 快速通读（一次完成，中等成本）

### 触发时机
段 0 收尾检查发现骨架三件套缺失 → 引导用户调用 abzu-teardown → 本技能启动。

### 内部四步流水线（token 成本控制核心）

#### 1a 结构审计（机械检查，不用 AI 深读）

产出 `结构审计.json`——json 格式见 [schema/拆书产物模板.md](../schema/拆书产物模板.md)·一 结构审计。

> 来源：analyze-hit-novel 的 structure-audit.json。骨架建立在被污染文本上会全盘失真——审计是信任地基。

#### 1b 章节索引轻扫（分批处理，每章 50-100 字摘要）

产出 `章节索引.csv`——**规范表头串（单一权威常量）与列语义、回填示例见 [schema/拆书产物模板.md](../schema/拆书产物模板.md)·二 章节索引**。

- **门禁：audit 建索引／定稿 投影回填／断点解析三处逐字与 schema/拆书产物模板.md·章节索引 表头串恒等**，任一处不一致＝实现 bug
- **1a 建全 12 列**（摘要/参与人物两列留空）→ **1b 定稿 投影回填**：摘要列←批次缓存索引行"摘要"段；参与人物←"人物"段（逗号分隔、整列引号包裹）；位置标记以 `位置:原文L起-L止` 记入备注列。沙盘 audit 原型实际只建 10 列（缺摘要/参与人物），属实现期待修项（修＝建全 12 列）
- 状态列取值（可用/空章/污染）与表头下行（全源 sha256＋解析器版本，断点续跑地基）的格式见模板·二；判定语义见 §断点续跑规格

> 这是 Stage 2"追踪式阅读"的地图——没有此索引，Stage 2 只能退化回线性重读。来源：analyze-hit-novel 的章节索引.csv + webnovel-writer 的分批章节卡策略。

#### 1c 关键章节深读（选 20-30 章，中等深度）

选取标准：
- 全书首 3 章 + 末 3 章（开局/结局锚定）
- 每卷首末章（卷间接口）
- 结构审计检测出的分卷边界章
- 人名频次表中的高频章节（高潮密集区）

每章产出 200-400 字深度摘要：六步拆解 + 双钩子 + 三维打分行（`打分|剧情{1-5}·情绪{类型}{1-5}·描写{1-3}`，三维各附≤15字理由——1d 合成与 Stage 1 终检"三节奏分开"依赖它；逐行格式见扫描工任务书 §3b）。

#### 1d 骨架合成（基于 1b 索引 + 1c 深读 + 首尾章，不重读全书）

## Stage 2 深度全书分析（延迟到卷纲首次启动，高成本）

### 触发时机
卷纲技能首次启动 → 进场检查发现 深度分析.md 不存在 → 触发生成。

### 读法：追踪式（基于 Stage 1 章节索引定位，不线性重读）

```
Step 1: 读 Stage 1 人物总表 + 伏笔总表 + 章节索引
Step 2: 逐人物追踪——从章节索引中筛选该人物出现的章节 → 只读这些章节 → 提取弧线
Step 3: 逐伏笔追踪——从章节索引中筛选该伏笔相关章节 → 只读这些章节 → 完成链条
Step 4: 逐关系追踪——选取 3-5 条核心关系 → 定位关键章节 → 提取演变
Step 5: 双时间线建构——基于伏笔链条+关系演变 → 标注调度标签
Step 6: 爽点循环深拆——选取 3 个最典型循环 → 逐层拆解四段式
Step 7: 合成 深度分析.md
```

### 产物 Schema：深度分析.md

完整 schema（人物弧线图/伏笔链条图/关系演变图/冲突矩阵/双时间线详图/爽点循环深拆/爆款机制四层/意图层深化——八节，含 frontmatter）见 [schema/拆书产物模板.md](../schema/拆书产物模板.md)·四 深度分析。

## Stage 3 分卷细拆（按需触发，**窗口拆解制**——成本路裁定 2026-09-29：全卷拆解的章节事实卡消费率低（仅章纲对照偶发消费），改窗口化省 60-80%）

### 触发时机与拆解窗口
卷纲技能启动第 N 卷规划 → 进场检查发现 分卷拆解/第N卷.md 不存在 → 触发生成。**默认只拆"对应窗口"**：参考作品中与本书精排区章位对应的参考章位 ±10 章（位置映射：本书精排区区间 ÷ 参考书总章数 × 参考书章节）——窗口外章节**不拆**，标记"未拆"；draft 章纲卡对照时命中未拆章位 → 触发**增量补拆**（单章/小批量，同一触发不做整卷）。作者明示"全卷拆"才全拆（呈成本预告）。

### 依赖关系
- **硬依赖**：Stage 1 骨架（必须存在）
- **软依赖**：Stage 2 深度分析（无则伏笔分析降级为"仅本卷内可识别的伏笔"，跨卷链条不完整——标注"深度分析未生成，伏笔视角受限"）

### 读法
只读原文中该卷段落（由 Stage 1 章节索引定位起止章）+ Stage 1 骨架 + Stage 2 深度分析（如存在）。

### 产物 Schema：分卷拆解/第N卷.md

完整 schema（章节事实卡 14 字段＋置信度/三维节奏曲线/六步实例化/伏笔操作明细/双时间线切片/卷间接口）见 [schema/拆书产物模板.md](../schema/拆书产物模板.md)·五 分卷拆解。

## 断点续跑规格（拆书进度.md 与 digest）

> 单状态文件纪律（SKILL.md §6）：书项目内唯一 checkpoint，禁止任何其他 checkpoint/receipt 文件增殖。本节为判定语义的成文规格＋文件结构指针（文件结构格式已抽取至 [schema/拆书产物模板.md](../schema/拆书产物模板.md)·六）；沙盘进度文件（中文受管标记/1b 与 1c 分表）为原型形态，实现以本节＋模板为准。

### 拆书进度.md schema

文件结构（受管区标记＋受管内容五件：meta 行/外置原文登记行/批次表/阶段表/最终态行）见 [schema/拆书产物模板.md](../schema/拆书产物模板.md)·六 拆书进度。受管区标记块两处双写，标记行逐字恒等于模板：

```
<!-- teardown:runtime-state:start -->
…受管内容…
<!-- teardown:runtime-state:end -->
```

### 断点三条件判定语义（会话重启时逐批次判定）

| 条件 | 判定语义 |
|---|---|
| 摘要全在 | CSV **摘要列**该批各章行全非空（须用**引号感知的 CSV 解析**——按逗号天真 split 会被摘要列内逗号欺骗产生误报，误报=重拆已拆章，违反永不覆盖） |
| 缓存完整 | 批次缓存**四节齐**（跨批状态/逐章事实/跨章观察/自查）**＋末尾 `<!-- teardown:cache-end:{batch_id} -->` 标记** |
| 范围hash一致 | 按该批行号段对原文**重算**各章 sha256，与 CSV 章 sha 列逐章比对；不一致=原文漂移→该批标失效（只失效覆盖批次，已有摘要不刷新） |

三条件全真→该批视为已提交；任一假→按批次表状态处置（已派未提交→重派；失效→失效重拆）。

### digest（聚合取料）规则

主会话聚合期只经 digest 取料、不整读缓存原文部分（隔离七条-4；oh-story 同款，已调研）。三规则：

1. **行级节匹配**：按 `^### `（三井号＋空格）行级标题切节——子串匹配会被 `#### 深卡头`击穿
2. **按窗口取**（三参数可组合）：
   - `--part observations`：只取各批次缓存的 `### 跨章观察` 节
   - `--fields {字段名}`：只取逐章事实中指定字段行（如 `--fields 深卡` 取全部深卡白描、`--fields 要点` 取全部要点行）
   - `--chapters {起-止}`：只取章窗口内的行（1d 合成/Stage 2/3 按需切窗）
3. **不回炉**：digest 只读不写，同一窗口重复 digest 幂等

### Stage 2/3 批次的断点适配

- **Stage 2 追踪批**：缓存**按对象分文件**（`_teardown_cache/追踪-{对象ID}-批{N}.md`——同章可能被不同追踪对象各读一次，缓存不共享；跨对象同章事实冲突以先到为准记入待核），逐文件登记进同一批次表
- **Stage 3 分卷批**：逐批追加进同一批次表（批次ID=`分卷-第{N}卷-批{M}`）；断点三条件判定语义不变

## 质量门控

| 指标 | 阈值 | 不达标处置 |
|---|---|---|
| 结构审计可用率 | ≥80% | 报告用户，标注可用范围，仅分析可用章节 |
| 章节索引覆盖率 | ≥95% | 补扫缺失章节 |
| 证据置信度 | 每条结论≥C | C 级标注"暂定" |
| Stage 2 伏笔链条完整率 | 已回收伏笔100%有回收章 | 未定位的标"疑似遗忘" |
| Stage 3 章节卡覆盖率 | 窗口内 100% 章节有卡（窗口拆解制；全卷拆＝该卷 100%） | 窗口外标"未拆"（非缺失）；窗口内缺章标"待补"（审查修复·2026-10-02 P0-2：质量门控同步窗口口径） |
