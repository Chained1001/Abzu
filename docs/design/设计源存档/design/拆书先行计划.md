# 拆书先行计划（先做好拆书技能，再以此为基础开发其他）

> 2026-10-02 ｜ 策略：拆书=最独立技能（零依赖）＋所有下游的供给端＋最佳工程试验场 → 先完整做好拆书，用真拆产物测试下游设计 → 再开发其他技能

## 一、为什么要拆书先行

1. **零依赖**：不消费任何其他技能的产物——可以独立开发、独立测试
2. **供给端**：大纲段1-4 全部消费骨架五件套、卷纲消费深度分析+分卷拆解、正文消费章节事实卡——没有真拆产物，下游测试全是假数据
3. **工程试验场**：批次处理（隔离七条/commit 门禁六项/断点续跑）、代理派工（扫描工四模式）、文件管理（受管区/sha256/原文隔离）——这些工程模式在拆书先跑通，其他技能复用
4. **方法论反哺**：真拆产物 → 反推大纲/卷纲方法论（现在各只有 5 条，完整拆书后可以充实）

## 四、工程问题提前暴露位（拆书先跑能发现的）

1. **批次处理**：扫描工代理的隔离七条/commit 门禁六项在实际运行中是否可行
2. **文件管理**：受管区标记/sha256/原文隔离在文件系统层面的实际操作
3. **断点续跑**：中断后恢复的受控值匹配
4. **产物完整性**：消费契约对表（下游真的能读到需要的字段吗）
5. **token 成本**：真实 914 章的全量索引/追踪式阅读的实际开销

这些问题在其他技能中同样存在——拆书先踩坑，其他技能少踩。
