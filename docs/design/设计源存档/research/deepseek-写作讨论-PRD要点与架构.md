一、项目定位
构建一套可以在 Claude Code 上运行的 AI 写作技能组插件

项目会上到 GitHub，采用 npx 形式安装和升级

可以被发布到 Claude Code 的 Market

分期开发：第一期大纲，第二期卷纲，第三期章纲+正文

二、核心设计哲学
2.1 模拟人类作家思维
要点：

人类作家不是流水线工人，想人物时金手指、剧情、世界观会同时冒出来

思考是网状的、并行的、来回横跳的

从模糊 → 逐渐清晰 → 落到纸面

技能不是执行器，是思维引导器

设计注意点：

不能写成“第一步做A，第二步做B”的流水线

要写成“当你思考X时，同时思考Y和Z”

由点及面，强制追问元素之间的交叉关系

允许模糊，不要过早收敛

2.2 业务流程 + 方法论分离
这是本项目最重要的架构决策之一。

概念	职责	回答的问题
业务流程	怎么想	先想什么、后想什么、和什么一起想
方法论	依据什么做	按什么标准、什么框架、什么逻辑
设计注意点：

业务流程管“节奏、顺序、并行、发散、收敛”

方法论管“标准、逻辑、框架、专业度”

两者不能混在一起

混在一起会变成：要么流水线，要么瞎编

方法论的正确位置：

方法论不是流程之外的“参考书”，是流程每一步的操作手册

流程说“做什么”，方法论说“按什么标准做”

方法论按流程步骤强制加载，不是按 AI 判断按需加载

每个流程步骤都有对应的、必须加载的方法论

2.3 设定贯穿全程
要点：

设定不是独立的前置阶段

大纲、卷纲、正文每个阶段都涉及设定的产出与迭代

设定存放在一个总设定文件夹里

设计注意点：

大纲阶段产出初步设定

卷纲阶段完善、修改、删减设定

正文阶段继续迭代设定

设定是“活水”，不是“死文件”

2.4 用户手动调用
要点：

技能之间不自动串联

用户显式选择调用哪个技能、哪个步骤

设计注意点：

每个技能启动时，先读创作进度.md，知道自己该读什么、该产出什么

用户可以在任意步骤停下来、回退、重做

2.5 设计原则：明确严谨，杜绝歧义
这是贯穿整个项目的写作规范。

核心思想：

不要让 AI 去猜、去找、去判断“这个可能是什么”。直接告诉它：读哪个文件、在哪、做什么。

具体表现：

文件引用用相对路径，不用名字

步骤指令直白，不绕弯

概念用词统一，不换同义词

判断条件写死，不给 AI 自由裁量

为什么重要：

省 token：AI 每“猜”一次，就是一轮内部推理

减少不确定性：写死之后，行为可复现

降低出错率：歧义是 AI 出错的温床

便于调试：路径写死，出错能快速定位

检查清单：

有没有“可能”“也许”“大概”“适当”“酌情”这类词？

有没有只写文件名、没写路径的地方？

有没有同一个概念用了多个词？

有没有“如果觉得……就……”这种让 AI 自己判断的写法？

三、关键技术设计
3.1 狗头军师式流程约束
参考来源： Claude Code 生态的 GrillMe / 狗头军师 skill

核心设计：

用一套强制的、分步的、可校验的流程，保证 AI 不因“自由发挥”而偏离专业水准

不教 AI“怎么想”，而是通过流程约束，确保 AI“必须想到”

可借鉴的具体机制：

强制三分法：区分“已知事实”“合理推测”“完全未知”，并明确告知用户未知部分

强制先处理情绪，再谈策略：对应写作，就是生成任何剧情前，先确认“当前章节的情绪基调是什么”

强制给出可执行建议：不满足于“分析问题”，必须给出“可直接使用的文本片段”

分层知识库 + 路由表：SKILL.md 只做路由，方法论按需加载

3.2 参考标尺
定位：

通用一份，适用于 100 万字到 300 万字以上

不按字数分档，用“固定层 + 比例层 + 衰减系数”计算

结构：

固定层（不随字数变）：

反派层级：4层（小/中/大/终局）

势力层级：3-4级

金手指台阶：5-7阶

主要人物：5-8人

主线：1主 + 2-3支

主角成长弧：3-4段

比例层（每100万字基准）：

小反派：5-8

中反派：1-2

大地图：3-4

支线：3-5

关键事件：15-20

衰减系数：

100万：×1.0

200万：×1.8

300万：×2.4

500万：×3.0

计算公式：

实际数量 = 基准值 × 衰减系数 × 题材修正系数

题材修正：

只改差异最大的2-3个维度，不重写整份标尺

玄幻：反派层级+1，地图数×1.5

都市：反派层级-1，打脸频率×1.3

悬疑：爽点密度×0.6，信息钩子密度×2

设计注意点：

基准值后续通过采风检索获取（找10本左右实际作品平均）

已有参考数据：100章左右、13-22个角色、每10-15章一次大打脸

3.3 采风检索
定位：

实时的、动态的、把整个网络当灵感库

对应人类作家遇到不会、不懂、灵感匮乏时，上网查、看、学的动作

贯穿整个创作链路

降级链路：

text
采风检索触发
    ↓
探测本地灵感库是否存在
    ↓
存在 → 先检索本地 → 命中返回 / 未命中转网络
不存在 → 直接网络检索
    ↓
提炼 + 返回
    ↓
可选：提示沉淀进灵感库
检索范围（六类）：

剧情结构 → 沉淀到灵感库/剧情零件

历史事实 → 沉淀到世界参照档案

人物原型 → 沉淀到人物设定/灵感库

文化元素 → 沉淀到世界参照档案

影视/动漫 → 沉淀到灵感库/写法参考

现实生活 → 沉淀到世界参照档案

设计注意点：

带上下文去搜，不笼统地“搜一下”

检索结果要抽象化，不直接抄

分门别类沉淀到正确位置

输出分两层：原始素材 + 提炼结果

网络能力本身不是瓶颈，开源方案成熟

难点在于 agent 的“灵魂”设计：问什么问题、带回什么、怎么抽象、怎么判断好坏、怎么决定沉不沉淀

3.4 待采风标记机制
定位：

并行思考中不触发检索，只触发标记

一轮思考结束后汇总，集中处理

触发时机：

卡点（推不下去了）

不确定（不知道好不好、有没有先例）

需要具体素材（真实细节支撑）

似曾相识（觉得和某本书像，想确认）

处理流程：

并行思考中插入【待采风】标记，继续思考

一轮结束后汇总，去重、排序

AI 自动查“明确需要查的”

把“不确定的”列给用户

检索结果注入下一轮思考

设计注意点：

不打断思考流

检索目标比中途搜更准

可以批量处理

3.5 三评委 agent
三个 agent：

agent	视角	评什么
读者评委	代入读者	好不好看、想不想追
作家评委	代入创作者	结构、逻辑、设定、节奏
编辑评委	代入市场	卖点、对标、标尺匹配
评估顺序：

作家评委（查硬伤）

读者评委（查体验）

编辑评委（查市场）

调用策略：

第一轮打磨：三个全跑

后续轮次：只跑“上一轮发现问题对应的 agent”

适用阶段：

草稿阶段不跑

打磨阶段跑

大纲/卷纲/章纲/正文统一适用

设计注意点：

三个 agent 不是投票，是各出一份报告，然后汇总

AI 评估仍然是模式匹配，不能全信，只能当参考

三个 agent 可能互相矛盾，需要定优先级规则

3.6 落地审查
定位：

每个文件落地后自动执行

轻量，一小段话就够

不自动修，形成报告让用户裁决

两类审查：

类型	时机	目的	强度
落地审查	文件刚生成完	格式对、内容没跑偏	轻量
质量审查	打磨阶段	因果、逻辑、动机、一致性	重（三评委）
落地审查报告格式：

发现什么问题

解释一下

几个推荐项让用户选

用户可自定义输入

记录位置： 创作进度.md

确定性校验交给脚本：

格式校验（字段齐不齐、模板对不对）

引用完整性（提到的 ID 在设定里存不存在）

信息校验（有没有出现“绝对不能释放”的信息）

视角校验（有没有出现上帝视角关键词）

原则：软件管确定性，AI 管创造性。

3.7 变更提案机制
定位：

正文阶段发现上游需要改时，不直接改，先生成变更提案

流程：

发现需要改

生成变更提案（含影响面分析）

用户决策

按影响面清单，逐个文件回改

重新做一致性检查

变更提案包含：

触发点

建议变更

影响面分析（章纲、卷纲、大纲、设定、伏笔）

建议方案（2-3个）

用户决策

设计注意点：

不是推倒重来，是定点修改

影响面分析靠 AI 推断，可能漏、可能错，必须用户裁决

改上游必然有连锁反应，只是成本可被控制

工程支撑：

人物/伏笔的关联索引（ID 系统）

版本控制

创作进度.md 记录变更历史

3.8 ID 系统
定位：

给所有“可被引用的实体”一个唯一标识，消灭歧义

ID 格式：

text
{前缀}-{三位序号}
示例：P-001、F-012、FS-003

规则：

前缀大写，2-3个字母

序号三位数

一旦分配，永不复用、永不更改

前缀表：

P：人物

F：势力/组织

L：地点/地图

G：金手指/能力

I：关键道具

FS：伏笔

E：关键事件

V：卷

C：章

别名处理：

一个人物可以有很多别名，但只有一个 ID

别名字段单独维护

收益：

消灭歧义（同名不同人、同人不同名）

支持影响面分析

支持一致性检查

支持版本对比

设计注意点：

不是所有东西都要 ID，只有“会被跨文件引用”的实体才给

ID 要有人类可读性（P-001 比 uuid 好）

ID 一旦分配，不能改

3.9 融合策略
定位：

采风检索回来的内容，怎么融合到现有剧情中

核心动作：找锚点

在现有框架里，找到一个能对接外部素材的位置

不是“哪里能放这个素材”，是“哪里能让这个意图成立”

融合五步：

抽象素材（表象层 → 机制层）

意图分析（机制层 → 意图层）

作者为什么这么写？

满足什么心理需求？

底层逻辑是什么？

找锚点

兼容性检查

生成融合方案（2-3个）

用户裁决 + 执行（可能触发变更提案）

意图分析的重要性：

融合不是搬运素材，是理解意图，然后在新的框架里，让这个意图重新成立

意图是“魂”，机制是“骨”，表象是“皮”

融合时，魂要保留，骨可以换，皮必须换

难度分层：

结构迁移 < 角色迁移 < 桥段迁移

设计注意点：

融合 agent 可能需要单独设计

融合贯穿全局，不只在大纲阶段

融合后的产物，走落地审查和三评委

3.10 参考作品的双层使用
核心区分：

主要参考作品：拆“结构”，完整拆书，产出地基点.md

次要参考作品：拆“零件”，按需提取，不拆全书

主要参考作品：

1 本，仅限书籍

完整拆书：三层拆解 + 双向拆解

产出：地基点.md + 拆书笔记.md + 参考作品反面清单.md

作为大纲的骨架基础

次要参考作品：

2-3 本，书籍/动漫/影视均可

不拆全书，按需提取“零件”

零件类型：人物原型、关系模式、桥段、氛围、能力机制、情感线

提取方式：定向检索，需要什么去找什么

产出：零件索引（本质上是一本书专属的迷你灵感库）

使用时机：

主要参考贯穿始终

次要参考按需触发

设计注意点：

次要参考的零件索引建议预提取，用到时才提会打断创作流

次要参考数量上限2-3本，太多会变成大杂烩

次要参考的零件索引优先级高于通用灵感库（更贴合当前项目）

四、内容质量设计
4.1 拆书三层
层级	内容	举例
表象层	写了什么	开篇是危机型
机制层	怎么做到的	前300字交代困境，前500字升级，前800字给出转机
意图层	为什么这么做	让读者产生“他怎么脱困”的期待
设计注意点：

拆书不能停在表象层和机制层，必须拆到意图层

意图层是跨题材、跨时代、跨文化通用的

三层都要有，只有表象层，迁移时不知道能换什么

拆书要双向：

正向：可继承的（结构、机制、意图）

反向：要避开的（雷点、崩点、争议点、缺点）

4.2 参考作品反面清单
定位： 单独一份文件，来源为网上有价值评论

筛选机制：

过滤：无脑刷屏、情绪宣泄、水军

保留：有具体指向、有分析、有共识、有建设性

产物：

雷点（读者骂得最多的）

崩点（后期战力崩坏、人设崩塌）

争议点（双女主拉扯、烂尾、挖坑不填）

缺点（节奏拖沓、感情线单薄）

用途：

大纲阶段：避开已知雷点

方法论过滤：怎么避开常见坑

打磨阶段：读者评委专门检查

落地审查：脚本检查

4.3 创作红线
定位：

基本规格里的非必填字段，建议填

硬约束，但允许用户临时解锁

全流程通用（大纲/卷纲/章纲/正文都读）

填写形式：

类型红线（无脑后宫、多女主拉扯、无脑系统流等）

剧情红线（主角被绿、重要角色无意义死亡、烂尾等）

设定红线（战力崩坏、金手指过于万能、世界观前后矛盾等）

风格红线（文风过于文青、对话过于书面、节奏过慢等）

自由填写

和参考作品反面清单的关系：

创作红线：用户主观偏好，优先级最高

反面清单：市场客观反馈，参考性避坑

冲突时以用户红线为准，但 AI 要提示

4.4 跨题材迁移
核心原则：用户规格 > 参考作品。

迁移不是“翻译”，是“先抽象掉原题材，再长出目标题材”。

层级	处理方式
题材外壳	必须换（宗门→学院、灵气→魔力）
故事机制	可以换，功能不变（师徒传承→导师制）
故事内核	不能换（主角的核心欲望、主线冲突本质）
规则层	重新设计（信息差在古代怎么运作）
设计注意点：

最容易翻车的是规则层，因为它不是“换”，是“重新设计”

抽象要深到“故事内核”层，不能停在题材标签上

4.5 章纲的三个约束
1. 节奏锚点（解决“提前写完”）：

在卷纲里定死每一段章数区间该完成什么

写章纲时，必须先看节奏锚点，确认当前区间应该完成什么

2. 信息预算（解决“提前透露”）：

在卷纲里定死每一卷可以释放、绝对不能释放、可以暗示的信息

写章纲时，必须遵守信息预算

3. 视角约束（解决“上帝视角”）：

章纲描述的是“读者在这一章能看到什么”，不是“世界真相是什么”

禁止出现“其实”“真相是”“他不知道的是”等上帝视角关键词

设计注意点：

这三个约束由卷纲产出，章纲执行

必须写死在 SKILL.md 里，不能靠 AI 自觉

4.6 正文写作的四段式
1. 校对（写之前）：

场景校对：读设定文件夹里相关的地点、人物、道具

人物校对：谁出场？各自当前状态？

信息校对：该让读者知道什么？

视角校对：谁的视角？能看到什么？

世界细节校对：先在「世界参照档案」里查

2. 入戏（写之前）：

他此刻的感官状态是什么？

他此刻的情绪是什么？

他此刻知道什么、不知道什么？

这一章他要经历什么？他会怎么反应？

3. 写作（写的时候）：

感官优先（先写看到、听到、闻到、感觉到什么）

对话代入（先想角色会怎么说，再落笔）

场景引用设定（不临时编）

信息控制（遵守章纲的信息预算）

4. 回看（写完之后）：

对照章纲：要完成的事完成了吗？

对照设定：有没有前后矛盾？

对照上一章：衔接顺吗？

节奏：该快该慢对了吗？

视角：有没有上帝视角？

细节一致性：和「世界参照档案」一致吗？

设计注意点：

正文技能的核心不是“生成文字”，是“模拟体验”

AI 要模拟一个视角人物，在这一章里经历了什么

不是“这一章要传达什么信息”，而是“我此刻正在经历什么”

4.7 世界参照档案
定位：

架空小说也有参照系

所有涉及具体世界细节的地方，都不能靠 AI 通用知识临时编，必须有来源，且来源要统一

结构：

参照系（主参照、次参照、架空程度）

已定细节（服饰、建筑、称谓、民俗、饮食）

待定细节

禁止（不得出现参照朝代之后才有的元素）

设计注意点：

第一次写到某类细节，拟定的内容要追加到档案

下次再写到，必须和这次一致

参照系里没有的，触发采风检索

采风检索的结果，沉淀进档案

五、提示词设计原则
5.1 明确严谨，杜绝歧义
核心思想：

把 AI 当成一个执行力很强、但不会猜心思的新人。你写什么，它就做什么。你不写清楚，它就瞎猜。

具体做法：

文件引用用相对路径，不用名字

步骤指令直白，不绕弯

概念用词统一，不换同义词

判断条件写死，不给 AI 自由裁量

为什么重要：

省 token：AI 每“猜”一次，就是一轮内部推理

减少不确定性：写死之后，行为可复现

降低出错率：歧义是 AI 出错的温床

便于调试：路径写死，出错能快速定位

5.2 并行思考的工程化
AI 输出天然是线性的，无法真并行。

解法：

不追求真并行，追求“咬合感”

由点及面：从一个元素强制牵出其他元素

交叉推进：不让 AI 分条列举

强制回环：新想法必须回头冲击旧想法

示例：

text
想到主角性格“固执”
→ 问：固执会对金手指产生什么影响？
→ 金手指如果是“必须灵活变通才能用”，那主角的固执就成了天然限制
→ 这个限制又会产生剧情：主角前期用不好金手指，被嘲笑
→ 被嘲笑又反过来强化他的固执
→ 一个点，牵出了四条线，而且它们互相咬合
5.3 AI 没有感觉的解法
核心问题：

AI 没有“感觉”，判断不了“好不好看”

但人类作家的“感觉不对”，可以拆解成可被规则捕捉的信号

解法：

把方法论变成检查清单，AI 就能“感觉到”问题

不说“我觉得不好”，说“不符合 X 标准”

触发机制三层：方法论自检 → 灵感库比对 → 采风检索

最终判断权交给用户

5.4 不要让 AI 假装有感觉
最重要的一条：

不要让 AI 说“我觉得这段写得不好”

因为它没有感觉，它说“不好”是幻觉

应该让它说：

“对照方法论第 3 条‘金手指必须有代价’，当前设定没有体现代价。这是一个问题点。是否要修改？”

把“感觉”换成“检查项”，把“不好”换成“不符合 X 标准”。

七、设计原则备忘
模拟人类作家思维，不是流水线

业务流程和方法论分离：流程管怎么想，方法论管依据什么做

明确严谨，杜绝歧义：路径写死，用词统一，不给 AI 自由裁量

软件管确定性，AI 管创造性：格式校验交给脚本，内容创作交给 AI

物理切断抄袭路径：原文只在拆书阶段被读，后续不再碰

意图是魂，机制是骨，表象是皮：融合时魂保留，骨可换，皮必换

框架先行，按需检索：先有故事冲动，再按需查灵感库

一次只改一层：打磨时不同时改人物和节奏

不追求真并行，追求咬合感：AI 输出是线性的，但结果可以像并行思考的产物

先跑最小版本，再逐步加回来：不要一次性设计完美

把 AI 当成不会猜心思的新人：写清楚，别让它猜

不要让 AI 假装有感觉：用检查项代替“我觉得”

方法论是流程每一步的操作手册：不是参考书，是必读项
