# webnovel-writer v8（DSH Scriptor 8.2.0）调研

> 2026-10-08 ｜ 定位：**日期戳调研快照**——对同类项目 webnovel-writer 最新产品线的深研结论与吸收决策；本文件是 DSH 宿主期权与"不 fork"论证的唯一案底。本地副本：桌面 `webnovel-writer/`（v6·master）与 `webnovel-writer-v8/`（v8 分支）。数据源：四子代理深研（产品架构/技能层/核心代码包/演进对比）＋110 issue 全量挖掘＋对抗性工程审计（本机实测：pnpm install 1m36s、1122 测试全绿、构建通过）＋产品 UX 恶意评审。前作：wnw v6 字段调研已并入三层咬合总设计 §五（吸收合并表），本文件是其 v8 续篇。

## 一、一句话结论

v8 是"把长篇网文生产线编码为磁盘契约"的高水准工程（三区八目录书仓＋Git 提交语义＋约 40 个工具＋11 技能），工程可靠性领先；但网文方法论与判断力偏薄（编辑通用维度、无量化判据），且有三个结构性病：规则密度逼近模型服从极限（127 处禁令零行为 eval）、token 成本盲盒（章稿全文进上下文 7-8 次＋材料无上限线性膨胀）、单章仪式成本击穿日更节奏。**裁定：不 fork、不二次开发（保留率倒挂——能留的底盘是我们要换的技术栈，要换的内脏是他留下的全部）；大量吸收机制思想，按零依赖技术栈自建。方法论对比结论：拆书与写作判断力 Abzu 深一个层级（判据可证伪/失效形态自报/六书反测/消费闭环自审四样 v8 皆无），工程可靠性（防伪造链/落地完整度）v8 暂时领先。**

## 三、不吸收（带理由）

- **TS monorepo／pnpm／esbuild 单文件打包／约 90 个 DSH rc 依赖**——与零依赖哲学冲突；核心层（skills/scripts/templates/产物）保持 `node:` stdlib＋纯文件
- **127 处禁令＋零行为 eval 的提示词路线**——我们走"少而硬＋写前十查机器闸"；禁令密度要设预算，服从性靠机器闸不靠上下文自觉
- **章后必停＋逐条处置发现项（建议级也不许留白）**——与连写模式差异呈报、作者口径契约冲突（日更节奏是硬需求）
- **定稿只增不改＋retcon 吃书仪式（错字也走全流程）**——保留小事便宜通道（章末写入/修订通道），事实级变更才走重流程
- **八维审读底本**——写前十查＋冷热回看已覆盖且更网文特化（平章三型/金手指对账/接钩义务/契约四问），不引入通用编辑框架
- **DSH 宿主绑定（dsh-baseline 锁单一 rc 版）**——仅期权，见 §五

## 四、反着做（v8 的教训直接立为我们的法）

**材料/组装各层设上限＋写测试断言**。v8 实锤：世界书条目"只增不改"追加事实节，备料只滤未来章事实、历史全留→材料包体量随书长线性增长，直接违反其自declared"体量不随书增长"不变量，且该不变量无任何测试断言。我们：组装表各层上限值法定＋单测断言"上限恒定不随章数变化"（吸收清单 #6 字数记账落地时同步立法）。

## 五、DSH 宿主期权（2026-10-08 裁定：记为期权，不进总设计，不做清单不为其开口）

- **事实**：DSH＝DeepSeek 官方开源 agent harness（MIT，24.6 万 star，"Everything is a Plugin"），当前 developer preview 且官方声明"将有破坏性变更"（v8 被 0.1.5→0.1.7→0.2.0-rc.2 反复打断的伤疤为证）。DSH 技能格式与 CC 近同构（name/description/disable-model-invocation），Abzu 的 markdown 技能＋零依赖脚本＋纯文件产物＝天然宿主无关核心
- **期权内容**：单核双壳——核心层宿主无关不变；DSH 壳＝薄适配（技能目录挂载＋脚本包工具化＋esbuild 单文件），一个核心两个薄壳，绝不两套产品线并树
- **触发信号（两者齐亮才启动）**：① DSH API 走稳（0.2.0-rc→正式版、插件接口冻结动向）；② draft 章 0 在真实语料连载验证通过
- **触发后动作**：1-2 天最小 PoC（挂技能目录＋包 audit.mjs 为工具），验证适配成本与破坏性变更痛感，再裁定是否立项
- **红线**：绝不 fork Scriptor（GPL-3.0＋保留率倒挂＋单人高速迭代 fork 即分叉地狱）
