# AI 长篇写作：痛点调研 × 开源项目机制对照

> 调研日期：2026-09-25。痛点清单来自中英文社区真实讨论（Reddit r/WritingWithAI、知乎、什么值得买、CSDN、GitHub issues 等），按热度排序；"AI 味/去 AI 味"话题按需求剔除。

## 一、痛点榜（按社区讨论热度排序）

| # | 痛点 | 典型原话 |
|---|---|---|
| P1 | 长篇一致性崩坏（设定/人设/世界观前后矛盾） | "写到 12 万字才发现主角断掉的腿在第 15 章'自己好了'"；"20-30 章后角色性格变、关系被忘、魔法体系不一致" |
| P2 | 上下文窗口装不下全书，越写越乱 | "即使 1M token 窗口对 300 万字也远远不够"；U 形记忆曲线（中间丢失） |
| P3 | 伏笔/承诺丢失（埋了不收、回收对不上） | "经常忘记前面埋下的伏笔，后续剧情衔接生硬" |
| P4 | 大纲执行跑偏（不按大纲写、自作主张压缩跳跃） | "AI compresses the story, loses track, or jumps ahead" |
| P5 | 节奏与篇幅失控（注水拖沓、赶结局、章末同一拍） | "Every chapter AI helps you write ends on the same beat" |
| P6 | 多角色声线趋同/人物混淆（voice bleed） | "角色慢慢被磨平成一个声音" |
| P7 | POV/知识边界泄漏（角色说出不该知道的信息） | "Can't keep a secret / not every character knows everything" |
| P8 | 修订引入新矛盾、上下文内新旧事实不分 | "修订后产生了新矛盾；旧细节和后续修正被同等对待" |
| P9 | 作者控制权与维护负担（工具只解一半，人肉盯盘） | "lorebooks 只是部分解法…我的时间全花在 keeping the system on track" |
| P10 | AI 只夸不批（sycophancy，次要） | "obsequious AI attaboys" |
| P11 | 中文网文生态特有：收入不稳 + 平台合规（生态层） | "AI 可辅助，严禁非真人自动化" |

## 三、对 Abzu 的可借鉴机制（纯文件、无向量库可行）

1. **六层摘要冻结（L0-L5）**：正文/单章/chunk/篇章/卷/全书各层摘要，写定即冻结——打 P2，防 P8 漂移
2. **Canon Ledger 账本**：facts（带 known_by 字段，解 P7）/ promises（伏笔带截止章节，解 P3）/ progression（能力境界只进不退）/ rules / timeline，**只追加不修改**——P3+P7+P8 组合拳最优解
3. **关键词触发的条目化世界书**：grep/脚本扫"最近一章+当前章纲"命中的实体名，选择性注入设定文件；核心设定常驻；**中文不用整词匹配**（SillyTavern 文档教训）
4. **写前门禁 + 写后确定性校验**：无章纲不写正文；写后查死人复活、payoff 先于 setup、未击发契诃夫之枪、命名违规、字数容差——可确定性脚本化（"continuity compiler"）
5. **双 agent 校验分离 + 引用原文举证**：写作 agent 不给自己把关；缓解 P9 人肉盯盘、P10 只夸不批
6. **弧卷双层滚动规划**：只细化近期 1-2 卷，远期留骨架，写完再展开——防百万字大纲一次规划必跑偏
7. **相关章节四维推荐**：写新章前按伏笔/角色出场/状态变化/关系找相关历史章节——无向量库用"实体出处索引 + grep 反查"替代，更确定
8. **章末下章计划 + 短期记忆重写**（RecurrentGPT）：对话状态不跨章，章末强制落盘，新会话冷启动加载
9. **剧情纲要同步更新 + 拆书导入映射**（含同人导入预筛映射表 + 整批撤销，QianBi 现成设计）
10. **命名规范表 + 副线超期提醒**（>20 章未推进自动提示）
11. **偏好记忆 + 方法论按需加载**（reference 而非常驻 prompt）
12. **快照与分支**：每卷收尾快照，git 管正文，探索剧情线成本极低

**不适合 Abzu 形态**（只能借思想）：向量库 RAG（用实体出处索引替代）、模型训练（借 AgentWrite"先分段计划再顺序写满"的提示模式）、GUI/服务端工作台（技能+hooks+脚本等价）、学术多 agent 全流水线。

## 四、定位建议

Claude Code 网文技能赛道已有 7k★（Oh Story，爆款方法论路线）与 3.2k★（chinese-novelist-skill，问答路线）玩家；**"确定性连续性机器"这条硬核路线尚无高星中文实现**。Abzu 以"纯文件账本 + 确定性校验门禁"为骨架、网文方法论为皮肤，与现有玩家错位。

## 补录（2026-09-25）：lingfengQAQ/webnovel-writer

> 本节为用户补充发现。原调研遗漏此项目，"确定性路线尚无高星中文实现"的结论**据此修正**。

- **规模**：7,060 星 / 1,194 fork，GPL v3，Python 3.10+，Claude Code 插件形态（master 分支 = v6，维护中）；v7 CLI 已冻结，v8 转向基于 DeepSeek Harness 的写作工作台（源码预览）。地址：https://github.com/lingfengQAQ/webnovel-writer
- **定位**："让 AI 写到几百章，依然记得住设定、接得住伏笔、守得住大纲"——**面向长篇连载的一致性系统**，宣称支持 200 万字量级。
- **核心机制**：
  - Story System：`.story-system/` 是唯一事实源，动笔前签"合同"、写完后提交 `CHAPTER_COMMIT` 入账；state.json、index.db、vectors.db、summaries/、memory 全是**派生只读视图**，projection_log 记录各路同步状态
  - 写章九步流水线：预检 → 刷新合同 → context-agent 生成写作任务书 → 起草 → reviewer 多维审查（blocking 问题阻断）→ 润色 + Anti-AI 终检 → data-agent 提取事实 → 提交并驱动投影 → 章节备份
  - 4 个代理：Context（任务书）/ Reviewer（审查）/ Data（事实提取）/ Deconstruction（拆书）
  - RAG 检索（embedding + rerank，未配 Key 自动退回 BM25 关键词检索）；长期记忆闭环（写前注入 + 写后沉淀）
  - 追读力系统（钩子 / 爽点 / 微兑现 / 伏笔债务追踪）；断点续跑（可信断点续写，不重写已可信部分）；只读 Dashboard 可视化；doctor / preflight / write-gate 运维命令；37 个题材模板
  - 面向作者的最终报告固定四态：已完成 / 部分完成 / 需要你处理 / 未完成
- **与 Abzu 的关系**：重叠 = "一致性优先"路线已被高星验证，需求真实；差异 = 它的写章是**一条龙自动跑完的工程流水线**（作者角色偏监工），Abzu 是**思维引导共创**（作者主导每步、裁决一切）；它重依赖（Python + RAG API Key），Abzu 纯文件零依赖、跨工具可移植；它无方法论知识库层、无融合代理、无三视角评委；协议为 **GPL v3（Abzu 只可借鉴设计思想，不得复制其代码或提示词文本）**
- **可吸收**：最终报告四态、断点续跑、章节级备份、"主链唯一事实源 + 派生只读视图"的投影思想、追读力量化维度、doctor 类运维命令
- **深读补充（docs/ 四份文档，2026-09-25）**：
  - **防幻觉三定律**：大纲即法律（Context Agent 强制加载章节大纲）/ 设定即物理（一致性实时校验）/ **发明需识别**（新实体必须入库并消歧——先匹配已有条目与别名，匹配不上才新建，防"同人不同名"）
  - **Strand Weave 节奏量化**：三线跟踪（主线 Quest 60% / 感情线 Fire 20% / 世界观线 Constellation 20%）+ 断档红线（主线连续不超过 5 章、感情线断档不超过 10 章、世界观线断档不超过 15 章）——P5 节奏失控的最具体可校验解法
  - **六维并行审查**：爽点密度、设定一致性（战力/地点/时间线）、节奏比例与断档、人设偏离（OOC）、场景连贯、钩子强度与期待管理
  - Context Agent（写前任务书）与 Data Agent（写后提取）读写分离；RAG 查询路由 + 无 Key 自动退回 BM25；体检报告可按紧急度过滤（status --focus urgency）；/webnovel-learn 从会话与用户反馈提取可复用写作模式入项目记忆；写章支持 标准/--fast/--minimal 三档强度
  - 多书管理用 workspace 指针文件 + 用户级映射兜底（Abzu 不采用：一书一文件夹更简单）
