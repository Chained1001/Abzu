# 权威 AI 写作项目 Agent 名册调研

> 调研日期：2026-09-25。来源：各项目 README / docs / 代码目录 / 关键文件原文。

## 一、各项目 agent 名册

### zenstory-ai/oh-story-claudecode（7.1k★）
7 个 subagent（按模型分层：Opus 架构 / Sonnet 写作 / Haiku 检查）：
- story-architect（Opus）：题材定位、大纲结构、钩子/反转、情绪弧线
- character-designer（Sonnet）：人设、声线、动机链
- narrative-writer（Sonnet）：正文写作、去 AI 味（写作管线内顺序调用）
- consistency-checker（Haiku）：事实冲突扫描、伏笔追踪、S1-S4 分级报告（高频低价）
- story-researcher（Sonnet）：CDP 搜索+多源交叉验证+结构化落盘
- story-explorer（Haiku）：**只读查询**角色/伏笔/设定/进度，避免污染主上下文
- chapter-extractor（Haiku）：导入旧书时章节规范化

8 个 hook：session-start/end、detect-story-gaps、pre/post-compact、validate-story-commit、**guard-outline-before-prose（唯一阻断型：无细纲禁建正文）**、check-prose-after-write。原则"只提醒不打断"。
核心哲学："对话管创作，文件系统管记忆"；方法论 100+ 文件按需加载。

### PenglongHuang/chinese-novelist-skill（3.2k★）
**没有专科 agent**，全是同构"写手工人"：串行（主 Agent 自驱循环，禁止中途提问）/ 子Agent 并行（章节切批次，批间并行，靠 status 字段认领避免写入冲突）/ Agent Teams（任务队列认领+SendMessage 协调）。写手统一输入：大纲+人物档案+上一章结尾 500-800 字+文风基准 → 章节+摘要+词典更新。细节亮点："动笔前最后读到的必须是正文语态文字"。

### voocel/ainovel-cli（2.1k★）
- Engine（**非 LLM 确定性主机**）：读事实层 → 纯函数决策表派发，零 LLM 调度开销
- Arbiter（单次 LLM 无工具）：歧路语义裁定，决策落 decisions.jsonl 可审计
- Architect：大纲/角色/世界规则；"指南针+视野滚动规划"
- Writer：每章六步（context→read→plan→draft→check→commit），提交结构化事实 JSON
- Editor：弧级七维质量评审
数据流："事实层确定，语义层自主"；代理间不直接通信，全走文件系统。

### forsonny/Claude-Code-Novel-Writer
7 个角色文件（本质是提示词人格）：chapter-writer（含**交接报告契约**：故事状态变化+连贯性事实+未解顾虑，禁止自称"可发表"）、plot-architect（setup-payoff 链）、character-developer（**知识状态**：知道/怀疑/隐瞒）、worldbuilder（规则必有代价，禁无功能百科）、continuity-editor（**8 区审计**：时间线/行程/知识秘密/物理状态/标识符/世界规则/setup-payoff/因果链；区分真矛盾与故意手法）、smart-planner（诊断进度→输出**单个最小高价值下一步**，反对 busywork）、error-recovery（修工作区状态，"稿件是 ground truth"）。

### jiaw-Zh/long-novel-writer
写后双 agent：写作者 + **独立校验 subagent**（明言"避免写作 agent 自我合理化"）。校验=字数硬门+8 项语义（正典冲突/POV/硬约束/进阶/命名/桥段重复/伏笔对齐/场景打分）。底座=canon 账本（facts/promises/progression/rules/timeline/naming/subplots）。

### danjdewhurst/story-skills
**零 subagent**：确定性 CLI（validate/continuity/pacing 等 18 命令，"像编译器对待类型错误"）+ 22 个手动技能。"能用脚本绝不给 LLM"——与 Abzu 哲学最接近。

### GLFzr/QianBi-Novel
三层审校分工：L0 本地脚本（正则拦硬伤）→ L1 LLM 六维终审（消费 must 契约，REJECT 按根因 ROOT_PROSE/OUTLINE/SETTING 定向修复，3 轮熔断）→ L2 **引证验真**（每条意见附原文引证，程序规范化子串验真，编造降级；k=3 投票）。

### obra/superpowers（流程性 agent 模式标杆）
implementer/task-reviewer/final-reviewer 三分离；**执行者禁止自建评审**；修复环 R1-3 唤回原执行者、R4-5 换人+更强模型、5 轮熔断后控制者逐条裁决落 ledger；"对话记忆活不过压缩，进度记在 ledger"；做成 subagent 的理由=上下文隔离（明说）。

### StoryWriter / DeepWriter（学术）
Outline（事件关系型大纲）→Planning→Writing（**动态压缩故事史**）；DeepWriter（AAAI 2026）：大纲阶段"专家 agent 审议+检索增强批评"——用外部资料批评大纲而非只批评成稿。

## 二、元模式

1. **确定性/语义性二分**是所有成熟项目的共同骨架
2. **证据约束评审**（引证+验真+投票）是对抗评审幻觉的最完整方案
3. **模型分层**（贵模型架构/便宜模型跑量检查）与"turn 数>token 单价"是成本共识
4. **做成 agent 的真实理由只有四个**：上下文隔离、并行、防自我合理化、成本分层——否则用 persona 文件或脚本就够

## 三、对 Abzu 的结论

已覆盖：三评委（第一梯队）、researcher（对齐）、**fusion（9 个项目均无对应，独有资产）**
真实缺口：①校对评委（语义一致性 8 区审计，底座=账本）②只读查询代理（explorer 型）③下一步顾问（smart-planner 型，思维引导的具体化）
增强件（非 agent）：④评审计据验真脚本 ⑤根因路由输出格式（ROOT_PROSE/OUTLINE/SETTING）
不该学：全自动写作管线、自动调度层、并行批量写手、error-recovery agent
可偷细节：动笔前最后读正文语态、交接报告契约、ledger 抗压缩+熔断、热上下文派生视图（≤12KB）
