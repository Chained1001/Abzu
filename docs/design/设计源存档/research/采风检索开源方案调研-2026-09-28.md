# 采风检索（researcher）开源方案调研

> 调研日期：2026-09-28。目的：为 researcher 任务书（docs/design/agents/采风检索.md）找联网检索层的设计参照。
> 结论先行：Abzu 不自建联网栈——宿主内置工具为基线、联网增强技能（web-access 类）为可选增强层；三源检索顺序与通道调度、来源分级、站点经验积累四个机制全部落进任务书 v1.2。

## 一、eze-is/web-access（MIT，约 9k★）

给 AI Agent"装上完整联网能力"的 Skill（https://github.com/eze-is/web-access），国内作者一泽 Eze，兼容所有支持 SKILL.md 的宿主（Claude Code/Cursor/Gemini CLI/Codex CLI 等）。

| 能力 | 说明 | Abzu 取用 |
|---|---|---|
| 三层通道调度 | WebSearch/WebFetch/curl/Jina/CDP 按场景自选组合 | ✅ 改造为"页面特征×信息量"双维度通道表（登录态/动态页→CDP；静态→抓取；纯发现→摘要） |
| CDP Proxy | WebSocket 直连用户日常浏览器，**天然携带登录态**，本地 HTTP API（3456 端口），闲置 tab 15 分钟自关 | ✅ 采纳思路：国内站点大量内容需登录才可见，这是裸 WebFetch 的死角——列为 CDP 通道的适用特征 |
| 并行分治 | 多目标分发子 Agent 并行，tab 级隔离 | 暂不取（Abzu researcher 是单席标准档；批量并行留二期） |
| 站点经验积累 | 按域名存 URL 模式/平台特征/已知陷阱，跨 session 复用 | ✅ 全盘采纳——正是"沉淀"哲学在操作层的同构：灵感库/_采风站点经验.md |
| 本地书签/历史检索 | find-url.mjs 跨 Chrome/Edge 查内部系统与历史访问 | ✅ 列为本地第二源可选增补（对应段2 步8"作者自己攒的资料"） |
| 媒体提取 | DOM 提取图片/视频 URL、视频截帧 | 不取（采风面向文本零件） |

设计哲学："哲学＋技术事实，不是操作手册——讲清 tradeoff 让 AI 自己选择"。与 Abzu"告诉路径不让 AI 找"相逆——**检索层采纳其通道自选思想但保留固定优先级表**（创作层不变）。

**架构决策**：web-access 定位为 Abzu researcher 的**可选增强层而非依赖**——README 明示的账号风险（社交平台自动化限流/封号）转为任务书安全注意。

## 二、zenstory-ai/oh-story-claudecode · story-researcher（约 7.2k★）

子代理定义全文已核（skills/story-setup/references/templates/agents/story-researcher.md）。7.2k★ 的爆款方法论路线玩家，已适配 Claude Code/ZCode/OpenCode 等七宿主——竞品档案重要样本。

| 机制 | 说明 | Abzu 取用 |
|---|---|---|
| CDP 优先/WebSearch 兜底 | CDP 拿全文；WebSearch 只有摘要 | ✅ 融入通道表；"摘要路径置信度上限=孤证"是我们的加强版 |
| 场景化查询表 | 事实查证/素材采集/灵感搜集三类九场景，每场景配搜索词修饰 | ✅ 改造为六类查询模板（历史+考证/现实+从业体验/剧情+写法…） |
| 来源 ABCD 分级 | A 学术官方/B 专业媒体/C 自媒体（不可单独引用）/D 小说影视（仅灵感） | ✅ 原样采纳为"来源级"，与结果级三态（已证实/孤证/推测）正交 |
| 引擎降级链 | Google→Bing→WebSearch，页面加载失败检测 | 部分取——引擎由宿主工具决定，国内场景百度优先 |
| URL 导航纪律 | 只从搜索结果 DOM 提取链接，禁止构造 URL | ✅ 原样采纳（红线） |
| maxTurns: 20 / disallowedTools: [Edit] | 预算与写权限约束 | 思路一致（我们：只写待裁决暂存） |
| 降级诚实 | 全链路不可用返回 failed＋gaps，不编造 | ✅ 与狗头军师"失败诚实降级"同源，互相印证 |

## 三、GPT Researcher（assafelovic/gpt-researcher，开源 deep research 框架）

plan-and-execute 范式（先由查询生成研究问题计划→并行抓取 20+ 源→聚合时交叉验证→综合报告）；偏见与幻觉靠多源验证而非单源可信。Abzu 取用：任务单查询词改写（2-3 变体）＝其研究问题规划；"至少 2 独立域名交叉"＝其聚合验证的最小化版本。

## 四、对 Abzu 的净结论

1. **不自建联网栈**：Abzu 纯文件零依赖不破——联网能力全部来自宿主（内置 WebSearch/WebFetch 为底线，web-access 类技能为增强）
2. 通道调度进任务书（双维度表），站点经验卡进沉淀体系（操作层零件）
3. 国内圈定与登录态问题是国内用户特有痛点，web-access 的 CDP 思路正好对症——README 建议在插件文档里向作者推荐该技能作为可选安装
4. 并行分治与媒体提取记为远期不取项
