# 术语表（Abzu 产品语言权威）

> 版本：v0.6（沿革见 CHANGELOG 与 git 历史）
> 定位：产品语言的唯一权威——宪法、文件规范、SKILL 正文、references 中的叫法一律以本表为准；本表与其他文档冲突时，以本表为准（发现冲突当次收口）。
> 用法：每条 = 中文名 + 一句话定义 + 英文对应（用于 skill 内文件与代码命名）。

---

## 一、工作流类

| 术语 | 定义 | 英文对应 |
| --- | --- | --- |
| 立项 | 确定卖点、题材、金手指、目标读者与参考作品的起始阶段，产出 `project.md` | concept |
| 世界观 | 构建世界设定、力量体系与势力的阶段 | worldbuilding |
| 分层大纲 | 总纲→卷纲→细纲逐层细化的大纲体系，每层只细化到当前卷 | layered outline |
| 总纲 | 全书骨架，规划分卷结构与主线大事件 | master outline |
| 卷纲 | 单卷的剧情规划，含本卷目标与关键转折 | volume outline |
| 细纲 | 当前卷逐章的拍点清单，是起草单章的直接输入 | chapter outline |
| 起草 | 按细纲写章节正文的阶段 | drafting |
| 修订 | 对已有正文做结构性修改 | revision |
| 润色 | 对已有正文做语言层面的打磨，不动结构 | polish |
| 阶段门控 | 每个工作流阶段产出后暂停，经作者确认才进入下一阶段的控制方式 | stage gate |
| 会话恢复 | 新会话开始时按既定顺序读取进度与追踪文件、重建上下文的行为 | session resume |
| 作家思维四问 | 生成步骤开工前的四问自检协议（理论选择／知识缺口／权衡评估／读者模拟），按步骤性质三级配档（全量／降级／免）——让 AI 像人类作家一样思考，压住空转与知识幻觉 | author-mind check |
| 一致性检查 | 核对人物言行、设定、伏笔是否前后矛盾的审查动作 | consistency check |
| 采风 | 问题驱动的定点资料调研——创作卡点处按当前需要检索参照（史料/范式/氛围/节奏/技巧），区别于扫榜（市场面）与拆书（整本机制）。**本词只作动作与角色义**——大纲阶段的阶段名／门控名／状态值／书目录一律用「资料收集」系（资料收集步／资料门／大纲-资料收集中／`资料/`），标尺类跨阶段资产见「参考标尺」。**范围提醒**：大纲阶段该动作实际指**对参考清单内各作品做全字段等量深采**（见设计文档第二章），不止于本条的卡点定点检索——两者同属 field research，只是层级不同。 | field research |
| 采风票据 | 采风产出的统一落盘格式：来源/用途/关键摘录/关联步骤标签，消费时按标签匹配载入 | field note |
| 采风员 | 逻辑角色：问题驱动定点调研的执行者，v1 为各域 workflow 内步骤分支，T1 候选物化为 agent | field researcher |
| 三评委 | 逻辑角色：读者/编辑/同行三视角独立审同一份大纲的评审组，只看产物不看创作过程，产出处方化报告 | three-judge panel |
| 逻辑角色 | 按职责与输入输出定义的角色（触发/输入/输出/产物/人设），物理形态可为 v1 分身/步骤或 T1 agent | logical role |
| 内容比对校验 | 采风产出与原素材的相似性/照搬校验，防采风采成照搬 | content comparison check |
| 上下文包 | 起草单章前按该章需要从真源动态装配的派生视图（细纲拍点+前情+快照+设定+伏笔+文风），不落盘 | context pack |
| 写后自检 | 单章起草后的一体化检查：一致性核对+伏笔登记+AI 痕迹扫描三合一 | post-write check |
| 参考作品（对标） | 立项必填的质量锚点作品（主参考 1 + 辅助 ≤3，AI 辅助寻找、至少确认 1 本）；是拆书域的输入清单与采风定向采集的锚点——设计文档中「对标作品」叫法以本词条为准 | reference work |
| 回读补问 | 立项流程中把已采集信息回读给作者、再按六类问题组（题材细化/主角种子/结局倾向/体量预期/更新节奏/雷区规避）补问的采集动作 | read-back follow-up |

## 二、写作项目文件类

| 术语 | 定义 | 英文对应 |
| --- | --- | --- |
| 写作项目 | 用户某本书的目录，由 skill 创建并遵循标准结构 | writing project |
| 手稿 | 章节正文文件，按卷分目录存放 | manuscript |
| 人物卡 | 单个角色的档案（身份、动机、能力、关系、口癖），一角色一文件 | character card |
| 前情提要 | 滚动更新的已写剧情梗概，供续写时快速重建上下文 | synopsis |
| 伏笔账本 | 登记伏笔埋设章节、计划回收点与回收状态的追踪文件 | foreshadowing ledger |
| 人物状态快照 | 各角色当前所在位置、已知信息与关系变化的追踪文件 | character states |
| 文风指南 | 记录叙事视角、语感偏好与禁忌的文件 | style guide |
| 参考标尺 | 从参考作品实测出的十组量级画像（范围值＋依据强度三级），供大纲/卷纲/正文跨阶段对表；**参考而非硬指标**——越界须按三级判定处置（见设计文档写法纪律 13） | reference scale |
| 进度 | 记录当前所处阶段与最近进展的文件，会话恢复的入口 | progress |

## 三、网文创作类

| 术语 | 定义 | 英文对应 |
| --- | --- | --- |
| 黄金三章 | 开局前三章的专门设计：悬念前置、金手指早现、钩子密度高于常规 | golden three chapters |
| 金手指 | 主角获得的超越常规的初始优势或成长体系 | golden finger |
| 爽点 | 读者获得情绪满足的剧情兑现点 | payoff |
| 期待感 | 读者对即将发生的兑现的预期，由铺垫制造 | anticipation |
| 章末钩子 | 每章结尾留下的悬念或牵引，硬性质量标准 | chapter hook |
| 节奏 | 剧情推进与情绪张力的快慢配比 | pacing |
| 卷 | 网文的结构单位，一卷包含一个完整的大剧情弧 | volume |

## 四、扫榜调研类

| 术语 | 定义 | 英文对应 |
| --- | --- | --- |
| 扫榜调研 | 六大能力域之一（域名），覆盖榜单采集、市场分析与选题决策；单次动作称扫榜 | scan |
| 扫榜 | 分析平台排行榜数据，提炼市场趋势与热门题材的调研动作 | scan |
| 扫榜报告 | 扫榜分析的产出报告，含市场洞察、题材候选与验证动作 | scan report |
| 选题决策 | 把扫榜结果转化为可执行选题建议的产物文件，后续立项的输入 | topic decision |
| 样本校验 | 判断榜单样本是否足以支撑结论的规则（样本量阈值与降级纪律） | sample validation |
| 数据质量三行 | 采集文件头部必须含的三行：数据质量、有效条目、问题摘要 | data quality header |
| agent-browser | CDP 采集依赖的浏览器自动化 CLI 工具（全局 npm 安装）——是工具不是 AI 分身 | agent-browser |
| 子代理 | Claude Code 中由主会话派生的 AI 分身（独立上下文），T1 触发后启用；区别于 agent-browser 这类工具 | subagent |
| skill 资产 | 随安装分发到用户机器的 skill 运行时文件（references/scripts），引用规则受部署自包含约束 | skill asset |
| 仓库治理文档 | 仓库根目录与 docs/ 下的规范、记录类文件——不随 skill 安装分发，引用可用 Markdown 链接 | governance doc |
| 调用双层 | skill 触发方式的分层裁定：六域 skill 入口唯一：/abzu-{域} 显式调用（自然语言不触发）；skill 间禁互调（跨域只经文件衔接）；预留命令薄壳属 user-invoked 编排层——与直呼同属用户显式发起，双层指「直呼域 skill / 薄壳编排」两级入口；详见 architecture §四 | model-invoked / user-invoked |

## 五、拆书分析类

| 术语 | 定义 | 英文对应 |
| --- | --- | --- |
| 拆书 | 对用户提供的参考书做结构化拆解，提炼可复用写作方法的分析动作；六大能力域之一（域名） | deconstruction |
| 六维拆书 | 从人物设定、关系图谱、冲突矩阵、双时间线、叙事顺序、三维节奏六个维度对单书做完整拆解的自包含产物 | six-dimension analysis |
| 双时间线 | 故事事件的真实顺序与读者获知的披露顺序两条线，二者的错位即信息差，是悬念调度的原料 | dual timeline |
| 三维节奏 | 剧情强度（1-5）、情绪强度（1-5）、描写密度（1-3）三个独立刻度，不得合并成一个节奏分 | three-axis pacing |
| 结构块（戏剧循环） | 拆书的语义最小单位：由缺口→加压→转折→兑现→新阅读债构成的完整章节块，按 2-5/5-12/12-30 章三档切分 | structure block |
| 证据三分 | 拆书结论的置信分级：明确（有书证）/强推断（≥2 处线索同向）/暂定（单一信号），全文档逐条标注 | evidence tiers |
| 爆款机制四层 | 解释亮点的四层框架：表层表现→叙事机制→读者心理→可迁移原则，缺一层即不合格 | hit mechanism layers |
| 机械章节索引 | 脚本生成的五列章节数据（章号/标题/定位符/字数/状态），只定位不承载语义，禁止模型手写替代 | mechanical chapter index |
