## 一、域职责与状态

大纲域（`abzu-outline`；占位·待建设）：立项、设定与全书总纲的规划——把「想写一本什么书」先压成一页规格，再沿资料收集、草稿、打磨定稿三步把规格长成全书大纲；产出书目录骨架与大纲域产物，文件树、字段与状态值见[书目录契约](../书目录契约.md)。

边界：本域管到**定稿门**为止——卷纲归卷纲域、细纲与正文归正文域；已退役域不参与（创作输入＝作者积累＋资料＋方法论＋灵感库）。

状态：设计真源（本组五件）已成文；`skills/abzu-outline/` 的域壳、references 与脚本尚未创建，归域建设批。

## 二、定义性约束

**约束集先行**：本域的一切创作决策都由**上游产物的约束集**驱动——规格先于资料、资料先于草稿。写规格时只收作者口述，不拿外部作品倒推作者意志（参考档案是资料收集步的产物，不进规格步的装载表）；采资料时以规格里的参考偏好为唯一分派依据；进草稿步时，**规格就是全部创作决策的约束集**——其**根本属性（题材／基调等）是生成的硬约束**（写玄幻不出科幻大纲）；**实测标尺不进生成**——它是大纲 v1 成形后（3.5 量级查）的**校验器**，治生成期 LLM 自己感觉不到的密度失衡（百万字只对抗一两个敌人组织这类病，生成完拿标尺一照才现形）；生成期各处只持**方法论默认密度感**。照常识「先多找参考再定写什么」在本域是反序——那会把本书写成参考书的仿品。

## 三、流程总览

### 1. 状态机与断点

当前阶段五值：**大纲-规格中/资料收集中/草稿中/打磨中/已完成**（粗枚举）；细定位靠**产物状态表**（每行=步骤号+产物+状态，行序即时间序）。断点续跑=读产物状态表→报「你在哪」→从缺口续。产物状态表由各步骤④产物落盘动作**同批追加行**（产物名/状态/备注），格式=三列表格（产物名｜状态｜备注），头部两行为「当前阶段」「产物状态表」标题——同批追加行，不由续跑时重建。

| 状态 | 子步骤 | 断点证据 | 续跑动作 |
| --- | --- | --- | --- |
| 规格中 | 1.0/1.1/1.2 | 目录与基本规格字段完备性/确认记录 | 读草稿→报缺项→续问；齐→重现门 |
| 资料收集中 | 2.1/2.2×N/2.3/2.4 | 档案头状态字段（只认档完）/标尺十组齐/确认 | 缺哪本补派；标尺不齐重合成 |
| 草稿中 | 3.1→3.5 线性 | 大纲.md 各节完备性（含伏笔速记埋收）+候选选定标记+**底盘停靠确认**+人物卡逐张（主角/反派/配角） | 报「故事核齐、骨架差 X 节」式定位→续 |

## 四、写法纪律

1. **步骤单元七字段**（序固定）：①作用〔一句大白话+一句心流锚〕②收集〔程序要干的事：读什么→取什么〕③怎么想④产物与完备校验⑤过关标准⑥交互〔逐字话术+{变量}占位〕⑦异常与降级。
2. **「怎么想」=思考指令**（问句链/因果指令），禁知识描述。生成型步骤走**四拍流水**：拍一·方法论问句 → 拍二·参考对照 → 拍三·量级参照 → 拍四·灵感注入；收集型步骤拍数递减。**四拍有权重**：每个生成型模块标**主拍**（本模块思考密度最高的一拍，问句从密），非主拍问句从简——四拍顺序不变，密度分配看模块性质。
3. **完备律（零待定推进）**：每步产物过关=必填字段全为具体值；「没想好」不停——现场给 2-3 个具体选项让作者选，或触发采风。比较想写的（灵感槽）除外。
4. **序号体系**：章中文序与步骤十位对齐；步骤 `N.M 步骤名`（名字为一级标识）；四拍定名；**门控命名制**（规格门/资料门/定稿门——阶段级硬停）区别于**停靠**（模块级条件停）。
5. **评委铁律**：三维度（编辑/作者/读者）苏格拉底问句，只呈报不拦截——处置权在作者，跳过须登记理由。
6. **数值纪律**：标尺类数值一律范围值+依据强度三级（锚定实测｜多源统计 N 源｜推演⚠️）；情绪用描述性文字，禁百分比。
7. **规格字段准入律**：只有「作者开书时真知道＋影响市场定位」的字段才进基本规格必答清单；创作决策类字段住创作步骤（有语境时再定），规格里最多留**可选倾向**——与「不收金手指/主角设定」同一原则的成文化。
8. **字段值必须可执行**：LLM 消费的字段，值要能直接转成写作/决策指令——基调等风格字段用**受控词表词组**（词表见附录 A-2，词序即主次（跨轴选词时为整体主次，同轴内为局部主次）），比例/百分比类伪精确数值不入字段（与第 6 条「情绪描述性」同源收紧）。
9. **统一情绪词表**：基调字段、参考标尺②情绪基调组、灵感库情绪爽点标签槽、评委问句的情绪判断、分卷五件套情绪弧线，五处共用[附录](大纲域设计-附录.md) A-2 词表——一处增词五处生效，查询对比才对齐。
10. **用户语言规范**（承旧 SKILL「话术零黑话」）：运行时对作者说的话一律大白话，内部术语只活在设计文档与文件层。对照表（不完整即增）——

    | 内部术语 | 用户话术 |
    | --- | --- |
    | 档案／档完 | 参考资料包／采完了 |
    | 内核定标 | 这本书的本质类型 |
    | 锚定实测 | 实测（从原书数据数的） |
    | 多源统计 | 多方印证 |
    | 推演⚠️ | 推算值（仅供参考） |
    | 级联 | 连带检查 |
    | 完备律／零待定 | 信息齐了才往下走 |
    | 灵光位 | 顺手翻到的灵感 |
    | 标尺 | 标尺（作者原词，保留） |

11. **亲和簇原则**：耦合的思考放同一模块或相邻模块（**亲和簇内聚**），簇间通过**显式接口**把结论传递给下游（**接口传递**），避免注意力折返——跨模块来回跳会稀释思考密度、诱发返工。首例＝[草稿步](大纲域设计-草稿步.md)「模块序」节的模块重排：金手指-主角-故事核同簇入 3.1，下游按「金手指三型／体系+底盘」两接口消费。
12. **作家思维四问**（正式名「作家思维」）：生成型步骤开工前先跑四问（问句链，写在 ③怎么想 的**最前**）——①**理论选择**：这一步该用哪套写作理论/方法论？为什么是它而不是别的？②**知识缺口**：这件事上我有哪些是记不准、可能过时、样本偏的？③**权衡评估**：这里有几条路可走？各自的代价与最坏情况是什么？④**读者模拟**：读者读到这儿会怎么反应——哪里爽、哪里会弃读、哪里看不懂？

    **三级配档**（级别写在 `③怎么想` 行首的方头括号标记里，形如 `〔作家思维：全量〕`）：**全量**＝四问全跑，用于产出创作决策的核心生成步骤（3.1／3.2／3.3／3.4——人设／冲突设计／大纲）；**降级**＝只跑③权衡评估＋④读者模拟，用于采集、统计、评审、处方类（1.1／2.1／2.2／2.3／4.1／4.2）；**免**＝确定性/机械步骤不跑（1.0／3.5／4.3）。**问与拍的关系**：四问是**开工前的前置自检**（回答「我该怎么想」），四拍是 ③怎么想 内部的问句流水（回答「这一步按什么顺序想」）；①的选定注入拍一，②的缺口影响拍二/三的对照口径。

    **落点（文件账本律）**：四问不是空转自省，结论必须有文件落点——①理论选择写进本步 ③怎么想 的首句；②知识缺口逐条落成动作（触发采风／联网核实／问作者），**不得带缺口硬写**；③权衡与④读者模拟的结论写进本步产物的对应字段（3.1 故事核小节／3.2 体系条款／3.3 分卷五件套与节点表／3.4 人物卡），产物无对应字段时写进该模块产物末尾的「已评估」备注。**④不替代评委**：读者模拟是**生成上下文内的自演**，与 4.1 读者评委的隔离素读（刻意不装标尺/规格/底盘）不是同一机制，不得用来省掉评委。

    **正例**＝3.1 故事核：全量四问——①定「本书用哪套故事核模型」、②暴露「这个题材我没数」当场触发采风、③在「爽点前置 vs 悬念前置」间取舍、④定「第一章给不给金手指」；四条结论分别落进故事核小节与该模块的「已评估」备注。**反例**＝3.5 草稿验收跑全量四问：四查是机械校验，四问在此**没有产物落点**（书还没给读者看，「读者模拟」只能空转；四查结论已有验收单模板承载），正是空转思考这个反模式要防的。
13. **参考标尺用法**（作者定性：**参考而非硬指标——故事性大于硬指标**）：标尺治的病是**内容密度失衡**（百万字只有两三个反派、主要人物三四个——上千章的作品不该如此匮乏），不是配额考核。

    **十组二分**：**可数组（5 组＋2 派生项）**＝真源已给区间、可由产物机械数出的组——①节奏目标（爆发密度/高潮周期 → 派生**节点数**）、③结构要点（暗线数/换图规划/条目数 → 派生**卷数**）、⑤人物梯队、⑥反派层级、⑦伏笔量；**不可数组（5 组）**＝②情绪基调、④主角压力、⑧读者情绪曲线、⑨爽点类型分布、⑩信息揭示节奏——只作**参照视角**（**3.5 量级查时**对一对量级感觉），不做偏离判定。

    **三层分工**：脚本数事实（从产物机械数出可数组实测值）→ LLM 提处置（对照区间给建议）→ 作者裁决（**改标尺**与**红灯处置**须作者确认）。**本期无脚本**——可数组实测值由 LLM 代跑，须在产物中显式声明「本值系代跑」（标尺脚本属 skill 建设批次）。

    **三级判定**（实测值 n、标尺的区间记作 [a,b]；偏离幅度＝**所在侧边界值**（缺口侧取下限 a、超出侧取上限 b）÷3，向下取整、最小 1）：**过**＝n∈[a,b]；**说明**＝偏离＜幅度（在产物里写一句为什么即可，不阻塞）；**须处置**＝偏离≥幅度。**记录用词**：判定为「须处置」后，产物状态表按四选之一记录为「**已处置**（补／删合／改标尺／接受并说明）」——「须处置」是判定态、「已处置」是落盘态，两者不混用。**判定统一落 3.5 量级查**（大纲 v1 成形后十组全对照，草稿期唯一定考点）；3.x 各模块拍三**不对照实测标尺**、只持**方法论默认密度感**（撑体量／压节奏的常识量级）——实测区间在生成期进场会诱发「对着区间写」，密度失衡的病从源头防（判定对象未成形的问题随之消失：3.5 时一切已成形）。

    **处置四选**（须处置时逐项选一，并落行产物状态表）：**补**——按本书自身工艺补足，**禁止为凑区间注水**（新增反派须带层级定位与镜像点、新增节点须带因果与功能、新增伏笔须有埋有收）｜**删/合**——超出时收缩密度（合并功能位、拆卷出场、砍冗余节点）｜**改标尺**——本书体裁/体量与标尺本就不同（非修炼类、短卷结构、平台节奏差异），修正数值并注明依据强度，**须作者确认**（标尺是跨阶段资产，卷纲/正文继续对表）｜**接受并说明**——评估后认为偏离合理（如本书就是「少反派·深反派」结构），写明理由标「已评估·接受」。

    **反机械红线**：差异大时先答「本书是否真需要这个量级」，再决定补／改标尺／接受——**不得为对齐区间新增无功能内容**。**正例**：规格需 10 个反派、区间 15-20 → 缺口 5＝下限 15 的 1/3 → 须处置；评估后若本书确实只需 10 个，出口是「改标尺为 10-15」或「接受并说明」，**不必然补 5 个**。**反例**：看到缺 5 个就派 5 个只出场一次的杂鱼反派——密度指标过了，内容密度更差了。

## 五、域交互细则

立项域准入律的流程细则（§十 上线验收清单的「准入律」条为验收要点，本节为其流程细则）：

1. 三问段式：段一自由聊（对话式）→ 段二回读默认（静默 + 回读）→ 段三选项列表 ≤3 + 对话式 ≤3。
2. **字段准入律**：终局口径与感情线不问——作者在段一主动说了才记倾向；有想法填，无则标「倾向待定」，不计入完备校验。
3. 收拢式重问：段三未答全时，把剩余必答项合并成一次问清单重问，不逐项追问。
4. 过程性动作默认执行（如建骨架）＋通报结果，不额外索取确认；有副作用的操作（写文件、调外部服务、删数据）才停靠确认。

三步式各段的话术、装载表与过关判据的逐字细则见[规格与资料步](大纲域设计-规格与资料步.md) 1.1；准入律字段清单见[附录](大纲域设计-附录.md) B-1。

## 七、灵感库接口（可选外部资产）

灵感库是**可选外部资产**——作者跨项目的独立资产（独立 git、跨书、不随本仓分发），本域只在草稿步拍四消费它。本域对它的定位与接口形态四条：

1. **只消费不生产**：本域只按槽检索取条目，不回写、不维护——条目的增删改由作者在库侧手工做。
2. **初期状态（手动库）**：演进三步走——手动库 → 消费验证 → 触发信号成立后立项工具化；触发信号＝条目过百／回写需求成型／多书同时消费，任一成立才评估做成工具或技能。
3. **不依赖三条**：命中则用；未命中即跳过并如实通报；库不可用＝降级而非失败（拍四跳过，产物「灵感来源」字段标「库不可用」）。**任何判据不得引用它**——本域验收清单与各步过关条件里不出现「必须命中 N 条」类断言。
4. **契约可演进**：库的字段／交互／检索协议是**待消费验证的假设**，可能随使用演进；本域只认「库侧存在该契约」与接口形态，不认版本细节。契约修订由库侧自持（自持 git、自持版本号），本仓不做副本、不做镜像。

仓内只写接口形态：不复述契约内容、不写仓内契约路径、不复制库资产。

## 九、跑通信号（It's working if）

作者不开 skill 内部即可自查——出现这些信号说明本域跑通了：

- 门控与停靠停下来时，你说得出「现在在第几步、卡在哪个产物」，不必翻聊天记录回想。
- 关掉会话再敲 `/abzu-outline`，它报出的位置和你记得的一样——断点从产物状态表读，不从对话记忆猜。
- 标尺亮红灯时你拿到的是**处置选项**（补／删合／改标尺／接受并说明），而不是一句「数字没达标」的判决。
- 大纲定稿后，每一卷的核心冲突句与卷末钩子你都说得出来；伏笔每条有埋有收，六节齐备。
- 三评委报告里出现「分歧点」而不是清一色同调——三位评委各执一双眼睛，不是同一个人说三遍。
- 采风断网或库不可用时流程照样往下走，且它明确告诉你「哪一处降级了」。

## 十、上线验收清单

域级条目（`/abzu-outline` 装入目标项目后逐条核对）：

- 仅显式调用 `/abzu-outline` 进入；入口判定按**文件证据**（无 `创作进度.md` → 全新开书）。

- 不越阶段：门控确认前不产出后续阶段实质内容（目标产物存在但为空模板即合规）。
