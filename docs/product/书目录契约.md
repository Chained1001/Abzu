# 书目录契约

> 定位：约束 skill 产出到用户书目录的文件：目录树、文件名、字段（跨域唯一衔接面）。
> 依据：迁移自**旧版** `docs/standards/产物契约标准.md` §1–§5、正反例与机检锚点（原文逐字，仅两条相对链接按新位置改指）；原始出处为旧仓《大纲阶段设计文档》§5.3 书目录结构与交接清单、旧仓《守卫与验收规范》§五.3 域产物格式机检契约。只收大纲／卷纲／正文三域相关，细则未定者标「待设计」。

## 一、条文

### 1. 用户书目录树（大纲域建齐，其余域共享）

```text
书项目/
├── 基本规格.md          # 三态：草稿 → 实测 → 定格
├── 创作进度.md          # 状态 + 产物状态表 + 断点
├── 资料/参考-{书名}.md   # 每书一档，文件名内嵌书名
├── 参考标尺.md          # 跨阶段资产（十二组量级画像）
├── 大纲/大纲.md         # 六节：故事核／因果链／大高潮／换图／分卷／伏笔速记
├── 设定/世界观底盘.md   # 底盘含预置地名清单
│   └── 人物卡/{角色}.md # 主角／反派／配角三类，一角色一文件
└── 打磨/草稿验收单.md  处方报告-R{N}.md  级联记录.md  定稿验收单.md
```

书项目目录由 skill 运行时创建（立项步建齐**本阶段用得到**的目录与空文件（阶段一完成时含 `创作进度.md`／`基本规格.md`），其余随各自阶段批建齐，门控确认前为空模板），**不进本仓库**。目录名与文件名一律中文（命名纪律见[命名标准](../standards/命名标准.md) §3）。

### 2. 产物字段契约（大纲域，已定格）

| 产物 | 文件名 | 关键字段／结构 | 状态值 |
| --- | --- | --- | --- |
| 基本规格 | `基本规格.md` | 五段式；必答字段零待定（书名可暂定但必须有值） | 草稿／实测／定格 |
| 创作进度 | `创作进度.md` | 头部两行：当前阶段、产物状态表标题；产物状态表三列（产物名｜状态｜备注），行序即时间序，由**门控与停靠确认点**的同批落盘动作追加行 | 大纲-规格中／大纲-资料收集中／大纲-草稿中／大纲-打磨中／大纲-已完成 |
| 参考档案 | `资料/参考-{书名}.md` | 头部状态字段（消费方只认「档完」）、稀缺度标注 | 待采／采集中／档完 |
| 参考标尺 | `参考标尺.md` | 十二组量级画像：范围值 ＋ 依据强度三级；跨阶段资产，供大纲／卷纲／正文对表 | 推演／锚定（公开样本）／实测／定格 |
| 全书大纲 | `大纲/大纲.md` | 六节齐备：故事核／因果链／大高潮／换图／分卷／伏笔速记（埋收对应） | 草稿／定格 |
| 世界观底盘 | `设定/世界观底盘.md` | 底盘含预置地名清单 | 草稿／定格 |
| 人物卡 | `设定/人物卡/{角色}.md` | 主角（含分阶段弧线）／反派（含层级定位 + 镜像点 + 弧线方向可选）／配角（含全书弧线方向），三类同模板 | 草稿／定格 |
| 打磨产物 | `打磨/` 下四件 | 草稿验收单／处方报告-R{N}／级联记录／定稿验收单；报告条目须全处置 | — |

门控与停靠确认点均须在产物状态表落行（落行式样如「世界观底盘-待确认」），否则续跑不得跳过。

### 3. 跨域衔接（唯一接口）

域间**禁互调**，跨域只经落盘文件衔接：生产者只落盘，消费者在自己域内定义如何查找与读取（细则归[触发与交互标准](../standards/触发与交互标准.md)）。大纲域 → 卷纲域的交接清单（定格态）：

`基本规格.md`｜`参考标尺.md`｜`大纲/大纲.md`｜`设定/世界观底盘.md`｜`设定/人物卡/*.md`｜`资料/参考-*.md`（档完态）。

### 4. 产物格式机检契约（可由脚本或文件系统确定性判定的断言）

| 产物（所属域） | 格式契约（机检点） | 生产端真源 | 机检载体 |
| --- | --- | --- | --- |
| 书目录骨架（大纲） | 立项步建齐**本阶段用得到**的目录与空文件（阶段一＝`创作进度.md`／`基本规格.md`）；门控确认前为**空模板** | [大纲域设计-附录](outline/大纲域设计-附录.md) | 待建守卫 |
| 规格完备（大纲） | 基本规格必答字段零待定、零空值 | [大纲域设计](outline/大纲域设计.md) 主件与分件 | 待建守卫 |
| 阶段值与状态表（大纲） | `创作进度.md` 阶段值落在五值枚举；门控／停靠点均落产物状态表行 | [大纲域设计](outline/大纲域设计.md) 主件与分件 | 待建守卫 |
| 大纲产物三件（大纲） | `大纲/大纲.md` 六节齐、`设定/世界观底盘.md` 非空、人物卡一类一文件 | [大纲域设计](outline/大纲域设计.md) 主件与分件 | 待建守卫 |
| 标尺十二组（大纲） | `参考标尺.md` 十二组齐、逐组带依据强度标注 | [大纲域设计](outline/大纲域设计.md) 主件与分件 | 待建守卫 |

### 5. 待设计（卷纲／正文域）

- **卷纲域**：产物文件名与字段**待设计**——该域尚无设计真源，原仓亦无对应断言，随该域建设另立（其输入＝§3 交接清单）。
- **正文域**：产物文件名与字段**待设计**，但原仓已有下列机检级契约点，作为该域设计的输入保留（细则随该域设计真源出现时收口）：
  1. 细纲文件中前三章条目存在，且每章含钩子／悬念要素字段。
  2. 起草前读取细纲、出场人物卡与状态／追踪类产物中的前情（会话恢复顺序）。
  3. 新章节文件落在正确的卷目录，编号续接上一章，无跳号。
  4. 章节字数落在 `基本规格.md` 声明的章节字数目标区间内。
  5. 章末存在钩子段（钩子质量以人工判断）。
  6. 写完更新 `创作进度.md`，受影响的追踪类产物（前情／伏笔／人物状态）同步。
  7. 改稿只修改目标章文件（其他章节文件字节不变）；若影响剧情事实，同步更新追踪类产物受影响条目。
  8. 修订后在 `创作进度.md` 留下修订记录。
  9. 伏笔核对逐条列出（埋设章节 ＋ 计划回收点 ＋ 当前状态），超计划回收点未回收者被明确标记。
  10. 伏笔核对**只读**——未修改手稿正文。

## 二、正例与反例

- ✅ 立项门控确认前：`创作进度.md` 与 `基本规格.md` 存在且为空模板（**本阶段用得到**的落点；不越阶段）。
- ✅ `创作进度.md` 的产物状态表逐行追加（「产物名｜状态｜备注」三列），门控确认落行「世界观底盘-待确认」。
- ✅ `设定/人物卡/林晚.md`（一角色一文件，中文名，落在 `人物卡/` 目录下）。
- ✅ `打磨/处方报告-R1.md`（轮次号体现在文件名，第二轮为 `-R2`）。
- ✗ 门控确认前就在 `大纲/大纲.md` 写入实质内容（越阶段——目标产物存在但非空模板即违规）。
- ✗ `设定/人物卡.md` 一张文件塞全部角色（一角色一文件是契约，不是建议）。
- ✗ 门控确认不落产物状态表行（续跑时无从判定，只能靠对话记忆——违文件账本律）。
- ✗ 章节文件落在根目录而非卷目录、或编号跳号（正文域契约点 3）。
- ✗ 伏笔核对顺手改了手稿正文（核对是只读动作，契约点 10）。
- ✗ 把 `参考标尺.md` 当硬指标卡死（标尺是参考；越界须按依据强度三级判定处置）。
