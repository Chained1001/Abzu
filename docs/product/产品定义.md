# 产品定义

> 定位：Abzu 产品层的总纲——做什么、给谁用、怎么算成功；域设计、契约、术语与验收文档均以此为上位。
> 依据：迁移自根 `AGENTS.md` 项目一句与 `README.md` 门面陈述，剥离开发底座后扩写；§七 路线摘要自存档 `docs/product/总纲.md` §五。

## 一、产品一句

Abzu 是跑在 Claude Code 上的 AI 写作 skill 套件（宿主唯一）——面向长篇网文的阶段化创作流程：从立项、设定、全书总纲，到单卷规划与章节撰写，按阶段推进、按门控停靠。

套件形态为三域各一 skill：大纲域、卷纲域、正文域（域清单与建设状态的唯一真源见[架构设计](架构设计.md) §一）。**大纲域阶段一（规格步）资产已建（088）**，卷纲域与正文域未建；`skills/` 已建——套件范围即此三域，无第四个域。

## 二、产品范围（三域）

| 域 | 命令 | 覆盖阶段 |
| --- | --- | --- |
| 大纲域 | `/abzu-outline` | 立项、设定、全书总纲 |
| 卷纲域 | `/abzu-volume` | 单卷规划与收卷判断 |
| 正文域 | `/abzu-write` | 章纲与章节撰写 |

域清单与建设状态的唯一真源在[架构设计](架构设计.md) §一；本表只作产品范围概览——详表（含建设状态）见该节。

## 三、与开发底座的分界

产品运行在用户机器上（安装与使用见 `README.md`）；本仓库根目录与 `docs/standards/`、`docs/specs/`、`scripts/` 属开发底座——不随产品分发，读者是开发者与开发用的 AI 工具。产品层设计（域设计、契约、术语与验收场景）落 `docs/product/`。

## 四、目标用户

**先自用、结构留门**——首位用户是作者本人，本阶段不面向外部新用户做专门引导。

- 先自用：文档与流程按作者自己的工作节奏写，不预设外部用户的知识背景。
- 结构留门：写法兼顾作者回看与陌生人读懂——术语有真源（[术语表](术语表.md)）、产物有契约（[书目录契约](书目录契约.md)）；不专门写新手指引与安装教程，安装说明归 `README.md`。

## 五、成功判据

三条，均可判定；**待作者校准**——判据方向已定，阈值与用于验收的样本书由作者确认。

1. **能力**：拿一本新书，从立项到定稿全程只用本套件（三域 skill），不借助会话外说明——流程能走完。
2. **质量**：每个域交付时没有"当时该问没问"的洞——待定项在交付前清零，零待定推进。
3. **可维护**：六个月后只看 `docs/`（产品层各件），能重建当时的意图与取舍。

## 六、范围与不做

范围：仅三域——大纲域、卷纲域、正文域（概览见 §二，真源见[架构设计](架构设计.md) §一）。

- **导入与抓取底座独立化不做**——抓取类能力不单独成域或成件，随所在域内置脚本随行。
- **独立审查技能不做**——评审以域内角色承担：三评委（读者／编辑／同行三视角）见[术语表](术语表.md)，不立独立技能、不立独立域。
