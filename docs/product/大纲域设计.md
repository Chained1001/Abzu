# 大纲域设计

> 定位：大纲域（`abzu-outline`）的产品设计——域职责、流程骨架、域交互细则与上线验收清单。
> 依据：上线验收清单迁移自**旧版** `docs/standards/测试与验收标准.md` §2.1（原文逐字）；流程骨架待设计。

## 一、域职责与状态

大纲域（`abzu-outline`；占位·待建设）：立项、设定与全书总纲的规划。产出书目录骨架与大纲域产物——文件树、字段与状态值见[书目录契约](书目录契约.md)。

## 二、流程骨架（待设计）

## 三、上线验收清单

- 仅显式调用 `/abzu-outline` 进入；入口判定按**文件证据**（无 `创作进度.md` → 全新开书）。
- 规格收集按三段式推进（段一自由聊 → 段二回读默认 → 段三选项列表 ≤3 ＋对话式 ≤3），**终局与感情线不问**（准入律，细则见 §四「域交互细则」）。
- 规格门停等作者确认，**确认前不进入下一阶段**（门控＝阶段级硬停，与模块级停靠区分）。
- 交互模态标注与实况一致（封闭选择走选项列表、开放采集走对话式、过程性动作默认执行）。
- 不越阶段：门控确认前不产出后续阶段实质内容（目标产物存在但为空模板即合规）。

## 四、域交互细则

立项域准入律的流程细则（§三 上线验收清单的「准入律」条为验收要点，本节为其流程细则）：

1. 三问段式：段一自由聊（对话式）→ 段二回读默认（静默 + 回读）→ 段三选项列表 ≤3 + 对话式 ≤3。
2. **字段准入律**：终局口径与感情线不问——作者在段一主动说了才记倾向；有想法填，无则标「倾向待定」，不计入完备校验。
3. 收拢式重问：段三未答全时，把剩余必答项合并成一次问清单重问，不逐项追问。
4. 过程性动作默认执行（如建骨架）＋通报结果，不额外索取确认；有副作用的操作（写文件、调外部服务、删数据）才停靠确认。
