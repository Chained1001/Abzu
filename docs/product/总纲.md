## 三、设计理念

- **域是平行的门，不是管道**：跨域无顺序锁，大纲可反复打磨、随时回改；唯一依赖是文件账本律的产物检查（缺产物＝提示，非门禁）。
- **生产者只落盘，消费者定义读取**（对应 Pipes and Filters 架构模式与数据耦合：每个 filter 只知输入输出，不知管道中其他 filter；域间只通过落盘文件通信，零调用、零预定义消费行为）：生产者的全部义务是把产物按共享约定落盘（文件名与落点归公共层）；如何查找、读取与使用，由消费方在自己域内定义并自行告知用户。跨域导航由各域入口自查 + skill 本名命令承担，域工作流不含流程衔接内容。
- **阶段门控只管域内工序**（如单章：章纲确认后才写正文），跨域顺序由作者决定。
- **会话恢复按文件证据**：域壳入口按文件证据（进度文件存在性与产物状态）定位续跑点，不凭对话记忆。
- **文件账本律**：工作流每一步必须落盘或修改某个文件，没有文件落点的步骤不存在；状态判定来自文件系统证据。此律是「域是平行的门」得以成立的前提——门与门之间只认落盘产物。

## 四、基础设施选型

### 4.1 承载架构（多技能骨架）

六域各一 skill + 未来 `abzu-setup`（T1 触发）。**决定性判据：六域共享同一份可变状态**（写作项目的 `基本规格.md` / `创作进度.md` / 手稿）——共享资产的归属方式是单技能与多技能两方案的分水岭。

| 维度 | 单 skill 六域（未采纳） | 多 skill 分立（现行） |
| --- | --- | --- |
| 共享资产 | 一份正本，零机制 | 需同步机制（前作为此养 64 组字节对账 + 守卫）或内嵌副本（漂移风险） |
| 精准入口 | 6 个一行命令薄壳（一次性十分钟） | skill 本名即命令，免费 |
| 上下文 | SKILL.md 薄总控常载 + references 按需读，与多 skill 持平 | 只载命中域 |
| 版本/安装 | 一份版本号、一个目录、两条 cp | N 份 frontmatter 对齐（前作为此建四轨守卫） |
| 触发 | 一条 description 收敛 | 六域同属「写小说」，自然语言互抢，靠直呼纪律压制 |
| 反向迁移 | 拆出容易（先合后拆） | 合并极难（前作从未做成，税一直交） |

实测数据支撑（前作 mo-shu v2.6.1）：六域合计 188 份 references / 约 26,000 行；跨 skill 同步副本 64 组。单 skill 形态下这 64 组塌缩为一份正本，总盘反而更小。规模躺在磁盘上而非上下文里——按需加载下，单次会话只进总控 + 当前域 workflow + 两三份方法论。

逃生舱：输入侧域（scan / analyze，不读写书目录）未来可低税拆出；产出侧四域深度耦合共享状态，不拆。

成长路径与拆分触发器：内容量增长（方法论/知识库/脚本扩充至数万行）**不构成**拆分理由——渐进披露下内容躺磁盘不进上下文；且共享约定随域增加而增值（单副本被更多域摊薄）。拆分由真实需求推动，不预先构建：

- **T1**：运行时组件物化需求出现（hooks／子代理进书项目，如正文域引入评审分身）→ 诞生 `abzu-setup`，届时评估组件重载域是否独立（参考实现：ECC 全家桶插件模式）。
- **T2**：外部用户提出选择性安装或市场分发需求 → 先以单插件打包整体 skill，仍不足再拆输入侧。
- **T3**：某域与书目录状态彻底解耦且需独立演进 → 可拆。

### 4.2 精准入口

多技能骨架下 **skill 本名即精准命令**：`/abzu-scan`、`/abzu-outline` 等由 Claude Code 斜杠菜单原生补全，无需命令薄壳（单技能时期的方案，随骨架切换退役）。域内细分操作按各域工作流的交互模态执行。

**唯一入口**：六域 skill 入口只有一条——`/abzu-{域}` 显式调用（description 声明触发边界，自然语言提及不触发）。理由：六域同属写作场景，自然语言模糊触发不可控、入口确定性优先（前作自然语言互抢为教训）；**模型自主匹配层已退役**（2026-09-07 参考 mattpocock/skills 单轴模型立法），「双层」此后指「域 skill 直呼」与「薄壳编排」两级入口。skill 之间**禁止互相调用**——跨域只经落盘文件衔接（§三「域是平行的门」）。预留的命令薄壳若启用，属 user-invoked 编排层：只可调用域 skill，域 skill 永不反向调用薄壳或其他域 skill。

### 4.3 部署与实测循环

```bash
改 skill → bash scripts/check.sh → npx markdownlint-cli2
        → 在目标项目目录 npx skills add Chained1001/Abzu -y   # 仓库内禁跑，check.sh [0] 守卫；离线备选 cp -r skills/abzu-scan ~/.claude/skills/abzu-scan
        → 新会话（新文件夹）敲 /abzu-scan 真测
```

v1 无部署器：没有 hooks／agents／项目级 `CLAUDE.md` 需要物化，安装即全部部署；书项目脚手架由立项流程自建；原版本兼容机制已随 036 批退役（见 [release-and-versioning.md](../standards/release-and-versioning.md) §四）。skills.sh 安装只携带 skill 文件夹（不含 `.claude/commands/` 薄壳）——六域 skill 本名即命令。

setup 等价物的触发条件：将来引入需要物化进书项目的组件（hooks／子代理／项目级模板）之日，才引入 `/abzu-setup`——此前不做。职责边界：setup 只处理**硬依赖**（物化组件落盘与依赖预检）；题材偏好、平台选择等**软配置不进 setup**，由各域工作流首用交互自行采集。

**行业安装原型对照**（2026-09-06 调研：awesome-novel-agent／webnovel-writer／oh-story／ECC／anthropics 官方）：

| 原型 | 安装 | 初始化 | 适用 |
| --- | --- | --- | --- |
| ① 零初始化纯技能 | skills.sh／插件市场／复制 | 无（技能自包含） | 纯知识/流程技能——Abzu 当前形态 |
| ② 首用即初始化 | 同上 | 域技能首步工作流自动 init（新目录检测→建骨架） | 产物需落进书项目（网文技能类最主流） |
| ③ 独立 setup 技能 | 插件市场 + setup | 独立部署技能物化 hooks/agents/知识库 + 版本哨兵 | 常驻确定性组件出现时——T1 之后的 Abzu 形态 |

Abzu 现状为原型①（标准、零摩擦）；「扫榜目录首用创建」已实现原型②的 init-on-first-use；T1 触发时按原型③立法 `/abzu-setup`。

### 4.6 版本与兼容

- 套件发布版本用三段 `X.Y.Z`，**四处一致**：已建壳 `metadata.version`／`.claude-plugin/marketplace.json`／git tag／CHANGELOG 版本段——细则见 [release-and-versioning.md](../standards/release-and-versioning.md)。
- 治理文档头注用两段 `vX.Y`，与套件版本各管其域、互不换算（细则见 [file-conventions.md](../standards/file-conventions.md) §五.2）。
- **写作项目兼容**四原则（新字段/新文件全部可选增量／老数据零丢失／迁移先备份／不兼容变更必须提供迁移说明）＋迁移执行边界（默认只输出迁移说明，自动改写用户书稿须单独立项裁定）；替代机制待新书项目设计定义。

### 7.1 工作流类

| 术语 | 定义 | 英文对应 |
| --- | --- | --- |
| 立项 | 确定卖点、题材、金手指、目标读者与参考作品的起始阶段，产出 `基本规格.md` | concept |

| 卷纲 | 单卷的剧情规划，含本卷目标与关键转折 | volume outline |

| 修订 | 对已有正文做结构性修改 | revision |

| 采风票据 | 采风产出的统一落盘格式：来源/用途/关键摘录/关联步骤标签，消费时按标签匹配载入 | field note |
| 采风助手 | 逻辑角色：问题驱动定点调研的执行者（**单点叫法**，设计文档与 agent-design 已对齐至本名），v1 为各域 workflow 内步骤分支，T1 候选物化为实体 agent | field researcher |
| 三评委 | 逻辑角色：读者/编辑/同行三视角独立审同一份大纲的评审组，只看产物不看创作过程，产出处方化报告 | three-judge panel |
| 逻辑角色 | 按职责与输入输出定义的角色（触发/输入/输出/产物/人设），物理形态可为 v1 分身/步骤或 T1 实体 agent | logical role |
| 内容比对校验 | 采风产出与原素材的相似性/照搬校验，防采风采成照搬 | content comparison check |

| 写后自检 | 单章起草后的一体化检查：一致性核对+伏笔登记+AI 痕迹扫描三合一 | post-write check |
| 参考作品（对标） | 立项必填的质量锚点作品（主参考 1 + 辅助 ≤3，AI 辅助寻找、至少确认 1 本）；是拆书域的输入清单与采风定向采集的锚点——设计文档中「对标作品」叫法以本词条为准 | reference work |

### 7.5 拆书分析类

| 术语 | 定义 | 英文对应 |
| --- | --- | --- |
