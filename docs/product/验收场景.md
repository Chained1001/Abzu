# 验收场景

> 定位：产品层的人工判断验收场景——全域通用条目、未建域待启用验收点与真机人工试跑命令步骤。
> 依据：迁移自原《测试与验收标准》§2.4／§2.5 与旧版 §3 的安装与真机命令（原文逐字，仅两条相对链接按新位置改指）；做法框架与记录约定见 `docs/specs/施工机制.md` §二「真机人工试跑」条。

## 一、全域通用（任意域可判）

- 域外休眠：与网文创作无关的请求（如「把这个 CSV 按销售额排序」）不触发任何 abzu 技能、不套域框架；调出某域后转提域外请求，正常执行不套本套件框架。
- 未建域如实告知：敲未建设域命令，模型如实告知「该域尚未建设」，不模拟、不代替、不产出占位内容。
- 域边界：本域内不顺手执行其他域的活；跨域意图移交对应域命令（域边界即合同边界）。
- 中断契约生效：中途要求停止或表达跨域意图时，先确认当前进度已写入文件再移交，不强行走完本域流程。

## 二、未建域待启用验收点

卷纲／正文域的**脚本检查级**契约点（编号续接、只改目标章、字数区间、伏笔只读核对等）已按分流落[书目录契约](书目录契约.md) §5，随各域设计定稿件出现时启用；本节只收人工判断要点。

## 三、真机人工试跑命令与步骤

1. 在目标项目目录装：`npx skills add Chained1001/Abzu -y`；离线备选：复制 `skills/abzu-{域}/` 到用户级 skills 目录。
2. 新开会话（新文件夹），敲 `/abzu-{域}` 跑该域主流程；宿主会话须具备命令执行（Bash）工具与 Node.js（版本见[运行环境标准](../standards/运行环境标准.md)）。
3. 逐条核对各域设计的验收清单节（[大纲域设计](outline/大纲域设计.md)／[卷纲域设计](volume/卷纲域设计.md)／[正文域设计](write/正文域设计.md)）与本文 §一 的全域通用条目，＋ `bash scripts/check.sh` 全绿结果。

人工试跑记录写入位置与每域最低测试要求见 `docs/specs/施工机制.md` §二「真机人工试跑」条（本件不复制）。

## 四、大纲域常备评估提示集（每版改动后必跑）

> 依据：skill-creator 评审结论——评估环从临场发挥积累成文为常备资产。五条各配预期（该出现的逐字话术、该落的文件行、不该出现的）；改一版跑一遍，发现的偏差按 `outline-stage-spec.md` 头注迭代纪律落在出错步近旁。

1. **全新开书全流程**（空目录起跑）：预期——建设状态行逐字；「在这个文件夹里开新书吗？」；弹窗三选（写哪一类——一格一类目可自填／平台／写多长）＋读者定位回读＋参考两问（纯文本同消息分行；第一本必填＝书；其余任意作品形式、0-3 个）；段一问雷区（带示例）、不被重问表单项；AI 补默认回读（含雷区捡拾确认）；段三选基调（AI 出 6-8 个逐行编号候选，作者选 2-6 个；超额直接请删减；段一未聊出雷区则保底补问）；1.2 出「核验过了：该填的都填上了，参考共 {N} 本、基调 {N} 个词，题材、平台、读者定位之间没冲突」且 `基本规格.md` 约束节有「本次核验结论」行；1.3 摘要 ≤3 条＋全文＋可点开路径＋「规格定了吗？定了就开始采风。」。全程无模态标注、无裸「我」／「咱们」、无 AI 代推荐参考书、无内部术语（字段／承诺性字段／三边／四节齐之类）进话术。
2. **续跑接回**（第 1 条选「先停下」后，新开会话再敲 `/abzu-outline`）：预期——按文件证据报「你在哪」；从「规格定了吗」接上，不重跑 1.0／1.1。
3. **「只是问问」分支**（首问选「只是问问」）：预期——只答疑，目录里不出现任何新文件。
4. **「要改」回环**（1.3 选「要改」→ 说一处要改）：预期——「哪儿要改？直接说。」→ 改完回 1.2 重核（核验行再出）→ 再进 1.3。
5. **红灯路径**（表单或对话给冲突组合，如题材「仙侠」＋平台与读者按女频深度文给）：预期——处置话术逐字（「{项}通常落在{建议区间}，你填的超出去了。两种走法：a 就按你填的（补一句说明）；b 改成建议范围——按哪个？」），按作者选择改值或带说明通过。

轨迹三看（不只看结果，也看轨迹）：入口思考时长（首测约 50 秒，应逐版下降）；同一文件是否被重复读；话术是否被润色（如「想过的画面」被改「想画的画面」）。
