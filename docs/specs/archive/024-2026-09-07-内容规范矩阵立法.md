# 规格：024 · 内容规范矩阵立法（按文件类别统一内容规范与风格）

> 本规格自包含。立法来源：作者裁定——「根据文件的类型或功能定位分类，为每一类制定统一的内容规范与风格标准，参考业界权威规范确立；痛点是同类文件内容风格各不相同（如各 SKILL.md）」。现状勘察（2026-09-07 现场实测）：① 五占位壳结构平行（同 18 行模板换域词，md5 互异属预期）② scan 壳 34 行五节，与 skill-writing §三 域壳模板节序一致 ③ references 10 份头注已统一（消费点/边界两行式——存量标杆）④ 七脚本均有文档头（JSDoc/# 块/docstring），但**节结构各自为政**（采集策略/功能列表/使用方式/前置随意组合，对照 qidian/scan-analyze/cdp-utils 三种样态）⑤ 治理文档头注大体三行但措辞有微差（glossary 版本行含初版日期、standards 用「沿革见 CHANGELOG」式）。预验（铁律④）：全仓「file-conventions §五」引用 = 0（节改号安全）；file-conventions H2 计数 5；skill-writing §三 模板段计数 4。

```markdown
### §五.1 脚本文档头四要素（sh＝# 块 / py＝docstring / js＝JSDoc——要素相同，形态随语言）

1. **用途**：一行——做什么、给谁用（消费方）。
2. **用法与参数**：调用命令示例 + 参数表（含默认值）；与 §一「输入校验」行（缺参→用法说明+退出 2）呼应。
3. **依赖与前置**：外部依赖、环境要求、降级路径（对齐 §一「降级声明」行）。
4. **维护入口**：平台改版/字段变更时改哪里（选择器位置、解析函数名）——012 号「平台改版维护入口」注释块的成文化。

（现状实证：七脚本均有文档头但节结构各自为政——025 对齐批按四要素统一。）

### §五.2 治理文档头注三行式（默认形态）

> **版本**：vX.Y（沿革见 CHANGELOG 与 git 历史）
> **定位**：……（角色一句话，含单点权威声明如适用）
> **依据**：……（architecture §七 权威层 / 语言业界权威 / 仓库规范，如实标注）

（键名加粗对齐存量标杆（file-conventions/markdown-style 等现行形态）；个别文档可加第四行分工声明（如本文件与术语表分工）；glossary 等既有偏离由 025 对齐批处理，本批只立默认形态。）
```
