## 第一篇·产品（What & Why）

### 一、设计理念

#### 1.1 模拟作家思维链

域 = 思维阶段，产物 = 思维中间态，门控 = 作家自我审查停顿。域间的产物消费关系 = 作家思维链中前一个念头喂养后一个念头的自然流动。本设计的首要约束是：**每一步的交互形态与产出内容，必须让作者感到「这就是我在想的事情」**。

#### 1.2 心流两层

大纲阶段自身有心流（搭世界/排剧情的沉浸），但其**产品目的是为正文心流供血**——细纲拍点密度 = 正文阶段「清晰目标 + 即时反馈」的来源。产品设计须同时保护两层：大纲阶段的交互批量化（防思维链断裂），正文阶段的上下文包装配（防心流破碎）。

#### 1.3 采风哲学

创作输入以作者积累与定点调研为主，拆书对标为辅非必需。采风不是独立阶段，而是嵌入创作思维链各环节的信息获取动作——触发场景包括：设定佐证、情绪采样、雷区规避、跨界碰撞、节奏参考、卡点技巧。素材范围：小说、动漫、影视、史料、真实事件等（开放集，不限列举）。

#### 1.4 侦察域配套

scan（市场面）与 analyze（整本机制）为增强输入：选题决策、拆书产物接入创作链时提供实证支撑；**缺席时创作链必须完整可用**（降级路径：作者自行判断方向 / 凭阅读积累替代拆书参考）。当前阶段 scan/analyze 放置一边，不作为写作链设计输入。

#### 1.5 双视角设计

思维链定义产品的灵魂（做什么、为什么这个顺序），工程化定义产品的身体（怎么做才跑得动）。两者在门控与产物上对齐，在步骤粒度与状态管理上分化：思维链的「交织」在工程上拆解为原子步骤 + 状态持久化；思维链的「心流」在工程上转化为上下文包信息密度优化。

#### 1.6 风格单路径（细纲党）

真实作家光谱上存在细纲党 ↔ 灵感流两态（灵感流 = 轻量前置、边写边发现故事），但灵感流依赖人类作者的品味直觉与整书长期记忆兜底——LLM 执行器走灵感流方差大，且三大管理机制全部失锚（上下文包装配的关键词、伏笔账本的计划回收点、章末钩子均以细纲拍点为输入）。**产品裁定单路径 = 细纲党**（2026-09-10 作者裁定：「让 LLM 走灵感流发挥极不可控且不稳定」）：拍点完整前置 + 批量交互 + 写作中禁大幅改细纲——交互规范见 §3.4。

#### 1.7 元认知原则（简易写作 AGI 的核心）

**系统在每个原子操作内部，像作家一样进行自对话**——不是被动执行步骤，而是主动思考四件事：

| 作家内心活动 | 系统行为 | 实现方式 |
| --- | --- | --- |
| 「该用什么专业理论？」 | **理论选择**——判断当前情境最适合哪条方法论，说明选择理由 | 原子操作嵌入「先选理论并说理由」强制自问 |
| 「我这块知识不够」 | **知识缺口检测**——识别缺失信息，触发采风 | 三层机制（见 §2.6） |
| 「这么写好处坏处是什么？」 | **权衡评估**——产出前列风险，不只事后审 | 原子操作嵌入「列出方案的一个风险」 |
| 「读者读到这里怎么想？」 | **读者模拟**——预演阅读体验 | 原子操作嵌入「从读者视角描述感受」 |

**实现基础**：LLM 不会自发拥有元认知，但**可以被指令引导着思考**——在正确的位置放正确的指令，让它被迫走一遍思考路径。方法论萃取件的职责从「告诉 LLM 知识是什么」升级为「引导 LLM 怎么思考」。

**方法论萃取件的双层形态**：

```markdown
❌ 知识描述形态（旧）：
  「冲突有五类：利益/信念/情感/身份/方法」

✅ 思考指令形态（新）：
  「你设计的冲突属于哪一类？
   只覆盖一类还是叠加了多层？
   读者会感到紧张还是烦躁？——紧张=想知道怎么解决；烦躁=觉得不合理
   如果把冲突撤掉，故事还成立吗？——如果成立，冲突不够核心」
```

**元认知触发频率**（终审裁定，两级 + 批量降级）：

- **核心生成步骤**（大纲/卷纲/人设/冲突设计）：全量触发四维自对话（理论选择 + 知识缺口 + 权衡评估 + 读者模拟）；
- **重复性操作**（填充/润色/短句优化）：降级触发——仅风险评估 + 读者模拟（防过载）；
- **批量操作**（多文件扫描类）：降级为结果校验，不做过程自对话。

#### 1.8 开放集原则

**作者举例是启发不是枚举**——作者给 ABC 时系统应主动考虑 DEF；系统设计不将作者的举例场景硬编码为穷举清单。素材范围、题材组合、冲突类型等均为开放集。

#### 1.9 参考作品必填

纯靠 LLM 从零想出好剧情成功率极低——**对标作品是质量锚点**。立项流程必须包含对标引导步骤（AI 辅助寻找），至少确认 1 本参考作品才继续。参考作品是拆书域的输入清单，也是采风定向采集的锚点。

#### 1.10 产物归属与权限规则（终审补全）

| 产物 | 生产域 | 编辑权 | 跨域读取 | 跨域修改 |
| --- | --- | --- | --- | --- |
| project.md | outline | outline（门控 1 后走修订流） | volume/write 只读 | ❌ 禁止 |
| 创作进度.md | 全域共享 | 各域写入自己阶段 | 全域 | 仅写入自己阶段的字段 |
| 设定集.md | outline | outline（门控 2 后走修订流+变更事件） | volume/write 只读 | ❌ 直接禁止；write 可发起变更请求 |
| 人物卡/*.md | outline | outline（设定面）/ write（快照面） | 全域 | write 只更新快照面，不改设定面 |
| 总纲.md | outline | outline（门控 2 后走修订流） | volume/write 只读 | ❌ 禁止 |
| 卷纲/卷N.md | volume | volume | write 只读 | ❌ 禁止 |
| 细纲/卷N.md | write | write（可随时调整拍点） | write 自身 | ✅ write 域内自由 |
| 手稿/... | write | write | style 只读 | style 只出报告不改手稿 |
| 追踪/* | write | write（每章写后更新） | write 自身 | ✅ write 域内自由 |
| 采风/*.md | 全域共享 | 写入域（谁采谁写） | 全域（按标签匹配） | 追加不覆盖 |
| 文风指南.md | outline（初稿）/ style（维护） | style | 全域 | ❌ 禁止 |

**冲突合并原则**：同一产物只允许一个域拥有编辑权；跨域修改通过**变更请求**机制（write 发起设定变更请求 → outline 确认后修改设定集 → 广播变更事件 → write 执行影响扫描），不允许直接跨域编辑。

### 二、采风

#### 2.1 三轴分工

| 能力 | 回答的问题 | 粒度 | 触发 |
| --- | --- | --- | --- |
| 扫榜（scan） | 市场怎么样？什么在火？ | 榜单面 | 定期/立项前 |
| 拆书（analyze） | 这一本整体怎么写成的？ | 整本书 | 参考书验证时 |
| **采风（本节）** | **我此刻的创作需要什么参照？** | **问题驱动的定点调研** | **创作全程卡点即触发** |

#### 2.2 五类创作诉求

1. **佐证设定合理性**：世界观/习俗/能力体系找现实或现有作品案例参照，避免设定悬浮与自相矛盾。例：唐代穿越文查史料、社会风俗与文化细节。
2. **情绪与氛围采样**：抓取一段故事/历史事件的情绪基调与氛围感迁移复用——不照搬剧情。
3. **规避雷区与同质化**：调研同类作品流行套路与读者反感桥段，避开烂俗、寻找差异化切口。
4. **拓宽脑洞、碰撞创意**：接触不相干领域素材做跨界转化，生成全新情节与人设。不同题材的故事可能外壳不同但内核相似——题材组合是开放集。
5. **参考叙事节奏**：学习优秀作品的节奏排布——战斗密度、情绪起伏、伏笔铺设的处理方式。

附加场景：卡点时借采风习得实操技巧（金手指设计、长篇大纲搭建等）。

素材范围：小说、动漫、影视剧、历史史料、真实事件等（开放集，不限列举）——研究对象为他人剧情设计与人物塑造思路。

#### 2.3 采风的嵌入位置

采风不是独立阶段，而是嵌入创作链各环节的信息获取动作：

| 环节 | 采风形态 | 对应诉求 |
| --- | --- | --- |
| 世界观构建 | 检索史料/地理/制度/风俗 | 佐证设定 |
| 人物设计 | 调研同类人设范式，规避俗套 | 避雷 + 碰撞 |
| 主线结构 | 研究剧情编排、节奏密度、金手指设计方法论 | 节奏参考 + 技巧 |
| 细纲卡文 | 检索同类桥段解法 | 碰撞 + 技巧 |
| 正文起草 | 情绪氛围参考 | 采样 |

**架构归宿**（终审收敛）：永久嵌入各域，不独立成域、不并入 scan——定点卡点调研属于创作内生动作，不属于市场扫描。

#### 2.4 采风产出的消费策略

采风落盘为统一票据（来源/用途/关键摘录/**关联步骤标签**）。消费时按当前步骤匹配关联标签，只载入相关票据——不把整个素材库塞进上下文。

**采风票据复用机制**（终审补全）：

| 规则 | 说明 |
| --- | --- |
| 跨章复用 | 同卷内任意章可按标签匹配复用 |
| 跨卷复用 | 标签匹配 + 状态检查（过期票据标注「已过期——设定可能已变更」） |
| 全书复用 | 设定佐证类票据全书有效（史料不变）；情绪采样类票据卷内有效（氛围随卷变化） |
| 权重规则 | 同章匹配多张同类票据 → 最新票据优先采用，其余降为参考；信息矛盾时按冲突处理行执行 |
| 过期判定 | 票据关联的设定字段被修改 → 票据自动标注过期 |
| 冲突处理 | 多张票据信息矛盾 → 保留新票据，旧票据标注「被 CF-NNN 取代」 |

#### 2.5 内容比对校验

采风产出与原素材的相似性/照搬校验（mo-shu 只立项未实现的教训补课〔源：批B81/B93 采风智能体，比对校验代码缺陷未投产〕）。产品行为：大纲/细纲中引用采风素材时，系统提示作者确认「迁移的是机制/氛围而非情节/表述」；技术设计见第二篇 §十二。

**相似度阈值**（终审裁定 N=8）：中文连续 ≥ 8 字与采风素材原文重合 → 抄袭预警 + 人工确认（作者确认迁移正当，或改写）。〔N=8 系终审裁定值；首本实测若误报过载，按 §八 定稿锁 minor 变更流程校准〕

#### 2.6 知识缺口检测——三层机制

LLM 没有真正的元知识（不知道自己不知道什么），但可以搭一个结构化机制让缺口暴露出来。三层设计从最可靠到最兜底：

##### 第一层：方法论前置检查清单（最可靠，机械式）

每个方法论萃取件头部加一个前置知识清单——应用方法论之前逐项检查：

```markdown
## 前置知识检查
- [ ] 当前故事的题材类型
- [ ] 主角的能力边界
- [ ] 世界观中的力量等级体系
- [ ] 同类题材 2-3 本成功作品的对手设计模式
- [ ] 目标读者对「对手换新」的疲劳阈值
```

缺项 → 触发采风或问作者。机械式检查，不依赖 LLM 元认知。

##### 第二层：上下文审计指令（LLM 驱动，补清单盲区）

workflow 里每个原子操作开头嵌入：

```markdown
在开始之前，列出本次任务需要但当前上下文中没有的信息：
- 你正在做什么（一句话）
- 做这件事你需要知道什么（列 3-5 条）
- 当前上下文里已有什么（逐条确认）
- 缺什么（说出来，触发采风或问作者）
```

LLM 能看见自己上下文里有什么——所以能做「需要 vs 拥有」的差集。这不是元认知，是**上下文盘点**。

##### 第三层：产出信号检测（事后兜底）

产出完成后扫描知识缺口信号：

| 信号 | 含义 |
| --- | --- |
| 泛化词汇（「大概」「可能」「一般来说」） | LLM 没有具体知识，在猜 |
| 缺乏具体细节（力量体系只有「强/中/弱」） | 没有参考过真实案例 |
| 数字无来源（「大概 20 章」「建议 3-5 个」） | 编造数据而非引用方法论 |
| 与采风票据高度相似 | 照搬而非消化融合 |

命中信号 → 标注「此段可能存在知识缺口」→ 作者决定重写或自行补充。

**三层协作**：

```text
原子操作开始
  → 第一层：方法论前置检查 → 缺项 → 采风/问作者
  → 第二层：上下文审计 → 缺项 → 采风/问作者
  → 执行产出
  → 第三层：产出信号检测 → 命中 → 标注 → 作者决定
```

### 三、创作链四阶段

**总览**：

```text
outline（全书规划）⏸① → volume（本卷骨架）⏸③ → write（细纲+正文+更新）⏸④⟳ → 下一卷 ↩ → 全书完成
                                      ↑⏸②（总纲+设定集确认后进入卷循环）
```

**四门控汇总表**（终审补全）：

| 门控 | 位置 | 确认对象（锁定内容） | 不可逆理由 |
| --- | --- | --- | --- |
| ⏸① 立项确认 | outline·立项后 | project.md + 文风指南初稿——锁定全书题材、卖点、核心方向 | 最高成本锁：全书方向 |
| ⏸② 总纲+设定集确认 | outline·打磨后 | 总纲 + 设定集 + 人物卡——锁定世界观、主线、人物弧光 | 决定全书骨架 |
| ⏸③ 卷纲确认 | volume·每卷 | 卷纲——锁定单卷戏剧结构、节奏、转折 | 决定本卷资源分配 |
| ⏸④ 细纲确认 | write·每卷首次 | 细纲拍点清单——锁定单章落点、情节推进、伏笔排布 | 正文心流的供给契约 |

#### 3.1 立项与大纲（abzu-outline）

对应思维链环节 1-2（创意孵化 + 核心抽象），是大纲域的入口环节（第零环节）——project.md 是后续所有环节的共享输入。

| 维度 | 内容 |
| --- | --- |
| 输入 | 作者灵感/采风素材（选题决策为增强非必需；**参考作品必填**——AI 辅助寻找） |
| 产物 | project.md（卖点/题材/金手指/目标读者/参考）+ 文风指南初稿 |
| 交互 | 开书双问（平台/方向）→ 灵感种子自由输入 → 回读补问 → **对标引导（必填）** → 定稿过目 |
| 门控 | ⏸① **立项确认**——决定全书方向，之后修改成本指数级上升 |
| 异常 | 采风素材不足 → 引导作者自由输入，不强制 |

对标引导详细流程：

```text
AI：「你有没有对标作品？想写的故事跟哪本书最像？」
├── 有 → 登记参考候选（主参考 1 + 辅 ≤3）
└── 没有 → AI 根据灵感种子推荐 2-3 本同类型热门作品
    → 作者翻阅后确认至少 1 本 → 继续
```

立项之后进入**设定⟷大纲并行模式**——两功能交叉推进、共享世界状态：

| 功能 | 思维模式 | 产物 |
| --- | --- | --- |
| 设定 | 世界一致性推理 | 设定集（力量体系/地理/势力/规则）+ 人物卡（设定属性面） |
| 大纲 | 因果与节奏推理 | 总纲（一句话故事/主线因果链/大高潮/分卷）+ 人物卡（弧线属性面） |

设定与大纲**深度互哺且非对称**：设定遵循「最小可行」为剧情承载，剧情推进持续倒逼设定补全。产品设计支持任意切换，共享世界状态。人物卡为独立实体（兼跨两功能）。

大纲打磨：三评委（读者/编辑/同行）处方化审 → 打磨循环 → 设定三查 → ⏸②。

⏸② **总纲 + 设定集确认**——此后进入卷级循环。

#### 3.2 卷纲（abzu-volume）

对应思维链环节 6（分卷规划）。每卷一个中等戏剧循环。

| 维度 | 内容 |
| --- | --- |
| 输入 | 总纲 + 设定集 + 上一卷末状态（伏笔/人物快照） |
| 产物 | 卷纲（本卷目标 / 关键转折 / 节奏块 / 卷末状态预期） |
| 门控 | ⏸③ **卷纲确认**——决定本卷资源分配 |

#### 3.3 细纲与正文（abzu-write）

对应思维链环节 7-8（细纲 + 开篇试写）+ 动态循环。**细纲与正文在同一域**——它们是一个不可分割的循环（细纲→写→发现节奏不对→改细纲→再写）。

**单章循环**：

```text
装配上下文包 → 读细纲拍点 → 起草 → 写后自检三合一 → 落盘更新
```

| 步骤 | 做什么 | 产出/更新 |
| --- | --- | --- |
| 装配上下文包 | 细纲拍点 + 前情提要（最近 W 字）+ 该章人物快照 + 涉本设定摘录 + 文风指南 + AI 痕迹清单 + 该章伏笔清单 | 上下文包（临时，不落盘） |
| 起草 | 按细纲拍点写正文 | 手稿（第 M 章） |
| 写后自检三合一 | ① 一致性：本章与设定集/前文矛盾核对 ② 伏笔：本章埋设/推进/回收登记 ③ AI 味：痕迹清单扫描 | 修正或确认 |
| 落盘更新 | 手稿落盘 + 前情提要滚动更新 + 人物状态快照刷新 + 伏笔账本登记 | 全部落盘 |

卷末：卷终检（全量一致性扫描 + 伏笔逾期核对 + 人物状态校准）→ 回到 abzu-volume 下一卷。

#### 3.4 风格单路径（细纲党）

单路径交互规范（2026-09-10 作者裁定取消双路径——灵感流分支退役，沿革见文末变更记录）：

| 维度 | 细纲党路径（唯一） |
| --- | --- |
| 前置完备度 | 分卷-分章-单章拍点完整前置（目标/障碍/结果/钩子） |
| 细纲时机 | 批量预出（⏸④ 前一次性出完整卷） |
| 写作中修改 | 禁大幅改细纲（大幅调整待本卷完稿后统一处理） |
| 交互方式 | 批量生成、批量校验、批量锁定 |
| 完备度校验 | 核心卖点 + 主线终点 + 主角欲望 + 逐章拍点四要素齐 |
| 交互密度 | ⏸④ 一次确认整卷，章间仅写后自检不停靠 |

### 四、三大管理机制（产品行为定义）

#### 4.1 上下文管理

渐进披露——何时载入什么：

| 时机 | 载入内容 | 来源 |
| --- | --- | --- |
| 会话恢复 | 创作进度 → 定位续跑点 → 汇报现状 | 创作进度.md |
| 章节起草前 | 上下文包（细纲拍点 + 前情提要 + 人物快照 + 涉本设定 + 文风 + 伏笔清单 + AI 痕迹清单） | 多源装配 |
| 卷纲阶段 | 总纲 + 上一卷末状态 + 设定集 | 多源装配 |

**设计原则**：上下文包不是固定内容——它是按当前章节需要从真源动态装配的**派生视图**。装配逻辑本身是工程问题（该章涉及哪些人物/设定/伏笔？），不是思维链问题。

#### 4.2 伏笔追踪

伏笔账本三态 + 计划回收点：

| 状态 | 触发 | 登记 |
| --- | --- | --- |
| 埋设 | 正文写完该章时 | 伏笔编号 / 埋设章节 / 内容摘要 / 计划回收章节 |
| 推进 | 正文写完该章时（中间提及） | 推进章节 / 推进内容摘要 |
| 回收 | 正文写完该章时 | 回收章节 / 回收方式 / 状态翻「已回收」 |

卷末核对：逾期未推进的伏笔清单呈报作者。

#### 4.3 一致性管理

| 时机 | 核对内容 | 方式 |
| --- | --- | --- |
| 写前 | 上下文包内含该章涉本设定与人物状态 | 装配时自动 |
| 写后 | 本章与设定集/前文矛盾核对 | AI 语义检查 |
| 卷末 | 全量一致性扫描（设定 vs 全部已写章节） | 结构化扫描 |
| 设定变更时 | 影响扫描：哪些已写章节引用了该设定 | 事件驱动 |

#### 4.4 设定变更事件

大纲域或写作中修改设定 → 广播事件 → 正文域订阅并扫描已写章节影响。职责分离：设定变更在大纲域（设定集是大纲域产物），影响检查在正文域。接口形态为事件驱动。

#### 4.5 文风校验机制（终审补全）

**文风指南的结构**（不是一篇散文，是可校验的规则集）：

| 节 | 内容 | 校验方式 |
| --- | --- | --- |
| 词汇偏好 | 作者常用词清单 / 禁用词清单 | 机械匹配（写后自检） |
| 句式特征 | 平均句长范围 / 短句占比 / 常用句式模式 | 统计比对（写后自检） |
| 叙事偏好 | 视角（第一/三人称）/ 描写密度 / 对话与叙述比例 | AI 判断（卷末审计） |
| 情绪基调 | 目标情绪关键词 / 禁区情绪 | AI 判断（卷末审计） |

**AI 痕迹清单**（写后自检用，从文风指南自动派生 + 通用清单兜底）：

| 类别 | 具体信号 | 校验方式 |
| --- | --- | --- |
| 高频 AI 词汇 | 然而/与此同时/不禁/仿佛/宛如/似乎/显得 | 机械匹配 |
| 段落均匀化 | 连续 N 段字数相近（±20%）、信息量均匀无个人波动 | 统计检测 |
| 过度解释 | 对已描述事件追加解释性总结段 | AI 判断 |
| 转折词滥用 | 单段 ≥ 2 个转折词 | 机械匹配 |
| 情绪扁平化 | 连续 3 章无情绪强度变化 | AI 判断（卷末审计） |
| 叙事视角漂移 | 三人称突然切一人称 | AI 判断 |
| 句式规整化 | 句式高度规整、对仗过度、书面僵硬 | 统计检测（句长方差/对仗密度）+ AI 判断 |
| 角色口语缺失 | 人物对话无个性化口癖（众口一书） | AI 判断（对照人物卡口癖） |
| 套话模板化 | 套话/模板化表达密集 | 机械匹配（套话清单）+ AI 判断 |

**迭代更新**：每卷末 style 审计后，如发现系统性偏差 → 更新文风指南对应节 → 下卷生效。文风指南变更记录追加在文件尾部。

### 十二、三大机制技术设计

#### 12.1 上下文包装配

装配算法：读当前章细纲拍点 → 提取关键词（人物名/设定词/伏笔编号）→ 按关键词匹配检索：人物快照（该章出场角色）→ 设定集摘录（该章涉及的世界观条目）→ 伏笔清单（该章计划推进/回收的伏笔）→ 前情提要（最近 N 字）→ 文风指南 + AI 痕迹清单。裁剪规则：只载入匹配命中项；无命中则不载入该类。输出为有序上下文包（细纲 → 前情 → 快照 → 设定 → 伏笔 → 文风）。

#### 12.2 伏笔账本状态机

三态转换：埋设 → 推进（0-N 次）→ 回收。每次转换由写后自检触发（AI 识别到伏笔相关内容时提示作者确认）。卷末核对 = 遍历账本中状态 ≠ 回收且计划回收章节 ≤ 当前章节的条目 → 呈报逾期清单。

#### 12.3 一致性检查触发与扫描

触发时机：写后自检（每章，AI 语义核对本章与上下文包中的设定/前文矛盾）；卷末全量扫描（结构化遍历设定集条目 vs 手稿内容）。扫描范围：设定集全条目 × 已写章节全文。报告形态：矛盾清单（设定条目 / 冲突章节 / 冲突内容摘要 / 严重度）。

#### 12.4 内容比对校验

时机：大纲/细纲中引用采风素材时，提示作者确认迁移的是机制/氛围而非情节/表述。校验规则：中文连续 ≥ 8 字与采风素材原文重合 → 报告并要求人工确认（终审裁定 N=8，实测校准条款同 §2.5）。报告：相似段对照清单（采风来源 / 设计文档位置 / 相似内容 / 建议）。

#### 12.5 AI 痕迹扫描

写后自检第三项：按 §4.5 AI 痕迹清单逐类扫描——机械匹配类（高频词汇/转折词/套话清单）由文本匹配覆盖，统计检测类（段落均匀化/句式规整化）由字数与句长统计覆盖，AI 判断类（过度解释/情绪扁平化/视角漂移/角色口语缺失）由 LLM 语义检查覆盖（写后轻检 + 卷末深度审计双层）。
