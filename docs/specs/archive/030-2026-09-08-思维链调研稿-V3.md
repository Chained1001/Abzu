## 二、调研发现：大纲阶段作家的思维链

综合来源（1）（2）（3）（5）（7）（10），网文作者在动笔前后的思维过程可归纳为**八个创作环节 + 一个贯穿性循环 + 一个跨环节行为**。八个创作环节依次推进，动态循环贯穿始终，采风嵌入环节 3-5 及 7。注意：这是「理想完整链」，实际作者的取舍见 §二.3。

### 2.1 思维链模型

1. **创意孵化与自我评估**：灵感/题材/金手指的点子出现后，作者先自我拷问——能不能写（能力匹配）、值不值得写（市场与竞争）、写得动吗（体量与耐心）。多数烂尾源于跳过此环节。
2. **核心抽象**：把点子压缩成「一句话故事」+ 核心卖点 + 对读者的**情绪承诺**（爽点类型：复仇/逆袭/养成/解谜…）。这是全书的北极星，后续所有决策向它回溯。
3. **世界观构建**：为承载卖点搭建世界——时间/空间/类型/**力量体系**/势力格局（来源 6、7）。知名作者经验：**先设定世界观，再设计升级体系**；中低层级贴近现实职业命名以增强代入感（来源 8，爱潜水的乌贼）。
4. **人物设计**：主角（欲望/缺陷/金手指的绑定）、反派（层次与同理点）、配角（功能位）。人物是卖点的载体，不是名单。
5. **主线结构**：起点→终点的因果链，大冲突节点与高潮排布——把「开始、铺垫、冲突、高潮、结束」结构化，防止故事脱节（来源 9）。
6. **分卷规划**：每卷一个中等戏剧循环（一个可兑现的中目标）。
7. **细纲**：当前卷逐章拍点——正文的直接输入。细纲质量直接决定正文写作是否流畅。
8. **开篇试写与验证**（第三方审阅新增）：细纲完成后，作者通常会试写开篇章节（3000-10000 字），验证文笔风格与题材的匹配度、主角人设从纸面到实际成文的落地感、开篇钩子的有效性，并感受「这个故事写不写得动」。试写结果经常**反向触发大纲与设定的修改**——发现人设不成立、节奏不对、卖点不突出，回头改。这是动态循环的第一个强制反馈点，也是「写不写得动」的最终检验。
9. **动态循环（贯穿性机制，非独立环节）**：写作过程中回头改大纲——「双向创作法」：从大纲细化到章，又从章的具体内容反过来调整大纲（来源 3）。卷纲往往在写完上一卷后才真正细化（last responsible moment）。开篇试写（环节 8）是本循环的第一次强制迭代。

**跨环节行为：采风**。上述环节 3-5 为采风的高频嵌入点，环节 7（细纲）在卡文时也会触发采风——它不是独立阶段，而是嵌入创作思维链的信息获取动作：

| 环节 | 采风的形态 |
| --- | --- |
| 世界观构建 | 检索对应时代/异世界的史料、地理、制度、风俗（例：唐代穿越文查唐代文化） |
| 人物设计 | 调研同类/跨品类作品的人设范式，规避俗套，寻找差异化锚点 |
| 主线结构 | 研究优秀作品的剧情编排、节奏密度、高潮排布；学习金手指设计、大纲搭建方法论 |
| 细纲卡文时 | 检索同类桥段解法，补充局部灵感 |

采风的触发场景全集：背景知识补全、设定合理性校验、情绪氛围采样、俗套规避、跨界创意碰撞、叙事节奏参考、写作技巧学习、灵感枯竭时的范式参考。素材范围：小说、动漫、影视剧、历史史料、真实事件。

### 2.2 关键实证观察

- **大纲党与灵感流并存**：「先有完整大纲再动笔」与「边写边构思」两类作者都存在，后者占比可能更高——因为完整大纲非常消耗时间（来源 2）。**最常见的轻量替代组合是「设定集 + 人物卡 + 灵感集」**——用离散文档替代结构化大纲，降低前期规划成本（来源 2）。**对本产品的启示：大纲功能不应强制单一形态，要支持从「粗纲流」到「细纲流」的光谱。**
- **粗纲/细纲分级**是行业共识：粗纲只记主干（如「萧炎三年之约以雪耻」），细纲逐章拍点（来源 2）。
- **起点大学**的毕业设计结构佐证了行业标准形态：**剧情大纲 + 开篇剧情细纲 + 部分正文 + 主要人物人设卡**（来源 4）——四件套，而非单一「大纲文件」。
- **卡文是基础设施问题**：据网文行业调研（来源 11），超过 76% 的签约作者每年经历 3 次以上严重卡文，单次平均持续 3-7 天。工程视角的诊断：卡文的本质不是「灵感枯竭」，而是**系统资源瓶颈**——当故事复杂度超出写作基础设施（大纲细度、设定完备度、素材储备）的承载能力时，写作进程被迫阻塞。灵感枯竭是表象，基础设施缺口是根因（来源 10）。
- **日更纪律靠流程不靠灵感**：头部作者「不能断更」被视为第一纪律，连续数年日更靠的是流程化（大纲前置、固定作息）而非灵感波动（来源 12、13）。

### 2.3 模式差异的启示

作者存在真实的风格光谱：**结构党**（重大纲细纲）↔ **感情流/灵感流**（轻大纲重状态）。产品的含义：大纲域的工作流不能假设单一形态——应支持「细纲党」的完整拍点流程，也必须支持「灵感流」作者只取粗纲+设定集的轻量路径，两者产出物在下游（正文）都应可用。

## 三、心流：大纲阶段的特征与产品设计含义

### 3.1 心流的产生条件（来源 14、15、16）

经典心流框架：**挑战与技能平衡、清晰目标、即时反馈、免打扰**。写作场景的对应：

- 挑战略高于技能 → 状态最好；过高（卡文）焦虑、过低（套路重复）无聊
- 心流需要**入场时间**（进入状态需要一段时间不被打断），且**打断的代价极高**——重新进入需要完整重建上下文
- 「恢复期」是被忽视的必要环节：潜意识整理（散步/睡前）常是情节问题的实际解决时刻（来源 17）
- 网文场景的额外约束：**日更压力下的时间碎片化**——作者往往在固定时段内必须产出定量字数，心流入场时间被压缩，因此「前置基础设施完备度」（细纲拍点、设定就绪）对能否快速进入心流的影响远大于一般写作场景

### 3.2 大纲阶段的两层心流（本调研的关键区分）

**第一层：大纲阶段自身的心流**——设定与情节设计的沉浸感（「搭世界」「排剧情」的乐趣）。此阶段被频繁提问打断 = 思维链断裂。

**第二层：大纲是正文心流的前置基础设施**——大纲的产品目的不是自身的沉浸感，而是为正文阶段提供「清晰目标 + 即时反馈」的供给。细纲缺拍点 → 正文每章都要现场决策 → 心流破碎 → 卡文/断更。

### 3.3 对产品设计的三条推论

1. **交互批量化**：大纲域的确认点必须少而重（关键产物停靠），不逐项问——保护第一层心流。与 scan 域「两问分开」的设计不同，大纲阶段的长链路思维更需要**沉浸优先、批量确认**。
2. **细纲是心流的供给侧**：细纲的拍点密度与钩子完备度 = 正文阶段的「清晰目标 + 即时反馈」来源。产品应把「细纲完备度」作为显式检查项，而非依赖作者自觉。
3. **打断恢复机制**：卡文与中断是常态而非异常（来源 11），恢复入口必须一键重建上下文（当前卷状态/伏笔/人物位置）——这直接要求大纲产物是结构化落盘的，而非对话记忆。

## 四、功能划分评估：「大纲域 = 大纲功能 + 设定功能」

### 4.1 划分的支持论据

1. **实件形态不同**：大纲产物是因果/节奏文档（粗纲/卷纲/细纲），设定产物是**设定集**（一致性词典：力量体系/地理/势力/规则）。形态、写法、更新节奏（大纲在卷间迭代 vs 设定集是贯穿全书的活文档）都不同。
2. **思维模式不同**：大纲 = 因果与节奏推理；设定 = 世界一致性推理。作者的心智模型确实区分「我在排剧情」和「我在搭世界」两个模式。
3. **同域共置的理由——深度互哺且非对称**：设定遵循「最小可行」原则为剧情提供承载，剧情则在推进中持续倒逼设定补全（「写到才定」是常态而非例外）。拆成两个独立域会切断这个双向倒逼循环，导致设定过度设计或剧情缺乏支撑。
4. **实证**：作者社区最常见的形态就是「设定集 + 人物卡 + 灵感集」与大纲并行维护（来源 2）——设定功能有独立的产物与工作流，不是一个附属步骤。

### 4.2 划分的张力（需第三方重点审）

1. **立项的位置**：卖点/题材/金手指/目标读者（立项环节）——金手指兼跨设定与大纲（它既是世界规则又是主线引擎）。建议：立项作为大纲域的**入口环节**（非并列功能），产出 project.md 后两个功能并行展开。立项对应思维链的环节 1-2（创意孵化 + 核心抽象），其产物 project.md 是后续环节 3-8 的共享输入。称其为「入口环节」是强调它的**门禁性质**——立项未确认时，世界观、人物、主线都不应大规模展开；它不是八环节之外的额外步骤。
2. **交织而非串行**：真实过程是「设定↔大纲」交叉迭代（先世界观再升级体系——来源 8；剧情压力逼出设定）。产品含义：两功能不能设计成先做完设定再做大纲的流水线，应支持**任意切换、交叉推进**，共享同一份世界状态。
3. **设定集的跨域生命周期**：设定集不止服务大纲——正文阶段的一致性管理要持续读它、改它。它是**贯穿全书史的活文档**，需要版本管理与变更追溯（设定变更 → 影响已写章节的检查）。
4. **设定党陷阱**：世界观构建的沉浸感可能变成「设定拖延症」——用无限细化设定逃避动笔。行业对策是「最小可行设定 + 核心约束精简」——只保留支撑叙事的关键设定规则（如来源 5 提出的「支柱」式框架），而非追求世界观完备性：设定为叙事服务，不为完备服务。产品应内建「设定充分度」的引导而非鼓励无限展开。
5. **采风的跨功能属性**（第三方新增）：采风是嵌入大纲与设定两个功能的底层行为——设定阶段采风用于史料检索与世界观参考，大纲阶段采风用于剧情范式调研与写作方法论学习。若将采风设计为独立功能，会割裂它与具体创作决策的即时关联；若完全分散在两功能中，又会丧失素材库的统一管理。建议：采风作为**域级共享能力**（素材库统一落盘），但触发入口嵌入各环节的具体决策点。
6. **人物卡的双重属性**（第三方新增）：人物设计兼跨设定与大纲——人物的能力、背景、世界观位置属于设定一致性范畴，人物的欲望弧线、冲突绑定属于大纲因果链范畴。实证上人物卡是独立维护的产物（来源 4，起点大学四件套之一），产品设计中应将其作为两功能共享的独立实体，而非任一功能的子项。

### 4.3 评估结论

**「大纲功能 + 设定功能」的划分合理**，且优于把世界观当作大纲的一个前置步骤（传统「先设定后情节」串行模型的反思）。建议的产品形态：**一个域、两个并行模式、交叉迭代、共享世界状态、立项为入口**，人物卡与采风为两功能共享的**横切**实体/能力——不归属于任一功能，但被两者同时读写。

此外，心流研究（§三）也支持同域划分：设定与大纲的交叉迭代若被拆成两个域，会在域边界产生额外的上下文切换成本，直接破坏第一层心流。同域共置是保护创作沉浸感的架构选择。

| 5 | 设定变更影响检查归谁？ | **归正文域的一致性管理，但触发源在大纲域**。设定变更发生在大纲域（设定集是大纲域产物），变更影响检查（哪些已写章节受影响）是正文域的职责。接口设计：大纲域发出「设定变更事件」，正文域订阅并执行影响扫描——职责分离，事件驱动。 | **待作者终裁**：事件驱动的接口形态（跨域机制，涉及 volume/write 域设计） |
