# 规格：032 · 触发方式单一化（显式调用立法）

> 本规格自包含。依据：作者 2026-09-10 口述裁定——「触发方式每个技能只有一种就是 /技能名，我们不需要那么多模糊的触发方式」。立法理由有先载：architecture §二 选型理由表触发行已记「六域同属『写小说』，自然语言互抢，靠直呼纪律压制」（mo-shu 作者实测教训）——本批将该软纪律升格为硬标准。
> 本批不含：命令薄壳启用（file-conventions 预留行不动）、skill 间禁互调规则（不变）。

## 一、现状锚点（2026-09-10 现场核验）

- **三实建壳有模糊触发句**：scan/analyze/outline 的 SKILL.md description 均为「触发方式：/abzu-{域} **或上述任一话题的自然语言**。边界：…」（grep 三文件命中；archive 013 规格同句为沿革豁免）
- **三占位壳已是单一式**：volume/write/style 均为「触发方式：/abzu-{域}。」——占位壳零改动，兼作立法正例
- **三 workflow 消费点行**：「进入{域}（/abzu-{域} **或自然语言命中**）时全量加载」——模糊措辞同源
- **skill-writing v0.6 §一 现行两条以自然语言触发为前提**：§一.1「写清触发条件与关键词，含触发方式（如 `/abzu` **与自然语言**）」（:9）；§一.3「**塞满可检索触发词**：用户的口语说法、术语表叫法、同义词」（:11）——本批须同步修订，否则新旧条款同文件矛盾
- **glossary v0.5 调用双层词条**（:75）：「六域 skill 一律 model-invoked（description 触发）、skill 间禁互调…、预留命令薄壳属 user-invoked 编排层；详见 architecture §四」——触发定义需修订
- **architecture v1.4 §四 调用双层段**（:66）：「六域 skill 一律 model-invoked（description 触发；斜杠直呼与本名命令同源）」——需修订；§二 触发行（:23）为立法理由保留
- **test-prompts v0.4 场景 prompt 三态**：场景 6/8 为双形态「`/abzu-scan（或：扫一下起点的畅销榜…）`」「`/abzu-analyze（或：帮我拆一下这本…）`」（备选括注）；其余六场景为纯自然语言问句；**场景 7 为域外休眠场景**（「帮我把这个 CSV 按销售额排个序」+断言「abzu 系技能保持休眠不触发」）——它是本立法的正向验证位，**不得加前缀**；其扩展断言「分别敲 /abzu-outline 等占位域命令，模型应如实告知该域尚未建设」已因 031 建成 outline 而失效（031 批涟漪遗漏，本批顺手修正）
- **README.md:27**：「安装后新开会话即可使用：敲 `/abzu-scan` 或直接说“扫一下起点榜”。」——自然语言教学句，立法后失效；**:45** 快速上手占位注的示例为自然语言形态
- marketplace.json 已核查：两处 description 均无模糊触发措辞，本批无需改动
