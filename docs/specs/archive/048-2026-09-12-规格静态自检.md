## 二、文件级改动清单

### 1. `scripts/check_spec_assertions.py`：新增静态自检阶段 [B]

**方向（不得改变既有动态阶段行为）**：在既有动态预验之外新增**静态自检阶段**（两项检查），并加 `--static` 开关。

**接口契约**：

- 用法：`python scripts/check_spec_assertions.py [--static] <规格路径> [更多规格路径...]`——支持多路径（check.sh 用）。
- **阶段集合**：无开关＝动态阶段 + 静态阶段；`--static`＝只跑静态阶段（**不执行规格内任何命令**）。
- **退出码契约（静态阶段分立，不改动态阶段口径）**：
  - 参数错误（无路径／路径不存在）：退出 2（承既有 `__main__` 行为）。
  - 静态阶段：**检查 B 报「计数不符」时退出 1**（事实性错误，非候选）；检查 A 与检查 B 报「基线漂移」时**不影响退出码**（候选／预期内漂移，宪法 §2）。
  - 动态阶段：**恒不影响退出码**（承 L7 头注原句，本批一字不改）。
  - `--static` 模式下按静态阶段定码；无开关时取「动态不动 + 静态按上述」的合成——即退出 1 仅可能来自静态阶段的「计数不符」。

**检查 A · 断言自噬预警**：

1. **节定位**：新增常量定位「文件级改动清单」节（形如 `^##[^#\n]*文件级改动清单`），复用既有 SECTION 常量定位「验收标准」节；两节均为 H2 起、下一个行首 `##` 止。
2. **断言解析**：在验收节内提取形如 `git grep -F -c -- "TOKEN" FILE` 的断言（`-F`／`-c`／`--` 顺序容错；非此形态命令跳过），得 `TOKEN` 与 `FILE`。
3. **子节归集**：在改动清单节内按 `###` 切分子节；每个子节记录**其全文**（含标题行、正文、围栏块内容、行内反引号内容）中出现的**路径样 token**——判据：形如 `[\w./-]+\.(md|js|sh|py|json|jsonc)` 的裸串，**且该串作为仓库根相对路径存在于磁盘**（**不以「含 `/`」为必要条件**——否则 `AGENTS.md`／`README.md`／`CHANGELOG.md` 等根级文件永不被命中，检查 A 对它们完全失明；2026-09-12 施工实跑发现的覆盖缺口，见 §八）；同时记录该子节的围栏块文本与**行内反引号内容**。
4. **计量**：`cur` ＝ 目标文件当前内容中含 `TOKEN` 的行数（**文件不存在记 0**）；`in_repl` ＝ 在「路径样 token 命中该 `FILE`」的**全部**子节中，`TOKEN` 在其围栏块文本与行内反引号内容里的出现**次数之和**（多子节求和；精确串匹配，不做后缀／模糊匹配）。
5. **跳过条件**：该 `FILE` 未被任何子节的路径样 token 命中 → 打印 `· 跳过（无对应替换文本，[B] 项或纯新增）`，**不计入预警**。
6. **输出**：`FILE` 命中且 `in_repl` 为 0 → 打印 `· 自噬预警（无命中）: TOKEN @ FILE —— 现行 {cur}｜替换文本内 0`；`in_repl` > 0 → 打印 `· 自噬预警: TOKEN @ FILE —— 现行 {cur}｜替换文本内 {in_repl}｜近似预测 {cur+in_repl}（未计删除，须人工核对到位期望）`。
7. **判定力声明与取数时点**：`in_repl` 计入行内反引号内容会**高估**（行内引用可能只是提及而非落盘文本），故本检查**只作预警、不作判定、不影响退出码**；其价值在于把「预测值与规格「到位」列的差」摆到规划方眼前。预测口径以**施工前**取数为准——施工后 `cur` 已含新增命中，预测会呈「到位值 ×2」形态（属预期，非缺陷）。

**检查 B · 计数实跑重算**：

1. **识别**：扫描规格全文逐行，识别「反引号包裹且**在磁盘上存在**的文件路径」＋「同一行内的 `N 字符` 或 `N 行` 声称」（`N` 容错千分位逗号与前后 `**` 强调符）。文件不存在于磁盘的路径**跳过**（那属新增件的预期，非计数错误）。**限额型数字不计**：`N` 之前（允许中间隔空格）紧邻 `≤`／`≥`／`<`／`>`／`最多`／`上限`／`不少于`／`以内`／`以上` 等限额标记的，不视为对当前尺寸的声称、直接跳过——如「条目 ≤ 400 字符」是限额而非实测值（2026-09-12 施工实跑发现的假阳性，见 §八）。
2. **实测**：字符数 ＝ 该文件按 UTF-8 解码后的 `len()`（保留换行符）；行数 ＝ `len(text.splitlines())`。两口径均与仓内既有实测口径一致。
3. **分级（本批新立，防必然红）**：
   - 声称的文件**未出现在改动清单节**（该节全文内做精确串匹配）→ 不符即打印 `x 计数不符: FILE 称「N 字符」实测 M` 并**置退出 1**。
   - 声称的文件**出现在改动清单节**（即本批要改的件）→ 不符只打印 `· 基线漂移（本批改动件，不阻断）: FILE 称「N」实测 M`，**不置退出 1**——现状锚点记录的是施工前尺寸，施工后必然漂移，属预期而非错误。
   - **已知边界（登记为 N7）**：分级只有「是否本批改动清单件」一维，工作树同时挂着**他批未提交改动**时，他批改动件若被在制规格 §一 引用了尺寸，会落「计数不符」支而阻断提交——与台账 C6（多批共存口径）同族，核验时须先判因。
4. **只覆盖 `字符` 与 `行`**：`条`／`项`／`处` 等量词随文件类型而定义不同（如「条目」＝ 以列表符起首的行），不做通用实测以免误报（扩量词登记为 N5）。

**其余契约**：

- **只读保证**：静态阶段不执行规格内任何命令、不写任何文件，只做文件读取与文本匹配。
- **路径解析基准（2026-09-12 产物审查 P1-2 立）**：静态阶段解析一切相对路径（规格内声明的目标文件、检查 B 的待测文件）一律以**脚本所在仓库根**为基准——循 `report()` 既有做法（`os.path.dirname(os.path.dirname(os.path.abspath(__file__)))`），**不依赖调用者 cwd**；无法定位仓根时报错退出 2。反例：非仓根目录直调会使全部路径 `isfile` 落假、检查 A 全打「跳过」、检查 B 零覆盖，末行仍报「无发现」且退出 0——**与真阴性不可区分的假绿通道**（产物审查实跑复现）。
- **输出骨架**：静态阶段以一行 `== 静态自检 ==` 起，随后逐项；全部断言均落「跳过／自噬预警」且无「计数不符／基线漂移」时，末尾打印 `· 无发现`。**阻断性输出的前缀为 `x` 加一个半角空格**（如 `x 计数不符: …`）——与 check.sh 各段失败提示及 `check_content.py` 的失败约定一致，便于在混排输出中一眼定位红行；非阻断项（跳过／自噬预警／基线漂移）一律用 `·` 加一个半角空格前缀。**全部条目落「跳过」时不得打「无发现」**，改述为 `· 全部跳过（未命中可解析目标——请核对调用位置与路径基准）`，与真阴性区分。
- **文档头更新（不动 L7 原句）**：「用途」段**另起一句**说明静态自检阶段与两段退出契约的分立；「用法」段补 `--static` 与多路径形态；「维护入口」段补静态阶段的接入位置（节定位常量与两项检查的函数）。**L7 原句「本工具退出码恒 0，仅呈报」一字不改**（承宪法 §2 口径与三处载体）。
- **允许的新增**：在 `__main__` 既有的 `sys.exit(0)` **之前**新增条件化 `sys.exit(1)`（静态阶段计数不符时触发）；既有 `sys.exit(0)` 的位置与取值不动。
