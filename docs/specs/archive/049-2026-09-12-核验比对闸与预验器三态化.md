## 二、文件级改动清单

### 1. `scripts/check_spec_assertions.py`：动态阶段三态化 + 静态「无发现」判据收紧 + 新增 `--verify` [B]

**方向（不得改变静态阶段既有行为与提取规则）**：`extract()` 的提取规则、`--static` 的输出格式与退出码契约、L7 原句均**逐字保留**；本批只动 `readonly()` 的判据、`report()` 的计数与摘要、`static_report()` 的末尾行判据、`__main__` 的模式分派，并新增 `--verify` 分支。

**A. 动态阶段三态化**（承 046 有效内容 + 台账 C3 + N3）：

- **放行面收窄**：:83 分支由 `e?grep|fgrep|wc|head|tail|ls|find|cat|bash|sh|node` **改为只保留文件类** `e?grep|fgrep|wc|head|tail|ls|find|cat`（**移除 `bash`／`sh`／`node`**）；**:91 的 `npx --no-install` 放行分支取消**（`npx` 可拉取并执行远端包）；**:89 的 `python -c` 分支保留但成为不可达死码**（新判据先行拦截），**须在代码注释中注明「不可达，保留以明示任意代码入口」**，不得删除后留下无说明的空缺。
- **不可审计判据**（命中即判不可审计、不执行；顺序在放行判据之前）：
  1. shell 解释器与包执行器整族：`^(bash|sh|node|npx)\b`；
  2. 解释器任意代码入口：`^(python3?|py)\b.*\s-c`（**不要求 `-c` 后跟空白**，故 `-c"x"` 形态一并拦下）；
  3. 裸解释器：`^(python3?|py)\s*$`；
  4. **引号外的 shell 元字符**：整行在**双引号与单引号之外的区间**含 `|`／`;`／`&`／`<`／`>`／反引号 中任一者。**引号内的元字符不计**——否则 `git grep -F -c -- "a|b" file` 这类**合法且安全**的固定串断言会被误判为不可审计而漏审（本仓规格的断言 token 常含 `|`）。命中该判据时，**SKIP 行须注明命中的字符**（如 `SKIP（不可审计形态：引号外 ;）`），以便判因；
  5. `sed` 非 `-n`（既有行为保留）。
- **残差类**：既非可审计、又不落上述五条判据者（如 `git branch`、`git rev-parse`），**仍走既有分支**并打印 `SKIP（非只读白名单形态）`——该文案不改。
- **三态输出**：不可审计 → 打印 `[i] {src} SKIP（不可审计形态…）: {cmd}` 并计入 `skipped`；可审计 → 执行并按原有格式打印退出码与输出摘要；未跑成（崩溃或超时）→ 打印 `[i] {src} CRASH（未跑成）: {cmd}` 并计入 `crashes`。
- **崩溃与超时归桶**：① 解码侧——`r.stdout is None or r.stderr is None`；② 编码侧——打印函数捕获 `UnicodeEncodeError` 并以 ASCII 兜底；③ **超时**——`subprocess.TimeoutExpired`。**三者一律计 `crashes`**，不得静默当作成功或混入 `ran`。
- **三桶摘要**：改为 `== 共 {n} 条：执行 {ran}｜跳过 {skipped}｜崩溃 {crashes} ==`，**`ran` 的自增移入成功路径**，使**三桶之和恒等于提取数**（`ran + skipped + crashes == n`）。崩溃非零时**追加警示行**（`! 有断言未跑成——预验证据不完整`）。
- **C3 命令不可用区分**：执行的返回码为 `126`／`127` 时，在摘要行内额外标注 `（命令不可用）`——区分「命令不存在」与「命令跑了但失败」，二者证据价值不同。
- **退出码不变**：动态阶段**恒不影响退出码**（承 L7 与 AGENTS §2 三处载体，本批一字不改）。

**B. 静态阶段「无发现」判据收紧**（本批对静态阶段的唯一例外）：048 批契约允许「有自噬预警」与「`· 无发现`」并存，实跑显示该组合易被误读为「全干净」（049 规格自查实测：9 条自噬预警 + 1 条跳过之后跟一行「无发现」）。故 `static_report()` 末尾行条件**收紧为「无计数不符／基线漂移**且无自噬预警**」**——有预警时改打印 `· 有预警 {k} 条（非阻断，请人工核对预测与到位期望）`。静态阶段的其余输出与退出码契约不变。

**C. `--verify` 核验比对模式**（新增）：

- 用法：`python scripts/check_spec_assertions.py --verify <规格路径>`；与 `--static` 互斥（同时给出时报参数错误退出 2）。**该模式不进 check.sh**。
- 三项比对：
  1. **改动面比对**（**级别：`· 提示`，非阻断**）：从规格「文件级改动清单」节提取声明的文件路径 token（复用静态阶段的节定位与路径判据）；与 `git status --porcelain` 的实际改动集（`M`／`A`／`D`／`R`／`??`，路径归一为正斜杠）比对，分别列出「声明但未动」与「动了但未声明」两侧。**两项豁免**：① `docs/specs/*.md` → `docs/specs/archive/*.md` 的同名移动视为同一文件（归档移动不计）；② **待验规格自身**（其路径出现在 `??` 或 `M` 中）不计入「动了但未声明」——该闸对每份在制规格都必然看到自身，若判阻断即常驻红。两侧皆空则打印 `· 改动面一致`。
  2. **过程产物三件**（**级别：`x 核验不符`，阻断**）：① `CHANGELOG.md` 含该规格号（从规格文件名解析前三位数字）的**条目行**——条目行判据与 §二.2 的守卫统一（列表符起首且同含规格号）；② `docs/specs/collab-log.md` 施工记录表含该规格文件名（basename）；③ 该规格已位于 `docs/specs/archive/`。三件缺任一即报阻断——**未落过程产物即核验未完成**（承 047 批补入的「挂账登记核对」同款精神）。
  3. **施工记录表结构**（**级别：`x 核验不符`，阻断**）：数据行序号是否 `1..N` 连续无重复、各行竖线数是否一致、末列（结果列）是否非空。不符即报阻断（**表是协作台账，结构损坏即账目失真**——047 批曾出过重复行）。
- **只读保证**：`--verify` 只读规格、磁盘与 `git status`（只读子命令），不执行规格内任何命令、不写任何文件。
- **出身说明**（防日后按 §6「不做清单·注册表类守卫」追问）：本模式**不新建登记表**，只读既有三件（CHANGELOG／施工记录表／archive）做**登记完备性核对**；出身＝AGENTS §5 反模式 #9（可机械化的纪律须固化为工具）与 047 批的挂账登记核对实例。

**文档头**：「用途」段补 `--verify` 与三态说明；「用法」段补 `--verify` 形态；「维护入口」段补三态与 `--verify` 的接入位置。**L7 原句一字不改**。**「用途」段不得复述三桶摘要的格式串**（复述会顶高 A7 的命中数）。
