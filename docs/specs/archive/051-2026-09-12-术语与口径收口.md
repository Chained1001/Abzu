### 1. `docs/standards/agent-design.md`：补「分身（工序角色）」轨道 [B]（新增小节，落位自定）

**1a. 新增一节**（建议置于 §一 之后、§二 之前，节号与后续节号由施工方按既有顺序顺延；节标题固定为 `## 二、分身（工序角色）与实体 agent 的分野`）。内容须含四要素：

- **两轨定义**：**分身**＝开发工具链用法，由规划方在会话内 spawn（独立上下文窗口），随会话存在、**无物化文件**；**实体 agent**＝运行时物化，有 `abzu-{角色名}.md` 文件、装进用户书项目，**待 T1 触发**（判据见本节之后的启用判据节）。
- **现行三个分身角色**（承 AGENTS §3.8 与 collab-log）：**施工分身**（只按规格施工、无 git 写权限）、**规格成稿审查分身**（施工前审规格，fresh context）、**产物审查分身**（施工后审产物，fresh context，不复用前者）——三者均为**默认工序**，工序细则以 `docs/specs/collab-log.md` 为单点权威。
- **与 T1 禁令的关系**：本节所载分身**不属**「实体 agent」，故不违该禁令。**同文件 `:25`「四条全不沾 → 不建 agent」、`:27`／`:29` 反模式条、`:52`「agent 内部禁止再 spawn」三处裸「agent」表述一律辖实体 agent，分身不适用**（防由 `:6` 的「agent 为上位概念」推出「分身也须过四条判据」）。**措辞规则**：本节之后新增／改动的条文，凡涉「agent」而需指实体者一律写「实体 agent」；**只对未来改动生效**，不回溯改造既有条文（与 §三 相容）。
- **术语边界**：分身与实体 agent 同属本规范的「agent」上位概念（Claude Code 子代理），二者是**同一机制的不同用途**，不是两套东西。
