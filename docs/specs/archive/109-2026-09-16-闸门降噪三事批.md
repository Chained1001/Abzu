## 六、被否决的替代方案

- **F2 改为"按 `re` 解释 token"（真实正则计数）** → 否决：规格里的断言 token 是 **grep 模式**（BRE），而 Python `re` 是 ERE——`^| G38 |` 在 BRE 里 `|` 是**字面**、在 ERE 里是**择一**，`re.match` 下 `^|` 会**对每行都成功**（恒命中）。两套语义不可互通，硬解释只会把假阳换成另一种假阳。故只做**能严格等价的子集**（`^` 前导锚），其余如实标"不可判"。
- **F2 干脆静默跳过含元字符的 token** → 否决：`施工机制` §四 段有「空转明示」精神（`A`／`B` 两类均设明示行），静默会让"未测"与"测了为 0"同形——正是本批要消灭的那种混淆。
- **F3 用"替换"而非"追加成因括注"** → 否决：块未命中目标件**是事实**（"未落实"成立），成因只是诊断；替换会丢掉事实面，且在成因判错时无处回退。
- **把 `#33` 的律（`规格写作标准` §5 补一条）也并入本批** → 否决：本批三条都是**守卫判据修复**，属工具面；立律属规范条目，且 `108` 刚因"改动面膨胀"吃了 10 条 findings。**律仍留开放项**（`#33` 行内已注明"尚未立"），本批只在 `#33` 行标"已部分机械化"。
- **F5 让判据直接核 `R` 的数值自洽（分段之和＝合计）** → 否决：`R` 的**真源**是规划方各段自述数之和，而其中若干段（如整改期自查）**未必有自述数**——工具算不出"应有之和"，只能算"已写之和"，会把"不全"误报成"不符"。故判据只核**分段标识存在性**，数值自洽如实写明**归人工**。
