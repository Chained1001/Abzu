# 协作日志（collab-log）

> **定位**：规划方/施工方分工协作的逐次登记与模板四件套——数据化调优协作流程（模型稳定性/粒度性价比/任务适配）。
> **纪律**：每次规格施工完成（核验通过或整改）追加一条；只记录事实与数字，不写过程叙事。

## 模板四件套

### 施工提示词

```
你是施工方。任务：按规格施工 {规格文件}。你没有 git 写权限，也无需尝试提交；完成后只输出核验请求。

1. 先读 AGENTS.md（宪法）与规格全文，再动手。
2. 严格按规格「文件级改动清单」施工——每条带自由度标记：[A] 逐字执行、[B] 按方向自定实现（不得改变行为）。
3. 偏差分级：P0 阻塞型（规格与现状冲突，继续会做错）→ 立即停下，输出全部改为偏差报告；P1 观察型（不影响施工）→ 继续施工，记入核验请求偏差记录。
4. 规格「禁止事项」为硬边界：禁止触碰清单外文件。
5. 全部完成后输出【核验请求】：改动清单逐文件对照规格、验收标准逐条自跑结果、偏差记录（P1）、未决问题。
```

### 核验请求（施工方产出）

```
【核验请求】
- 规格文件：{规格路径}
- 改动清单：逐文件对照规格改动清单
- 自核验结果：验收标准逐条 + 实际执行命令与输出摘要
- 偏差记录：P1 观察型偏差（如有）
- 未决问题：需规划方裁决的点（如有）
```

### 整改提示词（核验未通过时）

```
你是施工方。上一轮施工未通过核验。
- 核验结论：{逐条列出问题}
- 整改范围：{只允许改这些文件/这些点，其余维持原状}
- 整改后重新输出【核验请求】
- 禁止扩大整改范围，禁止"顺手"改其他东西
```

### 裁决请求（呈作者拍板）

```
【裁决请求】
- 背景：{一段话说明分歧/冲突}
- 选项 A：{描述 + 代价 + 收益}
- 选项 B：{描述 + 代价 + 收益}
- 我的建议：{选 X，理由}
- 请你拍板
```
