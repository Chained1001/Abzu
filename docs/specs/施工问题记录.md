## 填写规则

1. **时机**：修完立刻加，不等收尾。
2. **类型**五选一：**命令**（工具/命令用错）｜**格式**（Markdown/文件格式写错）｜**流程**（步骤漏了）｜**判断**（语义或结论错）｜**引用**（链接/节号/文件名指错）。
3. **场景**写短语（「跑核验」「写 Markdown」），同场景同措辞——聚类靠它。
4. **问题**和**修法**各限一句（≤30 字），细节留 commit message。
5. **加行前看表里有没有同类行**——有则原行**次数＋1**，没有才新增。
6. **等级**：**P0**（可能产出错误结果）｜**P1**（耽误进度但抓到）｜**P2**（顺手修的小事）。

## 沉淀方法（作者说「沉淀经验」时执行）

1. 读全表，按「类型＋场景」聚类。
2. 每簇判：次数 ≥ 3 且能机械判定 → 建议加进 `check.sh`；次数 ≥ 2 → 建议写进管这个主题的标准件；次数 = 1 → 问作者「还会再犯吗」，不会则删行。
3. 建议逐条呈报作者裁定。
4. 裁定通过后写规则或建检查器，原行加标记（「已入 X §N」或「已建检查」）。
