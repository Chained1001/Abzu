# Agent 设计规范（骨架蓝图版）

> 版本：v0.1（2026-09-06 骨架立法）
> 定位：Abzu 子代理（subagent）的命名、设计判据、结构模板与协作协议的单点权威——**占位蓝图版**：骨架与判据现已生效（约束设计与文档），实体 agent 的创建待 T1 触发（正文/审查域成熟）。
> 依据：Claude Code 官方 sub-agents 文档、Anthropic Building Effective Agents（编排/评审模式）、mo-shu 同域参考实现（8 agent 实战经验）。

## 一、命名与文件

| 项 | 规则 |
| --- | --- |
| agent 文件 | `abzu-{角色名}.md`，kebab-case，一角色一文件 |
| 角色名 | 职责即名（如 `evaluator`、`researcher`），禁泛化名（helper/util） |
| 目录 | 物化目标为书项目 `.claude/agents/`（由 abzu-setup 部署）；仓库内源码位待 T1 定（规划中：`templates/agents/`） |
| frontmatter | 官方字段：`name`（=文件名）、`description`（触发条件+边界，第三人称）、`tools`（白名单，最小权限）、`model`（按任务配级，廉价任务降级模型） |

## 二、启用判据（四条，命中才准建实体 agent）

1. **批量并行**：同构任务数量大，主会话逐个做效率不可接受
2. **上下文隔离**：重型阅读（数万 token 语料/榜单/全书）会淹没主会话，且结果只需蒸馏结论
3. **审查隔离**：评审者与创作者必须分身，防自审偏袒
4. **条件性重活**：轻量版主会话先做，复杂时才 spawn

四条全不沾 → 不建 agent。**fallback 主线程纪律**：任何 agent 不可用时，主会话必须能完成同等任务（降级而非中断）。

## 三、结构模板（每个 agent 文件的节序）

①frontmatter（官方字段）②角色定位一句 ③对象清单（审什么/读什么/边界）④纪律段（禁令+理由+红旗自检）⑤输出格式（结构化，先落文件后回传）⑥被调用协议（入参说明+失败语义）

## 四、协作协议

1. **上下文隔离**：spawn 只传任务增量；稳定规则由 agent 自身定义承接，不随调用重复
2. **结果回传**：结构化产出先落文件再由主会话消费（文件账本律）
3. **失败语义**：spawn 失败即 fallback 主线程，同一任务重试 ≤ 1 次
4. **权限最小化**：tools 白名单按职责最小配置；禁全量授权

## 五、T1 触发时的填充清单（占位 → 正式的差额）

- 实体 agent 清单与角色定稿（依正文/审查域需求，如 evaluator 三评委/研究采风分身）
- 物化部署方案（abzu-setup 的 agent 模板 → 书项目 `.claude/agents/`，含版本哨兵）
- agent 间通信格式细则（结构化回传 schema/order 文件模式）
- agent 产出评估基线（验收场景与质量判据）

## 六、维护

- T1 触发前：本文件为设计约束（不得创建实体 agent；涉及 agent 的设计讨论引用本文件蓝图）
- T1 触发后：按填充清单升级为正式版，变更记录 CHANGELOG
