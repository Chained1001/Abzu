# Markdown 写作规范（正文、排版与 AI 友好）

> 版本：v0.1（2026-09-05 立法）
> 定位：仓库所有 .md 文件正文写法的单点权威——结构、中文排版、AI 友好写作、符号与编码安全。文件命名归 [file-conventions.md](file-conventions.md)；术语叫法归 [../glossary.md](../glossary.md)。
> 依据：markdownlint 规则集（条文先行，工具配置见 `.markdownlint-cli2.jsonc`）、中文文案排版指北、Anthropic skill 写作实践、mo-shu 工艺教训。

## 一、结构规则

1. 标题逐级递进，禁止跳级（H2 之后不得直接 H4）。
2. 全文唯一 H1（文件标题）；小节从 `##` 起。
3. 代码块必标语言（`bash` / `json` / `yaml` / `markdown`）；中文话术、模板示例的围栏不标语言。
4. 超过 100 行的参考文件，头部放节目录——按节精读的前提。
5. 无序列表统一用 `-`；有序列表只在顺序有意义时使用。
6. 表格上下留空行；单元格内的竖线用 `\|` 转义。
7. 文件结尾保留一个空行。

## 二、中文排版

1. 中英文之间加空格（如：在 Claude Code 中运行）；中文与数字之间加空格（如：第 3 章）。
2. 全角标点与其他字符之间不加空格。
3. 标点不叠用（如 ！！、……。）。
4. 专有名词大小写正确：GitHub、Claude Code、markdownlint。
5. 中文语境省略号用 `……`，不用 `...`。
6. 移植文件（来源标注含「移植自」）的存量排版偏差豁免——移植保真优先，不做批量规范化；增量编辑部分仍须遵循本规范。

## 三、AI 友好写作

1. 术语一致：全文只用术语表的叫法，发现第二种叫法当次收口。
2. 示例优先于规则：教格式或风格必须给输入/输出对。
3. 指令用命令式语态（"读文件后再改"）。
4. 引用带节锚点：`stage-drafting.md`「章末钩子」节。
5. 禁互引：不写"格式同上、参照上文"——分段读取时读者看不到"上下文"。
6. 禁时间敏感表述：不写"X 年 X 月后用 Y"；只写当前方法，旧法记入 CHANGELOG。
7. 路径用正斜杠并用反引号包裹：`.claude/skills/abzu`。
8. 加粗纪律：单文件 `**` 数 ≤ 行数 ÷ 3；只加粗红线、路径、数字、闸门——重点太多等于没有重点。

## 四、符号与编码安全

1. 文件名禁用 Windows 保留字符 `\/:*?"<>|`，禁 emoji，不用空格。
2. 仓库内文件一律英文 kebab-case（写作项目书产物中文名豁免，同样禁符号）。
3. 全仓 UTF-8 编码、无 BOM。
4. 行尾统一 LF，由 `.gitattributes` 强制。

## 五、不采用的规则（带理由）

| 规则 | 理由 |
| --- | --- |
| MD013 行长度上限 | 中文与代码混排不适配 80 列，以段落可读性为准 |
| MD034 裸 URL | 本仓 URL 均在链接或反引号中，属误报噪声 |
| MD040 代码块语言 | 目录树、中文话术、模板围栏无语言可标，硬标 text 无渲染收益；真代码的语言标注由 §一.3 条文约束 |

其余规则以 markdownlint 默认集为准；新增不采用须改本文件并说明理由。

## 六、维护

- 违反本规范视同文档 bug：改文件当批顺手修，不单独开规格。
- lint 体检命令：`npx markdownlint-cli2`（配置见 `.markdownlint-cli2.jsonc`）；引入 CI 须先解冻不做清单的 CI 条目。
