# Markdown 写作规范（正文、排版与 AI 友好）

> 版本：v0.3（沿革见 CHANGELOG 与 git 历史）
> 定位：仓库所有 .md 文件正文写法的单点权威——结构、中文排版、AI 友好写作、符号与编码安全。文件命名归 [file-conventions.md](file-conventions.md)；术语叫法归 [../glossary.md](../glossary.md)。
> 依据：markdownlint 规则集（条文先行，工具配置见 `.markdownlint-cli2.jsonc`）、中文文案排版指北、Anthropic skill 写作实践。

## 一、结构规则

1. 标题仅用 H1–H3：全文唯一 H1（文件标题）居首，小节从 `##` 起，逐级递进禁止跳级；更深的层次用列表表达。
2. 代码块必标语言（`bash` / `json` / `yaml` / `markdown`）；中文话术、模板示例的围栏不标语言。
3. 超过 100 行的参考文件，头部放节目录——目录为手动列表（`- 节名`），不依赖渲染器 TOC 语法，条目与 H2 标题逐字一致。
4. 单文件超过 300 行（references 建议 300 行）应考虑拆分——拆分判据见宪法 §7。
5. 无序列表统一用 `-`；有序列表只在顺序有意义时使用；子列表缩进 2 空格。
6. 表格上下留空行；单元格内的竖线用 `\|` 转义；对齐标记可省略（默认左对齐）。
7. 段落之间空一行；文件结尾保留一个空行。
8. 不使用 HTML 注释与 HTML 标签（内部备注走规格或 git 历史）。

## 二、中文排版

1. 中英文之间加空格（如：在 Claude Code 中运行）；中文与数字之间加空格（如：第 3 章）；行内代码与全角标点邻接不加空格（如：运行 `npm install`）。
2. 全角标点与其他字符之间不加空格。
3. 标点不叠用（如 ！！、……。）。
4. 专有名词大小写正确：GitHub、Claude Code、markdownlint。
5. 中文语境省略号用 `……`，不用 `...`。
6. 引号三分：节名与需逐字复现的内容用「」（如「扫榜报告模板」节、「你倾向哪个选题？」）；中文普通引语用弯引号 ""；直引号 " 仅出现在代码与参数中。
7. 移植文件（来源标注含「移植自」）的存量排版偏差豁免——移植保真优先，不做批量规范化；增量编辑部分仍须遵循本规范。

## 三、AI 友好写作

1. 术语一致：全文只用术语表的叫法，发现第二种叫法当次收口。
2. 示例优先于规则：教格式或风格必须给输入/输出对——本文件 §三.9 至 §三.11 即此履约。
3. 指令用命令式语态（"读文件后再改"）。
4. 引用带节锚点：`scan-analysis-guide.md`「扫榜报告模板」节。
5. 禁模糊指代：不写"格式同上、参照上文、如前所述"——分段读取时读者看不到"上下文"；带明确节锚点的具体引用不受此限。
6. 禁时间敏感表述：不写"X 年 X 月后用 Y"；只写当前方法，版本沿革一律记 CHANGELOG（含本文件头部的版本行——只留版本号，不写沿革）。
7. 路径用正斜杠并用反引号包裹：`skills/abzu-scan`。
8. 行内代码与全角标点邻接不加空格（同 §二.1）。
9. 加粗：单文件 `**` 数 ≤ 行数 ÷ 3（数值上限为兜底）；定性规则优先——加粗仅用于红线、路径、数字、闸门四类，一段至多一处。
10. 箭头 `→` 仅用于流程映射与条件分支（起点 → 终点 / 条件 → 动作），禁作装饰；趋势枚举 `↑/→/↓` 中的 → 表示持平，为例外。

示例对照（✅ 合规 ｜ ✗ 违规）：

- 行内定义：✅ `**核心卖点**：读者为什么追` ｜ ✗ `**核心卖点**: 读者为什么追`（半角冒号）｜ ✗ `**核心卖点** ：读者为什么追`（冒号前空格）
- 引号分工：✅ 「你倾向哪个选题？」（停靠话术，逐字复现）｜ ✅ 这就是所谓的"降维打击"（普通引语）｜ ✗ 在锚点里用直引号 `"扫榜报告模板"节`
- 箭头：✅ `起点 → 终点`（流程）、`样本不足 → 降"中"`（条件）｜ ✗ `这是一本 → 非常好看的书`（装饰性断行）
- 加粗：✅ `**必须**落盘数据质量三行`（红线）｜ ✗ `这段**历史**讲的是过去`（无强调必要的装饰加粗）

## 四、符号与编码安全

1. 文件名禁用 Windows 保留字符 `\/:*?"<>|`，禁 emoji，不用空格。
2. 仓库内文件一律英文 kebab-case（规格主题中文与写作项目书产物中文名豁免，同样禁符号）。
3. 全仓 UTF-8 编码、无 BOM。
4. 行尾统一 LF，由 `.gitattributes` 强制。
5. 状态符号仅限 ✅（已就绪）与 🚧（已立项未建设）用于状态列与清单；禁装饰性 emoji。

## 五、不采用的规则（带理由）

| 规则 | 理由 |
| --- | --- |
| MD013 行长度上限 | 中文与代码混排不适配 80 列，以段落可读性为准 |
| MD034 裸 URL | 本仓 URL 均在链接或反引号中，属误报噪声 |
| MD040 代码块语言（全量要求） | 本规范采用**选择性标注**：真代码的语言标注由 §一.2 条文约束；中文话术、目录树、模板围栏无语言可标，全量要求不适用 |

其余规则以 markdownlint 默认集为准；新增不采用须改本文件并说明理由。

## 六、维护

- 违反本规范视同文档 bug：改文件当批顺手修，不单独开规格。
- lint 体检命令：`npx markdownlint-cli2`（配置见 `.markdownlint-cli2.jsonc`）；引入 CI 须先解冻不做清单的 CI 条目。
- 未来守卫待办：check.sh 可增「扫描 references 内相对 .md 链接」检查项（file-conventions §三 同款待办）。
- 固化检查工具的两条技术要求：围栏感知（代码块内 `#` 非标题——2026-09-05 误报教训）与正则词边界（`gb18030` 撞 `B\d\d` 误报教训）。
- 审计深度分级：核验深度映射施工自由度与文件类型，详见宪法 §3.6。
