# Skill 写作规范（SKILL.md 与 references 内容设计）

> 版本：v0.2（2026-09-05 增补：文件结构模板节、交互标注纪律；来源声明改两行）
> 定位：skill 内容（SKILL.md 正文、references 方法论、对用户话术）的写作与设计规范。正文格式归 [markdown-style.md](markdown-style.md)；文件命名归 [file-conventions.md](file-conventions.md)；行为验收归 [../test-prompts.md](../test-prompts.md)；版本归 [release-and-versioning.md](release-and-versioning.md)。
> 依据：obra/superpowers writing-skills 元规范（社区实战验证）、Anthropic skill 官方指南、mo-shu 工艺教训。

## 一、description（触发器，官方上限 1024 字符）

1. 第三人称，写清触发条件与关键词，含触发方式（如 `/abzu` 与自然语言）。
2. **禁写工作流摘要**——agent 会把流程描述当捷径跳过正文（superpowers 实证事故：流程写了两次评审，agent 只做一次）。
3. 塞满可检索触发词：用户的口语说法、术语表叫法、同义词。
4. 只在技能明确绑定某技术时提技术名，否则保持技术无关。

## 二、正文结构与预算

1. 预算分级（触发即全量加载的文件从严）：`SKILL.md` 目标 <300 行、硬上限 500 行；单 reference <300 行（宪法 §7 同源）。
2. 超过 100 行的 reference 头部放节目录（按节精读的前提）。
3. 流程图只用于非显然的决策、循环、二选一场景；线性步骤用有序列表；图内禁放代码（无法复制）。

## 三、文件结构模板（每类文件必备节序）

**SKILL.md（总控）**：①定位一句 + 六域平行门原则 ②会话恢复协议 ③域路由表 ④门控与交互原则 ⑤语言规则

**workflow-{域}.md（域工作流）**：①头部两行声明 ②域角色定位一句 + 核心信念（不设流程衔接表——跨域导航归 SKILL.md 中央路由，域工作流不管去向） ③Stage 1..N（每 Stage 含：做什么 / 读什么 / 产出 / 停靠点）④参考资料挂载表（文件 × 何时加载）

**方法论参考**：①头部两行声明 ②按主题分节（每节：问句 / 操作 / 反例）③超 100 行加目录

**模板文件（`*-template.md`）**：①定位注记（是什么产物 / 何时创建）②模板正文

## 四、指令形式匹配失效类型（superpowers 实证）

| 失效类型 | 正确形式 | 禁忌 |
| --- | --- | --- |
| 输出形状不对 | 正向配方：明确说输出"是什么" | 禁令措辞——实证反而增产不需要的内容 |
| 漏必要元素 | 模板必填槽位（结构上强制） | 靠叮嘱"别忘了" |
| 条件行为 | 绑定可观察谓词（"若 tracking/progress.md 存在则……"） | 模糊条件（"视情况"） |
| 纪律红线 | 禁令 + 理由 + 红旗自检清单 | "除非……"细则——重开谈判空间 |

## 五、流程与交互设计

1. Stage 命名：从 1 起编号（Stage 1、Stage 2……）；禁从 0 起、禁小数编号（Stage 2.5）、禁字母后缀（Stage A/B）。
2. 交互模态三规则：封闭选择（≤4 项）用选择弹窗（AskUserQuestion；候选超 4 个收高频 4 项，其余并入弹窗自带"其他"）；开放采集（自由表达）用对话式；过程性动作默认执行 + 可显式跳过。
3. **交互标注纪律**：workflow 正文每个用户问句后必须标模态——（弹窗：选项列表）或（对话式）；一个问句只承载一种模态，混合问题（如"选平台 + 说方向"）拆成两问。
4. 话术零黑话：内部术语（伏笔账本、阶段门控等）不得出现在用户可见话术里——话术用用户视角的自然语言。
5. 方法论用苏格拉底问句（问句迫使具体回答，杜绝"直面X"式标签答案）；模板空位用填空提示（`{____：主角此时错误相信____}`）。
6. 示例纪律：一个优秀完整示例胜过多个平庸示例；必须可套用、来自真实场景、注释讲"为什么"。

## 六、引用纪律

1. skill 资产内引用一律写 **skill 根相对路径 +「节名」**（如 `references/scan/scan-analysis-guide.md`「扫榜报告模板」节、`scripts/scan-analyze.js`）——运行时模型按 SKILL_DIR 直接拼出完整路径，零推断；禁裸文件名。
2. 深层资产互引不用 markdown 链接：链接目标按所在文件位置解析，与运行时按 SKILL_DIR 解析是两套语义，混用必有一方错；SKILL.md 位于根，两种语义一致，可用链接。文件内目录用锚点链接（`#节名`）不受此限。
3. 阶段文件头部两行声明：消费点（哪个 Stage 读、必读还是按需）/ 边界（与相邻文件的分工）。
4. 禁互引式引用（"格式同上"，同 markdown-style §三.5）；不用 `@` 形式链接（强制加载目标文件，烧上下文）。

## 七、评估闭环（RED-GREEN-REFACTOR）

1. RED：新能力先不带指令裸跑，记录失败选择与理由原话。
2. GREEN：写最小指令修正，重跑通过。
3. REFACTOR：把过程中新出现的合理化借口堵回指令，再测。
4. 场景清单与跑法见 [../test-prompts.md](../test-prompts.md)；修改 skill 后必跑（宪法 §3）。

## 八、内容主张规范

1. **情态三级**（约束力度从高到低，指令用词必须落在其中一级）：

   | 级别 | 用词 | 语义 |
   | --- | --- | --- |
   | 硬约束 | 必须 / 禁止 | 违反即错，无裁量空间 |
   | 强约定 | 默认 / 优先 | 可覆盖，但须说明理由 |
   | 启发式 | 建议 / 可以 | 模型自主裁量 |

   禁用未分级力度词（"硬性要求"统一写"必须"，"不许"统一写"禁止"）。

2. **数字断言标来源**：内容中的数字与阈值标注〔书证〕〔实测〕〔abzu 自定〕之一；自定阈值必须可被用户指令或 CLI 参数覆盖；无来源标注的数字不得写入新内容。
3. **占位符语法**：系统变量全大写英文（`{SKILL_DIR}`）；业务变量统一中文（`{平台}`、`{扫榜目录}`）；枚举选项 `{A/B}`；日期 `{YYYYMMDD}`。同一概念全文一种写法。

## 九、维护

- 格式问题归 markdown-style，内容设计问题归本文件；冲突时按此分工裁定。
- 新增文件类型时回写 §三 模板。
