# skill形态标准

> 定位：约束 skill 组本身：**目录形态（`SKILL.md` 必需；`references`／`assets`／`scripts` 三可选）**、`SKILL.md` 四节骨架、frontmatter 键（含调用控制键）、`references` 一层深与体积上限。
> 依据：旧仓《Skill 写作规范》全文 + 旧仓《文件规范》的 frontmatter 格式与内容规范矩阵两节（来源件已随 rebuild 作废，条文逐条迁移）；触发方式焊死为唯一入口显式调用，来源件为多域时期内容，已通用化改写。

## 目录

- 一、条文
- 二、正例与反例
- 三、机检锚点

## 一、条文

### 1. 目录形态（`skills/{skill 名}/`）

1. `SKILL.md`——固定名，每域一份，是入口；装进用户机器后由 skill 名路由。
2. `references/`——**按需加载的文档**（方法论／话术／规范／查询表）；**平铺**（不设 `{skill 名}/` 子目录层）；`references` 之间不互相链接（**一层深**：`SKILL.md` → `references` 为止，同层互引读者可能看不到对方）。
3. `assets/`——**模板与资源**（产物模板等需被填充／复制的骨架）；平铺。与 `references/` 的分工判据＝**被「读」的说明归 `references/`，被「填／复制」的骨架归 `assets/`**。
4. `scripts/`——运行时脚本与共享库；无脚本的域不建该目录。

现状：`skills/` 已建（`abzu-outline`——**阶段一（规格步）资产已建（088）**）（命名细则见[命名标准](命名标准.md)）。其中 2／3／4 为**按需建**——域无该类资产时不建该目录；仅 1 必需。**原「三件」表述与本标准机检锚点的「三件齐」断言一并废止**——「三件」含「可选项必须存在」之歧义。

### 2. `SKILL.md` 骨架（四节名固定，缺一即不合格）

H1 固定「{产品名} · {中文 skill 名}（{英文 skill 名}）」；正文节序：

1. 入口判定（每次会话开始）——按**文件证据**定位续跑点（如无项目进度文件即全新开书），不凭对话记忆；跨域意图告知对应 skill 命令与状态。
2. 工作流——指向域工作流文件，正文不复制 workflow 内容。
3. 门控与交互原则——门控停靠与交互模态的域内声明（细则归[触发与交互标准](触发与交互标准.md)）。
4. 语言——对用户话术的语言规则（同 §10 内容主张规范）。

### 3. frontmatter 键

```yaml
---
name: example-skill  # 示例：须与 skill 目录同名
description: <第三人称；能力名词化句 + 触发句 + 边界句，≤1024 字符；见 §4>
license: MIT
disable-model-invocation: true
metadata:
  version: "0.1.0"
---
```

- 官方约束（Agent Skills 开放规范）：`name` 小写字母/数字/连字符，≤64 字符，不以连字符开头或结尾，**须与目录同名**；`description` 非空 ≤1024 字符（须含做什么与何时使用）。
- 调用控制键 `disable-model-invocation: true`——**机制层**：禁模型自动触发（自然语言提及不触发），保留 `/{skill 名}` 显式调用与 `/` 菜单可见。**实测回写（四要素）**：宿主 **Claude Code 2.1.270**（VSCode 扩展，`cc_entrypoint=claude-vscode`）｜**2026-09-15**｜结论 **两项判据均成立**——① `/` 菜单列出该 skill（**须重载窗口**：扩展在激活时取一次命令快照，同窗口内新装或新删的 skill 不会被中途补入菜单）② 模型不能自主触发（模型侧技能名单**不含**带该键的 skill；同批实测中技能附件计数 13→14 的增量只来自未带该键的探针）。**发现的不一致**：生态侧参考校验器（pip 包 `skills-ref`，白名单六键）**拒收**该键（rc=1），而宿主官方文档列其为合法键且实测生效——本仓**保留该键**，外挂校验器只作规范符合度参考、不作门禁。键名与语义以宿主官方文档为准。**双轨**：description 触发句是文案层，本键是机制层，两轨缺一即不合格（触发形态细则见[触发与交互标准](触发与交互标准.md)）。
- 校验：**本地断言**（`check.sh [2]`）；**外部校验器仅走查期可选**（其白名单不含本仓硬约束键）。

### 4. description 三段式（触发器）

1. 第三人称，写清触发条件，含触发方式（`/{skill 名}` 显式调用）。
2. 禁写工作流摘要——agent 会把流程描述当捷径跳过正文（旧仓实证事故：流程写了两次评审，agent 只做一次）。
3. 可含可检索触发词（用户的口语说法、[术语表](../product/术语表.md)的叫法、同义词）——仅供命令面板与用户检索定位技能，**不构成自然语言自动触发授权**。
4. 只在技能明确绑定某技术时提技术名，否则保持技术无关。
5. 触发句一律为「触发方式：仅 /{skill 名} 显式调用；自然语言提及不触发。」——禁「或上述任一话题的自然语言」类模糊触发句（反例：旧仓实建壳旧触发句；同一产品下的多个 skill 同属一个工作面，自然语言互抢误触发，实测教训）。三段式＝能力名词化句 + 触发句 + 边界句；「当用户想…时使用」邀请式从句移除，能力描述用名词化句式。

### 5. 正文结构与预算

1. 预算分级（触发即全量加载的文件从严）：`SKILL.md` 硬上限 500 行（Agent Skills 开放规范）；目标 <300 行（预立法，随首批实例校准）；单 reference <300 行。行数阈值是**兜底**——下沉（progressive disclosure）的判据优先取**分支**：每个分支都要用的内联在文件内，只有部分分支会读的才沉到独立文件；行数只在无分支可判时兜底（拆分——按序列或按调用拆开文件——的判据见 §8）。**`assets/` 的模板与资源不计行数预算**——它们不参与「触发即全量加载」（由运行时按需取用），长度由产物字段数决定；头部两行声明照旧（属 skill 资产，见 §9.3）。
2. 超限处理序：先压缩 → 仍超则下沉冷路径 → 最后才调上限；**调上限须在 `CHANGELOG` 记录理由**（放宽标准是最后手段，不是第一反应）。〔出处：旧仓宪法 §7 体积纪律〕
3. 超过 100 行的 reference 头部放节目录（按节精读的前提）。
4. 流程图只用于非显然的决策、循环、二选一场景；线性步骤用有序列表；图内禁放代码（无法复制）。

### 6. 文件结构模板（每类文件必备节序）

**{域}-workflow.md**：①头部两行声明（消费点／边界）②域角色定位一句 + 核心信念（不设流程衔接表——多域骨架下无中央路由，跨域导航由各域入口自查 + skill 本名命令承担）③Stage 1..N（每 Stage 含：做什么／读什么／产出／异常分支／停靠点）④参考资料与脚本挂载表（三列：文件 × 作用 × 加载时机——作用帮模型判断与本问相关性，时机确定全量或按需）。**须含中断契约**，标准句式：「用户中途要求停止或表达其他域意图时，确认当前进度已落盘后移交对应域——建议使用对应 /{skill 名} 命令，不强行走完本域流程」。

**方法论参考**：①头部两行声明 ②按主题分节 ③超 100 行加目录——此三条为一切方法论类文件的底线；其下两子类：决策方法论（指导选择的文件）每节用 问句／操作／反例 形态；知识素材类（知识库／格式规范／操作手册）按其自然结构组织，不强套问句式。

**产物模板（`assets/{域}-{产物名}-template.md`）**：①定位注记（产物是什么／何时创建／生产者／消费方）②字段定义表（字段／说明／生产来源 Stage／必填性）③默认值与完整填写示例 ④模板正文（`{____}` 填空与 `{A/B}` 枚举）。**产物模板三要素**：字段定义、示例行、约束三件必须在，缺任一件即不合格。

### 7. 指令形式匹配失效类型（旧仓实证）

| 失效类型 | 正确形式 | 禁忌 |
| --- | --- | --- |
| 输出形状不对 | 正向配方：明确说输出"是什么" | 禁令措辞——实证反而增产不需要的内容 |
| 漏必要元素 | 模板必填槽位（结构上强制） | 靠叮嘱"别忘了" |
| 条件行为 | 绑定可观察谓词（"若项目进度文件存在则……"） | 模糊条件（"视情况"） |
| 纪律红线 | 禁令 + 理由 + 红旗自检清单 | "除非……"细则——重开谈判空间 |
| 步骤跳跃／合并 | 每步绑定一个落盘产物（文件账本律） | 多步合一、跳过中间产物——中间产物是下一站的输入 |
| 越权操作 | 域职责一句话写死 + 跨域意图移交对应域命令 | 在本域内顺手执行其他域的活——域边界即合同边界 |

### 8. 流程设计纪律

1. Stage 命名：从 1 起编号（Stage 1、Stage 2……）；禁从 0 起、禁小数编号（Stage 2.5）、禁字母后缀（Stage A/B）。
2. 话术零黑话：内部术语（如阶段门控）不得出现在用户可见话术里——话术用用户视角的自然语言。
3. 决策方法论用苏格拉底问句（问句迫使具体回答，杜绝"直面X"式标签答案）；模板空位用填空提示（`{____：{主体}此时错误相信____}`）。
4. **模板字段与生产策略同批**：产物模板新增／变更字段，必须同批在该域方法文件中补对应生产步骤（哪个 Stage、读哪个文件、怎么归纳）——无生产策略的字段＝永远空着，禁止入模板（旧仓教训：模板加四字段未补生产逻辑，被作者以"加字段没写 INSERT"点破）。
5. 示例纪律：一个优秀完整示例胜过多个平庸示例；必须可套用、来自真实场景、注释讲"为什么"。
6. 每步须给**完成判据**——判定这一步做完没做完的那句话，且须可判定（正例：范式判决「输出能被下游直接消费」；反例：以「已理解」「差不多了」这类不可判定的界作结）。要求度取强范式，即把「做到什么程度才算完」写满（如「能不问一个问题就开工」强于「给个改动清单」）。
7. 警惕 **premature completion**——后续步骤在上下文里可见时，注意力会滑向「想做完」，当前步骤被提前收尾。防御顺序：先磨边界（本步判据写清写完没）；边界确实磨不动、且观察到抢跑时，才拆分序列把后续步骤藏到别处。**藏只在真实上下文边界有效**（交接、下派 subagent）——同一个上下文里的内联拆分什么也藏不住。

### 9. 引用纪律（skill 资产）

1. skill 资产内引用一律写 skill 根相对路径 + 节名（如 `references/outline-workflow.md`「草稿步」节、`assets/outline-基本规格-template.md`、`scripts/init-book.js`）——运行时模型按 skill 根直接拼出完整路径，零推断；禁裸文件名。scripts 无节名概念，引用写路径即可；需指定入口时用 `scripts/xxx.js` 的 `functionName()` 形式。格式总表见[命名标准](命名标准.md) §5；指向仓库治理文档的写法见 `命名标准` §5。
2. 深层资产互引不用 markdown 链接：链接目标按所在文件位置解析，与运行时按 skill 根解析是两套语义，混用必有一方错；`SKILL.md` 位于根，两种语义一致，可用链接。文件内目录用锚点链接不受此限。
3. 阶段文件头部两行声明：消费点（哪个 Stage 读、必读还是按需）／边界（与相邻文件的分工）**（两行为必含项；可另加补充行——如映射说明、建设状态通报引用、出处）**。
4. 禁互引式引用（"格式同上"）；不用 `@` 形式链接（强制加载目标文件，烧上下文）。

### 10. 内容主张规范

1. **情态三级**（约束力度从高到低，指令用词必须落在其中一级）：

   | 级别 | 用词 | 语义 |
   | --- | --- | --- |
   | 硬约束 | 必须／禁止 | 违反即错，无裁量空间 |
   | 强约定 | 默认／优先 | 可覆盖，但须说明理由 |
   | 启发式 | 建议／可以 | 模型自主裁量 |

   禁用未分级力度词（「硬性要求」统一写「必须」，「不许」统一写「禁止」）；单条指令的力度词必须唯一、不得叠加（「必须优先」「禁止可以」均为无效表述——模型无法判定是硬约束还是启发式）。

2. **数字断言标来源**：内容中的数字与阈值标注〔书证〕〔实测〕〔自定〕之一；自定阈值必须可被用户指令或 CLI 参数覆盖；无来源标注的数字不得写入新内容。
3. **占位符语法**：系统变量全大写英文（`{SKILL_DIR}`）；业务变量统一中文（`{书名}`、`{平台}`）；枚举选项 `{A/B}`；日期 `{YYYYMMDD}`。同一概念全文一种写法。

### 11. skill 运行时规范

| 规则 | 内容 |
| --- | --- |
| 幂等性 | 重复调用同一 skill／命令，结果一致——不因重复执行产生副作用或破坏已有产物 |
| 副作用声明 | 域工作流必须声明：写哪些文件／目录、调哪些外部服务、有无不可逆操作 |
| 超时上限 | 每个脚本／外部调用有超时上限（如 HTTP 30s），超时后降级或报错 |
| 依赖前置 | 域文档声明运行时依赖，缺失时输出可操作的安装提示（依赖边界见[运行环境标准](运行环境标准.md)） |
| 降级行为 | 依赖不可用时的降级路径逐级声明，不得静默失败 |
| 用户确认 | 写文件／调外部服务／删数据等有副作用的操作，停靠等待用户确认后才执行 |
| 错误返回 | 失败时输出：什么错了 + 为什么 + 用户能做什么（三要素），不静默失败、不吞错误 |

### 12. 评估闭环（RED-GREEN-REFACTOR）

1. RED：新能力先不带指令裸跑，记录失败选择与理由原话。
2. GREEN：写最小指令修正，重跑通过。
3. REFACTOR：把过程中新出现的合理化借口堵回指令，再测——修改指令后必须回归全部已通过场景（防修一处坏三处），不得只测修改相关场景。
4. 域上线验收清单与真机走查做法见[测试与验收标准](测试与验收标准.md)；改 skill 资产后必跑（**是否必跑按[施工机制](../specs/施工机制.md) §二 重路径行的真机走查豁免判据**）。

## 二、正例与反例

- ✅ frontmatter 五键齐全且 `name` 与目录同名（示例：`name: example-skill` ↔ `skills/example-skill/`）。
- ✅ description 三段式（示例）：「Example 能力名：某能力的名词化描述。触发方式：仅 /example-skill 显式调用；自然语言提及不触发。范围限本 skill 覆盖的工作面，其余归 /another-skill。」
- ✅ H1 格式（示例：「Example · 示例域（example）」）+ 四节固定节名。
- ✅ 产物模板三要素齐备（字段定义表 + 示例行 + 定位注记约束）。
- ✅ 模板新增字段的同批生产策略：加字段的同批在 workflow 对应 Stage 补「读哪个文件、怎么归纳」。
- ✗ description 写工作流摘要（agent 照摘要走捷径，正文步骤被跳过——旧仓两次评审只做一次的事故）。
- ✗ description 写「或上述任一话题的自然语言可触发」（模糊触发句——同一产品下的多个 skill 同属一个工作面，自然语言互抢误触发）。
- ✗ 只在 description 写「自然语言提及不触发」而不加调用控制键（只有文案层、缺机制层）。
- ✗ `SKILL.md` 内复制 workflow 的 Stage 表（同一内容两份维护，改一处漏一处）。
- ✗ references 之间互相链接成链（违反一层深——读者看不到同层文件）。
- ✗ 模板加字段不补生产策略（"加表字段没写 INSERT"——字段永远空着）。
- ✗ 指令写「必须优先落盘」（力度词叠加，模型无法判定是硬约束还是启发式）。
