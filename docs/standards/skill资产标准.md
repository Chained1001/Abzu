# skill资产标准

> 定位：skill 组的形态、结构、触发与交互——目录形态、`SKILL.md` 四节、frontmatter 键、description 三段式、唯一入口与触发纪律、阶段确认点与交互模态、正文预算、模板、引用纪律、运行时规范、内容规范矩阵。
> 拆分触发：触顶 15,000 字符或第二个域落地细则膨胀时，按「主文件与触发／资产文件与交互」两件拆。

## 目录

- 一、条文
- 二、正例与反例
- 三、脚本检查点

## 一、条文

### 1. 目录形态（`skills/{skill 名}/`）

1. `SKILL.md`——固定名，每 skill（域）一份，是入口；装进用户机器后由 skill 名路由（命名与位置见[文字与命名标准](文字与命名标准.md) §1）。
2. `references/`——**按需加载的文档**（方法论／话术／规范／查询表）；**平铺**（不设 `{skill 名}/` 子目录层）；`references` 之间不互相链接（**一层深**：`SKILL.md` → `references` 为止，同层互引读者可能看不到对方）。
3. `assets/`——**模板与资源**（产物模板等需被填充／复制的结构）；平铺。与 `references/` 的分工＝**被「读」的说明归 `references`，被「填／复制」的结构归 `assets`**。
4. `scripts/`——运行时脚本与共享库；无脚本的域不建该目录。

现状：`skills/` 已建（`abzu-outline`——阶段一（规格步）资产已建）。2／3／4 为**按需建**；仅 1 必需；三者不必齐备。

### 2. `SKILL.md` 结构（四节名固定，缺一即不合格）

H1 固定「{产品名} · {中文 skill 名}（{英文 skill 名}）」；正文节序：

1. 入口判定（每次会话开始）——按**文件证据**定位续跑点（如无项目进度文件即全新开书），不凭对话记忆；跨域意图告知对应 skill 命令与状态。
2. 工作流——指向域工作流文件，正文不复制 workflow 内容。
3. 阶段确认点与交互原则——阶段确认点、中途暂停与交互模态的域内声明（细则归本件 §6／§7）。
4. 语言——对用户话术的语言规则（同[文字与命名标准](文字与命名标准.md) §17 内容主张规范）。

### 3. frontmatter 键

```yaml
---
name: example-skill  # 示例：须与 skill 目录同名
description: <第三人称；能力名词化句 + 触发句 + 边界句，≤1024 字符；见 §4>
license: MIT
disable-model-invocation: true
metadata:
  version: "0.1.0"
---
```

- 官方约束（Agent Skills 开放规范）：`name` 小写字母/数字/连字符，≤64 字符，不以连字符开头或结尾，**须与目录同名**；`description` 非空 ≤1024 字符（须含做什么与何时使用）。
- `metadata.version` 遵循 SemVer：行为变更（新阶段／新产物文件／流程规则变更）＝minor、措辞勘误＝patch、产物结构破坏性变更＝major；套件统一节奏同批 bump 各 skill。发布与分发纪律（版本号多处一致、发布流程、回滚）**未立法——随首个发布批立法**（首发尚未发生）。
- 调用控制键 `disable-model-invocation: true`——**机制层**：禁模型自动触发（自然语言提及不触发），保留 `/{skill 名}` 显式调用与 `/` 菜单可见。**实测结论（2026-09-15，宿主 Claude Code 2.1.270／VSCode 扩展；四要素与过程见 `archive/087`）**：① `/` 菜单列出该 skill——**须重载窗口**（扩展在激活时取一次命令快照）② 模型不能自主触发（模型侧技能名单不含带该键的 skill）。**并注**：生态侧参考校验器（pip 包 `skills-ref`）拒收该键而宿主实测生效——本仓保留该键，外挂校验器只作参考；键名与语义以宿主官方文档为准。**双轨**：description 触发句是文案层，本键是机制层，两轨缺一即不合格。
- 校验：**本地断言**（`check.sh [2]`）；外部校验器仅人工试跑期可选。

### 4. description 三段式（触发器）

1. 第三人称，写清触发条件，含触发方式（`/{skill 名}` 显式调用）。
2. 禁写工作流摘要——agent 会把流程描述当捷径跳过正文（实证事故：流程写了两次评审，agent 只做一次）。
3. 可含可检索触发词（用户的口语说法、[术语表](../product/术语表.md)的叫法、同义词）——仅供命令面板与用户检索定位技能，**不构成自然语言自动触发授权**。
4. 只在技能明确绑定某技术时提技术名，否则保持技术无关。
5. 触发句一律为「触发方式：仅 /{skill 名} 显式调用；自然语言提及不触发。」——禁「或上述任一话题的自然语言」类模糊触发句（同一产品下的多个 skill 同属一个工作面，自然语言互抢误触发，实测教训）。三段式＝能力名词化句 + 触发句 + 边界句；「当用户想…时使用」邀请式从句移除。

### 5. 唯一入口与触发纪律（机制层 + 文案层，双轨缺一不可）

1. 入口唯一：skill 本名即命令——`/{skill 名}` 显式调用，由宿主斜杠菜单原生补全，无需命令薄代理（命令薄代理见 §5 第 4 条）；本项目域名与命令一一对应的清单以产品层[架构设计](../product/架构设计.md) 域清单为准。
2. **自然语言模糊触发禁止**——机制键见 §3（`disable-model-invocation: true`）、文案触发句见 §4 第 5 条，两轨缺一即不合格——只有文案等于靠模型自觉（事故记录：纪律靠自觉不靠机制）。
3. 域间禁互调：skill 之间禁止互相调用；跨域只经写入文件衔接——生产者只写入文件，消费者在自己域内定义如何查找与读取（产物接口见产品层契约件，本项目＝[书目录契约](../product/书目录契约.md) §3）。
4. 命令薄代理（预留，`.claude/commands/{skill 名}-{路由键}.md`）属 user-invoked 编排层：只可调用域 skill，域 skill 永不反向调用薄代理或其他域 skill；启用前不得新增实例。
5. 域外休眠：与本项目创作领域无关的请求（领域范围见产品层《产品定义》；示例：「把这个 CSV 按销售额排序」）不触发任何套件内 skill、不套域框架；调出某域后转提域外请求，正常执行不套本套件框架。

### 6. 阶段确认点与中途暂停

1. **阶段确认点＝阶段级硬停**：每阶段产出后暂停，经作者确认才进入下一阶段；确认前不产出后续阶段实质内容（目标产物存在但为空模板即合规）。
2. 中途暂停＝模块级暂停：阶段内关键产物产出后暂停等作者过目，与阶段确认点分列。**暂停点三级**（阻塞强度递减，同一处只取一级、不得叠加）：阶段确认点＝阶段级硬停 ＞ 中途暂停＝模块级暂停 ＞ 不阻断的通报点——把中间结果亮出来即可继续（如「候选排序如下，按默认顺序往下走」），用户 AFK 时按默认继续，并在通报中声明「按默认 X 继续，不阻塞」。
3. 阶段确认点与中途暂停确认点须落产物状态表行（落行式样如「{产物名}-待确认」），否则续跑不得跳过——状态判定来自文件证据，不凭对话记忆。
4. 阶段确认点选项形态：确认／要改／先停（三选）；部分阶段确认点带域内附加项（如「查看中间产物／补充输入」）。
5. 中断契约（workflow 必含，标准句式）：「用户中途要求停止或表达其他域意图时，确认当前进度已写入文件后移交对应域——建议使用对应 /{skill 名} 命令，不强行走完本域流程」。
6. 未建域如实告知：敲未建设域命令时如实告知「该域尚未建设」，不模拟、不代替、不产出占位内容。
7. **未建阶段如实告知**：域已建但阶段未建时，进域先报该域建设状态；未建阶段不模拟、不代替、不产出占位内容。建设状态通报只落**域工作流**一处，skill 主文件与阶段文件引用、不复制。

### 7. 交互模态

1. 封闭选择（≤4 项）→ 结构化选项列表；候选超 4 个收高频 4 项，其余并入其自带「其他」。
2. 开放采集（自由表达）→ 对话式。
3. 过程性动作默认执行 + 可显式跳过。
4. 语义描述为主，工具名放括号标注——防宿主变更，也防模型见工具名即机械调用。
5. 交互标注纪律：workflow 正文每个用户问句后必须标模态——（选项列表）或（对话式）；一个问句只承载一种模态，混合问题（如「选平台 + 说方向」）拆成两问。
6. 交互标注一律**不用宿主 UI 词**（弹窗／界面）；形态按第 5 条既有计算方式。
7. **同一屏只出一种模态**（一条消息内可并列多个**同模态**问句——多字段一次问完）：**每句各自标模态**、**不混模态批**（同屏混模态会让结构化问句抢答、自由问句被推迟一轮）；仍受第 1 条『封闭选择 ≤4 项』约束。

### 8. 域内准入律（指针）

域内准入律（规格字段）属产品层业务规则——实例见产品层对应域设计（本项目＝[大纲域设计](../product/outline/大纲域设计.md)「域交互细则」节）；本件只作指认，不复制细则（细则只在那一件定）。

### 9. 正文结构与预算

1. 预算分级（触发即全量加载的文件从严）：`SKILL.md` 硬上限 500 行（Agent Skills 开放规范）；目标 <300 行（预立法，随首批实例校准；**关联实例判定标准：首个接近 280 行的 `SKILL.md` 出现**）；单 reference <300 行。行数阈值是**保底做法**——下沉的判定标准优先取**分支**：每个分支都要用的内联在文件内，只有部分分支会读的才沉到独立文件；行数只在无分支可判时保底（拆分判定标准见 §12）。**`assets/` 的模板与资源不计行数预算**——不参与「触发即全量加载」；头部两行声明照旧（§13 第 3 条）。
2. 超限处理序：先压缩 → 仍超则下沉按需读 → 最后才调上限；**调上限须在 `CHANGELOG` 记录理由**。
3. 超过 100 行的 reference 头部放节目录（按节精读的前提）。
4. 流程图只用于非显然的决策、循环、二选一场景；线性步骤用有序列表；图内禁放代码（无法复制）。

### 10. 文件结构模板（每类文件必备节序）

**{域}-workflow.md**：①头部两行声明（消费点／边界）②域角色定位一句 + 核心信念（不设流程衔接表——多域结构下无中央路由）③Stage 1..N（每 Stage 含：做什么／读什么／产出／异常分支／中途暂停点）④参考资料与脚本纳入表（三列：文件 × 作用 × 加载时机）。**须含中断契约**（标准句式见 §6 第 5 条）。

**方法论参考**：①头部两行声明 ②按主题分节 ③超 100 行加目录——三条为一切方法论类文件的底线；其下两子类：决策方法论每节用 问句／操作／反例 形态；知识素材类按其自然结构组织，不强套问句式。

**产物模板（`assets/{域}-{产物名}-template.md`）**：①定位注记（产物是什么／何时创建／生产者／消费方）②字段定义表（字段／说明／生产来源 Stage／必填性）③默认值与完整填写示例 ④模板正文（`{____}` 填空与 `{A/B}` 枚举）。**三要素**：字段定义、示例行、约束三件必须在，缺任一件即不合格。

### 11. 指令形式匹配失效类型（实证）

| 失效类型 | 正确形式 | 禁忌 |
| --- | --- | --- |
| 输出形状不对 | 正向配方：明确说输出"是什么" | 禁令措辞——实证反而增产不需要的内容 |
| 漏必要元素 | 模板必填槽位（结构上强制） | 靠叮嘱"别忘了" |
| 条件行为 | 绑定可观察谓词（"若项目进度文件存在则……"） | 模糊条件（"视情况"） |
| 纪律红线 | 禁令 + 理由 + 红旗自检清单 | "除非……"细则——重开谈判空间 |
| 步骤跳跃／合并 | 每步绑定一个写入文件产物（文件账本律） | 多步合一、跳过中间产物——中间产物是下一站的输入 |
| 越权操作 | 域职责一句话写死 + 跨域意图移交对应域命令 | 在本域内顺手执行其他域的活——域边界即合同边界 |

### 12. 流程设计纪律

1. Stage 命名：从 1 起编号；禁从 0 起、禁小数编号（Stage 2.5）、禁字母后缀（Stage A/B）。
2. 话术零黑话：内部术语不得出现在用户可见话术里——话术用用户视角的自然语言。
3. 决策方法论用苏格拉底问句（问句迫使具体回答）；模板空位用填空提示。
4. **模板字段与生产策略同批**：产物模板新增／变更字段，必须同批在该域方法文件中补对应生产步骤——无生产策略的字段＝永远空着，禁止入模板（教训：模板加四字段未补生产逻辑）。
5. 示例纪律：一个优秀完整示例胜过多个平庸示例；必须可套用、来自真实场景、注释讲"为什么"。
6. 每步须给**完成判定标准**——可判定的那句（正例：「输出能被下游直接消费」；反例：「已理解」「差不多了」）。要求度取强范式，把「做到什么程度才算完」写满。
7. 警惕**提前收尾冲动**——后续步骤在上下文里可见时，注意力会滑向「想做完」，当前步骤被提前收尾。防御顺序：先磨边界；边界磨不动、且观察到抢跑时，才拆分序列把后续步骤藏到别处。**藏只在真实上下文边界有效**（交接、下派 subagent）——同一上下文里的内联拆分什么也藏不住。

### 13. 引用纪律（skill 资产）

1. skill 资产内引用一律写 skill 根相对路径 + 节名（如 `references/outline-workflow.md`「草稿步」节）——运行时模型按 skill 根直接拼出完整路径，零推断；禁裸文件名。scripts 无节名概念，引用写路径；需指定入口时用 `scripts/xxx.js` 的 `functionName()` 形式。格式总表见[文字与命名标准](文字与命名标准.md) §4；指向仓库治理文档的写法亦见该节。
2. 深层资产互引不用 markdown 链接：链接目标按所在文件位置解析，与运行时按 skill 根解析是两套语义，混用必有一方错；`SKILL.md` 位于根，两种语义一致，可用链接。
3. 阶段文件头部两行声明：消费点（哪个 Stage 读、必读还是按需）／边界（与相邻文件的分工）**（两行为必含项；可另加补充行）**。
4. 禁互引式引用（"格式同上"）；不用 `@` 形式链接（强制加载目标文件，烧上下文）。

### 14. 内容主张规范（指针）

指令措辞力度三级以[文字与命名标准](文字与命名标准.md) §17 为准（已迁该件——本件只管 skill 形态与行为）。

### 15. skill 运行时规范

| 规则 | 内容 |
| --- | --- |
| 幂等性 | 重复调用同一 skill／命令，结果一致——不因重复执行产生副作用或破坏已有产物 |
| 副作用声明 | 域工作流必须声明：写哪些文件／目录、调哪些外部服务、有无不可逆操作 |
| 脚本契约 | 超时、依赖前置、降级、限速、脚本文档头——见[运行环境标准](运行环境标准.md) §4／§5 |
| 用户确认 | 写文件／调外部服务／删数据等有副作用的操作，中途暂停等待用户确认后才执行 |
| 错误返回 | 失败时输出：什么错了 + 为什么 + 用户能做什么（三要素），不静默失败、不吞错误 |

### 16. 评估闭环（裸跑→最小修正→堵借口→全量回归）

1. 裸跑：新能力先不带指令裸跑，记录失败选择与理由原话。
2. 最小修正：写最小指令修正，重跑通过。
3. 堵借口并全量回归：把过程中新出现的合理化借口堵回指令，再测——修改指令后必须回归全部已通过场景（防修一处坏三处），不得只测修改相关场景。
4. 域上线验收清单与真机人工试跑是否必跑按[施工机制](../specs/施工机制.md) §二 的「真机人工试跑」条；改 skill 资产后必跑（做法见同条）。

### 17. 内容规范矩阵（按文件类别——同类文件同类内容）

> 矩阵是路由层：每类文件的完整模板与细则在「结构以何为准」列所指处，本表管分类全覆盖与速查；**具体行优先于泛类行**。风格依据如实分三类标注：宿主与生态权威（Agent Skills 开放规范）、语言业界权威（PEP 8／PEP 257、Google Shell Style Guide）、仓库内部标准（[文字与命名标准](文字与命名标准.md)）。

| 文件类别 | 结构／内容以何为准 | 头部规范 | 风格依据 | 脚本检查 |

## 二、正例与反例

- ✅ frontmatter 五键齐全且 `name` 与目录同名（`name: example-skill` ↔ `skills/example-skill/`）。
- ✅ description 三段式（示例）：「Example 能力名：某能力的名词化描述。触发方式：仅 /example-skill 显式调用；自然语言提及不触发。范围限本 skill 覆盖的工作面，其余归 /another-skill。」
- ✅ 触发句 ＋ 调用控制键双轨齐备（文案层 + 机制层）。
- ✅ 产物模板三要素齐备（字段定义表 + 示例行 + 约束节）；模板新增字段的同批补生产策略。
- ✅ 域外请求（如「把这个 CSV 按销售额排序」）→ 不触发任何套件内 skill（无显式调用，域外休眠生效）。
- ✅ 本域内识别到另一域意图 → 写入文件当前进度后移交 `/{skill 名}`。
- ✅ 问句标模态：「你想从哪个平台发？（选项列表）」／「有什么绝对不写的？（对话式）」。
- ✗ description 写工作流摘要（agent 照摘要走捷径——两次评审只做一次的事故）。
- ✗ description 写「或上述任一话题的自然语言可触发」（模糊触发句——多个 skill 同属一个工作面，自然语言互抢误触发）。
- ✗ 只在 description 写「自然语言提及不触发」而不加调用控制键（只有文案层、缺机制层）。
- ✗ 在本 skill 内直接调用另一 skill 的流程（域间禁互调，域边界即合同边界）。
- ✗ 阶段确认点未确认就产出下一阶段实质内容（如规格门未过就产出后续阶段实体内容）。
- ✗ 一个问句混两种模态（「选平台 + 顺便说说方向」——须拆两问）；同一屏并列不同模态问句（须分模态批）。
- ✗ 未建域／未建阶段敲入命令后模拟产出占位内容（须如实告知未建设）。
- ✗ 靠对话记忆判定续跑点（须按文件证据——文件账本律）。
- ✗ `SKILL.md` 内复制 workflow 的 Stage 表（同一内容两份维护）；references 之间互相链接成链（违反一层深）。
- ✗ 指令写「必须优先写入文件」（力度词叠加，模型无法判定是硬约束还是启发式）。
