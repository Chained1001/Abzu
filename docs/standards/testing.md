# 守卫与验收规范（Abzu）

> 版本：v0.1（沿革见 CHANGELOG 与 git 历史）
> 定位：**守卫（机检轨）与域上线验收（人判轨）**的单点权威——哪道闸管什么、何时必须跑、一域上线要看哪几条、真机走查怎么做与记在哪、以及尚未闭合的守卫缺口。
> 依据：宪法 §0（验证与常用命令）／§2（脚本做确定性、AI 做语义）／§3（开发节奏与审计深度）＋仓库既有守卫实现（`scripts/check.sh` 六段、`scripts/check_content.py`、`scripts/check_spec_assertions.py`）。

---

## 一、守卫全景

### 1.1 `check.sh` 六段（机检确定轨）

| 段 | 管什么 | 失败口径 |
| --- | --- | --- |
| [0] 真目录守卫 | `skills/abzu-*` 是否被安装器符号链接化；`.agents/skills`／`skills-lock.json` 是否存在 | 置 `fail=1`（分发事故的机械拦截） |
| [1] 六壳 validate | `agentskills validate` 逐壳校验 frontmatter 与 description | 工具缺失或校验不过即 `fail=1` |
| [2] lint | markdownlint-cli2 全仓 `.md`（`--staged` 时收窄为暂存区 .md） | 违例即 `fail=1` |
| [3] 内容轨 | 引用闭合（治理文档相对链接与 skill 资产路径引用须实存）＋加粗密度＋TOC 存在性＋`SKILL.md` 行数＋CHANGELOG 条目限长 | `check_content.py` 退出 1 即 `fail=1` |
| [4] 规格静态自检 | 对在制规格跑静态阶段（见 1.3） | 「计数不符」置该段退出 1；「基线漂移」「自噬预警」只呈报 |
| [5] 脚本语法 | 逐 `skills/abzu-*/scripts/*.js` 跑 `node --check` | 任一不过即 `fail=1` |

退出码：全绿 `0`；任一段置红 `1`（末尾统一打印「检查未全绿，禁止提交」）。

### 1.2 预验器三态（动态阶段）

`scripts/check_spec_assertions.py` 从规格「验收标准」节提取命令断言，白名单只读执行，逐条按三态呈报：可审计（执行并打印退出码与输出摘要）／不可审计（命令形态本身无法只读审计，跳过并注明命中判据）／未跑成（取输出失败、打印时编码失败、超时——计入崩溃桶并追证据不完整警示行）。

摘要行恒为 `== 共 N 条：执行 X｜跳过 Y｜崩溃 Z ==`，且**三桶之和恒等于提取数**——和不等即工具缺陷，不得当作「差异可接受」。退出码恒 `0`（candidate 永不拦截：本工具只呈报）。

### 1.3 静态阶段四道检查（不执行规格内命令）

| 检查 | 报什么 | 阻断性 |
| --- | --- | --- |
| A 自噬预警 | 断言 token 被自家替换文本吞掉（呈报预测值与规格「到位」列的差） | 只呈报 |
| B 计数重算 | 规格内 `N 字符`／`N 行` 声称与实测的差（分「计数不符」与「基线漂移」两档） | 「计数不符」阻断；「基线漂移」只呈报 |
| C `[A]` 逐字落实 | `[A]` 项「替换为」侧文本是否逐字落在目标件（成对条目与多行形态） | 只呈报 |
| D 规格写作四类 | 嵌套反引号／代码跨度边缘空格／加粗引导行紧跟列表／规格内可解析相对链接 | 只呈报 |

### 1.4 何时必须跑

- 改任何文件后：`bash scripts/check.sh` 必须全绿（pre-commit hook 自动执行，宪法 §0）。
- 改 skill 资产后：在全绿基础上**真机走一遍该域主流程**，＋对照 §二 该域清单逐条核对（做法见 §三）。
- 非平凡改动收尾：另跑 `python scripts/check_spec_assertions.py --verify <规格路径>` 做改动面、过程产物三件、施工记录表结构三项比对（该模式不进 `check.sh` 门禁，见该脚本头注）。
- 约束：守卫零外部依赖、不跑 LLM、不联网（宪法 §5 反模式 #5／§6 不做清单）。

## 二、域上线验收清单

> 定位：一域上线前的人判验收基准——每条为走查者需判断的要点，不设数值断言。[机检] 型断言（产物格式契约）不在此列：它们落 [file-conventions.md](file-conventions.md) §五.3 与各域 `references/` 的产物格式节，由守卫／脚本机检；本节只保留会话行为型要点与指向。
> 粒度：一域 3–5 条；未建域的条目**预立法，随首批实例校准**（内容待该域建设时补）。
> 断言写法：条目写行为（触发形态／门控停靠／交互模态／不越阶段），产物名只在设计真源已定格时写入——未定格域用类别词（正例：大纲域产物名出自已定格的设计真源；反例：write／volume／style 域无真源，故用类别词）。真源变更时同批更新清单，不得只改清单（宪法 §1.5）。
> 判据来源：各域设计真源 ＋ 会话行为型断言四类（上述四类；来源件已退役收编，沿革见 CHANGELOG）。

### 2.1 扫榜调研域（`abzu-scan`；已建成·封存）

- 仅显式调用 `/abzu-scan` 进入；自然语言提及不触发（描述边界生效）。
- 空目录判定为全新扫榜、加载域工作流；非空目录按已有产物定位续跑点。
- 数据来源三级优先如实执行（脚本采集 → 用户提供 → 内置知识），走降级路径时明确标注「未实时校验」。
- 平台调性判断合理（男频审美 ≠ 女频），题材洞察逐条有榜单证据支撑。
- 机检指针（脚本路径可检）：起点榜走 **SSR 脚本采集**（`skills/abzu-scan/scripts/qidian-rank-scraper.js`，不需 Chrome）；分析阶段的确定性提取由 `skills/abzu-scan/scripts/scan-analyze.js` 承担，**未手写内联解析脚本**；同方向样本 <15 时可行性强制降「中」并写明先验证。产物格式契约见 [file-conventions.md](file-conventions.md) §五.3。

### 2.2 拆书分析域（`abzu-analyze`；已建成·封存）

- 仅显式调用 `/abzu-analyze` 进入；无 `拆书/` 目录判定为全新拆书。
- 两个停靠点各停一次（黄金三章快速预览后、爆款机制后），等作者确认才推进。
- 结构块判读为戏剧循环块（含缺口/加压/转折/兑现/新阅读债要素，或如实标注缺失），非逐章流水账。
- 爆款机制为四层解释（表层表现/叙事机制/读者心理/可迁移原则），无「节奏好」「人设讨喜」式空泛结论。
- 机检指针（产物树可检）：默认模式**无逐章语义产物**（语义分析文件仅 4 份 md，不存在逐章一文件的分析产物）；`拆书/{书名}/原文/原文.txt` 备份存在；`选题决策.md`「参考候选」字段值后追加〔已拆文验证 YYYYMMDD〕标注、其余字段与终裁记录未动。后两项产物契约见 [file-conventions.md](file-conventions.md) §五.3。

### 2.3 大纲域（`abzu-outline`；占位·推倒重设中）

- 仅显式调用 `/abzu-outline` 进入；入口判定**按文件证据**（无 `创作进度.md` → 全新开书）。
- 规格收集按三段式推进（段一自由聊 → 段二回读默认 → 段三选项列表 ≤3 ＋对话式 ≤3），**终局与感情线不问**（规格字段准入律）。
- 规格门停等作者确认，**确认前不进入第二章**（门控＝阶段级硬停，与模块级停靠区分）。
- 交互模态标注与实况一致（封闭选择走选项列表、开放采集走对话式、过程性动作默认执行）。
- 不越阶段：门控确认前不产出后续阶段实质内容（目标产物存在但为空模板即合规）。

### 2.4 卷纲域（`abzu-volume`；占位）

- 仅显式调用 `/abzu-volume` 进入；敲入后如实告知建设状态（不模拟、不顶替、不产出占位内容）。
- 清单其余条目待该域建设时补（预立法，随首批实例校准）。

### 2.5 正文域（`abzu-write`；占位）

- 仅显式调用 `/abzu-write` 进入；敲入后如实告知建设状态。
- 清单其余条目待该域建设时补（预立法，随首批实例校准）。

### 2.6 文风域（`abzu-style`；占位）

- 仅显式调用 `/abzu-style` 进入；敲入后如实告知建设状态。
- 清单其余条目待该域建设时补（预立法，随首批实例校准）。

### 2.7 全域通用（任意域可判）

- 域外休眠：与网文创作无关的请求（如「把这个 CSV 按销售额排序」）不触发任何 abzu 技能、不套域框架；调出某域后转提域外请求，正常执行不套本套件框架。
- 未建域如实告知：敲未建设域命令，模型如实告知「该域尚未建设」，不模拟、不顶替、不产出占位内容。
- 域边界：本域内不顺手执行其他域的活；跨域意图移交对应域命令（域边界即合同边界）。

### 2.8 未建域待启用验收点（预立法，随首批实例校准）

## 三、真机走查做法与记录

做法（仓库内禁跑安装器，见 `check.sh` [0] 段守卫）：

1. 在目标项目目录装：`npx skills add Chained1001/Abzu -y`（离线备选：`cp -r skills/abzu-{域} ~/.claude/skills/abzu-{域}`）。
2. 新开会话（新文件夹），敲 `/abzu-{域}` 跑该域主流程；宿主会话须具备命令执行（Bash）工具与 Node.js 20+（涉脚本域）。
3. 逐条核对 §二 该域清单，＋§一 的守卫全绿结果。

记录约定：

- 走查记录**落当批规格**（日期 ＋ 域 ＋ 通过/失败 ＋ 备注）——不另建台账（宪法 §6「不做全域欠账清单」条）。
- 条目失效（行为有意变更）：同批更新规格与本清单，禁止只改清单（宪法 §1.5 失败先判因）。
- 无当批规格时（如日常使用中发现问题）记入下一次改动的规格；存量真机走查欠账（031 批大纲域走查、029 批拆书域真测）列在《产品与技术总纲》§五 构想池，随新版走查销账。
- **每域最低测试要求**：①`check.sh` 全绿 ②该域 §二 清单逐条走查通过 ③涉脚本域加沙盘验证（幂等／异常态）④真机走查欠账不得超过下一个域建成。
