# 产物契约标准

> 定位：约束**怎么定义** skill 产物契约——通用契约要素与写法；具体产物的契约（文件树、文件名、字段与状态值）由产品层契约件定义。
> 依据：旧仓《大纲阶段设计文档》§5.3 与旧仓《守卫与验收规范》§五.3 的产物格式脚本检查契约（来源件已随 rebuild 作废，条文逐条迁移并抽芯为通用要素）；业务实例已整块迁入 [`docs/product/书目录契约.md`](../product/书目录契约.md)，本件只留方法。

## 一、条文

### 1. 四类通用契约要素

每份产物契约必须定义四类要素，缺一即不合格：

| 要素 | 定义什么 | 脚本检查典型形态 |
| --- | --- | --- |
| 目录树声明 | 产物落在用户项目的哪个目录、各文件与目录的创建时机 | 目录／文件存在性断言 |
| 字段与状态值枚举 | 每个产物的关键字段、状态值的封闭枚举与流转顺序 | 字段非空断言、枚举断言 |
| 脚本检查点 | 每条契约由哪道检查关强制、当前状态（已实现／待建／人工判断） | 契约行对照守卫的清单表 |
| 跨域唯一接口 | 跨域衔接只经哪些写入文件、交接清单的最终形态 | 衔接清单的文件存在性断言 |

### 2. 通用纪律

1. 契约只收可由脚本或文件系统**确定性判定**的断言；语义质量类判定标准归人工判断清单（分工见[施工机制](../specs/施工机制.md) §四）。
2. 状态判定来自文件系统证据，不凭对话记忆——阶段确认点与中途暂停确认点须落产物状态行。
3. 用户项目产物**不进本仓库**；命名纪律见[文字与命名标准](文字与命名标准.md)。
4. 细则未定的契约点一律标「待设计」，随该产物所属域的建设批收尾。
5. 域间**禁互调**，跨域只经写入文件衔接：生产者只写入文件，消费者在自己域内定义如何查找与读取（细则归[skill资产标准](skill资产标准.md) §5）。
6. **每个产物产出后须拿模板做一次机械对照模板核对**——把产物与该产物**所属模板**逐段对照（节序、必备字段、状态值枚举）；对照模板核对结论落产物状态行或当批逐条确认，**不凭记忆声称「已对照模板核对」**。出处＝`archive/099` §八 4 的欠账升为通则；同族见 `archive/100` §七 逐条确认。

### 3. 本项目实例

本项目的产物契约见 [`docs/product/书目录契约.md`](../product/书目录契约.md)——用户项目文件树、字段与状态值、格式脚本检查契约与跨域交接清单；同层的域设计见 [`docs/product/`](../product/) 下各域设计件（目录计算方式见[文字与命名标准](文字与命名标准.md) §1）。

### 4. 维护

- 具体产物的契约改动落产品层契约件；本件只在通用要素与纪律变更时改。
- 新增通用要素或纪律：先在产品层契约件出现实例，再同步更新本件 §1／§2；本条对「新增内容」生效，存量要素不回溯追责。

## 二、正例与反例

- ✅ 契约件四要素齐备：目录树 ＋ 字段与状态值枚举 ＋ 脚本检查点 ＋ 跨域唯一接口。
- ✅ 状态值写成封闭枚举并标出流转顺序（如 待建 → 建设中 → 已就绪）。
- ✅ 契约点标「待设计」并写明随哪个域的建设批收尾。
- ✅ 用户项目产物的名字在契约件里定义一次（本仓不建副本、不在多处维护）。
- ✗ 契约只写「产物大致有哪些字段」而不给封闭枚举（无法脚本检查）。
- ✗ 把语义质量判定标准（如文笔是否通顺）写成脚本检查契约点。
- ✗ 靠对话记忆判定续跑阶段（状态判定须来自文件证据——文件账本律）。
- ✗ 域间互相调用完成衔接（跨域只经写入文件）。
