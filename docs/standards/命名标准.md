# 命名标准

Abzu/
├── AGENTS.md                  # 入口与路由：红线、去哪读、常用命令
├── README.md                  # 门面：安装、使用、文档索引
├── CHANGELOG.md               # 变更日志（Keep a Changelog 格式）

├── .gitattributes             # 行尾归一（* text=auto eol=lf）
├── .gitignore
├── .markdownlint-cli2.jsonc   # lint 配置
├── docs/
│   ├── standards/             # 本目录：11 份标准，中文命名 {主题}标准.md
│   ├── product/               # 产品层：共享件在根（产品定义、架构设计、契约、术语表、验收场景），域件在子文件夹（中文命名）
│   │   ├── outline/           # 大纲域件
│   │   ├── volume/            # 卷纲域件
│   │   └── write/             # 正文域件

│   └── abzu-outline/          # 首个域——阶段一资产已建（088）
│       ├── SKILL.md           # 域壳（入口）
│       ├── references/        # 已建（阶段一资产）
│       ├── assets/            # 已建（阶段一资产）
│       └── scripts/           # 随各批落地
└── scripts/                   # 开发守卫与工具（仓库级）
    ├── check.sh
    ├── check_spec.py          # 规格静态自检（check.sh [4] 段调用）
    ├── check_content.py
    ├── patch_file.py          # 修订工具（四段式：校验 → 形态闸 → 写盘 → 回读）

**现状与预留**：`skills/` 已建（`abzu-outline`——**阶段一资产已落**：工作流／阶段文件／情绪词表／产物模板）；`.claude-plugin/`（分发清单）尚未建立。下表 skill 资产类目与插件清单类目为预留——规则先行，首个域落地时按本表命名。**「预留」与「预立法」是两类「尚未」**：预留＝该类目／位置**尚未启用**（「启用前不得新增实例」，触发为**事件**：T1 触发／首个发布批／user-invoked 层启用，到点**启用该位置**）；预立法＝条文有效但**缺实例来校准**（「随首批实例校准」，触发为**首个实例出现**，到点**校准并删标记**）——两者判据／对象／触发三面不同，**不得互推**。**同一类目可两态并存**——如本表「开发测试」行：**类目预留**（`scripts/` 下 `test-*` 类目尚未启用，**见该行关联实例判据**）＋ **条文预立法**（该类目下无实例可校准）——并存时**各按所属面判**，互不取消。

### 2. 命名总表

| 文件类型 | 命名规则 | 示例 | 位置 |
| --- | --- | --- | --- |
| 域名 | `{skill 名}`：英文 kebab-case（Agent Skills 规范硬约束），与 skill 目录同名；本项目域名清单见[架构设计](../product/架构设计.md) 域清单 | — | `skills/` |
| skill 壳 | `SKILL.md`（固定名，每 skill（域）一份） | — | `skills/{skill 名}/` |
| 域工作流 | `{域}-workflow.md` | `example-workflow.md` | `skills/{skill 名}/references/` |
| 阶段文件 | `{域}-stage-{阶段名}.md` | `example-stage-research.md` | 同上 |
| 域内参考文件 | `{域}-{主题}.md`，主题描述性命名 | `example-scaffold-spec.md` | 同上 |
| 产物模板 | `{域}-{产物名}-template.md`；默认独立成文件，内嵌仅限 ≤10 行微型模板（按 markdown 源码行数计） | `example-artifact-template.md` | **`skills/{skill 名}/assets/`** |
| 运行时脚本 | `{动词}-{对象}.{sh,py,js}` | `init-project.js` | `skills/{skill 名}/scripts/`（预留） |
| 共享库 | `{名词}-utils`（被同 skill 脚本引用，不直接执行） | `format-utils.js` | 同上（预留） |
| 一键入口 | `check.sh`（固定名） | — | 仓库根 `scripts/` |
| 开发守卫 | `check-{对象}.{sh,py,js}` | `check_content.py` | `scripts/`（仓库级） |
| 开发测试 | `test-{对象}.{sh,py,js}` | 无实例，预留类目（预立法，随首批实例校准；**关联实例判据：`ls scripts/test-*` 命中 ≥1**） | `scripts/`（仓库级） |
| 仓级开发工具 | `{动词}-{对象}.{sh,py,js}`（`.py` 按表注用 snake_case） | `patch_file.py` | `scripts/`（仓库级） |
| 规格 | `{序号NNN}-{YYYY-MM-DD}-{中文主题}.md`；序号三位递增、永不复用 | `059-2026-09-12-填充标准.md` | `docs/specs/`；验收全部通过后移入 `docs/specs/archive/` |
| 标准 | `{主题}标准.md`，中文命名，主题短而自描述 | `命名标准.md`、`产物契约标准.md` | `docs/standards/` |
| 协作机制 | `施工机制.md`（固定名） | — | `docs/specs/` |
| 产品文档 | `{主题}.md` 中文命名 | `产品定义.md`、`术语表.md` | `docs/product/`（共享件在根；域件在 `outline/`／`volume/`／`write/` 子文件夹） |
| 根目录治理文件 | 固定名（生态惯例） | `AGENTS.md`、`README.md`、`CHANGELOG.md`、`LICENSE` | 仓库根 |
| 根目录工程配置 | 固定名（工具惯例） | `.gitignore`、`.gitattributes`、`.markdownlint-cli2.jsonc` | 仓库根 |
| 插件清单（预留） | `.claude-plugin/marketplace.json`（工具惯例固定名） | — | 仓库根（预留） |
| 命令薄壳（预留） | `{skill 名}-{路由键}.md`，单行内容写调用行 `{skill 名} {路由键}`；启用前不得新增实例 | — | `.claude/commands/`（预留） |
| agent 文件（预留） | `{skill 名}-{角色名}.md`；T1 触发后启用（触发档位定义见 `docs/product/架构设计.md` §四）——启用前不得新增实例 | — | `.claude/agents/`（预留） |
| 用户项目产物 | 中文命名，不进本仓库——细则由该项目产品层定义 | 产物名由产品层契约件定义 | 用户工作目录 |

表注（扩展名口径）：`.py` 文件用 snake_case（下划线，Python 惯例），`.sh`／`.js` 用 kebab-case（连字符）——命名总表运行时脚本、开发守卫、开发测试、仓级开发工具四行的 `.py` 后缀以本表注为准（旧仓立法时的虚拟示例 `check-frontmatter.py` 未与实件对齐，实件对照为 `check_content.py`）。

表注（域前缀适用判据）：`{域}-` 前缀适用于主题名相对域、需消歧的 skill 资产（装入用户机器、被路由键检索）；名字已全局自描述的治理文档（`docs/` 下全部文件，如 `命名标准.md`）不加前缀——位置由文件夹表达，名字表达内容。

表注（规格行的扩展口径）：同批附件（随主规格产出的并列文档）沿用主规格序号、以语义后缀区分，不另编序号；作废批（规格前提失效未施工）同移入 `docs/specs/archive/`，文件名追加 `-已作废` 后缀并在正文头注标废。

### 3. 双语命名纪律

- 英文 kebab-case：skill 目录、references、脚本、守卫——开发者可见的一切；规格主题部分用中文（作者阅读的治理记录）。
- 中文名：产品文档（`docs/product/{主题}.md`（共享件）或 `docs/product/{域}/{主题}.md`（域件））与用户项目内的产物文件——前者由本仓库维护，后者由 skill 运行时创建、不进本仓库。
- 路径分隔符一律正斜杠（跨平台；反斜杠在 Unix 上失效）。

### 4. 文件名安全

文件名禁用 Windows 保留字符 `\/:*?"<>|`，禁 emoji，不用空格。仓库内文件一律英文 kebab-case 或本表规定的中文名（标准件、规格主题、产品文档、用户项目产物），同样禁符号。

### 5. 跨文件引用格式

| 场景 | 格式 | 示例 |
| --- | --- | --- |
| 同目录文件（仓库治理文档） | Markdown 链接 | `[命名标准.md](命名标准.md)` |
| 跨目录文件（仓库治理文档） | Markdown 链接（含相对路径） | `[AGENTS.md](../../AGENTS.md)` |
| skill 资产内引用（无论同目录跨目录） | 禁链接与裸文件名，用 skill 根相对路径文字 + 节名（**指向仓库治理文档时按本表末行**） | `references/outline-workflow.md`「草稿步」节 |
| 文件名提及（无需跳转） | 行内代码 | `CHANGELOG.md` |
| 指定小节（治理文档） | 文件名 + 节名 | `AGENTS.md`「红线」节 |
| 指向仓库治理文档（**部署副本内不存在**） | **维护出处：`{件名}` §N；运行时不必加载** | **维护出处：`书目录契约` §1；运行时不必加载** |

规则（按资产域分区）：skill 运行时资产（`references/`、**`assets/`**、`scripts/`）禁跨目录链接——部署副本会断链，必须自包含；仓库治理文档（根目录、`docs/`）允许跨目录 Markdown 链接——它们在编辑器与 GitHub 中阅读，链接是可用性加分。references 之间不互相链接（一层深纪律，见 [skill形态标准](skill形态标准.md)）。

**运行时资产引用治理文档**：skill 资产内**不得裸指向**仓库治理文档（**无标注地指向**）（`docs/` 下各件）——部署副本内不存在。凡**模型执行时必须知道**的事实（命令名、字段名、阈值），一律**自包含**写在资产内；凡**仅供维护追溯**的出处，写「**维护出处：{件名} §N**」并**明示「运行时不必加载」**。（**批次号型包外标记**——如「随某批未建」——**不属本条**；该类按各批上线时删除的到期制处理）

### 6. 本标准的维护

- 新增文件类型：先过 `AGENTS.md`「不做清单」与内生必要性自问，裁定通过后回写本表（命名规则 + 示例 + 位置）。
- 修改命名规则：先全仓 grep 涟漪面（改名／移动文件须同步更新全部引用）。
- 退役文件／概念：从表中删除行，退役记录进 `CHANGELOG.md`。
- 对齐类改动先审标准后审文件：对齐批第一步核对标准条文自身的实文依据，再审文件符合度。

## 二、正例与反例

- ✅ `skills/example-skill/references/example-skill-workflow.md`——英文 kebab-case、描述性主题名。
- ✅ `docs/standards/命名标准.md`——治理文档中文命名、无域前缀（位置由文件夹表达）。
- ✅ `docs/specs/059-2026-09-12-填充标准.md`——序号三位递增 + ISO 日期 + 中文主题。
- ✅ `docs/product/产品定义.md`——产品文档中文名，位置由文件夹表达。
- ✅ `check_content.py`——`.py` 用 snake_case（表注口径）。
- ✗ `skills/example-skill/references/工作流.md`——skill 资产用中文名，路由键检索不到。
- ✗ `docs/standards/命名规范.md`——标准件后缀不统一（同一概念两种叫法，发现第二种当次收口）。
- ✗ `tools/check_content.py`——守卫落在 `scripts/` 之外，目录即分类。
- ✗ `docs/specs/check-frontmatter.py`——守卫不进规格目录，规格目录只放规格与协作机制。
- ✗ 路径写 `docs\standards\命名标准.md`——反斜杠在 Unix 上失效，一律正斜杠。
