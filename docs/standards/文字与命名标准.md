### 1. 目录结构与命名总表

```text
Abzu/
├── AGENTS.md                  # 入口与路由：红线、路由、常用命令、模型执行通用准则
├── README.md                  # 门面：安装、使用、文档索引
├── CHANGELOG.md               # 变更日志（Keep a Changelog 格式）
├── docs/
│   ├── standards/             # 标准件：skill资产／文字与命名／产物契约／运行环境（热）＋版本与分发（冷，首发前不读）
│   ├── product/               # 产品层：共享件在根，域件在子文件夹（中文命名）
│   └── specs/                 # 施工机制.md＋守卫缺口清单.md（冷）＋在制规格；验收通过后移入 archive/
│       └── archive/
├── skills/                    # skill 资产（运行时：域壳与域内资产）
└── scripts/                   # 开发守卫与工具（仓库级）
```

### 2. 双语命名纪律

- 英文 kebab-case：skill 目录、references、脚本、守卫——开发者可见的一切；规格主题部分用中文（作者阅读的治理记录）。
- 中文名：产品文档与用户项目内的产物文件。
- 路径分隔符一律正斜杠（反斜杠在 Unix 上失效）。

### 3. 文件名安全

文件名禁用 Windows 保留字符 `\/:*?"<>|`，禁 emoji，不用空格；仓库内文件一律英文 kebab-case 或本表规定的中文名，同样禁符号。

### 4. 跨文件引用格式

| 场景 | 格式 | 示例 |
| --- | --- | --- |
| 同目录文件（仓库治理文档） | Markdown 链接 | `[命名标准.md](命名标准.md)` |
| 跨目录文件（仓库治理文档） | Markdown 链接（含相对路径） | `[AGENTS.md](../../AGENTS.md)` |
| skill 资产内引用（无论同目录跨目录） | 禁链接与裸文件名，用 skill 根相对路径文字 + 节名（**指向仓库治理文档时按本表末行**） | `references/outline-workflow.md`「草稿步」节 |
| 文件名提及（无需跳转） | 行内代码 | `CHANGELOG.md` |
| 指定小节（治理文档） | 文件名 + 节名 | `AGENTS.md`「红线」节 |
| 指向仓库治理文档（**部署副本内不存在**） | **维护出处：`{件名}` §N；运行时不必加载** | **维护出处：`书目录契约` §1；运行时不必加载** |

规则：skill 运行时资产（`references/`、`assets/`、`scripts/`）禁跨目录链接——部署副本会断链，必须自包含；仓库治理文档允许跨目录链接。references 之间不互相链接（一层深纪律，见[skill资产标准](skill资产标准.md) §13）。

**运行时资产引用治理文档**：skill 资产内不得无标注地指向仓库治理文档。凡**模型执行时必须知道**的事实（命令名、字段名、阈值）一律**自包含**写在资产内；仅供维护追溯的出处写「**维护出处：{件名} §N**」并明示「运行时不必加载」。（阶段指向型包外标记——如「随对应阶段批」——不属本条，按到期制处理；措辞统一用「随对应阶段批」。）

### 5. 用词规则

1. **一词一义**：同一概念全仓只用一个词；发现第二种叫法当次改齐（改一处，或把旧叫法登进 §6）。
2. **禁比喻借词**：不得借用实物、建筑、机械类比喻表达机制；机制叫什么，就写它做什么。
3. **禁中文单字缩写**：不得把单字当名词用（如「态」「面」单独成词）；须写全词。
4. **禁自造代号**：不得用自造简称指代检查项、流程或文件；编号是标签，引用处须复述它查什么。
5. **禁英文残留**：正文不得混用英文词（产品与生态固有名词、文件与命令名除外）；确无中文对应者，先入 §6 再统一替换。
6. **一句一事**：一句只写一件事；并列条件拆成短句。

### 9. 术语用法与治理词条

- 术语优先取既有通用词——预训练里已有的说法能免费招募先验；生造词须在同一处给出定义。每条 ＝ 中文名 + 一句话定义 + 英文对应；**例外**：平台标准词可径作词条名（如 `subagent`——宿主生态既定叫法），此时英文对应列与词条名同形。

### 10. 结构与排版规则

1. 标题仅用 H1–H3：全文唯一 H1 居首，小节从 `##` 起，逐级递进禁止跳级；更深的层次用列表表达。
2. 代码块标语言（`bash`／`json`／`yaml`／`markdown`，目录树用 `text`）；中文话术、模板示例的围栏不标语言。
3. 超 100 行文件头部放节目录——手动列表（`- 节名`），条目与 H2 标题逐字一致。
4. 单文件超过 300 行应考虑拆分（skill references 上限见[skill资产标准](skill资产标准.md) §9）。
5. 无序列表统一 `-`；子列表缩进以 markdownlint 实判为准。表格上下留空行；单元格内竖线用 `\|` 转义。段落之间空一行；文件结尾保留一个空行。
6. 不使用 HTML 注释与 HTML 标签（界标段除外——守卫定位用，见 §6）。条文分组用 `章.节[.条]` 前缀，脚本检查点表以该前缀引用。
7. 中英文之间加空格；中文与数字之间加空格；行内代码与全角标点邻接不加空格。全角标点与其他字符之间不加空格；标点不叠用；中文省略号用 `……`。
8. 引号三分：① 节名与需逐字复现的内容用「」；② 中文普通引语用直引号 `"`（本仓常态）；③ 代码与参数内的引号随语言惯例。

### 11. 符号允许清单

清单与状态列的**符号型**取值须出自本允许清单：`✅` 已就绪／已修入｜`🚧` 已立项未建设｜`🔴` 未修入或待处置｜`🔨` 校准中｜`⏳` 待讨论｜`➕` 开放集补充｜`⚠️` 风险或依据强度提示。

- 本允许清单只管**符号型**状态取值；文字型取值不受辖。产品文档可在其头部另设图例界定名单内符号的亚义——不得引入名单外符号，禁纯装饰性 emoji。
- 不属清单与状态列取值的符号不受辖：示例对照与命令输出样例中的正反例标记（`✅`／`✗`／`❌` 等）。

### 13. AI 友好写作

1. 术语一致：全文只用[术语表](../product/术语表.md)与本标准 §9 的叫法，发现第二种叫法当次收尾。
2. 示例优先于规则：教格式或风格必须给输入/输出对。
3. 指令用命令式语态（「读文件后再改」）。
4. 引用带节位置：`outline-workflow.md`「草稿步」节。
5. 禁模糊指代：不写「格式同上、参照上文」——分段读取时读者看不到"上下文"；带明确节位置的具体引用不受此限。
6. 禁时间敏感表述：不写「X 年 X 月后用 Y」；只写当前方法，版本沿革一律记 `CHANGELOG.md`。
7. 路径用正斜杠并用反引号包裹。
8. 加粗：单文件 `**` 数 ≤ 行数 ÷ 3（数值上限为保底做法）；定性规则优先——加粗仅用于红线、路径、数字、检查关四类，一段至多一处。计数计算方式＝`**` 标记出现次数；保底做法阈值只针对**叙事型文档**，以表格与编号条目为主要结构者（各标准件、产品层域设计、清单型文档）不计。
9. 箭头 `→` 仅用于流程映射与条件分支，禁作装饰。
10. **底座不写产品层的计数**：治理文档只写指向唯一出处的指针，不复述产品层会变的数字；确需引用时改写为「见 `X` §N」。
11. **引用须写到能唯一写入位置的那一级**：写 `X §N` 时须是该内容实际所在的那一级（`§一` 与 `§一.3` 混用会读到空节）；判定标准＝照该指针去读，必须直接读到内容。

### 14. 给 agent 读的文档

1. 指针：留在上下文里、指向别处材料并携带触发条件的那句话——`description`、`AGENTS.md` 里的指路行、`SKILL.md` 里的引用行都是它。决定 agent 何时去读的是**指针的措辞**；必需的目标配了弱措辞＝方差 bug，处置顺序是先磨措辞、磨不动才内联。指针做两件事：说清材料是什么、列出该触发的分支（反例：只写「详见标准件」而不写何时该去读）。
2. 两种负荷：新增任何文档或指针都花掉两种预算之一——context load（常载材料每轮烧 token 与注意力）与 cognitive load（人记住「有哪些文档、何时用哪份」的负担——花在需要人工判断处，其余处删掉）。
3. 下沉判定标准是**分支**：每个分支都要用的内联在文件内，只有部分分支会读的才沉下去；行数阈值只是保底做法信号。同一概念的规则、定义与注意放同一节；同一意思写两处（duplication）与碎在多处（scattering）是两种病，单一唯一出处律须同时覆盖这两维。
4. 修剪：环境也是唯一出处（配置、目录、`--help` 能查到的东西，复述＝缓存）；逐句找 no-op——模型默认就会照做的指令白花负荷；没有任何修剪纪律时，默认命运是陈旧层层沉积。

### 15. 禁令须配正向目标

1. 否定式反弹：以禁令驱动行为会把被禁行为拉进上下文并提高其可用度。条文首选正向写法，直接写要做的事（正例：「改文件前先读全文」；反例：只写「禁止删文件」）。
2. 禁令只在无法正向表达的硬护栏上保留，且须在同一处给出正向目标句。红线（`AGENTS.md` §一）、事故记录清单的「正确方式」列、`AGENTS.md` §四 不做清单速查形态，均视为已履行本节义务。
3. 存量条文按本节校正：「禁止 X」式条文须补正向目标句；补不出的说明是硬护栏，须同处给出理由与红旗自检。

### 16. 产品层文档范式

适用于 `docs/product/` 杄件与 `README.md` 的域条目。

1. 定义性约束：一句话写出该域区别于显然默认做法的那一件事，写成陈述句（反例：「关键点：本域很重要」式标签不携带信息）。
2. 跑通信号：作者不打开 skill 内部即可自查的信号；不得拿内部合规检查（lint 全绿、断言通过）冒充。
3. 角色定位：一句话标出该文档属链步、一次性配置、周期性，还是随时可用。
4. 常见问题：须来自真实来源，数量忠于证据；宁可少写也不注水。

### 17. 维护

- 新增文件类型：先过 `AGENTS.md`「不做清单」与内生必要性自问，裁定通过后回写 §1 总表。修改命名规则：先全仓 grep 涉及面。退役文件／概念：从表中删除行，退役记录进 `CHANGELOG.md`。
- 新术语：先查本标准 §9；没有 → 定义后同步更新该节，再在其他文档使用。改叫法：全仓 grep 涉及面（grep 词须含概念近义词）。退役术语：从本标准删除行。
- 违反本规范视同文档 bug：改文件当批顺手修。lint 体检：`npx markdownlint-cli2 "**/*.md"`。
- 治理文档条文不写批次叙事与裁定标记（定为规则与例外授权依据除外），沿革记 `CHANGELOG` 与 git 历史。
- 对齐类改动先审标准后审文件：对齐批第一步核对标准条文自身的实文依据，再审文件符合度。
