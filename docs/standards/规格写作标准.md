# 规格写作标准

> 定位：规格三要素、自审清单、自由度标记、断言写法。

## 一、条文

### 1. 何时需要规格（判定表）

| 变更类型 | 需要规格 |
| --- | --- |
| 新增／删除／重命名任何文件 | ✅ |
| 跨文件改动（≥2 文件） | ✅ |
| 新增或修改规范条目 | ✅ |
| 架构／流程／规则变更 | ✅ |
| 外审报告或外部参考研究驱动的修改 | ✅（报告转为规格附件，逐条标注采纳／拒绝及理由——**禁止拿到外审直接改文件**） |
| 单文件错别字／格式修正（<5 行） | ❌ 直接做（亮线阈值防「感觉很小」式逃逸；超限纯错别字走轻规格成本分钟级） |
| 复盘驱动的治理微调（≤3 文件，当批 `CHANGELOG` 留痕不计入；作者会话内逐项确认） | ❌ 免规格直接做（豁免条件缺一不可；与其他行命中时——若同时命中 `施工机制` §二 分流表「重」行的触发条件，以「重」为准；否则以本行为准（具体优于一般）） |

非平凡改动流程：探索现状 → 写规格存 `docs/specs/` → 作者确认 → 实施 → 验收 → 请求提交（协作角色与审查工序归[施工机制](../specs/施工机制.md)）。

### 2. 规格三要素（缺一不成规格）

1. 现状事实（锚点）：现文的行号、原文、计数——**必须现场 grep／read 确认，不得沿用对话记忆**。
2. 文件级改动清单：逐文件、逐条的改动项与依据／裁定对齐，无漏项。
3. 验收标准：每条断言可机检或可走查，且与改动清单不互斥。

规格命名（`{序号NNN}-{YYYY-MM-DD}-{中文主题}.md`）与归档位置见[命名标准](命名标准.md) §2。

### 3. 自由度标记与核验深度

| 标记 | 含义 |
| --- | --- |
| `[A]` | 逐字执行——替换文本与规格给出一字不差，一字之差即偏差 |
| `[B]` | 按方向自定实现——不得改变行为 |
| `[C]` | 按验收标准执行 |

核验深度分级（编号越大核得越深）：D0 模式扫描（残留词／格式／路径闭合，最低基线）｜D1 逐字核验（与规格文本 diff 为零）｜D2 通读核验（语义通顺、行为不变）。映射：`[A]` 级改动 → D1；`[B]` 级 → D2；`[C]` 级 → 按验收标准核验（不占深度级）；存量／知识文件最低 D0。扫描只能证伪不能证真——零命中仅表示"已知模式无违例"；扫出问题即升级该文件深度。

### 4. 规格自审（四条；各规格的「规格自审」节按此写）

与 `施工机制` §二 同源，本件不复制细则（单一真源）。

1. 锚点现场核过——规格引用的行号、原文、计数逐条现场 `grep`／read 确认，不凭对话记忆；射程含首现术语（自带释义或指向[术语表](../product/术语表.md)）与规格内「某文档 §N」引用的逐个现场核对。
2. 断言实跑过——每条验收断言写进规格前实际跑一遍（计数用 `wc -l`／`grep -c` 实数，禁目视估计），并核对断言 token 与自家「替换为」侧文本不互斥；审改项对照表一行一项不合并（合并后无法逐项核验）；含零命中目标的替换文本须用阿拉伯数字回避汉字自噬。
3. 禁止事项写明——逐条列出本批禁止触碰的文件与禁止动作（联网、采集、改动面外文件）。
4. **范围与期望同源**——断言若建立在某段范围（文件行段／节／清单）之上，其期望值须由**该范围**实跑得出（范围与期望取自不同侧即失守）。实例：088 成稿审查 F-02——迁移范围写 `:14`–`:52`（不含父标题 `:12`），而期望 4 是按**含** `:12` 的源件算的，施工后必红。

附加项：改动项与依据／裁定逐项对齐无漏项（清单完备）、规格内部与外部权威无冲突且时序依赖显式声明（矛盾检查）、**禁改面与改动面须逐件对账**——禁改面列举的每一件若同时出现在改动清单，必须在禁改面明示豁免（实例：076 批初稿的禁改面只豁免 `施工机制.md`，而改动清单另有 `规格写作标准.md` 等件，两次实撞后方立此条）；域建设批另加涟漪清单——grep 域上线验收清单本域词 ＋ 列全该域触及的设计文档节。

### 5. 断言写法（规格编写协议，硬约束）

1. 断言预验强制：规格送成稿审查前，验收断言的每条命令必须**实际跑一遍**（`wc -l`／`grep -c` 类计数实跑），预验摘要（含跳过项）附入规格自审——未预验的断言标注「未预验」并交成稿审查重点核验。
2. 节号复核：写「某文档 §N」引用时现场 grep 该节标题半句核对——锚点节号失准多发于凭印象。
3. 计数必须实跑：规格中任何数字（行数／条数／命中数／改动项数）必须用 `wc -l`／`grep -c` 实数，**禁止目视估计**（旧仓教训：五轮审查计数错 ≥5 发，全部是 AI 用眼睛做算术）；**行数断言的计数口径为换行符出现次数**、与 `wc -l` 一致，**禁**依赖 `splitlines()`（实例：076 F2 把行计数改在 `_read_target()` 返回的文本上按 `'\n'` 为唯一分隔切行——`splitlines()` 会在垂直制表符／换页符／NEL／行分隔符处额外切行，同一件会多算，窄域复核已实证）。
4. **断言与替换文本不得互斥**：验收断言的 grep token 写完后必须在替换文本中确认两件事——①token 在替换文本中存在 ②token 不会因替换文本自身的内容被意外命中（如替换文本含「其余七组」，grep「七组」又命中）。**汉字数字回避**：替换文本中与零命中目标同字面的汉字数字改用阿拉伯数字。旧仓三次连击教训：断言吞替换文本、断言对象与计数错、零命中吞立例句字样。
5. **替换范围显式限定**：「整段替换」「整行替换」指令必须写明「只替换 XX 括注和 XX 句，其余原样保留」——不限定则 `[A]` 级施工会删掉不该删的既有内容（旧仓教训：差点删掉六项产物要素，两轮审查才拦住）；修订既有条文时，判据是**新文本是否使旧文本失效**——失效即**改写**而非追加（实例：076 F6 的归档件纪律句修前那句「唯一例外是移入时的作废头注」（该件现文已改为「两处例外」），若只在句末追加第二例外，两句自相抵——窄域复核 N-5 实撞）。
6. 断言对象实存：断言引用的文件、节、字段须在施工前实存，或由本批改动清单显式新增。
7. 过程产物两项对照：改动清单末须对照过程产物两项（§6），防验收互斥。
8. **计数式断言须限定扫描面**：以 `grep -c`／`wc -l` 计数的断言，须写明扫描面（哪件、哪节、是否围栏感知）——禁凭「行首特征 ＋ 关键词」扫全件。**计数口径（计行／计出现次数／计文件数）亦须逐条标注**——同一命令在不同口径下差异极大（`grep -c` 计行、`grep -o … | wc -l` 计出现次数、`grep -l … | wc -l` 计文件数），不标注则复核时无法判定期望是否同源。反例：066 断言 4 初版按「行首竖线 ＋ 含状态词」扫全件，被正文规则行多计 1（19 ≠ 18）。
9. **一条断言只配一条命令与一个期望值**：一条断言写多条命令时，须拆成多条、每条自带期望（`期望 1` 式），**禁写**「一条三命令 ＋ 期望 1／2／91」这类多值聚合句。理由：零命中核对的期望取数在数字不唯一时保守跳过（`check_spec.py` 的 G15 口径），而按序配对依赖「数字序＝命令序」——**写反即静默误配**。反例（`067`:100 起的实测形态）：三命令断言写「期望 1／0／0」，子句多值使该断言的零命中核对长期未判。
10. **等价性断言的比对语料须排除本批全部改动件**：以「输出逐字节不变」作等价性断言时，比对语料须**排除本批改动的每一件**——否则被测变量不止一个（工具 ＋ 被批改的文本），文本一变输出即变，断言必假红。实例：073 批的语料含本批改动的 `CHANGELOG.md`（P0 实见）；075 批规格初稿的语料含本批改动的三件 `.md`，第四件（`规格写作标准.md` 自身——本条即落该件）由成稿审查抓出，据律重冻语料。

11. **扫描类断言须排除本规格**：以 `grep -r`／`grep -rc` 扫全仓的断言，若其**命令文本自身**含被扫字面（如替换表里的旧词），须**按路径白名单枚举扫描面**（只列活件面所属路径——**此形态下归档与本规格天然不在面内**）；次选在管道内按**裸文件名子串**排除本规格（如 `grep -v "081-…"`；**此形态只排除本规格，归档件仍在扫描面内、须另行排除**）——**禁用首路径前缀式**（`^docs/` 之类形态敏感，反斜杠环境静默失效）。否则该断言恒假——本规格既是被扫面又是扫描者。**过滤归档件不得依赖首路径前缀格式**（部分环境输出反斜杠路径，前缀式过滤会静默失效）。实例：080 断言 10、081 断言 1／3a／4c。
12. **断言目标件须写具体文件路径**：断言命令里的目标件须写到具体文件（如 `docs/standards/术语标准.md`），不得只写件数聚合（如「8 件」）——检查 A 的 hit 门按「目标件出现在改动行」判，聚合写法使该断言的零命中核对静默失守（081 实例：4 条断言靠人工实跑兜住）。
13. **范围与期望同源**：断言若建立在某段范围（文件行段／节／清单）之上，期望值须由**该范围**实跑得出——范围与期望取自不同侧必假红（实例：088 成稿审查 F-02，范围 `:14`–`:52` 不含 `:12` 而期望 4 按含 `:12` 算）。与 §4 自审第 4 条同源，本条是**写法**侧、自审条是**自检**侧。

### 6. 过程产物两项（非平凡改动必落）

1. `CHANGELOG` 条目——当批变更留痕（版本段格式见[版本与分发标准](版本与分发标准.md)）。
2. 规格本身——落 `docs/specs/`（含「审查记录」节）；验收全部通过后移入 `docs/specs/archive/`（移动不留副本）。**不建施工记录表**（旧仓机制已废：挂账与偏差的落点是当批规格的开放项，或对应标准的机检锚点行）。

当批开放项核对：当批产生的欠账须当批修完；修不完的写进当批规格的「开放项」节——无落点即核验未完成（规格随验收归档，由 git 历史承载）。禁止把欠账改成台账式清单重建——债跟着主题走，不跟着时间走。

### 7. 外部参考的转化

点名研读的仓库／规范，其研究成果须转为正式规格（本文件 §1 判定表对应行）后施工，逐条标注采纳（落位到文件节与自由度）／已覆盖（指认我方既有对应）／拒绝（带理由，防未来重复纠结）；裁定结论落当批规格的开放项或对应标准（模板见[施工机制](../specs/施工机制.md) §八）。

### 8. 立法质量（新增或修改规范条目时适用）

新增或修改规范条目须至少附一个正例或反例；无实例的条文标注「预立法，随首批实例校准」（标注者＝立法批，首批实例落地后由该批校准并删去标记）。**预立法标记须附「关联实例判据」**——即该条文一旦有实例时应出现的可判形态（如路径通配、字段名、串）；**判据写入该标记旁**。每批核销时逐条过一遍**本批改动面触及的**预立法标记：判据命中即**同批校准或删除该标记**（不得只留标记不校准）。**不采「超 N 批未校准自动升为待复核」**——那需要预立法登记台账与计数守卫，属**无事故出身的新机制**（`AGENTS.md` §四），且「N」无依据；本句为纪律句、不建台账。**执行面**：① 本批改动面**触及**的标准件内的预立法标记必核；② 改动面**未触及**的存量标记，**由任一后续批次认领清理**（**本条的存量 7 处已于 `096` 批一次清账**）——**不得以「本批未触及」为由长期搁置**。**认领须在本批规格的「本批核销」节记一行**（核销落本批规格，不另建台账）。

### 9. 治理文档条文的写法

治理文档条文不写批次叙事与裁定标记（立例与例外授权依据除外），沿革记 `CHANGELOG` 与 git 历史。

### 10. 被否决的替代方案（规格可选节）

把考虑过但未采用的做法与未采用原因写成一行一项——价值在复查（含归档后回看）时不必重新推演当时的取舍。

1. 触发条件：本批做过方案比较（多条实现路径、多种载体、改与不改）即记一节；无比较则整节省略，不留空节。
2. 写法：每条一行「方案 → 否决原因」，原因写当时的判据（约束、成本、失败模式）；反例：写「不合适」「感觉不好」类空判——复查时等于没记。
3. 落点：追加在规格的「本批核销」节之前（该节不存在时即「开放项」节之前）；模板见[施工机制](../specs/施工机制.md) §八。

## 二、正例与反例

- ✅ 锚点行号与原文现场 `grep` 后写入：「`AGENTS.md`:14 现文为『……』」。
- ✅ 计数实跑：`grep -c` 得 5，规格写「5 条」并附命令。
- ✅ `[A]` 替换范围限定：「只替换 A 括注和 B 句，其余原样保留」。
- ✅ 替换文本中把与零命中目标同字面的汉字数字改阿拉伯数字（如目标为「零命中七组」，替换文本写「其余 7 组」）。
- ✅ 断言预验摘要（含跳过项）附入规格自审。
- ✅ 改动清单末对照过程产物两项。
- ✗ 凭对话记忆写锚点（旧仓教训：3 处现状事实过时，施工时才暴露）。
- ✗ 目视估计计数（五轮审查计数错 ≥5 发，全是眼睛做算术）。
- ✗ 断言 token 被自家替换文本吞掉（预测值与「到位」列差 1）。
- ✗ 「整段替换」不写保留范围（差点删掉不该删的既有内容）。
- ✗ 断言引用的节号凭印象写（锚点节号失准）。
- ✗ 验收漏过程产物（`CHANGELOG` 条目／规格两项缺任一项）。
- ✗ 拿到外审报告直接改文件（须先转正式规格并逐条裁定）。
