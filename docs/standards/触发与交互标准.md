# 触发与交互标准

> 定位：约束调用形态（唯一入口显式调用）与交互（门控停靠、模态、准入律）。
> 依据：旧仓《架构决策记录》§四 精准入口机制与调用双层、旧仓《守卫与验收规范》§2.3 会话行为型断言、旧仓《Skill 写作规范》§五 交互模态（来源件已随 rebuild 作废，条文逐条迁移）；来源件为多域时期内容，已通用化改写。

## 一、条文

### 1. 唯一入口（机制层 + 文案层，双轨缺一不可）

1. 入口唯一：skill 本名即命令——`/{skill 名}` 显式调用，由宿主斜杠菜单原生补全，无需命令薄壳；本项目域名与命令一一对应的清单（唯一真源）见产品层[架构设计](../product/架构设计.md) 域清单。
2. **自然语言模糊触发禁止**，且必须写成机制键要求而非仅文案：`SKILL.md` frontmatter 设调用控制键 `disable-model-invocation: true`（键名与语义以宿主官方文档为准，未实测·待核——首个域落地时实测核对；键定义的单点权威在[skill形态标准](skill形态标准.md) §3）。文案层 description 触发句为「触发方式：仅 /{skill 名} 显式调用；自然语言提及不触发。」**两轨缺一即不合格**——只有文案等于靠模型自觉（反模式：纪律靠自觉不靠机制）。
3. 域间禁互调：skill 之间禁止互相调用；跨域只经落盘文件衔接——生产者只落盘，消费者在自己域内定义如何查找与读取（产物接口见[书目录契约](../product/书目录契约.md) §3）。
4. 命令薄壳（预留）属 user-invoked 编排层：只可调用域 skill，域 skill 永不反向调用薄壳或其他域 skill。启用前不得新增实例。
5. 域外休眠：与网文创作无关的请求（如「把这个 CSV 按销售额排序」）不触发任何套件内 skill、不套域框架；调出某域后转提域外请求，正常执行不套本套件框架。

### 2. 门控与停靠

1. **门控＝阶段级硬停**：每阶段产出后暂停，经作者确认才进入下一阶段；确认前不产出后续阶段实质内容（目标产物存在但为空模板即合规）。
2. 停靠＝模块级暂停：阶段内关键产物产出后暂停等作者过目（如底盘停靠、产物停靠），与门控分列。
3. 门控与停靠确认点须落产物状态表行（落行式样如「{产物名}-待确认」），否则续跑不得跳过——状态判定来自文件证据，不凭对话记忆。
4. 门控选项形态：确认／要改／先停（三选）；部分门控带域内附加项（如「查看中间产物／补充输入」）。
5. 中断契约（workflow 必含，标准句式）：「用户中途要求停止或表达其他域意图时，确认当前进度已落盘后移交对应域——建议使用对应 /{skill 名} 命令，不强行走完本域流程」。
6. 未建域如实告知：敲未建设域命令时如实告知「该域尚未建设」，不模拟、不顶替、不产出占位内容。

### 3. 交互模态

1. 封闭选择（≤4 项）→ 结构化选项列表（宿主中即 AskUserQuestion 工具；候选超 4 个收高频 4 项，其余并入其自带「其他」）。
2. 开放采集（自由表达）→ 对话式。
3. 过程性动作默认执行 + 可显式跳过。
4. 语义描述为主，工具名放括号标注——防宿主变更，也防模型见工具名即机械调用。
5. 交互标注纪律：workflow 正文每个用户问句后必须标模态——（选项列表）或（对话式）；一个问句只承载一种模态，混合问题（如「选平台 + 说方向」）拆成两问。
6. **待收口**：本条与旧仓「禁用 UI 词汇（弹窗／界面）描述交互」条字面互斥——旧仓标注用语「（弹窗：…）」正属该禁用词。方向二选一：(a) 改标注词汇为「（选项列表）」；(b) 给禁用句加限定（语义描述禁 UI 词汇、标注标签除外）。**待作者裁决**，裁决前一律用「（选项列表）」形态。

### 4. 准入律（规格字段）

1. 三问段式：段一自由聊（对话式）→ 段二回读默认（静默 + 回读）→ 段三选项列表 ≤3 + 对话式 ≤3。
2. **字段准入律**：终局口径与感情线不问——作者在段一主动说了才记倾向；有想法填，无则标「倾向待定」，不计入完备校验。
3. 收拢式重问：段三未答全时，把剩余必答项合并成一次问清单重问，不逐项追问。
4. 过程性动作默认执行（如建骨架）＋通报结果，不额外索取确认；有副作用的操作（写文件、调外部服务、删数据）才停靠确认。

## 二、正例与反例

- ✅ 用户说「帮我写本玄幻小说」→ 不触发任何套件内 skill（无显式调用，域外休眠生效）。
- ✅ 敲 `/{skill 名}` → 加载 skill 壳，入口判定按文件证据（无项目进度文件 → 全新开书）。
- ✅ description 触发句「触发方式：仅 /{skill 名} 显式调用；自然语言提及不触发。」＋ frontmatter `disable-model-invocation: true`（文案 + 机制双轨）。
- ✅ 本域内识别到另一域意图 → 落盘当前进度后移交 `/{skill 名}`，不强行走完本域流程。
- ✅ 门控停等作者确认后才推进；确认动作落产物状态表行。
- ✅ 问句标模态：「你想从哪个平台发？（选项列表）」／「有什么绝对不写的？（对话式）」。
- ✅ 过程性动作（建骨架）默认执行并通报：「项目目录建好了，目录和空文件就位。」
- ✗ description 只写「自然语言提及不触发」而不加调用控制键（只有文案层，靠模型自觉）。
- ✗ description 写「或上述任一话题的自然语言可触发」（模糊触发句——同一产品下的多个 skill 同属一个工作面，自然语言互抢误触发）。
- ✗ 在本 skill 内直接调用另一 skill 的流程（域间禁互调，域边界即合同边界）。
- ✗ 门控未确认就产出下一阶段实质内容（如规格门未过就产出后续阶段实体内容）。
- ✗ 一个问句混两种模态（「选平台 + 顺便说说方向」——须拆两问）。
- ✗ 未建域敲入命令后模拟产出占位内容（须如实告知未建设）。
- ✗ 靠对话记忆判定续跑点（须按文件证据——文件账本律）。
