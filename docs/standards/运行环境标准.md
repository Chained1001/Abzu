# 运行环境标准

> 定位：Node／Python 版本与探测链、零依赖承诺的边界、宿主（Claude Code）能力假设——「安装即用」的前提。
> 依据：旧仓《项目宪法》§0 会话起步与环境约定、存档 `AGENTS.md` §0 必读文档与环境约定段、旧仓《文件规范》编码与脚本编写规范两节、旧仓域文档的外部 CLI 依赖与降级声明（来源件与相关域已随 rebuild 作废，条文逐条迁移为通用规则，逐条出处见各条括注）。

## 一、条文

### 1. 宿主与版本前提

1. 唯一宿主 Claude Code（不做第二宿主适配）；宿主相关内容只出现在 `README.md` 安装说明。〔出处：旧仓不做清单「多宿主适配」条〕
2. 宿主会话须具备命令执行（Bash）工具；无命令执行能力的会话不可用于含脚本的域（域内动作会无法执行）。〔出处：存档 `AGENTS.md` §0 必读文档与环境约定段〕
3. Node.js 20+：涉脚本域的前提（脚本 + lint 工具链）；**该工具链经 `npx` 调用**——首次使用可能联网取包，此后走本地缓存（离线可用）；本仓不含 `package.json`，故 `--no-install` 形态不解决该依赖——此为「守卫零外部依赖」的**已登记例外**。〔出处：存档 `AGENTS.md` §0 必读文档与环境约定段；070 批补例外句〕
4. Python 探测链：`python3 → python → py` 依次探测；Python 三级链探测已落 `check.sh` [4] 段（缺失即明示置红；逐脚本不重复实现）。〔出处：旧仓《项目宪法》§0、旧仓 check.sh 头注〕
5. 宿主斜杠菜单承担命令补全（`/{skill 名}`），无需额外命令薄壳。〔出处：存档 `docs/product/总纲.md` §四 精准入口〕

### 2. Windows（Git Bash）约定

1. 一切命令按 Git Bash 语义执行；路径用正斜杠，**禁把反斜杠绝对路径喂给 sed／grep 等文本工具**（用 `cd` + 相对路径）。〔出处：旧仓《项目宪法》§0〕
2. 输出含中文前先 `export PYTHONIOENCODING=utf-8`（中文 Windows 默认 GBK 控制台）。〔出处：同上〕
3. pip 安装的 CLI 可能不在 PATH（入口在 `Python*/Scripts/` 下，如 `agentskills.exe`），找不到时先查该目录。〔出处：同上〕
4. 文本操作与 `git mv` 前确认目标目录存在（`mkdir -p` 先行，Windows 不自动创建）。〔出处：同上〕
5. npx 工具显式传 glob（如 `npx markdownlint-cli2 "**/*.md"`）；**退出码不经管道取**——`cmd | tail` 后的 `$?` 是 `tail` 的，必须接管道时取 `PIPESTATUS[0]`。〔出处：旧仓反模式清单第 6 条（lint 体检首轮误判违例数）〕
6. 命令行工具语义不可假定为 GNU 版：**守卫与断言实现不得依赖转义差异**——固定串用 `-F`、模式匹配优先用脚本语言（Python／Node）；核验复核以脚本语言实测为准。〔出处：063 批规格 §八 工具假阳性记录；**辅助事实**（个案、未稳定复现）：本机 `grep` 为 ugrep 函数封装（实测 `ugrep 7.8.4`），`\*` 等转义语义与 GNU grep 不一致〕
7. 同类实例：git 默认 `core.quotepath` 会把非 ASCII 路径引号化，脚本按后缀过滤会失效——取路径清单用 `git ls-files -z`。〔出处：060 批 A14 假阴性（脚本按后缀过滤失效）〕
8. **守卫与断言以 `shell=True` 执行子命令时的跨宿主语义须显式声明**——同一命令串在 Windows 与 bash 下的分词、引号与通配行为不同，跨宿主可复现性不可默认成立；确需 `shell=True` 者，须在脚本头注**显式声明两个宿主——设计宿主与实测宿主**（如「设计按 POSIX `sh`／实测宿主＝Windows `cmd.exe`」），并给出实测命令；**不得只写「已实测」而不点宿主**。**射程面内不满足者（如实记）**：`scripts/check_spec.py` 自身即用 `shell=True`（实测命中 **3 处**：`:25` 模块 docstring 自陈宿主语义、`:418` 与 `:1792` 两处 `subprocess.run`（行号按 `107` 批施工终态重算）），其头注只陈语义、未按本条声明设计宿主与实测宿主两值 ⇒ 本批**只立条文、不整改该件**（该项转 §八 开放项 7）。**并记前提冲突**：本条落在 §一.2 的「Windows（Git Bash）」约定下，而 `check_spec.py:25` 自陈 Windows 下走 `cmd.exe`——即**本仓实际执行宿主并非 Git Bash**；该冲突本批只如实登记，不裁定。出处：`078` 批头注补述与同族归档 3 件（规划方实测 `shell=True` 命中归档 **6 件**：`075`／`076`／`077`／`078`／`080`／`090`；前置审计记「4 件」，与本规格实测不符，见 §四.1）。

### 3. 编码与行尾

1. 全仓 UTF-8 编码、**无 BOM**；行尾统一 LF，由 `.gitattributes`（`* text=auto eol=lf`）强制。〔出处：旧仓《文件规范》§四；现行 `.gitattributes` 实件〕
2. 脚本读写文件显式指定 encoding（如 `utf-8`／`gb18030`），不依赖系统默认。〔出处：旧仓《文件规范》脚本编写规范「编码」行〕
3. 工作树出现 CRLF 属本地配置差异，不折腾（入库已由 `.gitattributes` 归一）。〔出处：旧仓规格复盘裁定：`.gitattributes` 入库归一已保证，工作树 CRLF 不折腾〕

### 4. 零依赖承诺的边界

承诺：「安装即用」路径零外部依赖——skill 运行时默认只用语言内置与宿主能力；守卫（`scripts/check.sh`）零外部依赖、不跑 LLM、不联网（**[1] 段 lint 工具链为例外**，见 §一.1.3）。〔出处：旧仓不做清单「CI 里跑 LLM 或联网」条与守卫纪律〕

依赖分三级，越级须走对应的声明与降级义务：

| 级别 | 内容 | 义务 |
| --- | --- | --- |
| ① 内置与宿主 | 语言内置模块、宿主工具与能力 | 默认路径，无额外声明成本 |
| ② 全局外部 CLI | Node 包／pip CLI 等装在用户机器上的工具（skill 脚本可依赖） | 域文档声明依赖与最低版本；缺失时输出可操作的安装提示；给出逐级降级路径；调用有超时上限 |
| ③ 仓库开发工具链 | lint、校验类 npx／pip 工具 | 路径探测可用性；缺失时**报红或明示跳过**，不得静默失败 |

**明确不做**：速查索引与各条**解冻触发关键词**见根 [AGENTS.md](../../AGENTS.md) §四「不做清单」（单一真源）；完整理由与逃生口见该节 git 历史原版本（`578815a` 及此前）；引入新机制前的内生必要性自问同见该节。

### 5. 脚本运行时契约

本契约适用于 skill 运行时脚本（`skills/` 域脚本）；仓库开发守卫 `scripts/check.sh` 为二值闸——`0` 全绿／`1` 任一段红或环境缺失，不适用本节五分类；其跳过项登记与收尾汇总的输出格式见[测试与验收标准](测试与验收标准.md) §1.1。

| 规则 | 内容 |
| --- | --- |
| 退出码 | `0` 成功／`1` 违规（含运行失败——产物不可消费）／`2` 参数或环境错误（条件不满足：先改条件再重跑）／`3` 需交互同意但当前为非交互环境／`4` 用户拒绝或取消（`3`＝问不了，`4`＝问了被拒）；缺／空／坏各明示；`1` 与 `2` 的判别看调用方动作；部分成功按 `1` 上报并在 stderr 明示缺失规模（有原因则逐条列出）〔出处：旧仓《文件规范》脚本编写规范「退出码」行（五分类）〕 |
| 错误输出 | 错误写 stderr（`console.error`），数据写 stdout（`console.log`），不混流〔出处：同表〕 |
| 输入校验 | 必填参数缺失或非法时输出用法说明并退出 `2`；可选参数的默认值须在用法（脚本头注或 `--help`）中标明——不得静默取默认值〔出处：同表；旧仓域脚本实测抓出「默认值只在代码里、用法未标」违例〕 |
| 输出格式 | 结构化数据用 Markdown，日志用纯文本，禁 JSON 散落 stdout〔出处：同表〕 |
| 降级声明 | 脚本头部或域文档声明依赖缺失时的降级行为〔出处：同表〕 |
| 限速 | 对外部站点的请求间隔与退避上限——单点权威在[安全与合规标准](安全与合规标准.md) |
| 脚本文档头 | 脚本文件头四要素：用途／用法与参数／依赖与前置／维护入口（形态随语言：sh＝`#` 块、py＝docstring、js＝JSDoc）；≤10 行的微型守卫可合并为两行：用途一句 ＋ 维护指向一句〔出处：旧仓《文件规范》§五.1〕 |

## 二、正例与反例

- ✅ 探测链守查写法：探测到可用解释器后以下一次探测为条件（旧仓实录：探测链第三行 guard 写错，`python3`-only 环境会把已正确的变量覆盖为 `py`——修正写法 `command -v "$PY"`）。
- ✅ 脚本头注写「用法」段，含每个参数的默认值（如 `--port` 默认 9222）。
- ✅ 依赖缺失时输出可操作提示（如「未找到 npx（本段需要 Node.js）」并置红）。
- ✅ 中文输出前 `export PYTHONIOENCODING=utf-8`。
- ✅ 退出码直取；必须接管道时取 `PIPESTATUS[0]`。
- ✅ 读写文件显式 `open(..., encoding="utf-8")`。
- ✗ 域脚本依赖一个全局安装的外部 CLI，而域文档未声明其缺失时的降级路径（旧仓实录：某域脚本依赖浏览器自动化 CLI，无依赖时无降级说明；该域已退役，条文抽象保留为通用规则）。
- ✗ 关键工具缺失时静默跳过当作通过（守卫须报红或明示跳过）。
- ✗ 把反斜杠绝对路径喂给 `sed`／`grep`。
- ✗ 给带 shebang 的脚本插入头部注释，把 `#!` 挤离首行（改完必跑语法检查）。
- ✗ 结构化 JSON 散落 stdout、与日志混流。
- ✗ 可选参数静默取默认值而用法不标（调用方无从知晓）。
- ✗ 断言依赖 `grep` 的 `\*` 转义语义——本机 `grep` 为 ugrep 封装，同一模式两种计数。
