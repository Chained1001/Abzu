# 评估场景（Abzu skill 行为验收）

> 版本：v0.4（沿革见 CHANGELOG 与 git 历史）
> 定位：skill 行为的验收基准（eval-first：先于详细文档存在）。**每次修改 skill 后必须重跑全部场景**（宪法 §3）。
> 评估闭环：新能力先裸跑记录失败选择与理由原话（RED）→ 写最小指令修正（GREEN）→ 把新出现的合理化借口堵回指令再测（REFACTOR）。本文件场景是 GREEN/REFACTOR 阶段的验收基准。
> 断言分级：`[机检]` = 可脚本或文件系统确定性判定；`[人工]` = 需走查者判断。跑法：新会话中按场景 prompt 原样输入，逐条核对断言。
> 状态分组：场景 1/6/7/8 为**当前可执行**（outline、scan、analyze 域已建设）；场景 2-5 为**待启用契约**（对应域建设后生效——eval-first：验收先于实现存在，未建设域命中时 skill 应如实告知未上线）。
> 前置：在目标项目目录安装 `npx skills add Chained1001/Abzu -y`（六壳全部装入），新开会话；宿主会话须具备命令执行（Bash）工具与 Node.js 20+——无命令执行能力的会话不可测（扫榜域全依赖脚本）。

## 场景 1 · 新书立项（当前可执行）

**前置条件**：在一个空目录中启动会话（无任何写作项目文件）。

**用户 prompt**：
> 我想开一本玄幻网文，讲一个废柴少年捡到能吞噬功法的神秘鼎，帮我从头开始

**预期行为**：

- [机检] skill 被触发（模型声明进入 abzu 工作流或直接执行立项阶段）
- [机检] 产出 `project.md`（含卖点、题材、金手指、目标读者、参考、章节字数目标）与 `文风/文风指南.md`
- [机检] 未产出后续阶段实质内容（不越阶段——`大纲/总纲.md`、`设定/设定集.md` 为脚手架骨架初稿豁免；不得出现卷纲/细纲/手稿文件及总纲实质剧情内容）
- [机检] `创作进度.md` 记录当前阶段为立项-待确认
- [人工] 立项产出后暂停询问确认，**未**在用户确认前进入世界观阶段（阶段门控）

## 场景 2 · 黄金三章规划

**前置条件**：已有一本通过立项确认的测试书（手工搭建：`project.md` + 基础设定）。

**用户 prompt**：
> 帮我规划一下开局前三章怎么写

**预期行为**：

- [机检] 细纲文件中前三章条目存在，且每章含钩子/悬念要素字段
- [机检] 读取了 `project.md`（产出内容与立项设定的题材、金手指一致）
- [人工] 规划体现黄金三章策略：第 1 章内出现核心悬念或金手指苗头，而非慢热开局
- [人工] 产出后暂停等确认

## 场景 3 · 续写下一章

**前置条件**：测试书已有 ≥3 章手稿、最新卷纲细纲、人物卡与追踪文件（前情提要、伏笔账本、人物状态、进度）。

**用户 prompt**：
> 继续写下一章

**预期行为**：

- [机检] 起草前读取了细纲、出场人物卡、`追踪/前情提要.md`（会话恢复顺序正确）
- [机检] 新章节文件落在正确的卷目录，编号续接上一章，无跳号
- [机检] 字数落在 `project.md` 声明的章节字数目标区间内
- [机检] 章末存在钩子段（人工判断钩子质量）
- [机检] 写完后更新了全部四个追踪文件（进度、前情提要、伏笔账本[如有埋设/回收]、人物状态[如有变化]）
- [人工] 新章人名、能力、已知信息与前情提要及人物状态快照无矛盾

## 场景 4 · 改稿

**前置条件**：同场景 3。

**用户 prompt**：
> 第3章节奏太拖了，帮我改一下

**预期行为**：

- [机检] 只修改 `第3章` 对应文件（其他章节文件字节不变）
- [机检] 若改动影响剧情事实，同步更新前情提要/伏笔账本/人物状态中受影响条目
- [机检] 修订后在 `创作进度.md` 留下修订记录
- [人工] 修改聚焦节奏（删冗、并段、前移钩子），不整章重写导致风格漂移

## 场景 5 · 伏笔核对

**前置条件**：测试书的伏笔账本中含至少 2 条"已埋设未回收"、1 条"已回收"的伏笔。

**用户 prompt**：
> 查一下我的伏笔有没有漏回收的

**预期行为**：

- [机检] 产出核对结果：逐条列出伏笔的埋设章节、账本登记的计划回收点、当前状态
- [机检] 超过计划回收点仍未回收的伏笔被明确标记
- [机检] 未修改手稿正文（核对是只读动作）
- [人工] 核对结果以呈报形式给出，不擅自改动账本状态（candidate 永不拦截：建议作者自己标记）

## 场景 6 · 扫榜调研（当前可执行）

**前置条件**：全新空文件夹（扫榜不依赖书项目）；机器已装 Node.js 20+ 与 Chrome（起点榜仅前者）。

**用户 prompt**：
> /abzu-scan（或：扫一下起点的畅销榜，看看最近什么题材火）

**预期行为**：

- [机检] abzu-scan 被触发（域壳入口判定：空目录 → 全新扫榜），加载 `references/scan/scan-workflow.md`
- [机检] 数据来源按三级优先执行：脚本采集 → 用户提供 → 内置知识（降级须标注"未实时校验"）
- [机检] 起点榜走 SSR 脚本采集（`node scripts/qidian-rank-scraper.js`，不需要 Chrome）
- [机检] 采集文件头部含数据质量三行（数据质量/有效条目/问题摘要）
- [机检] 分析阶段运行 `scan-analyze.js` 做确定性提取，未手写内联解析脚本
- [机检] `选题决策.md` 为模板 v2 十七字段完整填写（含读者代偿心理/开篇钩子公式/长期追读动力/题材雷区/参考候选等新增字段均非空）
- [机检] 产出扫榜报告与 `选题决策.md`；同方向样本 <15 时可行性强制降"中"并写明先验证
- [人工] 平台调性判断合理（起点男频审美 ≠ 晋江女频），题材洞察有榜单证据支撑

## 场景 7 · 域外请求休眠（官方测试矩阵：out-of-scope）

**前置条件**：任意目录，abzu 已安装（用户级或项目级）。

**用户 prompt**：
> 帮我把这个 CSV 按销售额排个序

**预期行为**：

- [人工] abzu 系技能保持休眠不触发——CSV 排序与网文创作无关（description 边界声明生效）
- [人工] 扩展：分别敲 /abzu-outline 等占位域命令，模型应如实告知"该域尚未建设"，不模拟、不顶替、不产出占位内容

## 场景 8 · 拆书分析（当前可执行）

**前置条件**：目标项目目录含参考书原文 `参考书.txt`（≥20 章且开头带目录块的 UTF-8 文本）；另有一份扫榜产物（如 `扫榜/起点都市高武_20260901/选题决策.md`）其「参考候选」字段含《参考书》书名；`拆书/` 目录不存在；机器已装 Node.js 20+。

**用户 prompt**：
> /abzu-analyze（或：帮我拆一下这本《参考书》，我想搞清楚它为什么火）

**预期行为**：

- [机检] abzu-analyze 被触发（域壳入口判定：无 `拆书/` 目录 → 全新拆书），加载 `references/analyze/analyze-workflow.md`
- [机检] `拆书/{书名}/原文/原文.txt` 备份存在；章节索引由脚本生成（`build-chapter-index.js` 被调用），`章节索引.csv` 为五列表头，未手写内联解析脚本
- [机检] 产物树齐全：`结构块.csv`、`黄金三章拆解_{书名}.md`、`六维拆书_{书名}.md`、`爆款机制_{书名}.md`、`证据与边界_{书名}.md`
- [机检] 默认模式无逐章语义产物（语义分析文件仅上述 4 份 md，不存在逐章一文件的分析产物）
- [机检] 选题决策.md「参考候选」字段值后被追加〔已拆文验证 YYYYMMDD〕标注，其余字段与终裁记录未动
- [人工] 结构块为戏剧循环块（每块含缺口/加压/转折/兑现/新阅读债要素或如实标注缺失），非逐章流水账
- [人工] 爆款机制为四层解释（表层表现/叙事机制/读者心理/可迁移原则），无"节奏好""人设讨喜"式空泛结论
- [人工] 两个停靠点各停一次：黄金三章快速预览后、爆款机制后等用户确认才推进

## 维护

- 新增场景：按上述格式（前置条件 / prompt / 分级断言）添加；场景须来自真实使用口吻。
- 断言失效（行为有意变更）：同批更新规格与断言，禁止只改断言（宪法 §1.5）。
- 每次跑完记录：日期 + 场景 + 通过/失败 + 走查备注（记入当次规格或 issue，不建独立台账）。
