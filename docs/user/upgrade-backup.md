# 备份、升级与卸载

## 升级到 0.0.5

0.0.2 把 0.0.1 时代的 `abzu-retrieval`、`abzu-companion`、`abzu-full` 三个安装包并入主包 `abzu`：检索增强与鲸鱼娘桌宠随主包提供，默认关闭。0.0.3 把五条功能入口的条目 id 统一换为 abzu 系（`abzu`、`abzu-embeddings`、`abzu-scenes`、`abzu-reranking`、`abzu-companion`；0.0.2 及更早为 `webnovel`、`webnovel-embeddings`、`webnovel-scenes`、`webnovel-reranking`、`whale-companion`），借零书、零插件设置的窗口完成，设置、凭据引用与停用状态按新 id 重新配置。0.0.4 移除鲸鱼娘桌宠，`abzu-companion` 条目随之消失，其余四条入口与全部设置、凭据引用不变。继续配套 DSH 0.2.0-rc.2，不需要更换 DSH。

1. 停止正在运行的会话。
2. 卸载单独安装过的 `abzu-retrieval`、`abzu-companion` 或 `abzu-full`（如果有）。
3. 更新或安装 `abzu` 到 0.0.4，应用变更并重启。
   成功时，已安装列表只剩 `abzu` 一个入口；设置中剩余四条入口使用 abzu 系新 id。

0.0.1 基于上游 webnovel-writer 8.2.0，包含其直接编辑、行内 Agent 建议、确定性字数统计与契约篇幅约定，修复旧书的世界书模块登记，并移植上游之后的四批缺陷修复。从 8.0.x 或 8.1.x 升级的旧项目仍须按 [旧项目需要更新作品契约](#旧项目需要更新作品契约) 补充篇幅约定。新界面见 [编辑器教程](editor.md)。

## 旧项目需要更新作品契约

升级之后，请为旧项目补充并确认“章节篇幅”约定，才能启用新的篇幅范围核对。升级插件不会替你决定每章写多少字，也不会重写原契约。未补充的项目仍可继续使用。脚本会显示“未配置”。不能据此宣布篇幅达标。

1. 按下文备份完整书仓和 profile。
2. 回到该书的主会话。
3. 让主控读取现有 `作品契约/契约.md`，并与你确认目标和宽松区间。
4. 保留“阅读体验与情绪承诺”的原有内容。
5. 追加下面的三级子节。通过原来的 `novel_update_contract` 更新该分部，并确认。
   不要只用新子节覆盖整个分部。

```markdown
### 章节篇幅
- 目标汉字数: 2000
- 下限汉字数: 1600
- 上限汉字数: 2400
```

上面只是两千字章节的示例。数值可以改。三项都是正整数，并且下限 ≤ 目标 ≤ 上限。其他说明放在相邻子节。正文汉字数含章标题，排除 frontmatter、候选事实、标点、空白和英文字母。使用脚本做实际统计。不要用模型估数。

可以直接对主控说：

> 请读取本书现有作品契约，保留全部已有约定，在“阅读体验与情绪承诺”里补充章节篇幅：目标 2000 汉字，范围 1600～2400。我确认这组数值，请通过契约更新工具保存；只更新契约，不改写现有章节。

6. 对当前唯一的待审稿运行原来的确定性审读脚本。
   成功时，`篇幅核对.约定.状态` 为“已配置”，数字与契约一致。
   没有待审稿时，在下一次正常审读中核对即可。不要为了测试创建假稿。
7. 契约变更之后，当前未定稿章的旧审读证据可能过期。沿原来的审读流程重新检查。
   偏长或偏短进入“文本规范检查”的普通发现项。可以修改，也可以由作者保留。没有新的审核步骤，也不会自动裁稿。历史定稿不因此重写。

如果旧书曾因世界书模块声明缺失而停在世界构建，升级后重新读取并成功确认已有条目，就会自动补齐模块登记。不需要用通用文件工具修改声明。

## 检索要单独更新吗

0.0.2 起四包合一：更新 `abzu` 一个包就同时更新工作台和检索增强，不存在组件版本组合问题。检索功能默认关闭；不想使用时在设置中保持对应条目停用即可，见 [配置教程](configuration.md)。0.0.4 起鲸鱼娘桌宠已移除，不再随包提供。

0.0.1 及更早版本的可选包不再发布，也不与新包同时启用；旧入口按上文步骤卸载。

## 旧包名迁移（8.0.0 起）

8.0.0 起，旧的 webnovel-embedding-provider 更名为 @linfengqaqtat/dsh-scriptor-retrieval。旧的 @linfengqaqtat/dsh-whale-companion 更名为 @linfengqaqtat/dsh-scriptor-companion。所有新版安装包都是 8.2.0，使用 DSH 0.2.0-rc.2。

> [!WARNING]
> 不要同时启用旧包和新包。

1. 先备份作品、profile 配置和凭据引用。
2. 停止会话。
3. 在 DSH 侧栏“插件”中卸载旧入口。
4. 按提示重启。
5. 再安装新入口。
   成功时，只启用新入口。

自定义模块的 name 覆盖，要按 [维护者迁移说明](../maintenance/cli-install.md) 更新。稳定的条目 id 和 config 保留。（0.0.1 时代的"完整版与写作/检索单装二选一"已随单包统一废止。）

## 备份两类资产

先停止相关实例，再分别备份。

- 工作区：书仓的全部文件、书仓 `.git`、草稿区，以及工作范围内的书房素材。书仓 Git 不能代替包含草稿和书房内容的完整备份。
- DSH home：profile 配置、设置，以及需要保留的会话。它可能包含凭据。备份应私下加密保管，不能提交到公共仓库。

记录主包、DSH 和 Node 的版本。

## 更新

1. 阅读目标版本的 Compatibility、已知问题和迁移说明。按 [版本对应表](install.md#为什么要固定-dsh-版本) 同时对齐 DSH 和插件。
   安装插件不会自动更新全局 DSH。版本不符时，按 [修复步骤](troubleshooting.md#dsh-版本不对怎么修复) 处理。
2. 完成备份。停止指定 profile 的运行实例。
3. 向同一个 profile 安装 npm 上的新精确版本，或下载并校验对应 `.tgz` 后再安装。
4. 重启。
5. 检查书房入口和技能是否各有一份。核对实际书仓状态。先用合成副本试写。
   成功时，书房可以打开，并且书仓状态与备份前的预期一致。

```powershell
dsh plugin --profile scriptor add abzu@0.0.11
dsh --profile scriptor --dump-config
```

上面展示的是命令写法。更新时换成实际的目标版本。0.0.2 起没有完整版与单装之分，`abzu` 是唯一入口；旧 full 或单装入口先卸载再安装主包，见 [安装教程](install.md)。

## 回退

代码回退和数据回退不是同一件事。如果目标版本改变了书仓格式，安装旧包不能自动还原已经迁移的数据。

> [!WARNING]
> 未提供迁移或回退证据时，不要在唯一原稿上尝试回退。

1. 停止实例。
2. 保存故障现场。
3. 按发行说明，使用兼容的旧包和对应的完整备份来恢复。

从完整备份恢复时：

1. 先停止实例。
2. 把损坏的书仓目录整个移走或删除。
3. 再把备份目录整体复制回原位置。

> [!CAUTION]
> Windows 上，书仓 `.git/objects` 里的文件带只读属性。普通删除会中途失败。
> 用资源管理器、`robocopy /MIR`，或先清除只读属性再删除。

4. 恢复后运行 `git -C <书仓> status` 和 `git -C <书仓> fsck`。
   成功时，两个命令的结果都是干净的。

本版不支持自动迁移 v6/v7 书仓。

## 卸载与重装

1. 先停止该 profile 的实例。
2. 运行 `dsh plugin --profile scriptor list --depth 0`，查看直接安装项。
   `remove` 只移除指定的直接安装项。full 不能替单装包办理卸载。

| 实际安装组合 | `dsh plugin --profile scriptor remove` 后的参数 |
| --- | --- |
| 0.0.2 及以后 | `abzu` |
| 0.0.1 时代混装了可选包 | `abzu` 加上列表中实际存在的 `abzu-retrieval` / `abzu-companion` / `abzu-full` |

例如 0.0.1 时代主包和检索包都装过，并且希望整套卸载：

```powershell
dsh plugin --profile scriptor remove abzu abzu-retrieval
dsh --profile scriptor --dump-config
```

> [!CAUTION]
> 不要把未安装的包名一起传入。否则 pnpm 会拒绝这次卸载。

3. 整套卸载后，核对配置里已经没有 `abzu`、`abzu-embeddings`、`abzu-scenes`、`abzu-reranking`（0.0.2–0.0.3 还有 `abzu-companion`；0.0.2 及更早版本的条目 id 为 `webnovel`、`webnovel-embeddings`、`webnovel-scenes`、`webnovel-reranking`、`whale-companion`）。
4. 核对直接安装列表里已经清空。
5. 再按安装教程重装。
   卸载不会删除作者的书仓、书房、设置或模型凭据，也不会清空 pnpm 的共享缓存。保留下来的作者资料不属于重复安装。
