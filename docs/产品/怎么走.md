## 4. 全流程总览

```text
灵感与立项 ──建书──▶ 定调设计（快速开写 或 逐部设计）──▶ 开写就绪
                                                            │
        ┌───────────────────── 每一幕 ──────────────────────▼──────┐
        │ 幕纲 → 每章（细纲 → 备料 → 起草 → 审读 ⇄ 改稿 → 润色 →    │

                                                            │

```

## 5. 开书阶段

### 5.1 入口与恢复

1. **会话开场**：主控先加载《工作台总控》。没有目标书的灵感讨论直接进《灵感与立项》；要操作既有书但没选定时先问书目。
2. **状态校准**：已有目标书时调 `novel_get_story_status`，动设计面之前再调 `novel_get_book_progress`（待补便签、窗口余量、未决偏离）。久未续写、换会话、刚选完书都先校准。
3. **回归简报**：三行必报，欠账行仅在 N>0 时追加（常态四行）——`上次停在：…｜上章收在：…（上章章摘要末行）｜本卷进行到：…（卷纲方向选择）｜欠账 N 条`（未决偏离为零时不追加）。
4. **选书**：`novel_select_book`；切书必须作者明确指定〔谈〕。

### 5.2 灵感与立项（`novel-inspiration`）

| 步骤 | 做什么 | 产出 |
| --- | --- | --- |
| 随手记 | 作者只想记录时原样保存，不评判不展开 | `书房/灵感池/<身份>.md`，一脑洞一文件 |
| 探索 | 给可比较的方向：熟悉题材里由人物处境长出的新发展，或特殊设定及其后果推演；每个方向讲清处境、动机、选择、后果、期待；一次只追问最影响方向的一件事 | 对话；值得保留的候选记入灵感池 |
| 从参考作品产生点子（可选） | 用参考库机制说明成立条件，再用本书人物与规则重新推演；原作事件链不直接照搬 | `novel_reference_report` 存入灵感池 |
| 收敛构想七要素 | 核心创意、题材与目标读者、主角核心欲望、主要冲突、核心看点、差异化方向、明确不要什么；可选起书名（3–6 个候选） | 构想草案 `书房/构想/<书名或代称>.md` |
| 建书 | 作者明确同意后调 `novel_create_book`；核心创意与题材读者必须非留白〔码〕 | 书仓脚手架，提交 `vol: 建书` |
| 选书与去向 | `novel_select_book`，然后让作者选快速开写或逐部设计 | — |

可选读的判据件：开书-读者与情绪定位（读者画像）、开书-构思与验证（一句话故事、元素组合）。

### 5.3 素材库与采风（`novel-forage`）

灵感库与采风检索独立成技能（从《灵感与立项》拆出；灵感池的随手记仍在立项技能），细纲、起草、评审、卷末各阶段按需加载。

**八部**（一部一册零件卡，部总数 8 封顶）：

| 部 | 收什么 |
| --- | --- |
| 人 | 人物原型（人设标签、反差矛盾点） |
| 地 | 方言风物、地域景观、现实场所 |
| 物 | 年代器物、物价、日常物件 |
| 事 | 时事与社会情绪、真实案件奇闻、历史事件 |
| 知 | 冷知识、行业职业细节、游戏规则机制、设定概念模式 |
| 言 | 台词金句、命名人名/地名/组织功法、圈层黑话（子标：金句语感／命名构词／黑话） |
| 象 | 古词古句·意象（诗词古文、雅称谚典、意象母题）、文化元素、感官素材 |
| 镜 | 影视动漫桥段、对标观察 |

- **零件卡十列**：序号、关键词、一句话（骨）、为什么好（魂）、化用启示、反例、来源、可信度、已用于＋第十列**时效**（三态：`长青`——默认且必填／`时效｜首发YYYY-MM-DD｜半衰期约N月`／`年代锚｜流行于YYYY年代`，供年代文/重生文对表）。
- **三条生产通道**：采风采集；存量盘点；作者说"存着"时主控直接记入当日暂存。触发源六个＝评审转来、开书备料、热梗补给、即席查询、存量盘点、幕纲锚点缺素材（幕纲「查证清单」与细纲「查证行」的【待采风】标记即任务单来源）。
- **采风 agent（两源）**：主控读采风检索底本，派采风 agent（或单条小任务内联）。依次查 ①素材库（本地灵感库索引＋各部零件卡去重＋灵感池对照）→ ②网络（只采国内源，按站点路由表选通道：时事热点→新闻聚合/门户、行业细节→行业站点/百科、冷知识→百科/科普站、方言风物→地方志/文化站、游戏机制→游戏 wiki、影视桥段→影评/百科；具体域名经验记 `_采风站点经验.md`，先经验后默认）；知识库不是采风对象。每条至少两个独立来源才标 `已证实`；单源 `孤证`、推理 `推测`、多例归纳 `归纳`；摘要类路径结果最高 `孤证`；境外源记「已排除」；网络不可用降级单源如实标注。结果写暂存不写正库。
- **裁决与归档**：暂存逐条呈作者，作者批"入/弃/改道"后主控归档（append 进对应部零件卡、索引计数+1）〔谈〕。
- **翻库与融合**：按部翻、按关键词 grep、按场景需求问三式；**四分管法**检索视图（人设标签库〔人/象〕、剧情钩子库〔事/镜〕、金句语感库〔言〕、对标拆书库〔镜＋参考库机制卡〕——素材仍存八部不分家，不另建目录）；翻到零件三去向（入材料包、固化进人物声线、激发新点子入池），落笔前过**融合三条**：梗与热点主要落人物台词与群像反应（叙述者慎用）；古代与异世界背景只取机制不搬原句；真实灾难与悲剧不娱乐化。写法类桥段参照已随本批迁出灵感库，落在《细纲备料》references/桥段参照.md。

### 5.4 定调设计总则（`novel-design`）

- **对谈纪律七条**：静默预填（呈报前先读判据件预填草案并写明推导来源）、候选裁决（每组决定给 1–3 个候选＋推荐＋一句依据）、追问限额（开放式追问全流程最多 3 个）、复述纠错（每轮开头复述当前决定）、兜底（"都行"取推荐并标可后改）、判据取件（判据件整件读）、待改清单（后面步骤发现前面要改时先记一行，写入前统一呈报）。
- **写入前先读目标**：对已存在的工件，先在主会话读一次再调工具。
- **章节篇幅**：契约"阅读体验与情绪承诺"分部内的"章节篇幅"子节，目标、下限、上限三个正整数；数值必须经作者同意，可以留白；之后细纲、起草、审读都按它核对。
- **留白合法**：没想好的部分标留白，不为填栏编造终极真相、最终敌人或结局。作者要保留的留白不擅填。

### 5.5 路径 A：快速开写

适合"先跑起来再细化"。省的是对谈轮数，不是内容。

1. 主控读构想快照，一次起草开写所需的最小完整设计：契约六部各一两句实质内容；世界书至少主角一条人物档案、一条世界规则；全书大纲只确认前两部（当下追求、处境、已知阻力），可加只填当前交手层的对手梯队；分卷只写本卷卷行；第一卷卷纲四段＋压力升级检查＋计划时间线（卷纲固定段规格与幕纲固定段规格在《卷幕规划》技能包 templates/）；近期窗口第一条＝第一章章名；信息释放台账一次性建账（建账流程照《卷幕规划》）。
2. **摘要过目**：5–8 行人话摘要（写什么、主角是谁、第一卷怎么走、留白和自拟了什么），末附一行**体量提示**——按篇幅档，把主要人物、对手层级、支线三项中与参考标尺建议差得最多的项列出来（不出完整对账表、不拦截）；分卷只排了 N 卷时同时提示「预定篇幅约需 M 卷（按单卷体量行估）」。作者说"看细节"或点名某件才展开全文；作者说"同意"即确认整包〔谈〕。
3. 按序写入：契约六部 → 世界书条目 → 全书大纲 → 分卷 → 卷纲与计划时间线 → 近期窗口。每次调用各自产生一笔 `design:` 提交（契约暂定或留白的部不提交）。
4. 调 `novel_get_book_progress` 核对没有"已确认但无内容"，向作者播报写入结果和留白项。设计面变为"开写就绪"后进入章节循环。

路径 A 不跑强制多方向，卷纲没有"方向选择"小节；不跑全书分卷粗排，卷行可只写本卷；是否跑两席评审和跨轨道自检，技能没有写明。

| 全景开场 | 一次呈报契约、世界书、全书大纲、分卷、卷纲五块，作者可从任一块聊起 | — | — | — |
| 设计草案（贯穿 1–7） | 对谈中定下的内容先逐件写进书房的设计草案，换会话时从这里接上 | — | — | `书房/开书/<书名>/设计草案/` |

### 5.7 确认前审查里的两席评审（可选）

两席评审是「确认前审查」（第 5.6 节步骤 7）的第三部分（可选，不默认强制）。全书大纲、分卷、卷纲首次确认前或作者点名时，主控按作家→读者串行派两个评审子代理，两席互不通气，各自只评一次；评审对象在逐部设计时是设计草案里的该件，作者点名评审已写入的工件时是真源文件。报告由主控落到 `书房/评审/<书名>/<对象>_<席位>.md`，发现项并入确认前审查一并呈作者裁决，🔴 项建议改完再确认，作者也可以带着问题确认。

| 席位 | 视角 | 查什么 |
| --- | --- | --- |
| 作家评审 | 手艺人 | 结构、逻辑、设定、节奏、续航与体量五维，每个判断落到判据节号或参考标尺行并逐字引证；续航与体量维查续航引擎、组合新意与差异化落地，并对照参考标尺产出对照表——宿主附来体量对账表时优先逐项核对「处理」列是否成立，无对账表时照旧从参考标尺逐行对标 |
| 读者评审 | 契约画像里的目标读者（模拟） | 雷点扫描、追读力、情绪兑现、一句话测试；输出弃读点预测表 |

评审意见里带【待采风：查询词】的项，作者同意后转采风。

### 5.8 开书之后改设计

适用于已确认的契约、全书大纲、分卷、卷纲、世界书要改。

1. 先查书级进度卡；契约只按部更新，绝不整体重写。
2. 去重：已有同源同向的待裁决提案就复用，已驳回且没有新依据的不重提。
3. 跑影响分析脚本 `影响分析.mjs`：沿来源引用反向找下游，列出可整改的未定稿下游和命中的已定稿章。
4. `novel_record_proposal` 登记提案，向作者前置呈报影响面。
5. 作者表态后 `novel_resolve_proposal` 记录决定〔谈〕。
6. 通过：未定稿下游同批整改，经确认工具写入；命中已定稿内容走吃书补偿（第 7.2 节）。影响面过大就拆成几个提案。

### 5.9 参考小说拆解（`novel-analyze`）

只处理作者自备的本地 TXT/EPUB，不下载、不接平台账户、不处理 DRM，不需要目标书。

1. **预检与导入**：`novel_reference_source` 预检（只回格式、字数、问题，不回原文），填来源元数据（作品、作者、版本、取得来源、允许用途、依据）后导入。
2. **计划与许可**：`novel_reference_analyze` 选范围，向作者说明原文会发送给哪个模型服务；作者明确允许后才运行〔码〕。
3. **顺序拆**：有界批次提取观察，引用必须落在实际读到的原文区间；中断可恢复。
4. **报告与机制卡**：`novel_reference_report` 生成报告和版本化机制卡。
5. **检索与重推演**：机制卡只借原理，用本书人物与规则重新推演出新点子再入灵感池；原作事实不进本书账本。

## 6. 章节循环

### 6.1 细纲（`novel-outline`）

1. **读篇幅、定级**：继承契约章节篇幅；按卷纲与账本信号定本章是关键章（卷首、卷内高潮、段内高潮、心动位、换图、伏笔到期兑现）还是过渡章，拿不准按关键章。过渡章走简章：核心七节照填（哪七节见《细纲备料》简章节），其余一行带过；过渡章的叙事单元可用「简写单元」（试点）：字段名照留六个、值可短到「这场要解决什么＋边界＋预想画面」一句，关键章仍用全规格。
2. **读窗口、卷纲与本幕幕纲**：锁定近期窗口里的本章任务；读卷纲"方向选择"的选定方向与已排除走向（无此小节即本卷未跑多方向）；读本幕幕纲的「章组排布」「线与伏笔」「出场人物」三段（未分幕的旧书跳过）。窗口没有可进入项时先 `novel_roll_window` 追加。
3. **按幕成批出细纲（默认节奏）**：进一幕的第一章前，读本幕幕纲把本幕各章细纲候选一次性排出来——章与章之间的钩、铺垫、伏笔排期一起排（钩型配比按幕算）；幕内章数超一次能稳妥组装量时分批（阈值在参考标尺），伏笔与钩的排期仍以整幕为单位。作者不想一次排完整幕时可只排前 N 章（原批量细纲并入，一次 ≤5 章）。
4. **写候选细纲**：主控撰写，`novel_new_outline_draft` 落盘。结构：定位段九节（来源窗口项、章节功能、视角与焦点、时空锚定、起止边界、故事线与承诺分配、信息边界、情绪与节奏目标、前置条件核对结果）＋四个固定小节（本章形状、已排除走向、冲突与爽点、章末双钩）＋叙事单元（目标、人物、时空、行动/冲突、信息披露、状态变化）。「前置条件核对结果」节内写**查证行**（`- 查证：<世界书条目仓内路径>｜<查什么>`——本章会写到、要先对照的世界常量/力量体系量级/人物档案/地图等；多条多行；无需查写「查证：无」；条目不存在的写 `【待采风：查询词】`；写条目全路径，材料包组装会按路径自动切片）。另有**取舍行**可选增补（`- 取舍：为保 <A> 弃 <B>，理由一句`，放「情绪与节奏目标」节内或单元行均可，想不清不写）。至少一行〔硬〕/〔软〕/〔自由〕约束标记，来源引用三选一（三种合法形态以《细纲备料》确认门槛为准；本卷已分幕时，卷纲引用之外另加本幕幕纲引用 `来源:故事剧情/卷规划/卷NN/幕纲/幕NN-幕名.md@版本`）。
   - 读：章纲四件判据（整件读）、本卷最近三章的"本章形状"、信息释放台账；可选查参考库机制卡与灵感库。
   - 想（单元排布）：拆并（时空、POV、目标变了几个，全同就合并；情绪大转向也切）、排序（顺时间线；最大信息单元前后配铺垫和反应；末单元只开一个问号）、配字（读者最想看的那一秒给足，交接带过，钩一两句；不足加事不加字）。
   - 想（写时整合）：情绪接力、信息边界推演、冲突强度定位、双钩还债预检、取舍显形（本章为保什么牺牲什么，想清了落一行取舍行）。
5. **写前十查**（主控执行，检查不是门禁）：
   - 机器四查：①三约束对照 ②能力越级与金手指对账 ③伏笔与验证到期 ④接钩预检。
   - 十查机械脚本 `十查机械.mjs`：⑥爽点铺垫对账（对照进行中的承诺与上一章章摘要）与⑧近五章重复比对的机械部分。
   - 过目单六查：⑤平章 ⑥爽点铺垫 ⑦动机三问 ⑧近五章重复 ⑨情绪落点 ⑩钩子承诺；另附雷点快扫、信息释放、配给合计三行。🔴 项呈作者裁决，不自动拦卡。
6. **呈确认**：一张表呈报门槛核对、情节点概述、十查结论；**逐章呈确认**——首章全目呈报（含十查全项），后续章只呈差异与各章十查🔴项。作者同意后 `novel_confirm_outline`〔谈〕。代码检查九节非空、至少一个完整单元、来源引用合法、窗口里有同名已确认条目〔码〕。提交 `design(chNNNN):`。**规划粒度变，确认粒度不变**：每章细纲仍逐章确认。
7. **重入与改纲**：修订确认细纲走候选再确认（版本+1）；人物自决类轻量改纲（只动单章、无下游影响）不跑影响分析；有下游影响先跑影响分析。原先按卷内高潮／约 10 章的段级回顾已由「幕末结算」取代（见第 6.10 节），卷纲偏差处的处理并入幕末结算，不另跑段级动作。

### 6.2 备料

1. `材料备料.mjs` 预览材料包（只算不写；默认段名/字数/完整性/缺口，需要逐字核对时加 `--全文 true`）。
2. 备料自查已前移到幕级：五项自查（主要人物超过 10 章未出场预警；预定死亡前 3 章内是否已埋日常细节；规划本章信息释放（同一信息再次释放须换载体，本章揭示量 ≤70%）；升级后 3 章内须实战首验；到期线索先排一次闲笔式强化）的判据单源在幕纲规格「备料自查」可选段，执行时机＝进一幕第一章前读本幕幕纲时一次过；备料段只做一句核对：幕纲里排的这一章要埋/要兑现的，细纲里有了吗——没有回细纲层补（重入勘误通道）。
3. `novel_assemble_materials` 落盘十段材料包：本章任务与确认细纲、硬约束禁区完成条件、当前事实与连续性、人物关系地点组织规则物件、时间位置与信息边界、故事线承诺线索、近期正文衔接、文风条目切片、暂定与警告、来源与版本清单。切片取最近内容：上一章定稿末尾 800 字、最近 3 章章摘要、时间线最近 20 条、文风最近 5 条、世界书事实最近 30 条。
4. 可选：自主补充材料（先预览再保存）；灵感库按关键词匹配 ≤3 条作参考。
5. 就绪播报：十段不是开写门槛，够不够开写由主控判断。

### 6.3 起草（`novel-drafting`）

1. **组装任务包**（按序）：第 0 件写作心智 → 广域视野两句（卷纲"卷末兑现"首句、契约情绪承诺首句）→ 任务目标（目标字数区间、逐单元字数配给）→ 确认细纲全文 → 材料包切片 → **文风基准**（三样按优先级：契约「叙事方式与文风基调」分部原文〔本书相对默认文风的调整〕＋本书记忆文风锚点条目〔取最近若干条〕＋默认文风全文；前两样与默认冲突时以前两样为准）→ 已登记补充 → 硬约束 → 本章创作准则 → 按场景功能选的写作卡与按索引选的 1–2 张散文卡 → 输出要求 → 交稿自查卡 → 候选事实段协议 → 写时发现（可选）→ 包尾语态样本（近三章章摘要里与本章同型的"语态样本"行）。开书即用默认文风写，不做开书前的文风对谈建档。
2. **写作心智**：写前重读、双位视角、在场、节奏跟随、角色自决、找乐子、读者在场、一气呵成（从第一句写到章末钩不中断；对包核对——写到衣着、称谓、物价、能力表现等具体处对照材料包，包里没有的不编造，就地标〔待查〕）。角色自决含**停笔报告**：某个叙事单元立不住（人物不肯动、因果接不上、细纲事件量明显不够写）时不硬写到底，只交一份报告不交稿，写明哪个单元、为什么立不住、建议细纲怎么改，主控走轻量改纲后再派。
3. 派起草子代理，**交付物二选一**——整章新稿或停笔报告（不产稿，草稿区无新文件，状态不变）。新稿产出 `稿N.md`（**收稿即待审稿**：`角色: 待审稿`、`选定: true`；重写稿先降级旧待审稿再写新稿），正文后附"草稿候选事实"段（事实、时间线、线索埋设与兑现、人物变化、场景升级、待查——`- 待查：<缺的东西>｜<出现在哪一段>`，只登记包里没有、正文已标〔待查〕的项），末两行是热回查与自评。
4. **验收**：只查不改；`核验字数.mjs` 机械统计正文汉字数并对照契约篇幅，字数不能用估数代替。
5. **欠产阶梯**：回炉扩写一次（每拍给新信息，可加 0–2 件卫星事件）→ 纯信息加密补写一轮 → 作者三选（收下、退回细纲、弃章）。超字交审读"一次净删"。收稿后把待查项汇总——先对世界书补查（查到→补进细纲查证行并在改稿轮落实），再素材库、再【待采风】；仍查不到或要作者定的并入定稿呈报的风险行，不阻塞审读。
6. **作者稿导入**：作者自己写的章用 `novel_import_draft` 导入，与 AI 稿地位相同；`角色: 待审稿`＝交审（默认用法）、`角色: 草稿`＝作者暂存还不交审；没有确认细纲时先反推细纲呈作者确认〔谈〕。

### 6.4 审读（`novel-review`）

1. `确定性检查.mjs`：要求唯一待审稿；算正文统计、篇幅核对与审读指纹；跑两个确定性模块——文本规范检查（篇幅、空稿、套话黑名单两条、连续空格，黑名单在 `review/src/checks.ts`）与设定与时序核对（细纲〔硬〕行的必须出现与禁止出现，语义类转交审读）。
2. 派全量审读子代理（默认一次覆盖九维）：章节结构、人物与关系、情节与因果、信息披露、线索与伏笔、节奏与张力、读者承诺、文风与表达、世界内合理性（能力对量级、时代穿帮、称谓礼制、物价度量耗时、季节天气与时间线、人物状态与上章衔接）。任务包按固定件在前、章别件在后排列（命中前缀缓存），材料全部内联（含世界常量与量级切片——按细纲查证行与材料包命中的条目粘贴，未建常量如实写）。需要深挖某一维时换单维底本。
3. 按模块逐个 `novel_record_review_findings` 回写，零发现项也要回写；回写必须带当前审读指纹〔码〕。
4. 处置：每条发现项取六值之一（已解决、已接受修改、作者保留、已驳回、无法判断、已转提案）；创作取舍呈作者；硬伤未处置不进定稿准备〔谈〕。**默认处置口径**（本书未另定口径时）：机器轨低/中与模型轨建议/仅供参考级、且修改建议可机械执行的发现项，主控直接按建议处置，不逐条呈作者，定稿呈报里列一行汇总，作者可翻案；高/硬伤级与涉创作取舍（走向、人设口径、单段删减超过两成——以该段字数为分母）的仍逐条呈报。
5. 处置路由：表达层记 `已接受修改`、改动说明写「留润色」（纯处置批），由润色一并处理；语义层回改稿；细纲层回细纲；材料层回备料；账本层回沉淀；涉及设定取舍的硬伤由作者裁决。同类问题两轮未解就升一级。记录与处置完成后进入《改稿》（第 6.5 节）；发现项全部处置、且不再需要改稿后，才进入《精修润色》（第 6.6 节）。

### 6.5 改稿（`novel-revision`）

1. 从状态查询取审核记录哈希，读待处理项。
2. 有正文改动时派改稿子代理：任务包＝改稿章程＋待审稿正文＋已授权处置清单＋硬约束＋契约文风。改稿方向先结构、再人物、最后文字，只改授权处。
3. `novel_apply_revision_batch` 落实：哈希不符、编号未知、上游条目混入都整批拒绝〔码〕；新稿版本+1，旧稿降级留档。
4. 正文或审读依据变了就重审；小改用 `novel_apply_revision` 快路。
5. 第 3 轮仍未解决时标"须作者决定"并附瓶颈诊断（建议，不是门禁）。
6. 涉及上游设定的问题走提案流程（第 5.8 节）。

### 6.6 润色（`novel-polish`）

发现项全部处置、且不再需要改稿后使用。

1. 取当前唯一待审稿（即审读通过的那一稿）作为源；作者手写或手改的稿默认不润色。
2. 任务包：第 0 件润色心智（删留 → 节奏 → 语态的先后序；弱段定位、删留三分判、位置判、语态接缝核、对白过句、停机与转呈）＋批 1 表达清理、批 2 节奏与重塑参考全文＋文风基准（与起草同一套三样：契约第五部调整＋本书文风锚点＋默认文风全文）与硬约束＋密度数值行＋正文（只送一次）＋候选事实原文。
3. 子代理先跑批 1（去 AI 痕迹、语言自然化、冗余精简），输出全文中间版；再跑批 2，输出修订指令集并定点落成终稿。
4. 落稿：先降级旧待审稿再写新稿；新稿 `生成模块: 润色`，`父版本` 指向取源那一稿（审读通过稿）。
5. 主控验收：必须出现与不得出现的词逐条核对；全章正文删减不超过两成〔谈〕（以源稿总字数为分母）；候选事实段原样保留。
6. **登记承接**：验收后调 `novel_record_polish`（传 `审核记录哈希` 与 `稿件`＝润色终稿路径）登记承接——工具核对保真与候选事实段、做确定性复核；被拒按原因退回相应批或交作者，不重跑审读脚本。作者稿或作者不要润色时以同一工具传 `跳过`＋`理由` 登记跳过。润色后不重跑九维语义审读，只做保真核对与两个确定性检查的复核。**承接登记后再要求润色＝换稿**——新润色稿不是被审稿的直接子稿，承接工具会拒；走重审（新审读轮）后再润色，或作者经编辑器手改。

### 6.7 沉淀组包（`novel-settle`）

1. 派沉淀对账子代理：输入确认细纲相关部分、材料包事实与线索段、计划时间线、作者已给处置与例外、世界书模块清单、待审稿全文。输出六段：五段时间线变更、账本变更、本书层记忆候选、章摘要（≤200 字，含语态样本与章末状态）、事实变更＋第六节「入档后回写候选」（人物认知增量/金手指代价/常量回写候选/写时发现分拣建议四小节——不进待定稿包七件、只供主控呈报与入档后回写，空节写「无」）。只核对、不落账。
2. `定稿备包.mjs` 预览七件。
3. 主控独立语义核对：主体、时点、原文证据、事实还是推测。
4. `novel_prepare_pack` 落盘待定稿包；候选格式先校验，失败零写盘〔码〕。章级卷对账列出计划、实际与偏离。

### 6.8 作者定稿裁决与入档

1. **呈报**「本章只需看这几处」三行制：①偏离项与处置选项（卷对账偏离项）；②需作者决定点——文风锚点（前五章各问一次，之后作者主动点名时再收）、写时发现去向中的例外、待查项仍未解决的；③风险行——润色确定性复核新增中/低项、保真保留项、建议级处置汇总（编号＋一句）。末尾折叠行：字数、七件变更计数。作者一次表态，请其批准或退回。偏离处置结论作为 `## 决策` 条目补进沉淀候选的本书层记忆段（条目名或正文逐字带偏离项名——进度卡按名匹配扣减未决偏离），重调组包随定稿原子写入。
2. **退回**：删掉待定稿包，按根因回改稿、细纲或提案流程。
3. **入档**：`novel_settle_chapter` 弹出作者审批〔码〕；等待期间包或契约有变化则批准作废；批准后写定稿章、章摘要、世界书事实、时间线、账本、本书记忆，单次提交 `ch:`。入档成功后自动清理本章草稿区五处（草稿/材料包/审核记录/待定稿包/候选细纲，含旧格式路径）并在草稿区快照仓留痕——草稿区体积不随书增长；清理失败不影响入档，存量旧书可跑 `草稿清理.mjs`（默认只算不写，`--执行 true` 补清）。
4. **入档后**：`novel_roll_window` 把窗口条目标为已消费；**按作者在定稿呈报里的表态逐件回写**——认知增量/金手指代价经 `novel_confirm_worldbook_entry` 写入（每件一笔 `design:` 提交，不再另行呈报；作者未点名否决的默认执行），常量已随事实变更段（模块=世界常量）随入档自动追加，复现两次以上的程序细则回写进对应局规则／世界规则条目的「程序细则（正文生长）」行；"写时发现"按分拣建议落处执行（记 pending→作者确认后排期）；更新信息释放台账。

### 6.9 跨章与连写

- **单章委托**（默认）：入档后停下，下一章是新委托。
- **连写授权**（作者明示"连写 N 章"）：入档后直接进下一章；细纲首张全目呈报，之后只呈差异行与必报行；审读与沉淀准备可以并行（并行的是准备，不是入档）。
- **到点收尾**：每轮最多 5 章（上限 5，到点必须汇报近况、窗口余量与欠账；续写须再授权）。
- 细纲确认后，备料、起草、审读、润色自动接续（顺序：起草→审读⇄改稿→润色）；遇到新的创作选择、上游变更、语义冲突、发现项处置、定稿裁决时停下交作者。

### 6.10 卷末

卷末章定稿后一批完成（幕末结算与卷末流程已拆到《卷幕规划》技能包，`novel-arcplan`）：

1. **卷级卷对账**：伏笔账、承诺账、信息释放台账逐行对齐，跨卷线索移交，规划下一卷的期待钩补偿位；写到 `书房/卷末/<书名>/卷NN-卷对账.md`。
2. **卷摘要**：`卷摘要候选.mjs` 汇编本卷章摘要与账本线索（缺章摘要时失败）；呈报时对照卷纲压力升级检查的卷末去向与终局暗手；作者同意后 `novel_confirm_volume_outline` 落盘。下一卷第一章的近期正文衔接会自动带上整份卷摘要。
3. **幕末结算**：每幕写完时触发（六步见《卷幕规划》「幕末结算」节，思考程序照该包步骤卡-幕末结算）：核对写时发现遗留（分拣在每章沉淀步已执行，草稿区随定稿清理；本步核对 pending 未消化条目与沉淀第六节遗留）、核对幕纲「线与伏笔」、更新出场人物状态、可选读者通读本幕定稿正文、结果写入本幕幕纲「幕末结算」段（`novel_confirm_volume_outline` 目标幕纲覆盖、版本+1）、写下一幕幕纲。**卷的最后一幕的幕末结算与本节卷末流程合并做**，不重复跑一遍。
4. **下卷注意事项**：问作者「这一卷写下来，有什么要提醒下一卷注意的？」——有则经 `novel_note_pending` 落 `故事剧情/分卷布局.md`「卷间衔接」节待补便签（文本以「下卷注意·卷<NN+1>：」开头）；对方法论/工具本身的意见属产品反馈，不记进书里；下一卷卷纲确认后清除便签。
5. **下一卷**：回到《卷幕规划》——开卷先读上卷遗产、跑强制多方向，再确认卷纲、计划时间线与第一幕幕纲。


## 7. 横切流程

### 7.1 恢复

`novel_get_story_status` 窗口化：完整返回「章号最大的 20 章＋未定位章」，其余章一行摘要（已定稿＋完成/未完成）；传 `最近N章` 或 `卷` 展开指定范围，返回带 `总数/完整返回数/省略数`。长书恢复不再把全书事实清单灌进上下文。状态查询不装配 recovery `injection`（不读材料包）；`novel_get_book_progress` 的章列表只列首尾各 15 章并标省略数，完整明细按卷查 `story_status`。

任何时候说"继续"，主控都按第 5.1 节校准状态、呈回归简报，再按建议环节与作者意图进入对应节点。中断的写入事务会在下一次写入前自动恢复。

### 7.2 吃书补偿

修改已定稿内容的唯一通道：先走提案与影响分析，作者裁决后 `novel_apply_retcon`；代码弹出作者审批〔码〕，提交 `retcon:`。

### 7.3 作者直接编辑

- 在书房编辑器里改真源工件（契约、大纲、世界书）并保存，产生 `fix:` 提交；主控收到保存通知后只核对差异与影响，有实质影响才呈报提案。
- 书稿编辑器：选区或右键发起润色、扩写、精简、续写、审读批注；`novel_editor_suggest` 产出行内建议，作者逐条采纳、拒绝或换一版，再保存。

### 7.4 检索增强（可选，默认关闭）

嵌入索引定稿切片，供 `novel_search_finalized` 检索已定稿内容；场景识别与重排可选。失败时显式降级。

### 7.5 备份与导出

`一键备份.mjs` 生成书仓备份与 SHA-256 清单；`最小导出.mjs` 把指定范围的定稿汇成合集（只含定稿）。两个脚本都属《最小导出》技能（`novel-export`）。

### 7.6 排障

作者反馈书写崩、写水、人设崩、伏笔没收时，主控读《排障-索引与改稿流程》的排障索引，按症状倒查病因层与对应判据件，再按操作量级决定改法。症状以重读时的感受或审读发现为入口（越写越平、突然泄气、卷末收不住、换图后接不上、读着水等）。
