# 创作域术语

创作领域的词：一个词在本产品里指什么。工程域术语（真源、回执、判据件等）在仓根 [GLOSSARY.md](../../GLOSSARY.md)，本文件不重复定义。

相关：[是什么](是什么.md)、仓根 [GLOSSARY.md](../../GLOSSARY.md)（工程域术语）。

## 9. 术语表

| 术语 | 定义 |
| --- | --- |
| 工作区 | 会话选中的作品根目录，可以放多本书，也是参考书库的作用域 |
| 书仓 | 一本书的目录与 Git 历史，含 `作品契约/契约.md`；书锁的作用域是它，不是工作区 |
| 书房 | 工作区下的跨书资产目录：灵感池、素材库、参考拆书成果、评审底本；跨书共享，不属于任何一本 |
| 主会话 | 某个工作区里与作品对应的主对话 |
| 主控 | 主会话中负责调度的 agent |
| 真源 | 已确认的设计与沉淀事实，只经专用工具写入。**注意同词异义**：工程语境里的「真源」指「某一类数据的唯一权威副本」（见 [GLOSSARY](../../GLOSSARY.md) 的单源义），两者不是一回事，看语境区分 |
| 留白 | 设计件里"没想好、不勉强填"的合法状态；它不是缺失值、不是待办，不该被填满 |
| 幕 | 分卷之下、章节之上的剧情单元（一本卷分若干幕，一幕章数中位约 25、常见 13–50 章），由幕纲规划；与理论里的"三幕结构"不是一回事 |
| 幕纲 | 一幕的计划书：本幕故事、线与伏笔、出场人物、查证清单、章组排布、幕末结算六段（＋可选备料自查）；真源 `故事剧情/卷规划/卷NN/幕纲/幕NN-幕名.md` |
| 幕末结算 | 一幕写完时的收束动作（替代段级刷新）：核对写时发现遗留、核对伏笔埋收、更新人物状态、可选读者通读、结果写入幕纲「幕末结算」段、写下一幕幕纲 |
| 卷幕规划 | 每卷每幕开头与收尾的技能（`novel-arcplan`，0.0.56 从定调设计与定稿沉淀拆出）：开卷走 强制多方向→卷规划→分幕→第一幕幕纲，收尾走 幕末结算→卷末与卷摘要；判据要点随两张步骤卡挂，卡住或深挖时整读对应判据件 |
| 设计草案 | 逐部设计时先写在书房的过程稿，聊完、作者确认待改项后再经工具写入真源 |
| 作品契约 | 一本书的顶层约定，分部更新、绝不整体重写 |
| 契约六部 | 题材与读者定位、核心看点与差异化、阅读体验与情绪承诺、主角原则与关系边界、叙事方式与文风基调、创作禁区与不可妥协项 |
| 章节篇幅 | 契约"阅读体验与情绪承诺"下的子节，目标、下限、上限三个正整数 |
| 快速开写（路径 A） | 一次起草全部开写所需设计、作者过目一次的设计路径 |
| 逐部设计（路径 B） | 契约、世界书、全书大纲、分卷、卷纲逐部细聊逐部确认的设计路径 |
| 对手梯队 | 全书大纲"核心冲突与对抗力量"内的反派分层子表（层级、存活周期、代表对手、出牌与去向） |
| 压力升级检查 | 卷纲第五段五核对项：激活层级对齐、对手出牌、卷末去向、终局暗手、本卷升级位 |
| 取数算式 | 引用参考标尺数值时的呈报行：`取数：参考标尺·<行 ID>` |
| 强度三档 | 参考标尺每行标注：`硬`＝红线（踩了要改）／`参考`＝典型区间（偏离要说明）／`对照`＝模式档参照（只提示不拦卡） |
| 单源资产 | 数值或判据的唯一数据源文件，其他位置只引用不内联 |
| 近期窗口 | 近期要写的章节清单，第一条条目名必须与第一章章名一致 |
| 章细纲 | 动笔前的一章计划，确认后才进入正文 |
| 写前十查 | 确认细纲前的十项检查，机器四查加过目六查 |
| 章末双钩 | 章尾并留的期待钩与悬念钩，设计期排期 |
| 材料包 | 起草前组装的十段材料，是切片不是全文 |
| 候选事实段 | 草稿正文后附的事实、时间线、线索、人物变化清单，供沉淀对账 |
| 待审稿 | 起草与必要修改完成后交审读的版本，同一时间只能有一份 |
| 停笔报告 | 起草子代理的两种交付物之一：某个叙事单元立不住（人物不肯动、因果接不上、细纲事件量明显不够写）时不硬写到底，只交一份报告不交稿，写明哪个单元、为什么立不住、建议细纲怎么改；主控走轻量改纲后再派 |
| 润色承接 | 审核记录中记明「当前稿是已审稿经润色的直接子稿、保真与确定性复核通过」（或作者登记跳过）的字段；推导据此认可审核仍有效（`core/src/evidence/record.ts` 的 `PolishCarryover`，由 `novel_record_polish` 登记） |
| 审读 | 一次按维度检查正文的运行（含审读指纹）；与"审核"不互换 |
| 审核 | 章节流程中的审核阶段，及审核记录、审核结论；是流程位置，不是一次检查行为 |
| 世界内合理性审读 | 全量审读第九维：正文写出的能力、风物、称谓、物价、时间与人物状态是否在本书世界自己定的边界之内（量级表、已展示锚点、世界常量、近期正文衔接对照） |
| 发现项 | 审读给出的单条问题，处置取六值之一：已解决、已接受修改、作者保留、已驳回、无法判断、已转提案 |
| 默认处置口径 | 本书未另定口径时的建议级发现项处置规则：机器轨低/中与模型轨建议/仅供参考级、且建议可机械执行的，主控直接按建议处置，定稿呈报列一行汇总，作者可翻案；高/硬伤级与创作取舍级仍逐条呈报 |
| 待定稿包 | 定稿前组装的七件加清单，供作者裁决 |
| 定稿 | 作者批准后写入 `定稿/` 并产生 `ch:` 提交的章节；只增不改，要改走吃书补偿 |
| 吃书补偿 | 修改已定稿内容的正式流程，留痕且需作者审批 |
| 故事账本 | 故事线、人物弧线、承诺、线索、时间线五本账 |
| 本书记忆 | 获批沉淀的本书层记忆（文风、决策两类；旧书的对话/灵感文件只读兼容） |
| 默认文风 | 起草、润色、审读共同的文风基准文件（五层立场）；契约第五部调整与本书文风锚点优先于它 |
| 信息释放台账 | 书房里按书记录"读者最终该知道什么"及逐章揭示进度的台账 |
| 回归简报 | 恢复时向作者呈报的近况：三行必报，欠账行在未决偏离 N>0 时追加（常态四行，N=0 时三行） |
| 卷对账 | 计划与实际的对照：章级随待定稿包生成，卷级在卷末汇总 |
| 心智条目 | 嵌在流程某一步上的思维程序，运行时不超过两行，带停机条件 |
| 判据件 | 知识库分发到技能里的方法论文件，规定怎么判断，按整件读；一次读一部分会漏判据 |
| 八部 | 灵感库的八个部（0.0.58 重排）：人／地／物／事／知／言／象／镜——一部一册零件卡，部总数 8 封顶 |
| 时效三态 | 零件卡第十列：`长青`（默认必填）／`时效｜首发YYYY-MM-DD｜半衰期约N月`／`年代锚｜流行于YYYY年代` |
| 采风 agent | 按《素材库与采风》采风检索底本派发的检索子代理：走素材库＋网络两源，产出十列零件提案落待裁决暂存，不写正库 |
| 参考标尺 | 节奏、比例、结构等数值的唯一来源；按规划三段（大纲／卷纲／幕纲）分节，章级执行期不查本表 |
| 体量对账 | 开书与分卷时按本书规划逐项对照参考标尺的检查：列＝体量项｜参考标尺建议（取数算式）｜本书规划数｜差额｜处理（补足／说明理由）；规则单源在参考标尺「体量对账」小节 |
| 世界常量 | 世界书的可选模块（写入时自动登记）：时代基线、风物速查、称谓与礼制、度量与物价、技术水平等速查表条目，写到具体处对照，不凭空编造 |
| 量级表 | 力量体系条目的可选节：逐阶写力量／速度／破坏范围／以一敌几／续航／感知范围／恢复／越阶代价，能判断「这一下他做不做得到」 |
| 已展示锚点 | 力量体系条目的可选节：正文写过某人在某阶做到了什么，后文不得写得更弱；超出要有理由（突破、法宝、代价） |
