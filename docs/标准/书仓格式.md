# 书仓格式与修改边界

此文概述贡献代码时必须保留的公共契约。解析与写入实现位于 `packages/core/src`，测试中的合成夹具是可执行示例。

## 文件真源

书仓通常包含 `构想`、`作品契约`、`故事剧情`、`世界书`、`定稿`、`账本`、`本书记忆` 和 `草稿区`。工作范围内的 `书房` 保存跨书素材。书 id 来自作品契约，不能凭目录展示名替代。

`故事剧情` 是书级规划树：`全书大纲.md`（九部）与 `分卷布局.md`（八部）在顶层，`卷规划/卷NN/` 下依次是卷纲、计划时间线、近期窗口、幕纲与章细纲。0.0.86 前该目录名为 `大纲`。

卷目录形如 `卷01`，章号全书连续，文件中的章号使用既有四位编号规则。不能把“本卷最大章号”当作本卷章数，也不能把窗口耗尽当作整卷完成。

### 幕纲（0.0.52 起）

幕是卷与章之间的剧情单元，一卷分若干幕。幕纲是真源工件，位置 `故事剧情/卷规划/卷NN/幕纲/幕NN-幕名.md`——卷号与幕号均两位数字（`幕01`），幕名走与章名相同的路径白名单校验（不含路径分隔符、保留名等）。0.0.57 起 frontmatter 带版本字段（首次 v1、再确认 +1、原样重跑复用；旧文件无 frontmatter，下次确认按 v1 起步，无需迁移）；段级状态另写在 `##` 段标题的尾注里，段名校验不受 frontmatter 影响。

正文含六个必备段，段名逐字固定：`## 本幕故事`、`## 线与伏笔`、`## 出场人物`、`## 查证清单`、`## 章组排布`、`## 幕末结算`。缺任一段标题即拒写，逐段报 `幕纲段落不完整:<段名>`；段可标 `〔留白〕`（开幕时「幕末结算」留白合法），标题须在位。另可加可选段 `## 备料自查`，不参与段名校验。段标题尾注（`〔已确认〕`／`〔留白〕`／`〔暂定〕`）在判段名时被剥离，与卷纲规则一致。

写入只经 `novel_confirm_volume_outline`（`目标: 幕纲`，另带 `幕` 与 `幕名`），随确认产生 `design:` 提交；幕纲不是设计面七态的必要条件——卷目录下存在 `幕纲/` 与幕纲文件不影响当前卷推导（旧书无幕纲行为不变）。确认细纲的来源引用可写 `来源:故事剧情/卷规划/卷NN/幕纲/幕NN-幕名.md@<版本>`，影响分析据此把幕纲变更传播到该章细纲。

结构化 Markdown 的 frontmatter、版本、模块标题、引用路径和哈希由对应解析器处理。草稿/候选不是已确认设计，定稿不是聊天里的一句“完成”。恢复进度从当前文件推导，不额外维护一套会话状态账。

### 卷纲/计划时间线版本字段与草稿区章键（0.0.57 起）

- 卷纲（`故事剧情/卷规划/卷NN/卷纲.md`）、计划时间线（`故事剧情/卷规划/卷NN/计划时间线.md`）与幕纲同批起写入 frontmatter 版本字段（`状态/版本/父版本/生成模块`）：首次 v1、正文变化 +1、原样重跑复用版本。旧文件无 frontmatter——下次确认按 v1 起步，无需迁移。确认细纲的 `来源引用` 写 `@版本` 时，影响分析把「引用版本大于文件当前版本」报为「引用了未来版本」提示（只提示，不改边的存在性；文件无版本沿用现状）。
- 草稿区五处工件的章键带章号：`草稿区/章细纲/卷NN-NNNN-章名.md`、`草稿区/材料包/卷NN-NNNN-章名/`、`草稿区/草稿/卷NN-NNNN-章名/`、`草稿区/定稿准备/卷NN-NNNN-章名/`、`草稿区/审核/卷NN-NNNN-章名.json`——章号四位，与确认细纲/定稿一致；未定位章（窗口新章，章:0）占位 `0000`。旧格式 `卷NN-章名`（无章号）读侧兼容：新键不存在时按旧键找，旧书无感；候选细纲在章定位之前落盘，按（卷、章名）认领任一键位上的同名候选。
- 定稿入档成功后清理本章草稿区五处（含旧格式路径），草稿区快照仓留痕；存量书可跑 `草稿清理.mjs`（`--book <root> [--卷 N] [--执行 true]`，默认只算不写）。写时发现的分拣在沉淀步完成后才清理——幕末结算第 1 步核对的是 pending 记录与沉淀第六节遗留。
- 审核记录随入档清理，跨章统计需要的那几列另存（0.0.87）：入档前工具从本章审核记录派生一份计数摘要到 `定稿/卷NN/审读摘要/NNNN-章名.json`（`paths.审读摘要`），随同一次 `ch:` 提交。内容只有模块发现项计数、严重程度分布（按 `归一化严重程度` 归并到高/中/低，认不出的原值计入「其他」）、处置分布、已处置/作者保留条数与审核记录哈希/审读指纹/审稿哈希——**不含问题说明等原文**，故可长期留。子目录与 `.json` 扩展名是有意的：定稿区所有章扫描器（检索、进度、导出、组装、章号冲突）只认 `定稿/卷NN/` 正下方的 `NNNN-章名.md`，该文件对它们全部不可见；卷内子目录先例是 `补偿/`。摘要纯派生、键序固定、无时间戳，同一份审核记录重跑产出逐字节相同的文本；入档重跑（补提交）命中可信收据即不重复提交，摘要重写只在字节不同时发生。


## 写入约束

### 章节篇幅约定

在作品契约的“阅读体验与情绪承诺”分部内，使用可选三级子节记录本书篇幅。下面是目标四千汉字的宽松示例，具体数值由作者确定：

```markdown
### 章节篇幅
- 目标汉字数: 4000
- 下限汉字数: 3500
- 上限汉字数: 4500
```

子节只含这三项正整数，满足下限 ≤ 目标 ≤ 上限；其他说明放在相邻子节。沿用 `novel_update_contract` 更新该分部，保留其中已有内容；所在分部确认后生效。缺子节的旧书保持兼容，不自动套默认范围。

更新契约分部只替换显式给出的分部：未给出的分部、六部之外的 `##` 小节、一级标题与 frontmatter 内容与顺序保留——不是逐字节：行尾统一为 LF，frontmatter 保留字段语义（内联列表可能改写为块风格、注释可能丢失）。漏写〔状态〕标签的分部按「留白」对待，但原正文保留。已配置「章节篇幅」的书，更新「阅读体验与情绪承诺」而不写该子节时，旧子节整块接回。两类输入会被拦下且不落盘：正文自带其它 `###` 标题（如 `### 篇幅要求`）以致缺合法「章节篇幅」子节，报「已拦下以免丢失原有篇幅」；该分部不带正文或置〔留白〕，报「已拒绝」——两句都以「章节篇幅」点名子节，可据此识别。子节写出来但三项不齐或不是正整数时，仍按原有篇幅校验报错，同样不落盘。这类拒绝不是篇幅的「配置错误」状态（后者指篇幅子节解析失败、审读核对该节失效），两者不混用。

不回溯旧数据：旧版本更新分部时清空过的正文或被抹掉的篇幅子节，只能靠书仓自身的 Git 历史找回。

细纲和起草继承约定，按本章任务分配预计篇幅。审读脚本按正文汉字数核对，包含章标题、排除 frontmatter 与候选事实；范围外的情况进入原“文本规范检查”发现项，沿用修改或作者保留等处置；不新增审核步骤，也不自动裁稿。契约修改后旧审读证据失效，需按原流程重跑。

### 审核记录（0.0.54 起润色承接）

章节顺序为「起草 → 审读 ⇄ 改稿 → 润色 → 沉淀」时，润色会改字，审核证据绑定的正文哈希与审读指纹随之失配。审核记录（`草稿区/审核/卷NN-NNNN-章名.json`，0.0.57 起键带章号；旧书 `卷NN-章名.json` 读侧兼容）据此新增可选字段 `润色`（`core/src/evidence/record.ts` 的 `PolishCarryover`），由唯一通道 `novel_record_polish` 登记：

```json
"润色": {
  "状态": "已润色",              // 或 "已跳过"
  "父稿哈希": "<被审稿正文 sha256；已跳过时＝稿哈希>",
  "稿哈希": "<当前稿正文 sha256>",
  "审读指纹": "<当前稿按现行算法的审读指纹>",
  "稿件": "草稿区/草稿/卷NN-NNNN-章名/稿N.md",
  "理由": "已跳过时必填",
  "确定性复核": [{ "模块名": "…", "严重程度": "中", "问题说明": "…" }],
  "时间": "<ISO>"
}
```

认定规则（`core/src/derive/scan.ts`）：记录无该字段时按旧规则判过期、承接为假；`已润色` 时当前稿哈希须等于 `稿哈希`、`父稿哈希` 须等于记录的 `审稿哈希`、当前指纹须等于 `审读指纹`，方可判未过期；`已跳过` 时当前稿哈希须等于 `审稿哈希` 与 `稿哈希` 且指纹未变。任一不符（润色后又改字、细纲升版、材料刷新）按现行规则判过期。字段非法（缺哈希/指纹/稿件/时间，或 `已跳过` 无理由）时整体丢弃该字段，不让整份记录解析失败；`computeReview`/`ingestFindings` 重置轮次时清掉该字段。

### 通用写入规则

- 所有输入路径均是受校验的仓内相对路径；拒绝盘符、路径逃逸、保留名和不受信任链接。
- 候选与普通文档修改复用原生观察和精确写入授权；并发修改使旧观察失效。
- 多文件定稿/沉淀保留事务边界，失败可恢复，不能拆成若干无保护覆盖。
- 作者批准绑定本次操作。取消、拒绝或迟到答复不能授权写入。
- 定稿、构想快照和其他冻结工件不通过普通编辑直接覆盖；影响已定稿内容的变更走已有补偿流程。
- 成功后可核对文件、账本及 Git 提交；提交失败不得重复升版或重写相同正文。

## 检索与派生数据

索引、缓存和材料包具有来源与新鲜度要求，不能代替正文、确认规划或账本。模型、维度、指令或原文变化后应按各自契约失效；模型服务失败时显式降级，不伪造增强效果。

## 兼容性

修改字段、路径、确认状态或格式版本时，附旧数据夹具、迁移/回退说明和验证。预览期也不能把不兼容数据变化藏在普通 patch 中。v6/v7 旧书不属于已验证的自动迁移输入。
