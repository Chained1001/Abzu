# 判据体系

方法论资产（判据件、参考标尺、写作卡、心智条目）的结构、来源与校准方式，以及它们从知识库提取进仓的管线。

相关：[技能编写规范](技能编写规范.md)、[技术现状](../技术/现状.md)。

**其他方法论资产**：

- **参考标尺**（`novel-design/references/参考标尺.md`）：节奏、比例、结构等数值的唯一来源，数字是参考区间不是配额。按**规划三段**分节——零、先定档（八个轴，一次定完）／一、大纲（全书大纲与分卷布局期）／二、卷纲／三、幕纲，另附「本书基线」「体量对账」「长度换算」三个附录。每行标强度三档：`硬`＝红线（踩了要改）／`参考`＝典型区间（偏离要说明）／`对照`＝模式档参照（只提示不拦卡）。**章纲与正文执行期不查本表**：章长归契约、起草与审读，章级红线（钩型配比、兑现密度、憋屈上限、章末未闭合项）内联在《写前十查》《全面审读》与《雷点清单》自带的判据件里，本表止于幕纲。
- **雷点清单**：常见毒点分类表，用作契约"创作禁区"的候选菜单与写前快扫。
- **写作卡**（`novel-drafting/agents/写作卡.md`）：场景卡七张（推进、塑造、动作、环境、开场、转场、趣味），按单元场景功能选用；散文卡组八张（句法节奏、零回指、对白工学、话题-述位、前景化、中心切换、连接词、修辞上探），默认按索引只读与本单元最相关的 1–2 张，作者点名或深挖时整组读；自查卡两张（POV、行文），含 AI 痕迹六条。
- **默认文风**（`novel-drafting/references/默认文风.md`）：起草、润色、审读共同的文风基准（叙述者／表达逻辑／节奏／语言／情绪与趣味五层立场）；密度类数值不在此文件，单源在写作卡。开书即按默认文风写；契约第五部只记本书相对它的调整，本书文风锚点（本书记忆·文风类条目）优先于它。
- **底本**：写前十查、全量审读与八个单维审读、作家/读者两席评审、改稿章程、沉淀对账、采风检索。
- **模板与规格**：世界书七类条目模板（人物档案、世界规则、力量体系、组织、地图、局规则、世界常量）、对手梯队子表规格（以上在定调设计）；卷纲固定段规格、幕纲固定段规格（0.0.56 起随《卷幕规划》）；章细纲固定小节规格（细纲备料）。
- **灵感库种子**：八部零件卡共 131 条（0.0.58 八部重排），首次翻库或采风时由《素材库与采风》展开到书房。

### 1.2 七原语：判据的推导根系

各判据件里的方法都能归到七条原语。原语是判据为什么成立的解释，供维护判据和遇到新情况时推导用（运行时判据件引用了这些原语，但没有定义它们）。

| 原语 | 原理 | 自检问题 |
| --- | --- | --- |
| 期待感 | 读者追读的动力是"还欠着一个没兑现的好结果"；彻底满足，追读就停 | 这里欠了读者什么？这笔账读者想不想收？ |
| 信息差 | 张力的大头在谁知道、谁不知道、读者比谁多知道一点 | 主角、对手、读者各知道什么？三列全等就是流水账 |
| 在乎×不确定 | 张力＝在乎程度×不确定性，任一为零张力归零 | 读者在乎这个人吗？结局一眼看到头吗？ |
| 代价 | 读者对"得到"的感受强度等于为之付出的代价 | 这个收获是白捡的吗？谁付了账？同时失去了什么？ |
| 动机链 | 人要东西，受阻，选择，被后果改变；只有这条链能推动故事 | 他此刻想要什么？什么在拦？他选了什么？后果是什么？ |
| 情绪兑现 | 读者投入了没兑现就是毒点；爽点是及时足额的兑现 | 这一章让读者付了什么情绪成本？还了什么？ |
| 变化 | 有效事件让人物的价值状态发生转变 | 这段结束后，谁知道的事、谁的关系、谁的处境变了吗？ |

### 1.3 人类参照带

五本成书（大奉打更人、诡秘之主、我真没想重生啊、绍宋、十日终焉）各抽 10 章做的机械统计，用作密度类判据的相对基线（提示级，不是阈值）：

| 指标 | 五书范围 | 用途 |
| --- | --- | --- |
| 句长标准差 | 16–46 字 | 句长均质化判据：人类方差大，AI 均质 |
| 相邻双代词起句（叙述句） | 0–0.7% | 主语重复：两连即异常候选 |
| 显式连接词 | 2.9–6.3 处/千字 | 密度本身不判错；成串、成对全套才是候选 |
| ≤8 字短句占比 | 5.7–39.6% | 快节奏书的短句带 |
| 对白行占比 | 23–49.5%（书级）；单章按章型：对白戏章 30–50%、叙事章 10–25%、独行章 3–10% | 对白参照；单章先分章型再对子带 |
| 感叹号 | 0.3–4.2 处/千字 | 书间差异大，只作单书对照 |

写作卡里另有带数值的密度预算：段末格言化 ≤2/章、比喻 ≤2/千字、破折号 0–1/千字（待实测校准）。

### 1.4 第三层：心智条目

心智条目是嵌在流程具体一步上的思维程序，每条在运行时不超过两行，并带停机条件（什么时候不用想）。全流程预算 30 条，目前进入运行时 30 条（0.0.58 起新增素材库与采风 2 条）：

| 阶段 | 条目（运行时标签） | 所在位置 |
| --- | --- | --- |
| 定调设计（7） | 规则连锁、金手指四轨道追问、配角功能一问、暗面一问、首尾镜像、弧光三型与落地两问、跨轨道自检 | `novel-design/SKILL.md` 各步骤 |
| 卷幕规划（1） | 卷级交叉思考（五条，核心问句挂步骤卡各步「同时想」） | `novel-arcplan/SKILL.md`「卷规划」节与 `templates/步骤卡-卷规划.md` |
| 细纲·单元排布（3） | 拆并、排序、配字 | `novel-outline/SKILL.md` 细纲段 |
| 细纲·写时整合（4） | 情绪接力、信息边界推演、冲突强度定位、双钩还债预检 | 同上 |
| 正文起草（8） | 写前重读、双位视角、在场、节奏跟随、角色自决、找乐子、读者在场、一气呵成 | 起草任务包第 0 件 |
| 精修润色（5） | 弱段定位、删留三分判、位置判、语态接缝核、停机与转呈 | 润色任务包第 0 件 |
| 素材库与采风（2） | 融合三条、四分管法 | `novel-forage/SKILL.md` 翻库节 |

贯穿各阶段的**恒定问题**有两族：读者在场（设计："读者买账吗？"；细纲："此刻最渴望什么？"；起草："他会猜到吗？"；润色："这句删了读者损失什么？"）和信息差（谁该知道什么、读者比主角多还是少、他此刻知道什么、这句是不是露了不该露的）。这里的"读者"是作者模拟的目标读者，是写作手段，不是真实读者数据。

## 2. 资产怎么进仓：提取管线

以下讲判据件从知识库提取进仓的工具与规则。上文讲资产的结构与内容，这里讲它们怎么来、怎么校准。

### 2.1 提取与筛选

1. 运行时判据件以仓内为准。知识库只在两种时候用到：项目初期按流程步骤提取方法论；作者说某项方法论优化了时，定向重新提取并集成。集成时按"纯写书技巧"的范围筛掉读者数据、平台运营之类内容。
2. 提取工具是 `node packages/bundle/scripts/kb-extract.mjs --source <知识库目录> --write [--out <目录>]`：映射表决定每个源文件分发到哪个技能，净版规则机械剥除来源行、编者注、理论编号锚，改写表处理逐字引语等既定编辑。定向集成时先 `--out` 到仓外临时目录，比对改动，筛选后再并入仓内。
3. `--check` 只比对不写，报告分发件与重新生成结果的差异。运行时件经筛选和重构后会与知识库有意不同，所以它只用来查看差异，不再作为发版检查。
4. 每个知识库件第 3 行是版本戳，标明最近一次提取所依据的知识库源版本。
5. 参考标尺、雷点清单、写作卡、底本、模板同样以仓内为真源。
6. **参考标尺的校准沿革**：v0.1–v0.3 以社区数据打底（2026-09-28）；v0.4 三层实测（2026-10-03：8 本机械审计、5 本 457 章切片、大奉与诡秘骨架层）；v0.5 五书校准（2026-10-11/12：大奉、诡秘、重生啊、绍宋、十日两轮独立拆解，七处冲突按分档、分带、豁免三种方式裁决）。校准报告与五书总对照在仓外证据存档（拆书校准、成品反推三轮），逐版改动见 git 历史。尚待校准：小/中反派的精确分级、关键事件全量计数、续航线容量、升级间隔数值、100 万字档样本（现仅半本）。运行时文件 v3 起只保留五列（id／项／参考／口径／说明／强度）与一句来源声明「只保留结论，不逐行自证」，不再保留逐行证据、校准过程与来源等级；本节的沿革记录因此是仓内唯一的校准追溯材料。
