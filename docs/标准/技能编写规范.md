# 技能编写规范

本规范约束 `packages/bundle/skills/` 下的全部运行时文件，以及新增或修改判据件、心智条目的方式。运行时文件是模型直接执行的程序，写法和代码一样要求可执行、单源、可验证。

## 1. 运行时文件分类

| 类别 | 位置 | 职责 | 谁读 |
| --- | --- | --- | --- |
| 节点技能 | `skills/<技能>/SKILL.md` | 节点内流程：何时做什么、调哪个工具、何时停下交作者 | 主控 |
| 子代理底本 | `skills/<技能>/agents/*.md` | 子代理任务书：输入契约、检查清单、产出格式 | 子代理（随任务包内联） |
| 判据件 | `skills/<技能>/references/*.md` | 方法论判据；35 个知识库件加预置件（参考标尺、雷点清单）与少量参考 | 整件读 |
| 模板与规格 | `skills/<技能>/templates/` | 工件模板、固定小节规格 | 起稿与核对时读 |
| 薄脚本 | `skills/<技能>/scripts/*.mjs` | 调用打包后 lib 的确定性 CLI；只算不写，或经写入器写入 | 主控在命令行运行 |
| 随包资产 | `skills/<技能>/assets/` | 灵感库种子等初始化资产 | 初始化时展开 |

技能加载名以 SKILL.md frontmatter 的 `name` 为准；frontmatter 必须是合法 YAML（测试会解析）。

## 2. 四层分工

运行时内容分四层，每层只做自己的事：

| 层 | 角色 | 单源位置 | 管什么 |
| --- | --- | --- | --- |
| 心智 | 调度器 | 各 SKILL.md 与任务包第 0 件中的心智条目 | 何时想、想什么、何时不想 |
| 判据 | 判据库 | `references/` 判据件、写作卡、雷点清单 | 想的时候对照什么标准 |
| 参考标尺 | 数值单源 | `novel-design/references/参考标尺.md` | 有数的红线从哪取数 |
| 工件 | 数据 | 书仓真源文件（契约、骨架、卷纲、细纲、账本） | 思维的输入与产出落点 |

心智只登记"此步查哪件"，不复制判据句；判据句写两处就会漂移。

## 3. 单源纪律

1. **数值单源**：节奏、比例、间隔等数值只写在参考标尺。SKILL 与底本引用时写取数算式行（`取数：参考标尺·固定层＋比例层×衰减×题材`），不内联数值。
2. **判据单源**：同一判据只在一个文件里写正文，其他位置写指针句（如"按散文卡组句法节奏卡三判据自查"）。
3. **协议串单源**：工具名、脚本参数、目录名、固定小节标题以代码为准。运行时文本点名它们时必须与代码逐字一致；`skills-core.spec.ts`、`skills-batches.spec.ts` 里有对撞测试。
4. **改单源时核引用**：改动单源后，搜索并核对全部引用位，同一提交里改齐。

## 4. 净版纪律

运行时文件只放模型能照做的归纳态内容。

1. **检测法**：把任务包里的每一句单独拿出来，模型能照做才保留。说明、身份、比喻、历史都照做不了，不进运行时。
2. **不写身份句和状态指令**：例如"你是资深作家""放下分析脑、成为主角"。改写成可执行的操作核（如"他此刻知道什么、不知道什么、身体感到什么、在怕什么"）。
3. **比喻只在解释位**：比喻不能放在规则位。
4. **剥除来源信息**：来源类型行、原话引用、可信度分级、编者推断标注、出处考古、变更记录，都不进运行时。知识库件唯一保留的元信息是第 3 行的版本戳。
5. **设计说明放在仓库文档或 git 历史**：理由、裁定过程、出处写进 `docs/产品文档.md`、`docs/技术文档.md` 或提交记录。

已知违例：`参考标尺.md` 末尾的「校准计划」「变更记录」两节约占全文 34%，每次整件读都会占用上下文，重构时移出。

## 5. 判据写法

1. **可执行优先**：优先写能落成检查项的判据（可呈报、可对账、可计数）。纯感悟型判据少放。
2. **负例正例化**：任何禁用句都要带替代动作（"禁 X，改 Y"）。不写"不要写得像 AI"这类抽象负例，它没有操作语义，还会抬高被禁内容的出现概率。
3. **能机械判定的交给代码**：计数、命名格式、路径、字数这类判断由代码或脚本完成，模型只做语义判断。现状缺口：破折号密度、比喻密度、句长分布等写作卡要求模型自己数，代码只算字数（见技术文档"已知问题"）。
4. **数值判据附打破条件**：说明什么情况下偏离合法。命中打破条件，或偏离作者自报值时，不记为发现项。
5. **用相对基线**：密度类判据以人类参照带作相对判断（见产品文档"人类参照带"），不用绝对的"AI 分"。
6. **整件读**：判据件按件整读，不按节切读；`§x.y` 是件内溯源注记。某一步长期只需要一小节，说明件的边界画错了，应该调整件的边界，而不是给读取行加节号。

## 6. 心智条目

### 6.1 条目结构

一条心智条目由八件组成，设计侧必须写全：

| 件 | 含义 | 为什么必须有 |
| --- | --- | --- |
| 触发点 | 流程中哪一步跑 | 没有触发点的思维指令会被模型每一拍均匀执行，均匀执行本身就是 AI 签名 |
| 思维序列 | 依次或并行想什么 | 顺序必须来自真实的信息依赖；没有依赖的子问标"并行" |
| 方法绑定 | 每一步对照哪个判据单源 | 防心智句与判据双源漂移 |
| 红线 | 不许发生什么 | 有数的写指标，无数的写禁行行为 |
| 落点 | 思维产出落在哪（申报行、自查行、正文决定） | 没有落点的条目无法观测、无法校准；纯内化判断必须声明"无落点" |
| 停机条件 | 什么时候不许想 | 制造执行分布的不均匀，这是人类思维与模型思维的分水岭 |
| 优先级裁决 | 与其他条目或约束冲突时谁赢 | 没有裁决规则时模型会就近默选 |
| 时序位 | 写前、写中还是写后 | 同一思维放错槽位就是在错的时点用对的思维 |

每条还要写出处，四选一：知识库件、参考标尺行、成品反推报告、作者裁定日期。四者都没有的候选只能停在待验证区，不进运行时。

### 6.2 运行时形态

进运行时的只有每条不超过两行的"运行时形态"：

- 触发点和时序位由条目在任务包里的位置与小节名表达，不写"何时跑"的说明句；
- 思维序列与红线压缩成两句可照做的话；
- 高频的停机短语（"不跑""让位"）保留在句内，跨条目的裁决表留给主控；
- 方法绑定与出处留在设计侧。

### 6.3 预算与生命周期

1. 每个阶段不超过 8 条，全流程不超过 30 条；候选条目不计入，作者采纳后才计数。新增须先删掉无用条目腾位，或由作者裁定扩容。
2. 预算管的不只是心智：同一任务包里同时在场的全部约束（硬约束、判据、心智、自查行）都要计总账。这本账目前没有实现。
3. 零消费即删：连续两批实测中，一条目没有任何可观测的消费（落点无产出、停机条件从未触发、审读发现项从未回指），就删除或降级到待验证区。这需要落点统计，目前也没有实现。
4. 全局裁决序：作者明示 ＞ 硬约束（禁区、信息边界、已排除走向） ＞ 参考标尺硬红线 ＞ 确认细纲（走向级） ＞ 文风画像 ＞ 条目之间按"生成让位于检查、检查让位于数据"排。
5. 自评纪律：模型自评只作定位信号（哪里最得意、哪里没劲），永不作合格判定。

## 7. 任务包工程

1. **自包含**：子代理看不到主会话，也不预装技能。所需的判据、材料、心智全部内联进任务包。
2. **首尾双锚**：必须持续在场的件（硬约束、心智运行时形态）放最前；一次性语料（细纲、材料包）放中间；紧挨生成点的锚（语态样本、落点自查行）放最后。中间件的关键要求由尾部自查行再点一次，抵消中部衰减。
3. **固定件前置**：每次不变的件排在前面，以命中宿主的前缀缓存。
4. **语态样本同型**：样本段落的场景功能与本章一致（打斗章用打斗样本）。
5. **主会话负载**：主控加载过的技能和读过的判据会一直留在会话上下文里，不会卸载。拆分技能、决定整件读的范围时，要估算一次完整流程的累计用量。

## 8. 规则依据

以下结论来自模型写作机制调研（2026-10-13），是上面各条规则的依据。外部证据多出自英文任务和非 DeepSeek 模型，规则进规范前要在项目主力模型上实测对照。

| 结论 | 证据强度 | 落到哪条规则 |
| --- | --- | --- |
| 同时在场的约束越多，全部满足的比例越低 | 强 | 心智预算、总约束账 |
| 长上下文首尾强、中部弱 | 强（Claude 系为主） | 任务包首尾双锚 |
| 示例能锚住显性统计特征（句长、口头禅、连接词习惯），隐性分布风格（修辞的分布、着力分配）模仿不可靠 | 中强 | 文风画像与语态样本管显性层；密度类问题交计数门禁 |
| 否定指令常被忽略，写出禁词会抬高它的概率 | 中强 | 负例正例化 |
| 自回归生成中不存在"回头修改"，真修订只能重生成或外部循环 | 机制事实 | 起草"一气呵成"防的是中断造成的上下文污染；修订靠润色与改稿轮 |
| 单次输出有长度墙，字数指令跟随不精确 | 强（机制）／中强 | 单元制排布、机械核验字数 |
| 提高温度增加多样性需配合选优 | 中 | 多版本择优（依赖宿主采样参数，未实现） |
| 自我校正只在表面层（格式、POV、禁词）有效，事实与一致性层自纠不可靠 | 强 | 写后自查只查表面层；事实核对必须对照材料包与账本 |
| 模型给自己的输出打分系统性偏高 | 强 | 自评只定位不判定 |
| 思考链语言会渗入正文 | 中（机制推演） | 正文生成少用思考模式（宿主配置） |

主要来源：FollowBench（arXiv:2310.20410）、Lost in the Middle（arXiv:2307.03172）、Language Models are not Naysayers（arXiv:2306.08189）、LongWriter（arXiv:2408.07055）、Large Language Models Cannot Self-Correct Reasoning Yet（arXiv:2310.01798）、Self-Refine（arXiv:2303.17651）、Self-Preference Bias in LLM-as-a-Judge（arXiv:2410.21819）。

## 9. 修改流程

1. **改判据件**：运行时判据件以仓内为准，直接修改。作者说某项方法论在知识库里优化了时，用 `kb-extract.mjs --write --out <仓外目录>` 重新提取，比对出改动，按"纯写书技巧"范围筛选后定向并入，不整件覆盖仓内版本。
2. **改预置件和 SKILL**：参考标尺、雷点清单、SKILL、底本、模板以仓内为真源，直接修改并核对引用位。
3. **登记**：新增或删除心智条目、判据件时，同步更新产品文档中的对应清单。
4. **验证**：运行 `pnpm test`（技能一致性与对撞测试）和 `pnpm check:public`（链接与公开内容检查）。
