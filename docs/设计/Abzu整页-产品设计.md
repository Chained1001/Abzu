## 0. 先说一句最重要的

作者的诉求是「进来之后**进行设计**」。这句话把一件事从可选项变成了必需项：

**书页必须能回答"这本书设计做到哪一步了、还差什么"。** 而设计面七态（`DesignPosition`：灵感阶段 / 作品定调 / 世界构建 / 全书大纲 / 分卷布局 / 当前卷规划 / 开写就绪）**客户端现在拿不到**——它只在 `novel_get_story_status` 的工具返回里（`packages/core/src/derive/design.ts:22-29`）。

没有它，进整页做设计等于进了一个空房间。所以本文的建议与原总设计相反：**书页第一期就要设计面七态，需要一条只读接口**。这是本文唯一需要作者批的数据面改动。

## 1. 第一屏：书架页

**明确答案：点 Abzu 图标进来，第一眼是书架页。不是"上次停留的位置"。**

理由：整页是 root scope，切会话不该换位置；而"上次位置"要落盘才能跨进程恢复，一落盘就要处理"书被删了/章号变了"这些失效情况。**书架页是一次点击就能到任何地方的根，代价小、没有失效问题。**

一个例外（不是"两者都有"，是返回栈）：**从对话切回整页时，回到刚才那一级**（进程内记忆，不落盘）。冷启动恒为书架页。

```text
┌────────────────────────────────────────────────────────────┐
│ 书架                                        [＋ 新建一本书] │
├────────────────────────────────────────────────────────────┤
│ ▶ 继续《长夜行》                                            │
│   卷02 · 第13章《夜渡》· 这章走到「审读」                    │
│                                              [进入 →]      │
├────────────────────────────────────────────────────────────┤
│ 《长夜行》                                                   │
│   已定稿 37 章 · 卷02 进行中 · 当前 第13章 审读              │
│ 《旧稿》                              ⚠ 书目缺少有效书id    │
└────────────────────────────────────────────────────────────┘
```

- 顶部「继续《X》」大卡：**当前书 + 当前章 + 当前环节**，一次点击直达章页。这是作者 90% 时候的意图，把最常做的事放在最上面。
- 下面才是完整书目。单书时两者重叠，不重复渲染（只有大卡 + 一行"书架里只有这一本"）。
- 每本书一行近况，数据来自 `shelf` 的 `progress`（`activeChapterLine` 现算，实测输出形如「卷02 第13章 夜渡 · 审核」这类一行话）。✅ 现成可用。
- 「＋ 新建一本书」→ **跳回对话**，不在页面上建书（建书要收敛构想七要素 + 〔谈〕确认）。

**本期不做**：新建表单、删书、改书名。

## 2. 四级层级怎么走

```text
书架页
  └─点书→ 书页
           └─点卷→ 卷页
                    └─点章→ 章页
```

四级都是**同一块整页区域换内容**，不是四个独立面板。顶部面包屑始终在位：

```text
书架 / 《长夜行》 / 卷02 / 第13章 夜渡
  ↑可点    ↑可点     ↑可点    当前
```

- 点面包屑任一级 → 回到那一级（仍在整页里）。
- 浏览器/宿主没有路由，所以**不做后退按钮**；面包屑就是返回路径。
- 唯一回对话的出口：点左栏任意会话。

**幕层不做。** 幕纲里「章组排布」是自由文本，代码没有章↔幕的机器可读映射，`/chapters` 也不返回幕归属。硬显示只能靠正则猜。**所以四级里没有幕，卷下面直接是章。**

## 3. 每一级放什么

### 3.1 书架页（工作区级）

| 区块 | 内容 | 数据 | 本期 |
|---|---|---|---|
| 继续大卡 | 当前书 / 当前章 / 当前环节 | `shelf.progress` ✅ | ✅ |
| 书目列表 | 书名 + 一行近况 + 书 id 异常提示 | `shelf` ✅ | ✅ |
| 新建一本书 | 跳对话 | — | ✅ |

### 3.2 书页（这一级是"进行设计"的主场）

```text
┌────────────────────────────────────────────────────────────┐
│ 书架 / 《长夜行》                          [进入当前章 →]    │
├───────────────────────┬────────────────────────────────────┤
│ 设计进度               │ 卷                                     │
│  开书        ✓         │  卷01  ✓ 37 章已定稿                  │
│  作品定调    ✓         │  卷02  ◐ 进行中 · 当前                │
│  世界构建    ✓         │  卷03  ○ 未开始                       │
│  全书大纲    ◐ 差2部   │  卷04  ○ 未开始                       │
│  分卷布局    ○         │  ─────────────────────                │
│  当前卷规划  ○         │  账本 5 本 · 本书记忆 文风12 决策4    │
│                        │  （点开只读查看）                     │
│ 还差什么               │                                        │
│  全书大纲第7、8部留白  │                                        │
│  [去对话接着设计 →]    │                                        │
└───────────────────────┴────────────────────────────────────┘
```

| 区块 | 内容 | 数据 | 本期 |
|---|---|---|---|
| **设计进度** | 六步各自到没到（✓/◐/○），当前停在哪一步 | **设计面七态** ❌ 客户端拿不到 | **需一条只读接口** |
| **还差什么** | 哪几部缺内容/留白/状态冲突 | 设计面的 `内容问题` 列表 ❌ 同上 | 同上 |
| **去对话接着设计** | 带话题跳回对话（"继续定全书大纲"） | — | ✅ |
| 卷列表 | 每卷号 + 定稿数 + 当前卷 | `/chapters` 按卷聚合 ✅（千章慢） | ✅ |
| 账本 / 本书记忆 | 条目数、可点开只读 | `tree` + `read` ✅（计数需客户端解析） | ✅ 简化为"文件在不在" |
| 进入当前章 | 跳到章页 | — | ✅ |

**为什么设计面必须在这页**：作者说"进这个页面进行设计"。设计工作的实际动作全在对话里（六步都是〔谈〕对谈），**页面如果只显示"没有数据"，那"进行设计"就变成"进来看一眼再回对话"，等于没做**。有设计进度，页面的价值才是"我知道差什么，然后带着这个认知去对话"。

**页面上不放"确认"按钮。** 契约六部、大纲九部、分卷八部的确认全是〔谈〕，由主控判断作者是否同意后调工具。页面只显示状态 + 跳对话。

### 3.3 卷页

| 区块 | 内容 | 数据 | 本期 |
|---|---|---|---|
| 卷标题 | 卷号 + 定稿数 / 计划章数 | `/chapters` ✅ | ✅ |
| 章列表 | 章号、章名、建议环节、是否定稿 | `/chapters` 过滤本卷 ✅ | ✅ |
| 卷纲 / 计划时间线 / 近期窗口 / 幕纲 | 文件名 + 可点开只读 | `tree` + `read` ✅ | ✅ |
| 幕分组 | 按幕列出本章 | 章↔幕映射 ❌ | ❌ 不做 |

**卷页的章列表是千章问题的关键**：`/chapters` 是全量扫描（1000 章约 21 秒）。所以卷页**不重复扫描**——从书页带过来的数据在整页内缓存，切卷不重新请求。冷进卷页才扫一次。

### 3.4 章页

**见[《章工作台-产品文档》](章工作台-产品文档.md)的 §2–§6**（三栏、7 环节点亮、中栏取文件优先级、只读规则、空态），全部继续有效。只改入口。

一句概括：左栏 7 环节（细纲→备料→起草→审读→改稿→润色→定稿），中栏这章的正文，右栏"有没有等你裁决的事"。

## 4. 对话还在不在

**明确答案：整页独占主内容区，对话整个切走，不内嵌、不并排、不做抽屉。**

理由三条：

1. **宿主结构上就不给。** 整页占 `main` 槽时，对话列被挤出，`sidebarRight.mounted` 变 undefined。要并排就得自己重做一份对话渲染，等于抢宿主的核心能力。
2. **和"不抢宿主"的纪律冲突。** Abzu 全程只借用公开插槽，对话是宿主的地盘。
3. **整页独占宽度正是要它的原因。** 章页中栏要放正文，书架页要放书目——挤着对话就没有"点进新页面"的意义了。

所以进整页后：

| 要做的事 | 在哪做 |
|---|---|
| 继续写这一章正文 | 章页中栏 |
| 看这本书设计到哪了 | 书页左栏 |
| 定契约、定大纲、裁决定稿、处置审读 | **回对话**（点左栏会话，或页面上的"去对话"按钮） |

**每个页面都要给一条回对话的路**，而且不能是"你自己去找侧栏"那种：

- 书页：「去对话接着设计 →」
- 章页：右栏「待你裁决」出现时给按钮；平时顶部条有"回对话"图标
- 书架页：每一行近况的右边，小字"继续写"→ 直接进章页；不需要对话时不打扰

## 5. 数据现实：能拿到什么、拿不到什么

| 需要的数据 | 现在从哪来 | 状态 | 页面上怎么处理 |
|---|---|---|---|
| 书目 + 一行近况 | `shelf` | ✅ | 直接显示 |
| 文件树 / 单文件读取 | `tree` / `read` / `resolve` | ✅ | 直接显示，只读判定现成 |
| 章列表 + 建议环节 + 定稿 | `chapters` | ✅ 但全量扫描 | 整页内缓存，切卷不重扫 |
| 搜索 | `search` | ✅ | 书房页可用 |
| 人物关系 | `graph` | ✅ | 书页可选入口 |
| 保存（`fix:` 提交） | `save` | ✅ | 章页中栏正文 |
| **设计面七态 + 内容问题** | `novel_get_story_status`（工具层） | ❌ | **书页最值钱的一块，需扩一条只读接口** |
| 章↔幕归属 | 幕纲自由文本 | ❌ | 不做幕层 |
| 审读发现项 | 审核记录 JSON | ❌ | 章页右栏显示「未接入」 |
| 账本未结项统计 | `账本/*.md` | △ | 简化为"文件在不在" |

**三条硬边界写进设计，不假装能取**：

1. **千章 21 秒**：进书页扫一次，之后整页内缓存。≥500 章的书允许首次卡顿，显示"正在读取章节…"。不做窗口化（要新 API）。
2. **设计面七态**：只有扩一条只读接口才能在书页显示。不扩就显示「未接入，回对话看」。
3. **审读发现项、幕层**：本期都不做，页面显示「未接入」或干脆不显示该块。

## 6. 做到哪一步算形态成立

**最小可成立形态（M1）——三屏打通：**

| # | 做什么 | 验收 |
|---|---|---|
| 1 | 侧栏 Abzu 图标 → 进整页 → **书架页** | 点图标换整页，书目列出，条目高亮 |
| 2 | 书架页点书 → **书页**：卷列表 + 设计进度（或「未接入」） | 面包屑变两级，能点回书架 |
| 3 | 书页点卷 → **卷页**：本章列表 | 面包屑三级，能点回书页 |
| 4 | 卷页点章 → **章页**：三栏 + 正文 | 面包屑四级，能一路点回书架 |
| 5 | 点左栏会话 → 回对话；再点图标 → 回到刚才那一级 | 位置不丢（进程内） |

**M1 成了的标志**：作者能指着屏幕说"我在《长夜行》卷02 第13章，这一章在审读，我要回去写上一章就点面包屑"——**而不是"我刚才开着哪几个 tab"**。

M1 不含：设计面七态、幕层、审读发现项、新建表单、页级深链、刷新恢复。

**M1 之后按价值排：**

| 序 | 内容 | 依赖 |
|---|---|---|
| M2 | 书页的设计进度（设计面七态） | **一条只读接口** |
| M3 | 章页右栏的审读发现项 | **一条只读接口** |
| M4 | 页级深链 / 刷新恢复 | 宿主路由，或接受"带参进入一次" |
| M5 | 幕层 | 章↔幕映射 |
