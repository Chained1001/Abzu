## 1. 形态与要解决的问题

### 1.1 一句话

**Abzu 是一张「章工作台」页面：左边选章，中间只放这一章的东西（正文、或它的细纲材料、或它的上下文），右边告诉你这一章现在卡在哪一步、能做什么。**

页面的主语是**一章**，不是"一本书的所有功能"。卷、幕、全书大纲都是这一章的上游，进得来、看得见，但不占据中栏。

### 1.2 它对应现状的哪几条病

| # | 现状的病 | 实测依据 | 这页怎么解 |
|---|---|---|---|
| 1 | **没有整页，写正文和对话抢宽度** | 正文编辑器挂在 `sidebar.right.pane.tab`，右栏默认视口 45%、上限 70%（`dsh-client-ui-layout` 的 `RightbarOwnerProps`）；`layout-swap.ts` 还要靠 DOM 探测才能把对话挪到右栏 | 整页占中栏，正文有几栏宽就几栏宽；两侧栏可收起 |
| 2 | **入口都在抢别人的界面** | `workspace-slots.tsx` 整个替换了 `sidebar.workspaces`（原生工作区列表要靠 `mountNativeEntry` 镜像才能留住）；可视化挤在 `conversation.view` 的 tab 条里 | 侧栏只加一个自己的条目（`sidebar.panellist`），原生工作区列表交回去 |
| 3 | **生命周期绑会话** | `conversation.view` 是 session scope，切会话就没；右栏 tab 也是 session scope | `main` 是 root scope，切会话不重置；书与章是页面自己的选择，不是会话的 |
| 4 | **没有位置感** | 书稿能从 4 个地方点开（输入框按钮、文件树、可视化列表、侧栏书房），点开都只是"右栏换一格" | 侧栏条目高亮 + 页头面包屑 + 左栏当前章高亮，返回规则只有一条 |
| 5 | **补丁感** | `layout-swap.ts` 依赖 `[data-rightbar-col]` / `[data-sidebar-right-panel]` 猜宿主结构，宿主改版即自检失败、功能静默消失 | 整页用宿主的公开插槽，不猜 DOM |
| 6 | **"这一步做完了吗"说不清** | 事实清单行间可同时成立，`deriveChapterFacts` 明确写"建议无权威、不参与门禁"；而 `workflow-view.tsx` 目前用节点标记"操作状态" | 右侧照实列 11 行成立/不成立，建议环节单独标注为"建议" |

### 1.3 一条不能破的纪律

**这一页不新增任何需要维护的状态。** 章的所有状态都从文件推导（`deriveChapterFacts`，输入是 `scanChapter` 读出的文件事实，纯函数）。页面只做三件事：读文件事实、显示、把作者的动作转成对已有工具的调用。

页面上唯一允许"记住"的是**界面偏好**（上次停在哪一章、左栏展开到哪一卷、上次用的中栏模式）——它不是书的状态，不参与任何判据，存本地即可。

## 2. 信息架构

### 2.1 三栏各放什么

```text
┌──────────────┬────────────────────────────────────┬──────────────────┐
│ 左栏 · 章树    │ 中栏 · 这一章的工作面                 │ 右栏 · 这章怎么了   │
│              │                                    │                  │
│ ▼ 卷01        │ ┌ 页头：书名 / 卷01 / 第12章 章名    │ 环节实况          │
│   第01章 ✓    │ │        [正文] [规划] [上下文]      │  1 章细纲(待定位) ○│
│   第02章 ✓    │ ├────────────────────────────────┤  2 章细纲(待确认) ○│
│ ▸ 第12章 ◀当前 │ │                                  │  3 写作备料      ○│
│   第13章      │ │   正文 / 规划 / 上下文            │  ...             │
│              │ │   （当前模式的内容）                │ 11 完成          ○│
│ ▼ 设计        │ │                                  │                  │
│   作品契约      │ │                                  │ 建议环节          │
│   世界书        │ │                                  │  写稿（非权威）    │
│   全书大纲      │ │                                  │                  │
│   卷纲/幕纲     │ │                                  │ 叠加标记          │
│              │ │                                  │  ⚠ 审核证据已过期  │
│ ▼ 书房        │ └────────────────────────────────┤                  │
│   灵感池       │                                    │ 就地工具          │
│              │                                    │  检索索引         │
└──────────────┴────────────────────────────────────┴──────────────────┘
```

**左栏 · 章树（选章，不编辑）**

- 顶部一个"书"选择器（当前工作区下可能有多本书，`shelf` 返回书目）。
- 主体按**卷 → 章**分组。卷折叠、当前卷默认展开。
- 每章一行显示：章号、章名、一个状态词。状态词取 `/chapters` 已返回的 `status`，也就是 `建议.环节`——**它是建议，不是位置**，所以行上不加"进度 5/11"这类读数。
- 已定稿章给一个静止的完成标记（`finalized`），区别于"建议环节＝完成"。
- "设计"分组：契约、世界书、全书大纲、卷纲幕纲。是这一章的**上游**，点开在中栏以只读方式看（现有 `authorReadOnlyReason` 已规定其中大部分只读）。
- "书房"分组：灵感池、参考库等跨书资产。
- 左栏底部保留现有书房的**搜索**（书名/文件）——千章书没有搜索不可用。

**中栏 · 三个模式**

三个模式都是**章本位**，切换不改变"当前是哪一章"。

| 模式 | 放什么 | 可编辑？ |
|---|---|---|
| **正文**（默认） | 这一章的定稿正文（若已定稿）或当前待审稿/草稿 | 定稿只读（吃书补偿流程）；草稿可编辑 |
| **规划** | 这一章的细纲（确认版/候选版）、材料包清单、审核记录、待定稿包 | 候选细纲、草稿区可编辑；材料包/审核/定稿准备只读 |
| **上下文** | 这一章要用到的世界书切片、上一章定稿末尾、相关账本行、本书文风锚点 | 全部只读 |

"上下文"这一栏是**只读的聚合视图**，不是新的数据源——它展示的就是起草任务包会装进去的那些切片，让作者能提前看"这次 AI 会看到什么"。这条很重要：它是**透明度**，不是新功能。

**右栏 · 这章怎么了（只读 + 就地动作）**

- **环节实况**：11 行逐行亮/暗，行名照抄代码里的 `环节`（章细纲(待定位)、章细纲(待确认)、写作备料、写稿、审核、改稿、润色、定稿准备与沉淀、作者定稿裁决、定稿入档、完成）。多行同时亮是正常的，必须照实显示。
- **建议环节**：单独一块，标题就写"建议环节（非权威）"，副文案说明"取最后一个成立的环节，只作参考，判断归主控"。
- **叠加标记**：照抄 `叠加标记`（如"审核证据对当前稿过期→须重审"、"有草稿但无唯一待审稿→核对稿件角色"、"细纲"、"窗口无可进入项→当前卷规划滚动补充"）。
- **就地工具**：检索索引（现 `sidebar.right.pane.tab` 的索引面板搬入）、审读发现项（若有）。

### 2.2 章级流程环节与"点亮"规则

**点亮 = 该行的事实成立**，数据源唯一：`deriveChapterFacts` 的 `事实项[].事实`。

| 行 | 环节 | 成立条件（代码单源，`derive/derive.ts` + `scan.ts`） |
|---|---|---|
| 1 | 章细纲(待定位) | 近期窗口有可进入条目 |
| 2 | 章细纲(待确认) | 有候选细纲 |
| 3 | 写作备料 | 有已确认细纲 |
| 4 | 写稿 | 材料包状态＝段齐备 |
| 5 | 审核 | 有唯一待审稿 |
| 6 | 改稿 | 有审核记录且审核证据未过期 |
| 7 | 润色 | 审核完成且润色未承接 |
| 8 | 定稿准备与沉淀 | 审核完成且润色已承接且待定稿包不完整 |
| 9 | 作者定稿裁决 | 待定稿包完整且裁决≠已退回 |
| 10 | 定稿入档 | 待定稿包完整且裁决＝已批准 |
| 11 | 完成 | 已定稿 |

**三条显示纪律**：

1. **不做单值进度条。** 行间可同时成立，画成"进度条走到第 N 格"是错的。
2. **不改写术语。** 行名与代码一致，方便作者和主控对话时对得上。
3. **`null` 就是 `null`。** 现有 `stage-health.ts` 里 `settingDebt` / `pendingReview` / `pendingReReview` / `changes` 恒为 `null`，注释写明"绝不以 0 冒充已接通"。右栏若展示这些指标，一律显示"—（未接入）"，不得显示 0。

### 2.3 一处必须避开的现状不一致（已核实）

`packages/bundle/src/study/workflow-types.ts` 的 `workflowStages` 顺序是：细纲 → 备料 → 写稿 → **润色 → 审读 → 改稿** → 沉淀 → 定稿。

但 0.0.54 起真实顺序是**起草 → 审读 ⇄ 改稿 → 润色 → 沉淀**（`derive.ts` 第 7 行注释、`产品文档` §6 与 §6.6 都是这个顺序；`git log -S` 可见 0.0.54 那笔提交）。

**结论：新页面一律以 `deriveChapterFacts` 的行序为准，不沿用 `workflowStages` 的顺序。** 现有"写作流程"视图的节点序是错的，退役或修正时一并处理。这条标 **待 Dev 会签**。

## 3. 导航

### 3.1 进入这一页

| 从哪进 | 怎么进 | 落到哪 |
|---|---|---|
| 左侧栏"章工作台"条目 | 点条目 | 上次停留的章；没有则落到"最近一章"（章号最大的未定稿章，没有则最后一章） |
| 对话里的书稿链接 | 点链接 | 整页打开，定位到该章的中栏「正文」 |
| 工具结果卡片（如 `novel_confirm_outline`、`novel_settle_chapter`） | 卡片上的"查看" | 整页打开，定位到该章，中栏切到对应模式（细纲→规划，定稿→正文） |
| 左栏章树 | 点某章 | 同页，中栏换章，**不导航** |

### 3.2 返回

- **一条规则**：点左侧栏任意会话 → 回到对话（`selectPanel(null)`）。会话列表此时由宿主管，Abzu 不再替换它。
- 侧栏"章工作台"条目保持高亮（`aria-current="page"`），直到回对话。
- 对话与整页是**同级**，不是父子，所以不做"返回上一页"按钮——避免和浏览器的返回语义混淆。

### 3.3 深链

**现状（已核实）**：书稿链接是 `?abzu={"sessionId","ref"}`（`study/links.ts`），带 `sessionId`，且落到右栏编辑器，**不是页级深链**。刷新后由 `index.tsx` 的 `parseStudyLink` 恢复，恢复的是"某个会话的右栏某文件"。

**这页需要的深链**：书 + 卷 + 章（＋可选模式）。三种可选做法，**待 Dev 会签**：

1. 复用 `?abzu=` 但扩展为页级寻址（书 id + 章号 + 模式）；
2. 页面自己维护一个不依赖 URL 的"当前书/章"，深链只用于"从对话跳进来"这一次性定位；
3. 新的 URL 形态。

**产品要求（不涉及选型）**：
- 同一个链接发给未来的自己或别人，打开应落在同一章。
- 刷新不应丢掉当前章。
- 刷新不应丢失未保存的正文——这是现有 `beforeunload` 已有的保护，整页必须保留。

### 3.4 页面内的位置感

四个锚点，缺一不可：

1. **侧栏条目**高亮当前页面（宿主负责）。
2. **页头面包屑**：书名 / 卷NN / 第NNNN章 章名。点上级可回到该卷的章列表（不离开整页）。
3. **左栏当前章**行高亮 + 所在卷自动展开。
4. **中栏模式**三选一可见，当前模式可辨。

另外：切章时若有未保存正文，**必须拦一次**（现有 `store.hasUnsaved()` + `beforeunload` 的机制要延伸到"页内切章"这个动作上）。标 **待 Dev 会签**。

## 4. 空态与异常态

文案尽量沿用仓里已有的真实句子，别另造一套。

| 场景 | 页面长什么样 |
|---|---|
| **没有打开工作区会话** | 中栏一句「打开一个工作区会话后，即可浏览作品与共享资料。」左栏章树留空骨架。侧栏条目仍可点，点了就这页。 |
| **工作区里没有书** | 左栏「当前工作范围还没有作品。可在对话中开始构想，或切换到已有书仓的工作区。」中栏引导回对话（"回对话开始构想"按钮 → `selectPanel(null)`）。 |
| **有书但一章都没有** | 左栏列出书，章树区「这本书还没有章节。」右栏不显示 11 行（没有章就没有事实清单），显示"这本书还没有开始写"。 |
| **章没有细纲** | 事实清单只亮行 1（或全暗，此时叠加标记带「窗口无可进入项→当前卷规划滚动补充」）。中栏「规划」模式显示"这一章还没有细纲"，并给出"回对话让主控排细纲"的入口。**不在页面上直接触发排细纲**——那是对话的事。 |
| **材料包过期 / 审核证据过期** | 右栏叠加标记照实显示（如「审核证据对当前稿过期→须重审」），中栏「规划」对应块加一条警示。不改任何门禁行为，只呈现。 |
| **子代理失败**（`WorkflowCall.state` 为 `error` / `stopped`） | 右栏就地工具区显示「操作失败，请查看对话中的错误详情。」/「操作已中断，请核对已有结果。」（沿用 `workflow-types.ts` 的 `resultState` 文案）。**页面不重试、不代劳**——Abzu 的纪律是子代理失败时不代劳。 |
| **读取失败**（API 报错） | 该列局部报错，不白屏。沿用 `StudyApiError` 的 message，如「书房服务尚未就绪，请刷新后重试」。 |
| **千章书** | 左栏按卷折叠，默认只展开当前卷；章树滚动虚拟化。**注意现状**：`/chapters` 是 `service.chapters(space)`，对每章跑一次 `scanChapter`，**全量、无窗口**（`service.ts:237`）。整页左栏若一次列全部章，这是性能风险，标 **待 Dev 会签**。 |
| **文档只读** | 中栏顶部一条只读说明，用 `authorReadOnlyReason` 的原话：「定稿更正通过吃书补偿流程处理」/「建书构想快照已冻结」/「过程工件由业务工具维护，只读」/「结构化工件由业务工具维护，只读」。编辑区变只读视图，不隐藏。 |
| **文档格式异常** | `readOnly: '文档格式异常，只读'`，照实显示，不给编辑。 |
| **文件超大** | 超 4 MiB 不打开：沿用「文件超过 4 MiB，不能在编辑器中打开；内容未截断」。 |
| **无共享资料** | 左栏书房分组「当前书房暂无共享资料」。 |

**空态的一条总规矩**：空不等于错。没细纲、没章、没书都是合法状态，用引导语气；只有真错误（IO、格式、服务不可用）才用错误样式。

## 5. 作者确认点

### 5.1 这页上不新增确认点

**所有需要作者拍板的动作，仍然走现有通道**：对话里呈报 + 主控判断，或代码强制的审批弹窗。理由：确认点的性质（〔码〕/〔谈〕）由[产品文档](../产品/是什么.md)第 8 节定义，页面是新的呈现方式，不该改变授权面。

| 动作 | 性质 | 在这页上的样子 |
|---|---|---|
| 定稿入档 | 〔码〕审批弹窗 | 页面只显示"待定稿包完整、裁决已批准"→可入档；点入档**触发宿主审批弹窗**，弹窗走原生，不在页内自造 |
| 吃书补偿 | 〔码〕审批弹窗 | 定稿只读；页面上给"走吃书补偿"的说明与跳转对话入口 |
| 契约/大纲/分卷/卷纲/细纲确认 | 〔谈〕 | 页面**不提供**"确认"按钮。这些确认在对话里呈报、由主控调工具 |
| 写时发现待查项、风险行处置 | 〔谈〕 | 只读展示，处置回对话 |
| 润色/扩写/精简/审读/续写/按要求改 | 生成行内建议，作者逐条采纳 | **作者在这页上做**：选段 → 发起 → 建议回填 → 采纳/拒绝。复用现有六种 intent，不新增 |

### 5.2 严格只读

按 `authorReadOnlyReason`（`core/src/revise/document.ts:62`）：

- `定稿/` 下所有文件
- `构想/` 下所有文件
- `草稿区/材料包|审核|定稿准备|批次` 下所有文件
- 非 `.md` / `.txt`
- 超过 4 MiB
- 「不是可编辑的书仓文档」的其他情形

**只读的东西照样要能看**——不能因为只读就藏起来不显示。

### 5.3 一条容易被忽略的

页面上任何"看起来能改书"的按钮（哪怕只是触发对话），都必须写明它**只是发起请求**，不会直接改文件。现有编辑器已经这么做（六种 intent 全部走"请求 → 主 Agent → 回编辑器 → 作者采纳"，`EDITOR_DELIVERED_MESSAGE` 明说"已送到编辑器，等待作者决定是否采用；不要再直接修改文件里的这段文字"）。新页面沿用这个口径。

## 6. 验收标准

每条都是"前置 / 操作 / 预期"，QA 可直接反推用例。标 ⚠ 的是依赖待会签项，可能要先降级为"骨架验收"。

### 6.1 整页与导航

## 7. 关键取舍与不选什么（与现有界面的关系）

### 7.1 保留

| 界面 | 为什么保留 |

### 7.2 退役

| 界面 | 理由 | 时机 |
|---|---|---|
| `workspace-slots.tsx` 对 `sidebar.workspaces` 的整体替换 | 抢占宿主导航；`mountNativeEntry` 镜像宿主是补丁 | 与整页上线同批 |
| `conversation.view` 的"可视化"tab | 与整页信息重复；且 session scope 会随会话重置 | 先并存一版（见 7.3） |

### 7.3 先并存一个版本

| 界面 | 并存理由 | 退出条件 |
|---|---|---|
| 会话内"可视化"tab | 作者现在会"边聊边看图谱"；一刀切会掉习惯 | 整页上线满一个版本、作者确认不再用 |

### 7.4 明确的非目标

- 不在这页上做卷/幕级别的规划（那是方案 A 的外层导航，本期不做）。
- 不新增工具、不改门禁、不改任何 `novel_*` 工具的语义。
- 不做多人协作、不做移动端。
- 不在这页上做"确认细纲/确认卷纲"这类〔谈〕动作。

## 8. 待确认：待 Dev 会签

已自查实的（写文档依据）：

- `main` 是 root-scope keyed 插槽，`conversation` 为保留 key；`ctx.layout.selectPanel(id)` 选页面、`selectPanel(null)` 回对话；选未注册 key 抛错并保留当前选择。
- `sidebar.panellist` 是 root-scope list 插槽，条目取 `id` / `order` / `label`，宿主按 order 排序并渲染高亮。
- DSH 自带"插件"页、"定时任务"页就是这两个插槽的组合，可作参照。
- `useSession(host)` 读 `host.sessions.list` 里 `retainedBy.mainView`，是 root 级服务，**页内可用**；`callStudy` 由服务端 `runtime.agents.get(sessionId)` → `session.header.cwd` 得工作区。所以"当前工作区"能从主会话取到。
- 第三方注册走 `guardedSlots` 代理，只校验"插槽是否已声明"（未声明抛 `slot "x" is not declared`），非 chain 自动分配 priority；仅 `tool.view.cordis` 特判。机制上第三方可注册。

要 Dev 会签的：

1. **`layout` 服务要加进 `inject`**：现在 `client/index.tsx` 的 `inject` 没有 `layout`，调 `selectPanel` 得先加。确认可行。
2. **第三方注册 `main` / `sidebar.panellist` 实测**：机制上通，但 Abzu 从没这么用过，需实测一次。
3. **`/chapters` 全量扫描的性能**：`service.chapters` 对每章跑 `scanChapter`，无窗口。千章书整页左栏能否接受？要"能忍/不能忍 + 量级"。
4. **书与章的归属**：书（`book:<id>`）与章（卷+章号）做成页面自身选择状态、不绑会话——确认这样不会和"切书必须作者明确指定"（〔谈〕纪律）冲突。
5. **页级深链**：现有 `?abzu={sessionId,ref}` 是会话绑定的右栏链接。页级深链（书+卷+章）宿主是否保留 query、刷新能否恢复。
6. **页内切章的未保存拦截**：`store.hasUnsaved()` 目前只在 `beforeunload` 用，延伸到"切章"这个动作需要什么。
7. **`workflowStages` 顺序错误**（第 2.3 节）：退役"写作流程"视图或修正顺序，需 Dev 判断影响面。
