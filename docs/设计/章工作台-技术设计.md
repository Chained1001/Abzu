## 1. 要解决的问题：三个前置问题

### 1.1 root scope 与 session 绑定的矛盾

**结论：工作区靠「主会话 cwd」，书与章靠「页面自身状态」，不新增不依赖 session 的 API。**

依据链：

1. `main` 是 root scope keyed 槽，除保留 key `conversation` 外「receive no Session binding」——`dsh-client-ui-layout/lib/types/client/index.d.ts` 的 `SlotMap['main']` 注释原文如此。
2. 但页面里拿得到主会话 id：`useSession(host)`（`client/hooks.ts:6-8`）= `mainSessionOf(host)`（`client/host.ts:67-77`），读的是 `host.sessions.list` 的 `retainedBy.mainView` 行。这是 root 级 list 服务，不依赖当前页是哪个面板。
3. 服务端把该 sessionId 还原成工作区：`study/web.ts:192-196`，`runtime.agents.get(sessionId)` → 校验是 root agent → `agent.session.header.cwd` → `new StudyService(cwd)`。所以 `callStudy(sessionId, …)` 实际是在问「那个会话的工作区里有什么」，而这个 sessionId 是 root 级可得的。
4. 书（`book:<id>`）与章（卷 + 章号）是本书仓内的相对位置，与 session 无关，只能由页面自己记住。`chapter-target.ts:45-57` 的 `createWorkbenchSelection` 就是这个状态：`Map<sessionId, ChapterTarget>`，纯内存、不落盘、`dispose` 时清空。

**为什么不是 URL 参数**：宿主没有路由，`selectPanel` 只是内存里的一个 key（见 1.4）；URL 只能作为「初次进入」的入口，不能承载页面状态。

**为什么不新增 API**：唯一缺口是「不选会话也能列出书仓」，而主会话 id 在 root 侧拿得到，`shelf` 方法本来就在（`study/web.ts:219`），代价为零。扩一条无 session 的路由会同时扩一份鉴权面，不值得。

**这条与「切书必须作者明确指定」的关系**：页面自身状态只决定「看哪一本」，不触发任何写操作、不改变书仓的当前书；所有写路径仍然是 `save`（`study/web.ts:227-231`），它按 `ref.space` 定位。不冲突。

### 1.2 整页与右栏互斥后，发现项放哪

**结论：做页内第三栏，不设法复用右栏。**

依据：`dsh-client-ui-sidebar-right/lib/types/client/service.d.ts` 的 `mounted` 注释——「The Session on screen, or `undefined` while none is (a global panel fills the main column, or no Session is selected)」。整页占据 main 时，右栏没有 on-screen session，宿主按设计不渲染其会话内容。`chapter-target.ts:59-65` 的 `mountedSessionOf` 把这个口径固化成一行可测逻辑。

两个次要理由：

- 右栏的展开态是作者自己 store 里的记录，页面去 `toggleExpanded` 会把作者原本展开的右栏收起来（`index.tsx:61-64` 现在就是因为这个原因在关文档时才 toggle）。
- 右栏宽度是视口 45%（`RightbarOwnerProps` 注释：normal 模式按测得的列宽），和页内第三栏（260–320）不是同一个几何体系。

页内第三栏的另一面代价：整页态下右栏原有的文件预览、检索索引面板都看不到。这写进第 6 节风险。

### 1.3 新增 `main` 注册的影响面与 `layout-swap` 的去留

**现有 9 处注册点位核对无误**（逐条 `slots.register` 数，`grep` 结果）：`shell.overlay`（`index.tsx:112`）、`conversation.input.right`（`index.tsx:113`）、`conversation.view`（`index.tsx:117`）、`sidebar.workspaces`（`workspace-slots.tsx:38`）、`sidebar.right.pane.tab`（`indexing.tsx:148`）、`sidebar.right.pane.tab.title`（`native-documents.tsx:98`）、`sidebar.right.tab.document`（`native-documents.tsx:128`，注册两个 key）、`tool.call.toolview`（`tool-result-card.tsx:35`）、`settings.models.footer`（`retrieval/client.tsx:196` 与 `retrieval/auxiliary-client.tsx:139` 两处共用同一 slot）。新增 `main`（`chapter-workbench.tsx:47`）是第 10 个注册点位。

**影响面：面板未选中时严格为零；选中时的真实影响是三块。**

| 表面 | 整页打开时 | 依据 |
| --- | --- | --- |
| `main`（新增） | 唯一渲染的中栏 | keyed 槽按选中 key 渲染一个占用方 |
| `conversation.input.right`、`conversation.view` | 不渲染，会话内容整列让位 | 这两个是会话 scope，随对话列一起卸载 |
| 右栏全部（含 `sidebar.right.*`） | `mounted === undefined`，会话内容不渲染；各 tab 的展开态留在该会话自己的 store | `service.d.ts` `mounted` 与 store 说明 |
| 左栏 `sidebar.workspaces`（含书房树） | 照常渲染 | root scope，与 main 选择无关 |

新增注册本身没有「抢占」问题：`main` 是 keyed，key 用 `abzu-chapter-workbench`（`chapter-target.ts:6`），避开保留字 `conversation`；`selectPanel` 传未注册 key 会抛错并保留当前选择（`layout/lib/types/client/service.d.ts` 的 `@throws`）。

**`layout-swap` 的取舍（显式条目）**：

删掉的是「对话与右栏左右互换」这个功能本身，**没有等价替代**。它靠 DOM 探测宿主结构（`layout-swap.ts:30-45` 的 `probeFrame` 认 `[data-rightbar-col]`、`grid` 容器、`[data-sidebar-right-panel]`），宿主一改版就 `probeFrame` 返回 `undefined`、功能静默消失——这是仓库里最脆的一处。

替代方案不是另一个换列技巧，而是「作者不需要换列了」：正文在整页中栏有几栏宽就有几栏宽，不再和对话抢宽度。原本靠互换想解决的问题（对话占着好位置、正文被挤）在整页形态下不存在。

**时机**：第一步不动它（`index.tsx:114` 的注册与 `layout-swap.css` 全部保留，7 个用例照跑）。按产品文档 §7.2 的口径，整页上线满一个版本后再删。删的时候要一起处理：`index.tsx:12/97/114` 的 import、样式拼接与注册，`layout-swap.ts`、`layout-swap-handle.tsx`、`layout-swap.css`、`tests/layout-swap.spec.ts`，以及 `localStorage['abzu-layout-swap']` 的残留（`readSwapPreference`/`writeSwapPreference`，读不到就是 false，不会报错）。

### 1.4 关于「深链」的事实

宿主没有 URL 路由。`selectPanel` 改的是 layout store 的 `panelInfo`，该 store 的注释写明是 transient preferences（`layout/lib/types/client/stores.d.ts` 开头）。所以：

- 刷新页面一定回到对话，**整页位置不保留**。这是宿主能力边界，不是实现缺陷。
- 现有 `?abzu={"sessionId","ref"}` 是会话绑定链接（`study/links.ts:10-13`），打开后立刻 `history.replaceState` 把参数删掉（`index.tsx:132-142`）。可以把它扩成「带章位置的一次性入口」：解析出 ref → `chapterTargetOf` → `openWorkbench`，参数照样删。**能做到「从外面带参数进来定位到某章」，做不到「地址栏可分享的页级地址」。**

## 2. 硬约束（来自 PM 规格，实现时不得偏离）

1. **环节点亮只有两个字段**：`status`（11 行事实推出的建议环节字符串）与 `finalized`，都来自 `service.ts:237-251`。11 行布尔事实没有暴露到客户端，**不许为此改 service 返回结构**。
2. **映射表唯一**（`derive.ts:27-39` 的行序反推）：细纲（待定位）/细纲（待确认）→ 细纲；写作备料 → 备料；写稿 → 起草；审核 → 审读；改稿 → 改稿；润色 → 润色；定稿准备与沉淀/作者定稿裁决/定稿入档 → 定稿；完成 → 7 项全完成。当前环节「进行中」，之前「完成」，之后「未开始」；`作者定稿裁决` 时「定稿」标「需裁决」；`finalized === true` 时 7 项全「完成」并忽略 status。
3. **UI 不得据此禁用按钮或拦截操作**。`status` 是参考值，标签后缀统一带 `· 参考`，`title` 写明「按文件推导的建议环节，不参与门禁」。`derive.ts:1-3` 的注释也是这个口径：不产出权威位置、不参与门禁。
4. **取不到数据一律「未接入」/「暂无」**，不许显示 0、不许猜内容（与 `stage-health` 的「不伪造 0」一致）。
5. **入口只有两类**：书房树点章级文件；对话侧解析出章号时。其余文件点击保持右栏现状。
6. **返回唯一出口**：顶部「返回书稿」→ `selectPanel(null)`，记住刚才那章。
7. **正文必须在页内渲染**，不回右栏。
8. 不新增 `export *`；改行为必带回归测试；不自行提交/推送/打 tag。

## 4. 数据流

### 4.1 点一章 → 页面拿到数据

```
书房树 TreeRow.onClick (browser.tsx)
  → chapterTargetOf(entry.ref)                    // 不是章文件就 store.open 走原路
  → selection.choose(sessionId, target)           // 纯内存
  → host.layout.selectPanel('abzu-chapter-workbench')
      └─ 未注册会抛错并保留当前选择（layout service.d.ts）
ChapterWorkbench 挂载
  → useSession(host) → mainSessionOf → sessionId  // host.ts:67-77
  → useChapterTarget(selection, sessionId)        // chapter-workbench.tsx:15-17
  → useStudy(sessionId, 'chapters', { space })    // hooks.ts:15-28
      → callStudy → POST /api/abzu/study/chapters
      → service.chapters(space)                   // service.ts:237-251
```

拿到 `ChapterView` 后，页面按 `volume+chapter` 找到当前章，取 `status`/`finalized` 喂 `deriveChapterStages`。

**这里有个已知性能问题，见 6.1。**

### 4.2 正文 → 编辑 → 保存

文件优先级（PM 规格 §1）：`定稿/卷NN/NNNN-章名.md` → 待审稿 `草稿区/草稿/卷NN-NNNN-章名/稿N.md` → 确认细纲。取第一个存在的；都没有就空态。

- 读：`callStudy(sessionId, 'read', { ref })` → `StudyService.read`，返回 `{ document, body, hash, version }`。
- 编辑：**复用现有 `createEditorStore` 那一个实例**（`index.tsx:43` 建的那个），不新建第二套。理由：`store` 已经管着 buffer / 脏标记 / 保存队列 / `hasUnsaved`（`store.ts:86`），`beforeunload` 拦截也挂在它上面（`index.tsx:105-107`）；新建一套等于把未保存拦截和保存结果通知复制两份，必然对不上。整页里渲染的是同一份 buffer，只是换了个容器。
- 保存：`store.save` → `callStudy(sessionId, 'save', { ref, hash, body, operationId })` → `service.save`（`study/web.ts:227-231`）→ 成功后会 followup 通知主 agent（`notifySaved`）。这条链路整页不改，页内只是换入口。
- 并发/冲突：沿用现有 `hash` 前置校验（`study/web.ts:229-231` 先 `service.read(ref)` 再 `acceptedFor`）。

### 4.3 切章时的未保存拦截

`store.hasUnsaved()`（`store.ts:86`）现在只用于 `beforeunload`。切章动作要新增一次同样的询问：目标章有未保存 buffer 时先提示。**这是新行为，要带测试**，不是复用现成的。

## 6. 关键取舍与不选什么（已知风险与不做）

### 6.1 `/chapters` 全量扫描：**千章不能忍**

`service.chapters(space)`（`service.ts:242-249`）对 `listChapters` 的每一章都跑 `scanChapter` + `deriveChapterFacts` + `findPendingReviewDraft` + 4 次 `existsSync`，无窗口、无缓存（`scan.ts` 里每章 6 次 `readText`、1 次 `readdirSync`）。

我在合成书仓上实测（本机、`--experimental-transform-types` 直跑 core，非 esbuild 产物）：

| 规模 | `listChapters` | 逐章 `scanChapter` |
| --- | --- | --- |
| 200 章（4 卷 × 50） | 22.9 ms | **2904 ms**（中位，3 轮） |
| 1000 章（20 卷 × 50） | 131.7 ms | **21068 ms**（约 21 ms/章） |

线性增长、主线程同步文件 IO。**千章书整页左栏要等 20 秒，不能忍。**

缓解手段（本期只做前两条，都不改 service 返回结构）：

1. 整页只为「当前卷」取章：`chapters` 的入参是 `space`，所以要么在第 2 阶段的页面里只展示当前卷、其余卷折叠后按需取；要么新增一条 `chapters-page` 方法按卷窗口取。**这属于扩 API，需要作者批**——按 PM 口径第一版不加。
2. 页面拿到结果后在内存里按卷缓存，避免每次切章重扫整本。
3. 长期：`scanChapter` 的缓存键 = 文件 mtime/hash，属 core 层优化，单独立项。

**第一版实际上限**：单卷 50 章量级（约 1 秒）可接受；超过 500 章的书会明显卡。这条写进验收标准，不要写「可交互时间 ≤ X」这种做不到的阈值。

### 6.2 `workflowStages` 顺序与真实流程不一致（PM 报的 bug，我确认成立）

`study/workflow-types.ts:2-17` 的章节组顺序是 细纲 → 备料 → 写稿 → **润色 → 审读 → 改稿** → 沉淀 → 定稿；而 `derive.ts:31-38` 的事实行序是 写稿 → 审核 → 改稿 → 润色 → 定稿准备与沉淀。即「润色」在现有视图里被排到了「审读」前面。

影响面**很小**：`workflowStages` 全仓只有两处引用，都在 `client/workflow-view.tsx`（第 40 行取当前 stage 的 label、第 64 行取调用记录的 label）。它不参与派生、不参与门禁，注释第一行写明「Display vocabulary only」。

结论：**是显示顺序问题，不是逻辑错误；本期不改**。新的 7 环节表以 `derive.ts` 行序为准，写在 `workbench-stages.ts` 里，与旧视图并存。旧视图要不要修/退役，等整页上线后按产品文档 §7.2/§7.3 一起决定。

### 6.3 宿主没有路由

刷新回到对话，位置丢失；深链只能做「带参数进来一次」。见 1.4。不要在文档或 UI 里承诺「可分享的页面地址」。

### 6.4 整页态下右栏能力消失

文件预览、检索索引面板在整页里看不到。第一版接受：作者要看这些就返回对话。若以后要在页内提供，是「页内第三栏加 tab」的活，不是把右栏塞回来。

### 6.5 第三方注册 `main` / `sidebar.panellist` 未实测

机制上通：宿主对第三方包用 `guardedSlots`（应用包内 `client.js`），它只做三件事——校验 `options.name` 是字符串、对非 `chain` 槽自动分配 priority、对 `tool.view.cordis` 特判 key。声明层面 `sidebar.panellist` 由 `ui-sidebar` 在 `sidebar` 的 children 里声明（`{ kind: 'list', scope: 'root' }`），`main` 由 ui-layout 声明。

但 **Abzu 从没以第三方身份注册过 `main`**，`chapter-workbench` 是本仓第一次。这一点已由 `chapter-workbench.spec.ts` 用 `SlotCore` 覆盖了注册语义，**真机（宿主里装包后可见）仍待手工验证一次**——验收时必须做。

### 6.6 明确不做

- 设计面（契约/大纲/卷纲）不进整页；卷幕层导航不进。
- 审读处置、定稿裁决的**操作**不进页内，只显示状态 + 跳回对话。
- 不改任何写入路径、不改 `novel_*` 工具语义、不改 `service.chapters` 返回结构。
- 不做多人协作、不做移动端。
- 不删 `layout-swap`（本期只是不再依赖它解决宽度）。
