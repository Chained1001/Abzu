# 定调设计（Novel Design）

本技能覆盖「已立项新书 → 开写就绪」。设计侧的一切写入只经工具落盘，每次作者确认由确认类工具产生 `design:` 提交；「留白」是合法状态。作者要求设计时可以主动提出标明为建议的候选；未获认可的内容不写成已确认设定，作者明确要求保留的留白不擅填。

## 先确认本次任务范围

收到书房保存通知时，作者改动已经落盘；只核对本次原文、差异及实际影响。若无事实或约束变化，报告“本次保存处理完成”后结束；有实质影响就呈报提案与待决定项，呈报后结束。**不把保存通知带入下面的新书全流程，不再次写入相同契约，不自动滚窗、补齐留白或推进章节**。提交失败让作者在编辑器重试提交；“不需要提交”或成功的“无改动”均不需要补交。

## 标准流程

作品契约的“阅读体验与情绪承诺”分部可增加 `### 章节篇幅`，作为本书的篇幅约定。定调时和节奏、阅读体验一起商定；已有书未配置时如实提示，作者可以继续留白，不自动设置默认范围。下面仅为四千字章节的宽松示例（三档话术与基准照 references/参考标尺.md 每章字数行取（示例数值仅格式演示）），数值须经作者同意，使用原 `novel_update_contract` 更新该分部并保留已有内容：

```markdown
### 章节篇幅
- 目标汉字数: 4000
- 下限汉字数: 3500
- 上限汉字数: 4500
```

子节内只写这三项正整数，下限 ≤ 目标 ≤ 上限；说明文字放在其他子节。范围随所在分部确认，暂定内容不能当已确认约束。计数为脚本正文汉字数，含章标题，不含 frontmatter 与候选事实。以后细纲、起草、审读继承此项；超范围走原审读发现项与处置，不增加审批步骤，不自动裁稿。

可选**章型浮动条款**（**高级选项，非默认推荐——新手与依赖脚本篇幅核对的书不启用**）：启用前先知悉限制——core 契约解析器接受浮动行落地前，契约一旦写入浮动行，确定性脚本遇浮动行报「配置错误」、篇幅核对整节失效（处置见段末现状注记），如需使用请知悉此限制并经作者明示同意。单一区间与章型事件容量错配时（单场交锋章/温情落点章写到密度饱和、硬扩即注水），经作者同意可在子节内加一行章型例外——例：`- 章型浮动: 常规 3500-4500｜过渡 2800-3200｜高潮 4000-5500`。主三项正整数行式不变，浮动行各档写「低-高」区间、各档给 ±12.5% 容差带——档区间内＝达标，档区间两缘外扩 ±12.5% 内＝容差带（呈作者裁量），超出容差带＝欠产/超产走既有处置（浮动档验收机械可判，不按单值目标卡严格口径），数值与圈选哪些章型一律经作者同意；各档独立：过渡档允许低于主区间下限（下浮即其用途）、高潮档允许高于主上限；浮动档数值按本书已发稿实测产出分布拟——回炉扩写可拉 30-50%，档目标高出常态产出分布过多时必然反复走作者保留，数值应落在分布带内。细纲、起草、审读继承浮动条款：审读按本章章型的档区间（含容差带）判差额；脚本篇幅核对按全带（全档最小值～全档最大值）核对，章型未注明按主区间。core 契约解析器接受浮动行落地前，确定性脚本遇浮动行报「配置错误」、篇幅核对整节失效——此时差额由人工按本章章型的档区间（含容差带）判。

与作者商定数值时可给三档参考话术（源自本技能包 `references/参考标尺.md` 每章字数行的三档参考）：快节奏档 2100-2500（十日型）、标准档 3500-4500（诡秘/大奉型）、长章档 5500+（历史文型，章长弹性大）。三档是候选参考不是默认值，本书另有节奏安排时以作者自报为准；这些数值与注释只在对谈话术里出现，绝不写进契约子节或其他工件——子节内仍只认上述三项正整数。

### 路径 A：快速开写

作者想先跑起来、以后再细化时走本路径：你按构想快照一次起草开写所需的全部设计，作者过目一次，同意后逐件经工具写入。省的是对谈轮数，不是内容——只有标注、没有正文的「已确认」一律不写。

1. 与作者确认「先跑起来再细化」，读 `构想/构想快照.md`；
2. 一次起草当前所需材料，必要部分写一两句实质内容：
   - 契约六部；
   - 世界书最小模块：人物档案（至少主角一条）、世界规则（至少一条）——条目正文按 `templates/世界书/` 下对应模板起稿（人物档案/世界规则/力量体系/组织/地图/局规则/世界常量七份），留白合法，不强制填满；
   - 故事骨架九部结构保留，只须确认「主角目标与成长轨迹」「核心冲突与对抗力量」的当下追求、处境和已知阻力；其余七部可显式暂定或留白，不为填栏编造终极真相、最终敌人、人物终点或结局。已有兴趣可记暂定猜想；骨架若加「对手梯队」子表（规格见路径 B 第 3 步），只填当前卷实际交手的层级，更高层整行〔留白〕合法——与不为填栏编造最终敌人同规矩；
   - 分卷布局：「故事阶段分配」下写本卷卷行（如 `- 卷01：……〔已确认〕`），其余七部作者没想法就留白；
   - 第一卷卷纲（叙事结构、弧线、线索推进、卷末兑现四段齐全，没想好的段标留白）与计划时间线；卷纲同样执行「压力升级检查」段（规格照《卷幕规划》技能包 templates/卷纲固定段规格.md）——检查不是发散，不违反本路径不跑强制多方向；
   - 第一卷分幕一行（卷纲「叙事结构」段：每幕幕号、幕名、一句任务、大致章数）＋**第一幕幕纲**（照《卷幕规划》技能包 templates/幕纲固定段规格.md 起稿；路径 A 可简：本幕故事、线与伏笔、章组排布三段写实，出场人物、查证清单、幕末结算三段留白）；
   - 近期窗口第一条＝第一章章名（确认细纲要求章名与窗口里可进入的条目同名）；
3. **摘要过目**（默认第一步）：用 5-8 行人话摘要呈报——书写什么（题材＋核心冲突一句话）、主角是谁（身份＋金手指）、第一卷大概怎么走（主线冲突＋卷末兑现方向）、关键取舍（什么留白了什么自拟了），末附一行**体量提示**：按篇幅档，把主要人物、对手层级、支线三项中与 `references/参考标尺.md` 建议差得最多的项列出来（不出完整对账表，不拦截；分卷只排了 N 卷时同时提示「预定篇幅约需 M 卷（按单卷体量行估）」）。作者说「看细节」或点名某件（如「看骨架」）才展开对应工件全文；作者直接说「同意」即视为确认整包（含留白）。摘要末行提示：「想看任何一件的全文，点名即可」；
4. 作者明确同意后按序写入：`novel_update_contract`（六部逐部）→ `novel_confirm_worldbook_entry` → `novel_update_skeleton` → `novel_update_volume_layout` → `novel_confirm_volume_outline`（卷纲、计划时间线、第一幕幕纲各一次）→ `novel_roll_window` 追加第一章条目；
5. 写完查 `novel_get_book_progress`，确认没有「无内容」标记，向作者播报写入结果与留白项。

路径 A 同样执行：压力升级检查（检查不是发散）、对手梯队子表（只填当前交手层）、章节篇幅三档话术、信息释放台账建账（卷01 卷纲首次确认前一次性，建账流程照《卷幕规划》「卷规划」节）、契约第五部只记相对默认文风调整的口径（无调整写「沿用默认文风」，见路径 B 步骤 1）。判据引用与取数算式在路径 A 可选——一次起草时按需参考，不强制逐步走读。

## 对谈纪律

1. **静默预填**：每步呈报前先读该步判据行点名的知识库节，预填草案并在呈报里写明每个提议的推导来源（出自哪节哪条判据），不空手开放式提问；
2. **候选裁决**：每组决定给 1-3 个候选＋你的推荐＋一句依据；作者可回「默认」（取推荐项）、「换一项」或「深挖」（对某个候选展开）；
3. **追问限额**：开放式追问全流程最多 3 个会改变结果的问题，裁决式（选边/确认）追问不计入；已有信息足够先提建议，一次只追问最影响方向的一件事；
4. **复述纠错**：每轮呈报开头先用一两句复述当前决定状态，作者只纠关键误差，不要求复述全部细节；
5. **兜底**：作者说「都行」→取推荐项并标「可后改」；说「都要」→按主案执行、其余归置一行待后议；对谈不因等待答复卡死；
6. **判据取件**：本技能包 `references/` 已全为拆分件（《开书-*/人物设计-*/世界观-*/大纲-*/卷纲-*》）与两份预置件（《参考标尺》《雷点清单》）——判据**整件读入**，不按节切读；文内「判据 §x.y」为溯源注记，节号即件内标题可直接定位；同一步不同时全量加载多份判据件。
7. **待改清单**：对谈中在步骤 N 发现步骤 M（M<N）的已定内容需修正时，不中断当前话题——写一行待改项（格式：`待改：步骤M·工件·字段 —— 现值X → 建议改Y，原因Z`），继续当前思考；五步全部聊完、准备写入前，「确认前审查」的第四部分统一呈报全部待改项让作者逐条确认，然后按修正后的内容按序写入。

### 路径 B：深度定制

**进场先验种子（可跳过）**：契约对谈开始前提示作者——「先写 300 字试试这个开头？测试通过，这段就是第一章的底子」。作者自写或授权你代写；双检：写的时候激动吗？按读者画像自问想看下一章吗？没过不拦开工——小偏差在后续对谈中吸收，方向性推翻走契约修订，不推翻立项。产物用通用写工具落 `<工作范围>/书房/开书/<书名>/种子底子.md`（300 字原文＋头部两行测试结论）。

**全景开场**：种子之后、进入步骤 1 前，向作者一次呈报五个领域的概览——
"今天我们会聊五块内容：①契约（你的书写给谁、核心卖点是什么）②世界书（世界观和主角）③骨架（故事走向和对手）④分卷（每卷的大致节奏）⑤卷纲（第一卷的具体计划）。你可以从任何一块聊起——想先聊世界观、先定主角、还是先聊核心冲突都行；想到哪块聊到哪块，我帮你记住所有决定；全部聊完后按序一次性写入。"
作者没有特别偏好时按默认顺序（1→5）推进。

**设计草案**：路径 B 对谈中定下的内容先逐件写进 `<工作范围>/书房/开书/<书名>/设计草案/`（契约.md、世界书.md、故事骨架.md、分卷布局.md、卷<NN>-卷纲.md；通用写工具，书房资产非真源）——换会话时先读这个目录接上进度；体量对账与「确认前审查」（跨轨道自检、两席评审、待改清单均在其内）都在草案上做；作者确认全部待改项后，按 契约→世界书→骨架→分卷→卷纲与计划时间线→窗口 的顺序经各确认工具写入，下文各步点名的工具即该件写入时用的工具。

1. **契约六部**逐部对谈（题材与读者定位 / 核心看点与差异化 / 阅读体验与情绪承诺 / 主角原则与关系边界 / 叙事方式与文风基调 / 创作禁区与不可妥协项），每聊定一部记入设计草案，写入时调 `novel_update_contract`——「已确认」随确认产生 `design:` 提交，「暂定/留白」只写文件；
   第五部「叙事方式与文风基调」只写本书相对默认文风的调整（默认文风单源在《正文起草》技能包 references/默认文风.md——第三人称限知、先处境后解释、短段快节奏、口语化书面语等；例如「叙述者带吐槽」「对白比例偏高」「句子偏长、古雅」），没有调整就写「沿用默认文风」；不必和作者长谈文风，作者没想法就用默认；
   判据：读 [开书-读者与情绪定位](references/开书-读者与情绪定位.md)＋[开书-构思与验证](references/开书-构思与验证.md) ＋ [大纲-主线与骨架](references/大纲-主线与骨架.md)；
   - **第六部候选菜单**：对谈「创作禁区与不可妥协项」时把 [雷点清单](references/雷点清单.md) 逐类过一遍——作者圈选的雷点升格为本书禁区写入第六部，未圈选的不构成约束；
   - **情感主线声明（可选）**：骨架设「情感主线」子位的书（见步骤 3），本部对齐一句情感主线的情绪承诺与收束形态——承诺什么情感体验、以落定式还是渐近线式收束；与骨架子位同口径，两部说法不一致时呈作者裁决；
2. **世界书**：`novel_confirm_worldbook_entry` 写入/确认条目；
   判据：读 [人物设计-主角](references/人物设计-主角.md)＋[人物设计-金手指设计](references/人物设计-金手指设计.md)＋[人物设计-配角与群像](references/人物设计-配角与群像.md)＋[世界观-规则与铁则](references/世界观-规则与铁则.md)＋[世界观-力量体系与天花板](references/世界观-力量体系与天花板.md)；
   - **条目起稿**：条目正文分别按 [人物档案条目模板](templates/世界书/人物档案条目模板.md)、[世界规则条目模板](templates/世界书/世界规则条目模板.md)、[力量体系条目模板](templates/世界书/力量体系条目模板.md)、[组织条目模板](templates/世界书/组织条目模板.md)、[地图条目模板](templates/世界书/地图条目模板.md) 起稿——按模板起稿，留白合法，不强制填满；悬疑无限流/规则怪谈类作品的单局规则用模块「局规则」登记（首次确认条目时自动登记进 `世界书/模块声明.md`），条目按 [局规则条目模板](templates/世界书/局规则条目模板.md) 起稿；**世界常量条目（建议）**：历史、古代、架空、年代文强烈建议建模块「世界常量」一条到几条，条目正文按 [世界常量条目模板](templates/世界书/世界常量条目模板.md)，其他题材可选；历史文已有的「史实基线」（书房资产）保留，世界常量里的时代基线可指向它；**待回填协议**：模板新增结构节（认知节/铁则表/境界表等）不强制回填旧条目——旧条目下次经 `novel_confirm_worldbook_entry` 写入时按当版模板补齐缺节，留白合法；不为回填主动重写未变动条目；
   - **规则连锁**：写新世界规则条目前 read 本模块已有条目——新规则与已有规则之间有没有矛盾？有没有可以互相强化的组合？同一事实两说的致命冲突修掉；矛盾不一定消除——"铁则A限制X × 金手指B需要X"＝天然冲突引擎，这种矛盾要利用不要修补；
   - **金手指四轨道追问**（§2.4 力量体系对谈期过一遍）：这个金手指兑现主情绪吗〔情绪〕？它长出什么新困境〔剧情〕？受哪条世界铁则限制〔设定〕？安全感三连——它给主角什么安全感→这安全感杀死什么矛盾→怎么再造可控的不安全感？四问都接得上，金手指才同时挂在情绪、剧情、设定上；四轨道聊完按 [力量体系条目模板](templates/世界书/力量体系条目模板.md) 金手指轨道位落四行（代价分型/反制方式/代劳边界/可见度牌——枚举值照模板单源，此处不重述），想不出的行留白不编；
   - **配角功能一问**（人物档案条目起稿时逐个常驻配角过一遍；判据 §2.7 配角功能怎么配）：他占八功能哪一位——情绪（拉扯情绪）/困境（制造会恶化的阻碍）/方法（给解决途径）/冲突（扛最终对决）/背景（攒嘲讽质疑、结局释放）/伪装（误导再转折）/任务（强制开支线）/全局（分阶段推大方向）？零功能配角砍掉或与同功能配角合并；把主角拿走他还想干什么——答不上＝工具人，补独立动机；
   - **暗面一问**（§3.1/§3.8 对谈时每条铁则问一次）：谁在规则下受害？——受害处即冲突土壤；答不出受害者，这条铁则还只是设定不是压力；

## 重入

- **先查书级进度卡再动手**：哪些分部留白/暂定/无内容、哪些工件有待补便签、本卷未决偏离；

- **路径 B 每一卷首次确认卷纲前都跑一次强制多方向**（见《卷幕规划》「强制多方向」节）；路径 A 不跑，同一卷卷纲修订与滚窗不重跑；
- **段级刷新改幕末结算**：每幕写完（不是每约 10 章）做一次幕末结算，轮次与六步在《卷幕规划》「幕末结算」节；**卷纲偏差处理分档**——分档边界定义单源在《细纲备料》重入节「幕末结算与卷纲偏差分档」：小偏差直接改候选卷纲→再确认（版本+1），不跑影响分析（与细纲人物自决轻量改纲同款通道）；大偏差仍走卷纲修订（回《卷幕规划》「卷规划」调整再确认）＋影响分析前置呈报；窗口批量追加用 `novel_roll_window` 逐条补——不是每章滚一次；
- 骨架/分卷覆盖式写入会版本+1：改前跑影响分析脚本（本技能包 `scripts/影响分析.mjs`，只算不写；失败按《工作台总控》「脚本失败分流」表处理）做**影响分析前置呈报**，作者裁决通过后受影响未定稿下游**同批整改**，整改按序经各确认工具写入、各自提交（提交摘要带提案编号便于追溯）；已定稿下游走吃书补偿；影响面过大拆提案；
- 工具返回 `ok:true` 即本次操作完成；`commitState: unchanged` 表示内容已在提交中，`not-required` 表示当前状态不需要提交，均不能当成提交失败，不为产生新提交而重复调用或添加无关内容。不同的已获授权操作可继续；同一轮重复空操作会由宿主结束轮次。
- 只有 `ok:false` 且明确提交失败（新工具为 `commitState: failed, retryable:true`）才处理失败原因后，按原参数**最多补试一次**；仍失败就停止并呈报。旧结果没有结构化字段时也必须区分成功与失败，不根据“未产生新提交”触发重试。原生读取/版本冲突先读文件核对，不能覆盖新内容。
