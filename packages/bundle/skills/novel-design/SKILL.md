# 定调设计（Novel Design）

本技能覆盖「已立项新书 → 开写就绪」。设计侧的一切写入只经工具落盘，每次作者确认由确认类工具产生 `design:` 提交；「留白」是合法状态。作者要求设计时可以主动提出标明为建议的候选；未获认可的内容不写成已确认设定，作者明确要求保留的留白不擅填。

## 先确认本次任务范围

收到书房保存通知时，作者改动已经落盘；只核对本次原文、差异及实际影响。若无事实或约束变化，报告“本次保存处理完成”后结束；有实质影响就呈报提案与待决定项，呈报后结束。**不把保存通知带入下面的新书全流程，不再次写入相同契约，不自动滚窗、补齐留白或推进章节**。提交失败让作者在编辑器重试提交；“不需要提交”或成功的“无改动”均不需要补交。

## 标准流程

作品契约的“阅读体验与情绪承诺”分部可增加 `### 章节篇幅`，作为本书的篇幅约定。定调时和节奏、阅读体验一起商定；已有书未配置时如实提示，作者可以继续留白，不自动设置默认范围。下面仅为四千字章节的宽松示例（3500 基准——作者裁定 2026-10-11，原两千字示例按裁定废止），数值须经作者同意，使用原 `novel_update_contract` 更新该分部并保留已有内容：

```markdown
### 章节篇幅
- 目标汉字数: 4000
- 下限汉字数: 3500
- 上限汉字数: 4500
```

子节内只写这三项正整数，下限 ≤ 目标 ≤ 上限；说明文字放在其他子节。范围随所在分部确认，暂定内容不能当已确认约束。计数为脚本正文汉字数，含章标题，不含 frontmatter 与候选事实。以后细纲、起草、审读继承此项；超范围走原审读发现项与处置，不增加审批步骤，不自动裁稿。

可选**章型浮动条款**：单一区间与章型事件容量错配时（单场交锋章/温情落点章写到密度饱和、硬扩即注水），经作者同意可在子节内加一行章型例外——例：`- 章型浮动: 常规 3500｜过渡 2800｜高潮 4500`。主三项正整数行式不变，浮动行只写各档目标正整数，数值与圈选哪些章型一律经作者同意；各档独立：过渡档允许低于主区间下限（下浮即其用途）、高潮档允许高于主上限；浮动档数值按本书已发稿实测产出分布拟——回炉扩写可拉 30-50%，档目标高出常态产出分布过多时必然反复走作者保留，数值应落在分布带内。细纲、起草、审读继承浮动条款：审读按本章章型的档判差额；脚本篇幅核对按全带（全档最小值～全档最大值）核对，章型未注明按主区间。core 契约解析器接受浮动行落地前，确定性脚本遇浮动行报「配置错误」、篇幅核对整节失效——此时差额由人工按本章章型的档判。

与作者商定数值时可给三档参考话术（源自本技能包 `references/参考标尺.md` 每章字数行的三档参考）：快节奏档 2300-2500（十日/道诡型）、标准档 3500-4500（诡秘/大奉型）、长章档 5500+（历史文型，章长弹性大）。三档是候选参考不是默认值，本书另有节奏安排时以作者自报为准；这些数值与注释只在对谈话术里出现，绝不写进契约子节或其他工件——子节内仍只认上述三项正整数。

### 路径 A：快速开写

作者想先跑起来、以后再细化时走本路径：你按构想快照一次起草开写所需的全部设计，作者过目一次，同意后逐件经工具写入。省的是对谈轮数，不是内容——只有标注、没有正文的「已确认」一律不写。

1. 与作者确认「先跑起来再细化」，读 `构想/构想快照.md`；
2. 一次起草当前所需材料，必要部分写一两句实质内容：
   - 契约六部；
   - 世界书最小模块：人物档案（至少主角一条）、世界规则（至少一条）——条目正文按 `templates/世界书/` 下对应模板起稿（人物档案/世界规则/力量体系/组织/地图五份），留白合法，不强制填满；
   - 故事骨架九部结构保留，只须确认「主角目标与成长轨迹」「核心冲突与对抗力量」的当下追求、处境和已知阻力；其余七部可显式暂定或留白，不为填栏编造终极真相、最终敌人、人物终点或结局。已有兴趣可记暂定猜想；骨架若加「对手梯队」子表（规格见路径 B 第 3 步），只填当前卷实际交手的层级，更高层整行〔留白〕合法——与不为填栏编造最终敌人同规矩；
   - 分卷布局：「故事阶段分配」下写本卷卷行（如 `- 卷01：……〔已确认〕`），其余七部作者没想法就留白；
   - 第一卷卷纲（叙事结构、弧线、线索推进、卷末兑现四段齐全，没想好的段标留白）与计划时间线；卷纲同样执行「压力升级检查」段（规格见路径 B 第 6 步）——检查不是发散，不违反本路径不跑强制多方向；
   - 近期窗口第一条＝第一章章名（确认细纲要求章名与窗口里可进入的条目同名）；
3. 整份呈作者过目：概述当前内容及留白，标明哪些是你的提议。契约必要部分及骨架前两部不足时说明缺口；其余远期留白不阻塞当前就绪。确认含留白的整份文档不意味着所有分部改成已确认，已确认但空白仍需处理；
4. 作者明确同意后按序写入：`novel_update_contract`（六部逐部）→ `novel_confirm_worldbook_entry` → `novel_update_skeleton` → `novel_update_volume_layout` → `novel_confirm_volume_outline`（卷纲、计划时间线各一次）→ `novel_roll_window` 追加第一章条目；
5. 写完查 `novel_get_book_progress`，确认没有「无内容」标记，向作者播报写入结果与留白项。

路径 A 同样执行：压力升级检查（检查不是发散）、对手梯队子表（只填当前交手层）、章节篇幅三档话术、信息释放台账建账（卷01 卷纲首次确认前一次性）。判据引用与取数算式在路径 A 可选——一次起草时按需参考，不强制逐步走读。

## 对谈纪律

1. **静默预填**：每步呈报前先读该步判据行点名的知识库节，预填草案并在呈报里写明每个提议的推导来源（出自哪节哪条判据），不空手开放式提问；
2. **候选裁决**：每组决定给 1-3 个候选＋你的推荐＋一句依据；作者可回「默认」（取推荐项）、「换一项」或「深挖」（对某个候选展开）；
3. **追问限额**：开放式追问全流程最多 3 个会改变结果的问题，裁决式（选边/确认）追问不计入；已有信息足够先提建议，一次只追问最影响方向的一件事；
4. **复述纠错**：每轮呈报开头先用一两句复述当前决定状态，作者只纠关键误差，不要求复述全部细节；
5. **兜底**：作者说「都行」→取推荐项并标「可后改」；说「都要」→按主案执行、其余归置一行待后议；对谈不因等待答复卡死；
6. **按节引用**：读本技能包 `references/` 知识库时，用读取工具按 `## §x.y` 标题定位后只读该节，不整文件读入；同一步不同时全量加载多份知识库文件。
7. **待改清单**：对谈中在步骤 N 发现步骤 M（M<N）的已定内容需修正时，不中断当前话题——写一行待改项（格式：`待改：步骤M·工件·字段 —— 现值X → 建议改Y，原因Z`），继续当前思考；五步全部聊完、准备写入前，先呈报全部待改项让作者逐条确认，然后按修正后的内容按序写入。

### 路径 B：深度定制

**进场先验种子（可跳过）**：契约对谈开始前提示作者——「先写 300 字试试这个开头？测试通过，这段就是第一章的底子」。作者自写或授权你代写；双检：写的时候激动吗？按读者画像自问想看下一章吗？没过不拦开工——小偏差在后续对谈中吸收，方向性推翻走契约修订，不推翻立项。产物用通用写工具落 `<工作范围>/书房/开书/<书名>/种子底子.md`（300 字原文＋头部两行测试结论）。

**全景开场**：种子之后、进入步骤 1 前，向作者一次呈报五个领域的概览——
"今天我们会聊五块内容：①契约（你的书写给谁、核心卖点是什么）②世界书（世界观和主角）③骨架（故事走向和对手）④分卷（每卷的大致节奏）⑤卷纲（第一卷的具体计划）。你可以从任何一块聊起——想先聊世界观、先定主角、还是先聊核心冲突都行；想到哪块聊到哪块，我帮你记住所有决定；全部聊完后按序一次性写入。"
作者没有特别偏好时按默认顺序（1→5）推进。

1. **契约六部**逐部对谈（题材与读者定位 / 核心看点与差异化 / 阅读体验与情绪承诺 / 主角原则与关系边界 / 叙事方式与文风基调 / 创作禁区与不可妥协项），每聊定一部调 `novel_update_contract`——「已确认」随确认产生 `design:` 提交，「暂定/留白」只写文件；
   判据：读 [01_开书](references/01_开书.md) §1.2、§1.4、§1.6、§1.7、§1.11 ＋ [04_大纲](references/04_大纲.md) §4.2；
   - **第六部候选菜单**：对谈「创作禁区与不可妥协项」时把 [雷点清单](references/雷点清单.md) 逐类过一遍——作者圈选的雷点升格为本书禁区写入第六部，未圈选的不构成约束；
2. **世界书**：`novel_confirm_worldbook_entry` 写入/确认条目；
   判据：读 [02_人物设计](references/02_人物设计.md) §2.2、§2.3、§2.4 ＋ [03_世界观设计](references/03_世界观设计.md) §3.1、§3.2、§3.8；
   - **条目起稿**：条目正文分别按 [人物档案条目模板](templates/世界书/人物档案条目模板.md)、[世界规则条目模板](templates/世界书/世界规则条目模板.md)、[力量体系条目模板](templates/世界书/力量体系条目模板.md)、[组织条目模板](templates/世界书/组织条目模板.md)、[地图条目模板](templates/世界书/地图条目模板.md) 起稿——按模板起稿，留白合法，不强制填满；**待回填协议**：模板新增结构节（认知节/铁则表/境界表等）不强制回填旧条目——旧条目下次经 `novel_confirm_worldbook_entry` 写入时按当版模板补齐缺节，留白合法；不为回填主动重写未变动条目；
   - **规则连锁**：写新世界规则条目前 read 本模块已有条目——新规则与已有规则之间有没有矛盾？有没有可以互相强化的组合？矛盾不一定消除——"铁则A限制X × 金手指B需要X"＝天然冲突引擎，这种矛盾要利用不要修补；
   - **金手指四轨道追问**（§2.4 对谈时过一遍）：这个金手指兑现主情绪吗〔情绪〕？它长出什么新困境〔剧情〕？受哪条世界铁则限制〔设定〕？猫腻三连——它给主角什么安全感→这安全感杀死什么矛盾→怎么再造可控的不安全感？四问都接得上，金手指才同时挂在情绪、剧情、设定上；四轨道聊完按 [力量体系条目模板](templates/世界书/力量体系条目模板.md) 金手指轨道位落四行（代价分型/反制方式/代劳边界/可见度牌——枚举值照模板单源，此处不重述），想不出的行留白不编；
   - **暗面一问**（§3.1/§3.8 对谈时每条铁则问一次）：谁在规则下受害？——受害处即冲突土壤；答不出受害者，这条铁则还只是设定不是压力；
3. **故事骨架**：`novel_update_skeleton`（九部，覆盖式，再确认版本+1）；按作者兴趣展开深度，远期仍可留白。保留已建立期待与创作意图，不改成重复的事实账本；旧书已确认终局继续有效，不自动降级或清除；「核心冲突与对抗力量」部内加 `### 对手梯队` 子表——表列、强制取数算式行与存活周期映射按 [对手梯队子表规格](templates/对手梯队子表规格.md) 填，取数各因子照实取自 `references/参考标尺.md` 后呈报，禁止凭印象给数；代表对手与出牌去向想不出的层级留白，不为填表编造；首次确认或作者点名时可选走下方「确认前评审（可选）」两席审读；
   判据：读 [04_大纲](references/04_大纲.md) §4.15、§4.14、§4.2、§4.8、§4.10、§4.7；
   - **结局镜像卡**（骨架「结局与终局」相关部对谈时过一遍）：结局倒推两问——让主角回到开头那一刻，他不会再做同样选择吗？激励事件砸出的创伤，在结局怎么被主题回应？两问都接不上，结局部还只是「赢了」不是「完成了变化」；「完成了变化」落到行为上验——结局处他的哪个具体选择，是开头那个他不会做的？指不出这个选择，变化就还停在宣告；
   - **激励事件三问**（骨架「故事阶段与关键转折」部谈到开端时过一遍；判据 §4.12 激励事件怎么设计）：为什么偏偏此刻发生（时机压力）？为什么砸中这个主角（命中必然——绑定过往创伤，不是天降巧合）？主角为什么不躲开（无法回避——彻底打破日常，回不去了）？三问接不上＝开端只是「事情发生了」不是「不得不发生」；
   - **反派正当性两问**（对手梯队子表逐层代表对手过一遍；判据 §2.10 反派怎么设计才不工具人）：他为什么相信自己是对的（立场正当性）？他的组织与资源凭什么撑到这一层（体量正当性）？答不上的层级是纸片人，留白也别编；
4. **分卷布局**：`novel_update_volume_layout`（八部，同上）；「卷目标与卷末状态」部内每卷一行主战层级表行——`卷NN｜主战层级（小/中/大/终局）｜升级关系`；主战层级与存活周期口径取自 `references/参考标尺.md`，升级关系须落到四来源之一并写实：新层有伏笔在先／旧层存活周期耗尽／双层承担者切换（切换在本卷如何呈现写明）／同层内变（对手不变，强度/形态升级——同层承担者出牌更极端或形态质变写实）；这些表行只写「卷目标与卷末状态」，绝不写进「故事阶段分配」小节——该小节的卷行是进度解析位，同卷两行会报状态冲突；首次确认或作者点名时可选走下方「确认前评审（可选）」两席审读；
   判据：读 [04_大纲](references/04_大纲.md) §4.5、§4.6、§4.3 ＋ [05_卷纲](references/05_卷纲.md) §5.1；
5. **强制多方向**（本卷首次确认卷纲前必跑；卷纲修订与滚窗不跑，路径 A 不跑）：
   - 读 `作品契约/契约.md` 的「核心看点与差异化」「阅读体验与情绪承诺」两部，列出作者已确认的承诺、禁区和既定事实，标注「不参与发散」。题材惯例只作候选参考，不自行加入“主角必须变强”等硬要求；
   - 提出三条因果、人物选择或信息组织明显不同的路线；可用一条典型版作对照，但不默认它最好，也不强制把作者意图改成典型套路；
   - 依据本卷矛盾选择发散轴，如代价承担者、揭露顺序、人物立场、解决问题的方式；不同路线应有实质差异，不局限于固定短表，也不只改名称；
   - 每个方向都写代价与放弃项，只有好处的方向打回重写；
   - 三个方向呈作者选择或组合。卷纲末尾「方向选择」小节格式按 [卷纲固定段规格](templates/卷纲固定段规格.md) 填——`已排除走向` 只记作者明确否决的走向，未选方案不自动成为禁区；

**跨轨道自检**（五步聊完、写入前最后一道，呈报错位项供作者裁决）：
- 契约·情绪承诺 ↔ 骨架·核心冲突——情绪承诺在冲突里有兑现路径吗？
- 世界书·金手指 ↔ 骨架·主角目标——金手指能支撑主角达成目标吗？
- 世界书·铁则 ↔ 分卷·升级关系——铁则允许的升级节奏跟分卷规划对得上吗？
- 契约·创作禁区 ↔ 骨架·全部九部——有哪部踩了禁区？
- 分卷·主战层级 ↔ 骨架·对手梯队——层级行和梯队表对得上吗？
错位项呈报作者：接受（记 novel_note_pending）或修正（回到对应步骤调整）；不错位则报告"五轨对齐"。

## 重入

- **先查书级进度卡再动手**：哪些分部留白/暂定/无内容、哪些工件有待补便签、本卷未决偏离；
- **分部更新，绝不整体重写契约**；
- **路径 B 每一卷首次确认卷纲前都跑一次强制多方向**；路径 A 不跑，同一卷卷纲修订与滚窗不重跑；
- **卷内段级滚窗**：每完成一个卷内高潮（或约 10 章）做一次段级回顾——输入＝本段已定稿章摘要（实际走向与卷纲的偏差、人物活了的新脉络），据此重排下一段窗口；卷纲要修订先走卷纲修订（回步骤 6 调整再确认），窗口批量追加用 `novel_roll_window` 逐条补——不是每章滚一次；
- 骨架/分卷覆盖式写入会版本+1：改前跑影响分析脚本（本技能包 `scripts/影响分析.mjs`，只算不写；失败按《工作台总控》「脚本失败分流」表处理）做**影响分析前置呈报**，作者裁决通过后受影响未定稿下游**同批整改**，整改文件列入确认工具的 `批次文件` 一并整批提交；已定稿下游走吃书补偿；影响面过大拆提案；
- 工具返回 `ok:true` 即本次操作完成；`commitState: unchanged` 表示内容已在提交中，`not-required` 表示当前状态不需要提交，均不能当成提交失败，不为产生新提交而重复调用或添加无关内容。不同的已获授权操作可继续；同一轮重复空操作会由宿主结束轮次。
- 只有 `ok:false` 且明确提交失败（新工具为 `commitState: failed, retryable:true`）才处理失败原因后，按原参数**最多补试一次**；仍失败就停止并呈报。旧结果没有结构化字段时也必须区分成功与失败，不根据“未产生新提交”触发重试。原生读取/版本冲突先读文件核对，不能覆盖新内容。
