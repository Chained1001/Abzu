# 变更影响分析

> 件定位：剧情、设定、人物变更的分级判据、变更包模板、依赖顺序与回归口径。消费位：《定调设计》重入「影响分析前置呈报」与大纲记录｜《卷幕规划》重入「卷纲修订／大偏差」｜《工作台总控》「提案与吃书补偿」。
> 单源声明：L0-L4 判据、变更包字段、依赖顺序与吃书补偿四件只在本件；SKILL、步骤卡与审读底本只写指针，不内联模板。
> 适用范围：作者一句「把张三改成厨师」、审读发现项根因在上游真源、写作中发现前置事实不成立、卷级走向调整，都先按本件定级出包，再动任何文件。仅改字词句读、事实与因果不变的表达层修正不在此列。

## 一、何时必须读本件

命中任一条就必须先读本件、先出变更包，再写入：

- 改人物身份、职业、外貌、年龄、能力、动机、关系方向、知识来源或认知状态；
- 改世界规则、力量体系、金手指规则、组织、地图、世界常量中的硬约束；
- 改契约六部、主角原则、关系边界、创作禁区、叙事方式与文风基调；
- 改故事骨架、分卷布局、卷纲、幕纲、细纲里的主线走向、卷末兑现、伏笔埋收、章序；
- 审读发现项的根因落在上游真源，而不是本章文字；
- 目标内容已定稿或已发布，却仍要修正；
- 作者给出单点指令，但没有说明下游怎么处理。

不必读本件：只改表达层的润色；不动事实的错别字与排版修正；作者在编辑器里已经落盘、且只涉及一处措辞的保存通知（按《定调设计》「先确认本次任务范围」核对即可）。判断拿不准时按高一级处理，先读本件。

## 二、L0-L4 分级

### 定级四问

按顺序问，命中即停，取最高一级：

1. 这次改动只动表达、读者理解的事实不变？是＝L0，结束；
2. 只动单章内可核实的事实，不动人物动机、关系方向与长期设定？是＝L1；
3. 会改变人物的身份、职业、动机、关系方向、能力用法、知识来源，或某段剧情的走向？是＝L2 起；
4. 会改变世界规则、契约承诺、全书结构，或目标文本已定稿／已发布？前者＝L3，后者按 L4 处置。

**就高不就低**：同一变更既动表达又动事实，按事实级；既动人物又动规则，按 L3，人物部分降为子项；同一变更包里可以有多条子项，但只定一个主级。**混级拆包**：两条以上互不依赖的变更分别出包，不合并成一个巨型包；影响面跨两卷以上、同时动两条以上主线、或需重写本卷四分之一以上章节时，拆提案分步走。

### 五级

| 级别 | 名称 | 改什么 | 典型触发 | 影响面 | 必经通道 | 已写章节 |
|---|---|---|---|---|---|---|
| L0 | 表达 | 字词、句式、段落节奏、对话口气、描写密度；事实、因果、人物口径不变 | 审读表达层发现项、润色 | 当章文本 | 润色或改稿；不跑影响分析，不出变更包 | 不涉及定稿改写；定稿后文字修正走作者编辑器手改，不回本件 |
| L1 | 局部事实 | 单章内可核实的事实：道具位置、时间、天气、在场人、某句台词、场景细节；不动动机、关系方向与长期设定 | 写作发现、审读事实项、沉淀勘误 | 当章＋相邻章 | 候选事实→沉淀回写；若同时改设计工件，跑影响分析并出轻量变更包 | 未定稿改稿；已定稿走吃书补偿 |
| L2 | 剧情人物 | 身份、职业、动机、关系方向、能力用法、知识来源；某段剧情 A→B；伏笔埋收方式 | 作者要求、审读根因、卷级调整 | 骨架以下到正文，加账本与摘要 | 完整变更包＋影响分析前置呈报＋作者裁决 | 未定稿同批整改；已定稿走吃书补偿 |
| L3 | 硬设定契约 | 契约六部、世界铁则、力量体系与台阶、金手指规则、组织／地图／世界常量中的硬约束、主角原则、关系边界、创作禁区、叙事方式 | 设定重构、主线根因、读者承诺破裂 | 全书所有下游 | 契约修订＋完整变更包＋提案＋作者裁决＋全链回归 | 已定稿内容按 L4 处置，不直接重写定稿 |
| L4 | 已定稿已发布 | 已入档定稿或已发布文本本身；变更只能通过补偿落地 | 事实更正、连续性修复、读者承诺修复 | 已定稿＋后续正文＋账本／摘要 | 吃书补偿＋提案＋作者裁决；定稿区只增不改 | 正文补偿、认知补偿、承诺补偿、账本／摘要补偿四件齐全 |

**L3 与 L4 不是同一维度**：L3 说的是变更意图有多深，L4 说的是目标文本处于什么状态。一次 L3 变更若命中已定稿章节，包主级仍是 L3，已写章节按 L4 处置；不要因为「已经定稿」就把整包降成 L4，也不要把 L4 当成比 L3 更高的创作权限。

**职业变更的定级**：职业只是身份标签、换掉不影响能力与主线时是 L2；职业承载金手指、力量体系、世界规则或全书主线时升 L3。**知识来源的定级**：只换信息载体、知道的内容不变是 L2；新来源改变了世界规则、反派身份或读者认知前提时升 L3。

## 三、变更包模板

### 必填字段

变更包是呈报与落实的共同底稿，不是写给作者看的散文。每一格都要能被下游直接执行；写不出证据的格子留「待查」，不凭印象填。

| 字段 | 填写要求 |
|---|---|
| 旧 | 旧事实原文或旧口径，附来源路径、版本或章号；不凭记忆复述 |
| 新 | 拟改后的原文或新口径，细到字段、句子、条目；不写「改成更合理」 |
| 原因 | 触发源＋证据：作者原话、审读发现项编号、正文冲突处、时间线矛盾点 |
| 影响人物 | 逐人列身份、动机、关系、能力、认知的变化；没有变化的人不列 |
| 影响关系 | 每条核心关系写「从什么变成什么」，以及变化由哪个事件支撑 |
| 影响能力 | 金手指、力量体系、台阶、代价、反制方式、代劳边界是否变化 |
| 影响知识 | 谁知道、谁不知道、何时知道、误知什么；对照人物档案认知节与信息释放台账 |
| 影响社会 | 组织、制度、经济、舆论、地图与势力范围是否变化 |
| 事件链 | 前因→事件→后果；时间线、动机链、在场人、目击者逐项核 |
| 伏笔 | 已埋、拟埋、拟兑现、失效各列；附线索账编号或章号 |
| 读者承诺 | 契约情绪承诺、卷末兑现、承诺账；读者已经建立的期待怎么接住 |
| 受影响工件 | 逐件写：路径｜当前版本或章号｜状态（未定稿／已定稿／已发布）｜处理 |
| 已写章节处理 | 无／改稿／吃书补偿／保留旧文并在后文圆；四选一，不写「看情况」 |
| 最小改法 | 只改必要字段、保留其余的下限方案；写明它撑不住什么 |
| 彻底改法 | 全链对齐方案；写明代价：重写章数、进度、读者记忆重建 |
| 吃书补偿 | 仅命中定稿或发布时填；按第五节四件补偿逐件写，不写「后文解释一下」 |
| 回归验证 | 按第六节列本次必跑的核对项与通过标准 |
| 作者裁决 | 待裁决／通过最小改法／通过彻底改法／驳回／拆分；附提案编号与裁决记录 |

### 受影响工件怎么取

1. 先跑影响分析脚本做反向闭包：`node <resourceBase>/scripts/影响分析.mjs --book <bookRoot> --变更路径 <仓内相对路径>`。脚本只算不写，只报事实，不判断该不该改；
2. 把脚本报出的未定稿下游、已定稿命中、解析失败分别读进「受影响工件」；脚本没报但语义上依赖本次变更的工件，也要人工补列并写明理由；
3. 逐件核当前版本与状态：未定稿可同批整改；已定稿或已发布只能补偿；解析失败先修引用，不带着坏边推进；
4. 不凭印象估影响面，不把草稿区受影响文件列入确认工具的 `批次文件`；
5. 变更落地后复跑一次，确认没有新增未处理下游；闭包不收敛就不算改完。

## 四、按依赖顺序改

### 顺序链

**依赖顺序（不可跳层）**：契约 → 世界书 → 骨架 → 分卷 → 卷纲 → 幕纲 → 细纲 → 正文 → 账本/摘要。

上游是下游的来源：契约定承诺，世界书定事实与规则，骨架定走向，分卷定体量与接口，卷纲定本卷结构，幕纲定章组，细纲定章内事件，正文落字，账本与摘要记录已发生。先改下游会造成两套事实并存，下一章又按旧上游写回去；先改上游再逐层下推，才能让影响面收敛。

### 逐层改法

| 序 | 层 | 改什么 | 落盘通道 | 改完核对 |
|---|---|---|---|---|
| 1 | 契约 | 六部逐部更新；只改受影响分部，不整体重写，不抹掉书 id 与既有分部 | `novel_update_contract` | 六部口径一致；「已确认／暂定／留白」状态未被顺手改写；没有为填栏编造默认值 |
| 2 | 世界书 | 人物档案、世界规则、力量体系、组织、地图、世界常量中受影响的条目；认知节与铁则表优先 | `novel_confirm_worldbook_entry` | 条目之间无同一事实两说；认知节写清谁知道什么；铁则与力量体系不互相拆台 |
| 3 | 骨架 | 主角目标与成长轨迹、核心冲突与对抗力量、关键转折、线索悬念伏笔、人物弧线与关系、结局方向 | `novel_update_skeleton` | 九部保留；对手梯队与分卷主战层级对得上；未把远期留白硬填成终局 |
| 4 | 分卷 | 卷目标与卷末状态、故事阶段分配、主线与支线分布、卷间衔接、主战层级 | `novel_update_volume_layout` | 卷行用两位阿拉伯数字；卷行状态不与小节标题冲突；卷末状态能接住下一卷 |
| 5 | 卷纲 | 叙事结构、弧线、线索推进、卷末兑现、压力升级检查、计划时间线 | `novel_confirm_volume_outline` | 卷末兑现仍可达；压力升级检查五项逐项过；方向选择只在路径 B 首次确认时出现 |
| 6 | 幕纲 | 本幕故事、线与伏笔、出场人物、章组排布、查证清单、幕末结算 | `novel_confirm_volume_outline`（目标：幕纲） | 幕任务与卷纲对齐；线与伏笔能落到具体章；章组区间合计等于本幕章数 |
| 7 | 细纲与窗口 | 章细纲固定小节、信息边界、章末双钩、单元与冲突爽点、近期窗口条目 | `novel_confirm_outline`、`novel_roll_window` | 细纲逐章确认；信息边界不越章；窗口条目与章号连续；旧候选按修订流程升版 |
| 8 | 正文 | 未定稿改稿或重写；已定稿只做补偿，不直接改 | 起草／改稿／润色工序；定稿区走 `novel_apply_retcon` | 新事实在正文里有来源；角色不知道的事不表现成知道；改过的章重跑审读 |
| 9 | 账本/摘要 | 线索账、承诺账、信息释放台账、本书记忆、章摘要、卷摘要 | 沉淀与账本更正流程；卷摘要走候选→确认 | 账本行与正文一致；摘要不复述旧事实；信息释放累计比例按新章重算 |

### 同批整改纪律

- 受影响未定稿下游**同批整改**：一次确认、逐件提交，提交摘要带提案编号，便于回溯；
- **不跳层**：骨架没定就不改分卷，卷纲没定就不排幕纲，幕纲没定就不出细纲；
- **不夹带**：变更包外的顺手修改不进本批，另开变更包或记待改；
- **不挂账**：本批能改完的不留到下一卷；影响面过大拆提案，写清拆分边界与先后顺序；
- 每层改完复跑影响分析，确认下游闭包没有扩大；上游变更导致下游大面积重排时，回退到上一层重定，不在下游硬圆。

## 五、已写章节的处理：吃书补偿

未定稿章节走改稿或重写，不叫吃书。已定稿或已发布章节只能补偿：定稿区只增不改，补偿事件留痕，读者看到的是「后文把前文圆回来」，不是「前文被偷偷改掉」。

**四种处置，四选一，不写「看情况」**：

| 处置 | 何时用 | 做法 | 禁止 |
|---|---|---|---|
| 无 | 变更不触及已写章节 | 在变更包里写明「无」并附影响分析结果 | 不跑影响分析就写「无」 |
| 改稿 | 目标章仍在草稿区、未定稿 | 按新上游重写或改稿，重跑审读后重新定稿 | 拿改稿通道去改定稿区 |
| 吃书补偿 | 目标章已定稿或已发布 | 按下方四件补偿落地，登记提案与补偿记录 | 直接编辑定稿正文；把补偿当撤销 |
| 保留旧文并在后文圆 | 旧文仍有价值、硬改代价过大 | 作者裁决后在后续章用新证据、新视角或角色改口圆回来 | 不登记补偿、不告诉读者；把作者裁决省掉 |

**吃书补偿四件**（缺一件不算补偿完成）：

1. **正文补偿**：用新事件、新证据、新证人、新视角，让新事实在故事里有来源；不是旁白改口。例：旧章说「父亲失足落水」，后文用遗书、验尸记录或目击者翻案；
2. **认知补偿**：解释角色为什么现在才知道、为什么之前记错、谁在撒谎或隐瞒；同步人物档案认知节。角色不能无缘无故从不知道变成知道；
3. **承诺补偿**：读者已经建立的期待不能凭空消失。原伏笔、爽点、关系承诺要么在新线里兑现，要么转成新钩子并登记承诺账；不能当作没发生过；
4. **账本／摘要补偿**：线索账、承诺账、信息释放台账、本纪记忆、章摘要、卷摘要同步到新事实，防止后续章继续引用旧口径。

**补偿纪律**：先呈报后执行；`novel_apply_retcon` 只在提案回路走完、作者明确批准后调用；补偿记录写清关联提案编号、旧事实、新事实与补偿位置；作者驳回就停，旧计划继续有效，不抹去正文已经建立的期待。

## 六、回归验证

变更包写完不算完成，回归通过才算。按主级取必跑项：

| 核对项 | 通过标准 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|---|
| 影响分析复跑 | 无新增未处理下游；解析失败已清零 | 可选 | 必跑 | 必跑 | 必跑 |
| 逐层对账 | 契约、世界书、骨架、分卷、卷纲、幕纲、细纲、正文、账本／摘要逐层口径一致 | 不涉及层可跳 | 必跑 | 必跑 | 必跑 |
| 认知一致性 | 不知道的人没表现出知道；知道的人有来源；误知有解释 | 可选 | 必跑 | 必跑 | 必跑 |
| 事件链与时间线 | 前因、后果、在场人、时间顺序能闭合 | 必跑 | 必跑 | 必跑 | 必跑 |
| 伏笔账与承诺账 | 已埋有回收或明确转钩；读者承诺未被无声取消 | 可选 | 必跑 | 必跑 | 必跑 |
| 卷末兑现与升级位 | 本卷卷末仍能兑现；升级位没有被变更吃掉 | 不涉及 | 必跑 | 必跑 | 必跑 |
| 已写章节补偿 | 四件补偿齐；补偿位置与提案编号可查 | 命中才跑 | 命中才跑 | 命中才跑 | 必跑 |
| 正文审读 | 改过的章重跑确定性检查与语义审读，无新增硬伤 | 改稿才跑 | 改稿才跑 | 改稿才跑 | 改稿才跑 |

回归结论写回变更包与提案裁决记录；未通过项列明「未通过／待作者裁决」，不得用「基本一致」「问题不大」代替。作者带伤接受时，在裁决记录里写明接受了哪一项风险。

## 七、作者裁决与提案

- **必须呈作者裁决**：L2 以上的最小／彻底二选一；任何命中已定稿或已发布的吃书补偿；影响面过大需要拆提案；契约层根因。
- **不必单开裁决**：L0 表达层；L1 局部事实在既有审读与沉淀授权内处理；但 L1 一旦命中已定稿，仍按 L4 走补偿裁决。
- **提案通道**：整理变更包后调 `novel_record_proposal`，传域、类型、内容、来源与本次影响分析摘要；作者明确表态后调 `novel_resolve_proposal` 回写通过或驳回；通过后未定稿下游按依赖顺序同批整改，已定稿内容走 `novel_apply_retcon`。
- **作者未表态**：停在「待裁决」，不改已定稿，不替作者选最小或彻底，不把建议当决定；已有待裁决提案时复用，不重复登记。
- **作者驳回**：停止该变更包；旧计划继续有效；不把驳回项删成不存在，也不在正文里偷偷按新方案写。
- **作者说「都行」**：给出推荐方案与理由，按推荐执行并标「可后改」；涉及已定稿补偿时不适用，仍须明确批准。

## 十一、反例：单点硬改会怎样

- **只改世界书人物职业**：骨架仍写厨子、卷纲仍排酒楼、正文仍称「张小厨」、账本仍记「掌勺」——下一章按旧身份写，审读报设定冲突与「不知道的人表现出知道」；
- **只改正文一句话**：细纲、卷纲、骨架没动，下一章又按旧动机写，读者看到人物反复；
- **只改契约**：下游没有同批整改，影响分析复跑仍有未处理下游，等于两套设定并存；
- **只改已定稿章节**：定稿区被直接编辑，历史留痕断裂，后续章仍引用旧事实；
- **把吃书补偿当撤销**：后文没有补偿事件，读者只看到人物突然改口，读者承诺破裂。

判断标准只有一条：上游改了，下游是否按依赖顺序同批对齐，回归是否通过。没做到，就还是单点硬改。
