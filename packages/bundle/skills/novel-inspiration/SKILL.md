# 灵感与立项（Novel Inspiration）

本技能覆盖「零散脑洞 → 候选探索 → 可立项构想 → 建书」。先判断作者要记录、探索还是立项；一次重点解决一两个方向问题。未经作者明确同意，严禁进入建书。

## 标准流程

作者要求探索时，给两类可比较方向：熟悉题材中由人物处境和选择长出的新发展，以及特殊设定及其后果推演。每类用一小段故事发展讲清处境、动机、选择、后果和期待，再给少量自然长出的开放分岔。差异不能只有换人名、地点或能力名称；题材惯例只是参考，不自动成为硬限制。不用临时设定、人物失智或固定反转配额制造新意。

短段发展用于探索，不是待入稿正文。分岔可以全部推翻，不预设终点，也不自动成为正式路线、事实或兑现义务。可用问答、具体发展试探、人物选择推演或参考作品分析，不连续出选择题代替材料。作者表达偏好后保留他喜欢的部分、改变不满意的机制；已有信息足够就先提建议，一次只追问最影响方向的一件事。已有明确路线时沿该路线探索，不强迫重新二选一。方向清楚后再收敛七要素；明确只想记录时不启动探索。

1. **随手记**：仅要求记录时，保留作者原意，不评判、不主动展开。用通用写工具落到灵感池 `<工作范围>/书房/灵感池/`，一条脑洞一个 `.md`，frontmatter 三项——`状态: 候选`、`身份:` 与文件名同值、`来源快照:` 落 ISO 时间戳。探索中将值得保留的候选与作者原话区分记录。
2. **收敛七要素**（要素名与 `novel_create_book` 的 `concept` 参数字段逐字对应，呈报与调用照抄）：
   - **核心创意**——一句话卖点；
   - **题材与目标读者**——大类+细分与对标气质；
   - **主角核心欲望**——最想要什么，动机能否支撑长篇；
   - **主要冲突**——谁在阻碍，能否逐级升级；
   - **核心看点**——追更的爽点/悬念/期待感；
   - **差异化方向**——同类里独特的记忆点；
   - **明确不要什么**（创作禁区）——明确不写的桥段、人设、走向。
   收敛时可参考（可选）：《定调设计》技能包 references/01_开书.md 的 §1.2（读者画像三空——他是个__、现实中最缺__、我给他__）、§1.9（一句话故事四要素——主角+欲望+阻碍+代价）、§1.7（元素组合出新意——熟框架换一个关键变量）——如当前会话已加载该技能包可按节读取；未加载不阻塞，仅凭七要素自带判据。题材考据需要外部资料时，走下方「采风与灵感库」节。

   （可选）作者需要起书名时：给 3-6 个候选，三条路各 1-2 个（反差公式/堆标签/动词情绪）；核心三要素（题材/金手指/爽点）至少一项入名；生成候选前可翻 `<工作范围>/书房/灵感库/古词古句·意象/零件卡.md` 取词（雅称/意象词可直接入名，无库跳过）；作者未选任何一个＝全毙，追问"心里有没有必须出现的关键词"再生成一轮。
3. **呈报确认**：七要素整理为构想草案，用通用写工具落 `<工作范围>/书房/构想/<书名或代称>.md`，再呈作者；未定的要素写「留白」，`核心创意` 与 `题材与目标读者` 两项必须非留白，其余五项可留白，不要求全部定死才立项；获明确同意后调 `novel_create_book`，七个要素字段一个不缺地给全，`concept.状态` 必须为「已确认」。
4. **跃迁**：建书由工具完成——书仓脚手架、构想快照冻结、书id 写入契约、`vol:` 首次提交（草稿区不入库），设计面跃迁为「作品定调」。**建书不自动切书**：拿 `novel_create_book` 返回的 `bookId` 调 `novel_select_book` 落定当前书，再向作者说明两条去向——快速开写（《定调设计》路径 A：一次起草、作者过目确认）；深度定制（《定调设计》路径 B：逐部细聊）。

## 工具

| 工具 | 何时用 | 不要 |
|---|---|---|
| 通用写工具（灵感池） | 每个脑洞当场落 `书房/灵感池/` | 把灵感池当真源;写在书仓里 |
| 通用写工具（灵感库） | 采风暂存、裁决后零件卡归档、消费回写「已用于」列均落 `书房/灵感库/` | 未经作者裁决写正库（零件卡/索引）;把灵感库当真源 |
| `novel_create_book` | 七要素已确认后一次调用 | 构想不完整或未确认时调用;重复建同名书 |
| `novel_select_book` | 建书返回 `bookId` 后落定当前书 | 未经作者明确指定就切到别的书 |
| `novel_record_memory` | 对谈中出现值得记的决策/建议/解法 | 把七要素本体抄进记忆（建书前的载体是 `书房/构想/` 草案，建书后是构想快照） |

## 灵感元数据

新灵感条目可在原三字段之外另加 `schemaVersion: 1`、`类型: 随手记|对谈候选`、`标签: [标签]`；旧条目和自由正文无需迁移，未知字段保留，`来源快照` 始终是 ISO 记录时间。

## 从参考作品产生新点子

按当前问题选择性调用 `novel_reference_query({action: 'search', query, tags?})`，分别看作者点子与有效参考机制；不强制每次都搜索。想从自备小说拆解时加载 `novel-analyze`；没有原文或可用分析时，只能推荐正规获取链接或讨论公开作品资料，不能声称已经拆过。

引用机制说明一般问题及成立条件，再由本书人物、处境和规则重新推演具体发展。原作特有事件链、人物组合和结局不能直接变成本书路线；原作事实不能写成本书账本事实。多书相似之处只称多书观察，不当原创性、版权或市场效果证明。

探索实际产生新点子后，用 `novel_reference_report` 的 `save-idea` 自动保存候选，提供固定的 `参考书/原文版本/机制/机制版本` 引用、正文、标签及本次 `operationId`，同次失败重试沿用身份，不为同源不同点子复用身份。机制生成本身不入池；作者明确收藏机制时存简短笔记与引用，机制正文仍在参考库维护。入池不等于本书采纳，正式采用仍走既有确认流程。依据失效只提示核对，不删除或改写作者点子。

## 采风与灵感库

**建库初始化**：首次采风或翻库前，`<工作范围>/书房/灵感库/`（书房共享库，零件跨书通用）不存在时先建八个类别子目录——`历史事实/`、`文化元素/`（下设热梗零件单独子标）、`剧情结构/`、`人物原型/`、`台词金句/`、`古词古句·意象/`（下设三子标：诗词古文〔人物台词引用〕、雅称谚典〔雪→六出、月→冰轮，章名标题用〕、意象母题〔月雪灯舟——文化内涵＋经典用法＋化用方向〕）、`影视动漫/`、`现实生活/`；根下落空 `索引.md`（每类一行：类别｜零件数｜一句话范围｜最近更新，零件数初始 0）与 `_采风站点经验.md`（站点通道经验，按域名一条）；`_待裁决_采风_{YYYY-MM-DD}.md` 由采风执行时按日落暂存。库已存在不重建。

**池库分工**：`书房/灵感池/`＝创作点子（一脑洞一文件，随手记产物，已存在不动）；`书房/灵感库/`＝采集零件（一类一册——裁决后 append 进对应类 `零件卡.md` 追加行，防碎片化）。**两库互不合并**。**池库互转**：翻库或读零件激发的新点子按随手记入池，frontmatter 记激发它的零件序号；池内点子需要素材支撑时，采风任务单的来源标记带池子身份（点子文件的身份名），零件采回即有挂靠。

**零件卡字段**（一行一零件，九列逐字照抄）：`序号｜关键词（2-4个）｜一句话（骨）｜为什么好（魂·原理一句）｜化用启示（适合什么质地的人物/场景，不写"用在第X卷"）｜反例（何时不可信/不可用）｜来源｜可信度｜已用于`。序号＝类简称＋采集日期＋两位序（如 `台词-20261010-03`；类简称＝古词/台词/剧情/人物/历史/文化/影动/现实，册内同日顺延）；可信度四态：已证实（≥2 独立来源）/孤证（单源）/推测（综合推断）/归纳（模式归纳型零件无逐字例证）——孤证与归纳常态入库，标注即诚实；`已用于` 归档时初始为空，零件被某本书消费后回写该书书名；类别列只在暂存报告出现（裁决路由用），归档后类别即所在目录，不另立列。

**索引与检索**：不建复杂索引——关键词列在零件行内，检索一律 `grep "关键词" <工作范围>/书房/灵感库/*/零件卡.md`；`索引.md` 维持类级轻量（类别｜零件数｜一句话范围｜最近更新），计数对账＝各类零件卡内数据行数与索引该类计数相等，归档时计数+1、最近更新改当日。

**触发源五个**：①评审转来——《定调设计》确认前评审指导意见的【待采风：查询词】标记，作者同意后汇总成任务单；②开书备料——立项期题材考据（作者说「帮我查查这个题材」）；③热梗补给（trend-patch）——作者点名补梗或评审建议，查询式「梗名＋出处/用法」，梗句逐字入库＋首发日期＋半衰期标注，作者裁决后可固化进人物档案条目模板声线节口头禅（转长青）；④即席查询——作者点名即查；⑤存量盘点——对已有灵感库盘点补缺，任务单来源标记写报告路径，跳过网络源，去重照走。

**执行**：读本技能包 [采风检索](agents/采风检索.md) 底本全文，组装任务包派发子代理，或在主对话内联执行（单条小任务）——均按底本走三源与红线：①知识库＝技能包 references 的 §x.y 节级判据，命中即不采、指路返回；②本地＝`书房/灵感库/` 索引＋各类零件卡去重＋`书房/灵感池/` 点子对照；③网络＝宿主联网工具可用时（查询词中文、只采国内源、境外源记「已排除」、摘要类路径结果最高标孤证；不可用降级两源如实标注；存量盘点触发源固定不走本源）。采风报告 return 后暂存落 `书房/灵感库/_待裁决_采风_{YYYY-MM-DD}.md`（派发时由子代理按底本落盘；内联执行时由你落）。

**裁决交互与归档**：暂存一行一条呈作者——`序号｜一句话｜为什么好｜去向建议`，作者逐条批「入/弃/改道」；裁决后由你（主 Agent）机械归档——「入」与「改道」按去向 append 进对应类 `零件卡.md`（一行一零件，九列全填，类别列不入册）＋`索引.md` 该类计数+1、最近更新改当日，「弃」不归档；评审转来的零件消费去向写回 `书房/评审/{书名}/` 对应评审报告的建议列。零件好坏与采用与否由作者裁决，你不评判不筛除。

**拆书与采风边界**：有原文＝拆书机制卡（走《参考小说拆解》受管拆解）；无原文、只有别人的解析＝采风灵感库（走本节）。

## 翻灵感库

作者要翻灵感库时（写前找参照、起名取词、点子要素材），按需求选一式：

1. **按类翻**：读 `<工作范围>/书房/灵感库/索引.md` 看各类一句话范围与零件数，再读目标类 `零件卡.md` 全册；
2. **按关键词 grep**：`grep "关键词" <工作范围>/书房/灵感库/*/零件卡.md`——关键词从题材、场景元素、情绪词取，多试两三个变体；
3. **按场景需求问**：作者只描述场景需求（如「写一场雪夜告别」）时，你自提关键词（场景元素＋情绪词）去 grep，命中零件连同「为什么好＋化用启示」一并呈报。

翻到零件后三去向：

1. **入材料包**：走《细纲备料》「自主补充材料」，`来源` 带 `域: 书房` 与零件卡路径，机制现成；
2. **固化进人物档案**：热梗转长青通道的泛化——台词句式/口头禅类零件经作者裁决后固化进人物档案条目模板声线节；
3. **激发新点子入灵感池**：按随手记落 `<工作范围>/书房/灵感池/`，frontmatter 记零件序号。

**过期软提示**：呈报命中零件时，写法类（剧情结构/台词金句/影视动漫）采集逾 2 年、现实生活类逾 3 年的附一句「采集已逾 N 年，建议复核」——只提示不拦用，逾龄从序号前八位采集日期起算。**消费回写**：零件被本书采用（入材料包/固化进人物档案）后，回写零件卡对应行「已用于」列（书名）。

## 重入（作者推翻构想）

- 本书建成后其构想不回改：方向变化走契约修订（《定调设计》），构想快照冻结；**开另一本新书仍走本技能**；
- 未建书、推翻部分要素：只重聊被推翻的项，已收敛项从 `书房/构想/` 的草案里复用，区分字段缺失与合法留白，不把其余五项留白当成不能立项；
- 灵感池旧点子可随时翻出重组。
