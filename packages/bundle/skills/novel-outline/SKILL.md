# 细纲备料（Novel Outline）

本技能分两段：**细纲段**（章细纲，跨真源边界，必须走工具确认）与**备料段**（材料包，幂等重建）。候选细纲的正文由你撰写、经 `novel_new_outline_draft` 的 正文 参数落草稿区，本技能只定流程与契约。

## 细纲段：标准流程

先读作品契约“阅读体验与情绪承诺 / 章节篇幅”。已确认时继承目标和上下限，未配置或未确认如实注明，不由主控补成固定默认值。在现有“情绪与节奏目标”中说明本章完成的主要任务、结束后的变化及预计总篇幅，并在叙事单元行加「预期字数」增补行（行式与合计判据见 [章细纲固定小节规格](templates/章细纲固定小节规格.md) 可选增补行节——各单元预期合计≈本章目标字数，合计低于目标＝细纲事件量不足→加单元〔加事〕不硬堆字）；预算可调整，不变成额外确认门槛。

四千字示例可以集中完成一次交锋：局面与压力约 600、主要行动与交锋约 2400、结果与余波约 1000；这是分配重心的例子，不是所有章节的固定比例或结构。若细纲同时承诺多次交易、重要人物登场和关系转变，应减少本章任务量或提出拆并建议，保留主要行动的动机、过程和结果。修改已有确认细纲或窗口仍沿用原修订流程，不自动拆章、不靠灌水凑下限。

约束按来源分级：作者明确要求和既定事实形成硬边界；推荐手法属于软建议；未限定的局部写法保留自由空间。不要把自己提出的节奏、句式或未选路线自动升级为硬约束。

上层远期暂定/留白不是本章必须补齐的终局。当前章确实需要某处方向时说明缺口，按《工作台总控》提出候选并复用已有提案；作者采纳后再写。参考书机制只作建议材料，先核对当前证据状态，不将原作事实、结局或未采纳分岔升级成本书约束。

**章纲分级（落候选前先定级）**：

- **关键章**＝卷首章／卷内高潮章／段内（章组）高潮章／卷纲心动位★章／换图章／伏笔/线索到期兑现章；**过渡章**＝其余；
- 判据源＝卷纲「卷末兑现」「心动位」行与分卷「卷目标与卷末状态」的主战层级行；段内（章组）高潮章判据源＝卷纲叙事结构段的章组排期；伏笔/线索到期兑现章判据源＝写前十查③线索到期过滤命中（预期兑现区间覆盖本章的已埋/已示线索）——机械信号优先、不凭体感，判定拿不准时按关键章走；
- 关键章走全规格：固定小节全填＋写前十查全项；
- 过渡章走**简章**：定位段核心节（视角与焦点／信息边界／情绪与节奏目标／起止边界／前置条件核对结果／冲突与爽点／章末双钩）照常填——「前置条件核对结果」一句话版（动用能力/代价已结/无越级一句话说明，无动用时写「无前置条件」），其余节一行带过或显式留白——留白合法，细则照 [章细纲固定小节规格](templates/章细纲固定小节规格.md) 简章节；
- 确认协议不变：约束分级＋来源引用两道硬门槛照过，core 空模板不动；
- 写前十查机器四查照常跑（机械零成本），⑧近五章重复放宽为隔章跑——放宽口径见 [写前十查](agents/写前十查.md) 章纲分级放宽节。

**按幕成批出细纲（默认节奏）**：

- **进入一幕的第一章前**：读本幕幕纲 `大纲/卷规划/卷NN/幕纲/幕NN-<幕名>.md`，把本幕各章的候选**一次性排出来**——章与章之间的钩、铺垫、伏笔排期一起排（钩型配比按幕算，不是按单章算）；幕纲「章组排布」段定本幕分几组、每组任务，本步把组落到章；
- **幕内分批**：一幕章数超过一次能稳妥组装的量时分批排（阈值照 `references/参考标尺.md`「幕内分批出细纲」行取，此处不写死数字）；**伏笔与钩的排期以整幕为单位**——分批只影响候选落盘的批次，排期视角仍整幕看；
- **确认仍逐章**：排完候选后**逐章呈确认**——首章全目呈报（含十查全项）；后续章只呈差异与各章十查🔴项（沿用原批量细纲的呈报方式：只呈「与首章的差异行＋各章十查🔴项＋钩型/伏笔排期变化行」）；`novel_confirm_outline` 逐章调用（core 协议不动——**规划粒度变，确认粒度不变**：每章细纲仍逐章确认，每章定稿仍作者批准）；首章确认后作者改了某项影响后续章（如伏笔排期变了），后续章候选同步改再呈；
- **作者不想一次排完整幕时**：可只排前 N 章（原「批量细纲」通道并入本节——作者点名章数时按点名数排，一次 N ≤5 章，规则同上）；
- **批量组装**：一次读齐本批各章的窗口条目与卷纲／幕纲上下文，再逐章落候选（每章各落一份候选文件，共享同一次组装的上下文）——场景卡选择跨章看（第 2 章的动作高潮场景与第 3 章的调剂场景在同一次组装中选定，不各自独立选）；钩型配比跨章规划（各章章末双钩放在一起看——危机钩兑现章号跨章排、张力类占比按本幕窗口算而非单章）；伏笔排期一批过（本批内到期的伏笔、新埋的前向铺垫行，在批量视角下一次排——跨章保温触点同批排定）；灵感库自动匹配一次跑本批（备料段「灵感库自动匹配」机制在批量下同款复用）；
- **批量滚窗**：批量细纲确认后可批量滚窗——一次组装本批窗口条目，`novel_roll_window` 逐条调用补位（core 协议不动，只是组装时机变）；
- **批量写时发现反馈**：批量确认后起草阶段产生的写时发现（候选事实段 `## 写时发现` 节），指向本批后续章的，在下一章细纲组装时优先消化——批量模式发现→反馈逐章接续，不积压到批外。

1. **读窗口、卷纲与本幕幕纲**：`大纲/卷规划/卷<NN>/近期窗口.md` 锁定本章任务与拆并关系（已消费/已失效条目不再是候选章）；同目录 `卷纲.md` 的「方向选择」小节取本卷 `选定方向` 与 `已排除走向`，该小节缺失即本卷未跑多方向；同目录 `幕纲/幕<NN>-<幕名>.md` 取本幕「章组排布」「线与伏笔」「出场人物」三段——本章属哪章组、本幕要埋/要兑现什么、谁在场（幕纲未写＝旧书未分幕，按卷纲与窗口照常走，不强行补幕纲）；
2. **落候选**：思考程序按 [步骤卡-章细纲](templates/步骤卡-章细纲.md) 走（步骤卡试点：判据要点在卡上，卡住或作者深挖时整读对应件）；调 `novel_new_outline_draft`（卷/章名/正文/来源引用）在草稿区生成候选。正文含两段——
   - **定位段**：来源窗口项及拆并关系、章节功能、视角与焦点、时空锚定、起止边界、故事线与承诺分配、信息边界、情绪与节奏目标、**前置条件核对结果** 九节，其后另加四节——`### 本章形状`／`### 已排除走向`／`### 冲突与爽点`／`### 章末双钩`；四节写法与既有节固定行（时间行、核心情绪前→后、POV 增减知、承上/交下、信息预算四行、跨章资产行——本章无新埋时写「本章新埋：零」声明行等）逐行照 [章细纲固定小节规格](templates/章细纲固定小节规格.md) 写。「本章形状」写它前先读本卷已确认细纲最近三章的同一节：不足三章就读现有的，早先的章没有这一节就跳过，本卷首章回上一卷 `章细纲/` 目录读；与近期形状比较以发现无意重复；重复若服务本章目标可以保留，不为求异硬换结构；「已排除走向」只承接卷纲或作者本次明确排除的走向，未选路线不自动排除；查证行（行式见规格「既有节固定行」节）写在「前置条件核对结果」节内——细纲正文里写了 `世界书/….md` 条目仓内路径的，材料包组装会自动把该条目切片进「人物、关系、地点、组织、规则、物件」段（现有机制），所以查证行务必写条目全路径；
   - **细纲段**：叙事单元列表，每单元六个字段——`目标`、`人物`、`时空`、`行动/冲突`、`信息披露`、`状态变化`，字段名逐字照抄（第四项本身带斜杠）；行内约束分级 `〔硬〕〔软〕`，无标记＝自由空间；单元可另加可选增补行——`- 决定（三型）：行动／挂起（＋重启条件）／承受（＋处境改变＋代价）`、`- 场景功能：推进/塑造/展开/预置`、本章单元实现卷纲「心动位」时该单元行标 `★`（情绪锚不是顺序锚——选读该单元写法判据时可加权重，判据见规格）——可选增补不参与确认校验，缺了不拦、写了不校；
   - **单元排布**（细纲段单元列表落笔时）：
     - **拆并**：拆单元时数维度：时空-POV-目标变了几个，全同且功能同就合并；情绪大转向同场也切；长跨度压成连排小条
     - **排序**：排单元先顺时间线；最大信息单元前后配铺垫和反应；大战中途可插一拍众生反应；末单元只开一个问号
     - **配字**：配字先问读者最想看哪一秒：那一秒给足，交接带过，钩一两句；合计不足加事不加字
   - 判据取件（步骤卡试点）：深挖判据件（照步骤卡「深挖」列）：《章纲-信息与情绪》等四件，整读——章纲域已全拆分件化，不按节切读；写「信息边界」节时本书记忆有文风类条目时，其内容——信息释放节奏与章形钩型偏好——可参照；`### 章末双钩` 节判据照 [章细纲固定小节规格](templates/章细纲固定小节规格.md)「章末双钩」节的行式与红线指路写；
   - **双参照（可选）**：①机制卡——本章含标志场景型（打脸/对决/升级/告白等）且 `<工作范围>/书房/参考书/` 已有受管参考书时，可选调 `novel_reference_query search`（关键词从场景型与本章元素取）查一次机制卡；命中的机制卡读作写法参照——对照它怎么铺节奏、怎么压信息、怎么放钩；**借魂不借形**：不复制事件、人物组合与结局；没拆过参考书直接跳过，不提示不阻塞；②灵感库零件卡——本章需要特定意象或台词句式时，`grep "关键词" <工作范围>/书房/灵感库/*/零件卡.md`（关键词＝场景元素＋情绪词）；命中零件的「化用启示」读作写法参照，**借骨不借皮**：取句式与化用方向，不搬例证原文；两路都可选不阻塞，灵感库未建直接跳过；
   - **确认两道硬门槛（写候选时就带上，不等到确认再补）**：①**约束分级**——正文至少一行带行内标记 `〔硬〕`/`〔软〕`/`〔自由〕`（放「章节功能」或单元行里，不要另开「约束分级」小节）；②**来源引用**——合法形态只有三种：`来源:<仓内相对路径>@<版本>`（如 `大纲/卷规划/卷01/卷纲.md@1`，版本用对应工件当前版本号）、`来源:作者自定义`、`来源:对谈共创`；锚点、行号、绝对路径、纯工件名都无效。本卷已分幕时，卷纲引用之外另加本幕幕纲引用 `来源:大纲/卷规划/卷01/幕纲/幕01-<幕名>.md@<版本>`——幕纲改后影响分析据此把该章细纲列为下游。空模板不含标记行，照抄空模板必然过不了确认；
   - **写时整合**（写定位段各节时的心智模式——不是先写完再逐项查，而是写时就同时想；与步骤卡的分工：写时整合是落定位段各节时的心智，步骤卡是落笔前的排程——两者并用不互斥）：
     - **情绪接力**：写「情绪与节奏目标」时同时想——上章末读者带什么情绪走、本章转到什么情绪、本章在卷里是铺垫期、高潮期还是收束期；本卷首章无上章时改读卷摘要末段，过渡章简章只跑前两问
     - **信息边界推演**：写「信息边界」时同时想——读者此刻最渴望知道什么、最不想让他们知道什么、哪个信息给一半比全给更抓人；过渡章简章只跑「最不想让他们知道」＋释放量对账（≤70% 口径见章细纲固定小节规格『信息边界』行）两问
     - **冲突强度定位**：写「冲突与爽点」时同时想——冲突强度在卷里排第几、上一章是什么级别、读者看完这章够不够"想翻下一章"；过渡章简章降为强度一句判断
     - **双钩还债预检**：写「章末双钩」时同时想——下章细纲已经排了什么（近期窗口可读）、这个钩下章拿什么还、下章没排时钩子够不够指引下章方向；卷末章（下章为下卷首章）兑现章号跨卷登记，不判兑现距离
     - **取舍显形**：本章为保什么牺牲什么（高潮强度 vs 铺垫量、双线进退），想清了落一行取舍行（行式见规格「可选增补行」节）
3. **改候选**：候选落盘后需要调整的，用宿主 `edit` 逐单元替换（一次一个单元或一节，old_string 取该单元完整多行原文），改完 `read` 回读；不整文件重写，也不为标点级差异反复打磨；确认失败报字段缺失时只补缺的单元；
4. **写前十查**：候选落盘后、呈确认前，读本技能包 `agents/写前十查.md` 全文执行——机器四查（①三约束对照／②能力越级＋金手指对账／③伏笔/验证到期／④接钩预检）你机械跑，过目单六查（⑤平章／⑥爽点铺垫／⑦动机三问／⑧近五章重复／⑨情绪落点／⑩钩子承诺）进呈确认件；⑥⑧的机械部分先跑本技能包 `node <resourceBase>/scripts/十查机械.mjs --book <bookRoot> --卷 <卷> --章 <章> --章名 <章名>`（只算不写，一次输出⑥⑧两查的机械结果），读结果再叠模型判断——口径见底本⑥⑧条；十查底本的判据来源补充知识库引用——⑤平章检查对照 [章纲-章型与开篇](references/章纲-章型与开篇.md) §6.1（一章写什么）的"变化"判据；⑥爽点铺垫对照 [章纲-冲突与爽点](references/章纲-冲突与爽点.md) §6.4 的铺垫要求；⑨情绪落点对照 [章纲-信息与情绪](references/章纲-信息与情绪.md) §6.9（三件均为拆分件，整件读）；查完进步骤 5 一张表呈报，不拆两轮；
5. **呈确认**：呈确认件统一格式（一张表，三段）：
   - **门槛**（工具校验必拒项）：约束分级标记有吗？来源引用合法形态吗？——失败＝工具必拒，改完再呈；
   - **四查结论行**：①三约束：… ②能力对账：… ③伏笔/验证到期：… ④接钩：…；
   - **六查过目表**（固定六行）：⑤平章 … ⑥爽点铺垫 … ⑦动机 … ⑧重复 … ⑨情绪落点 … ⑩钩子承诺 …；
   - **雷点快扫行**（固定行）：感情线/战力兑现/煽情/视角切换类单元按 [写前十查](agents/写前十查.md) 底本文末的高发雷点内联判据快扫，命中项与无命中各写实一句；
   - **信息释放行**（固定行，接雷点快扫行后）：本章揭示登记（释放哪些清单条目、序号与状态流转）＋大揭示章 ≤70% 判据按本章口径核对（豁免口径见规格，累计已释为信息行不作案据）＋连续 2 章零揭示＝信息饥渴预警（呈报不拦卡；未建账写「未建账」，判据见 [写前十查](agents/写前十查.md)）；
   - **配给合计核对**（半句）：各单元「预期字数」合计对照本章目标——合计低于目标＝细纲事件量不足→加单元（加事）不硬堆字；
   - 🔴 项（越级/到期未兑现/平章）标红呈作者裁决——十查是检查不是门禁；两类检查一张表呈报，别分成两轮。

   向作者概述定位与情节点，获明确同意后调 `novel_confirm_outline`（卷/章/章名/summary/`批次文件`），只传章键，不重传正文；章号须与近期窗口和已确认细纲连续，不确定时先问作者。

## 细纲段：重入（已有确认细纲再进＝改细纲，不是重拟）

- 真源已有确认细纲、草稿区重新出现候选＝修订流程：改完候选再 `novel_confirm_outline`，**版本自动 +1**；
- **已定稿章的细纲勘误（笔误/小修）同样走候选→再确认**：该章窗口条目已消费不影响确认（真源已有确认细纲即重入，版本 +1、父版本指旧版，定稿 frontmatter `来源细纲版本` 不回写）；只改设计工件时跑影响分析脚本呈报即可，**无需吃书补偿**；正文若受影响另走提案/吃书；
- **人物自决类轻量改纲**：正文层发现「人物不会这么做」而细纲要改时——改动限于单章内的行动/冲突字段、不产生下游承诺变更（无伏笔/线索/窗口条目受影响）的，按勘误通道同款处理：改候选→再确认（版本 +1），不跑影响分析、不吃书补偿；有下游影响则仍走影响分析前置呈报；
- 改前跑影响分析脚本（本技能包 `scripts/影响分析.mjs`，只算不写；失败按《工作台总控》「脚本失败分流」表处理）做**影响分析前置呈报**：受影响未定稿下游同批整改，整改文件列入 `批次文件`，**整批一次确认、一次 `design(chNNNN):` 提交**；已定稿下游走吃书补偿；影响面过大拆提案；
- **幂等可重放**：真源已落位、候选已删时重跑确认＝只补提交不重写文件；确认结果带 `commitState`，`unchanged` 表示无新增提交、不是失败，不为产生新提交重复调用；工具报「已落盘但未提交」（`commitState: failed, retryable: true`）处理失败原因后重跑补提交。
- **幕末结算与卷纲偏差分档**（替代原段级刷新）：每幕写完（不是每约 10 章）做一次幕末结算，轮次与六步在《卷幕规划》「幕末结算」节；**卷纲偏差处理分档**（本处为分档边界定义单源，arcplan 侧重入节只引用本处）：幕末结算时核对实际走向与卷纲的偏差——小偏差（线索推进方向调整/弧线细节微调/心动位移位，不影响卷末兑现与主战层级）→直接改候选卷纲→再确认（版本+1），不跑影响分析（与细纲人物自决轻量改纲同款通道）；大偏差（卷末兑现变了/主战层级升了/分卷接口动了）→仍走《卷幕规划》卷纲修订＋影响分析前置呈报；窗口批量追加用 `novel_roll_window` 逐条补——不是每章滚一次。

## 备料段：材料包（十段固定结构）

先跑备料脚本 `node <resourceBase>/scripts/材料备料.mjs --book <bookRoot> --卷 <卷> --章 <章> --章名 <章名>`（只算不写，输出给出十段全文与在缺清单；失败按《工作台总控》「脚本失败分流」表先分流，两类都排除＝脚本缺陷，停下报作者）读包判断；确认后调 `novel_assemble_materials`（卷/章/章名）落盘到 `草稿区/材料包/卷<NN>-<章名>/`（写入器内重算，幂等重建）：

本章任务与确认细纲／硬约束禁区完成条件／当前事实与连续性／人物、关系、地点、组织、规则、物件／时间位置与信息边界／故事线承诺线索／近期正文衔接／文风〔条目切片〕／暂定与警告／来源与版本清单。

各段是**切片不是全文**：近期正文衔接＝上一章定稿末尾＋最近章摘要，账本段按最近条目与本章命中取用；任何段一律全文进包，不设上限也不截断，「材料清单.json」逐段记 `字数`（包记 `合计字数`）供你自行判断体量。

- **重入＝幂等整包覆盖**；已消费版本的条目固定，条目更新不得让已确认工件静默失效；
- **备料自查前移**：原五项自查（出场频率／死亡预埋／信息释放规划／验证到期／伏笔保温）已前移到幕级——判据正文单源在《卷幕规划》技能包 templates/幕纲固定段规格.md「备料自查」（可选段），执行时机在「按幕成批出细纲」读本幕幕纲时一次过，不再本章逐章重查。备料段此处只做一句核对：**幕纲里排的这一章要埋／要兑现的，细纲里有了吗**——有了继续，没有回细纲层补（改已确认细纲走重入勘误通道），不等到稿子写完才发现；
- 返回值带缺口清单（细纲与来源级）与**写作就绪播报**，逐段完整性查 `材料清单.json` 的 `段[].完整性`；十段是声明式编排，**不是开写门槛**，够不够开写由你向作者如实播报后判断；
- 书房里作者自备的资料严禁把正文抄入真源区，引用只写来源路径与版本。

## 自主补充材料

十段是自动备料基线。发现早期伏笔、关系变化、作者决定或资料未覆盖时，先读取相关原文，再调用 `novel_assemble_materials` 补齐本章材料；普通选料无需逐项再请作者批准。开书期存在 `<工作范围>/书房/开书/<书名>/种子底子.md` 时，第一章备料可经补充操作（域: 书房）把种子底子带进材料包；灵感库零件可作另一路补充来源——按《灵感与立项》「翻灵感库」命中的零件，同样经补充操作（域: 书房）引零件卡路径进包，机制现成。

**灵感库自动匹配**：组装本章材料包时，按本章确认细纲的关键词（场景元素＋设定域＋情绪词）grep `<工作范围>/书房/灵感库/*/零件卡.md`，命中零件不整卡内联——只取命中零件行的「化用启示」列＋「一句话（骨）」列，作可选参考列表（≤3 条）附入《正文起草》任务包组装参考；命中零件确要原文的，再经补充操作（域: 书房）引零件卡路径正式入包——自动匹配是提示，正式入包仍走既有补充通道；灵感库未建时直接跳过不提示。

1. 传 `模式: 预览` 与 `补充操作`，每项 `操作: 设置`、稳定 `编号`、`标题`、`理由`、`性质: 原文|建议`，以及 `来源: { 域: 本书|书房, 路径, 起行?, 终行? }`。本书路径相对书仓，书房路径相对同工作范围的 `书房/`；禁止用索引或检索结果代替原文。
2. 核对返回的 `补充预览[].原文`。保存时传 `模式: 保存`、预览返回的 `材料清单哈希`，并把 `补充预览[].操作` 作为 `补充操作` 原样带回，其中已含 `来源.读取哈希`。只传短引用及校验值，不重传原文，不自行算哈希。
3. 修改某项用同编号重新预览和设置；移除用 `{操作: 移除, 编号}`。不传操作或传空数组都是保留，不是清空。移除后清单不再登记，遗留附件不能再读入模型。
4. 普通重建保留已选摘录；来源过期、清单冲突、附件损坏时按提示重读、预览并显式设置或移除，不手改清单/附件，不把新来源悄悄盖在旧依据上。

补充与十段在同一 `材料清单.json` 中，快照在 `补充/<编号>.md`。理由、来源、行范围、哈希、性质和字数都在清单；补充原文保真，建议不当作事实。需要缩小范围时由主控显式调整选料，不在写稿或审读侧偷偷截断。

## Off-limits

- 状态取值按工件取族，不自造近义词：候选细纲与确认细纲的 `状态` 属工件族（候选／已确认）；材料包状态属轮次族（组装中／段齐备／段有缺／有冲突／已过期／已消费；段齐备/段有缺只是各段在缺的如实播报，够不够开写由你判断）；卷规划各件属计划族（已确认／暂定／留白）；
- 涉及未写章节走向变动先出建议稿，不直接覆盖卷规划与世界书；
- 草稿区工件可丢弃可重建，大胆迭代；确认状态与各段在缺如实播报，不粉饰「已就绪」；
- 走向定在卷纲层：细纲承接卷纲选定方向与作者明确排除项，不擅改走向；需要改变时另提建议。本章形状每章自选，不受此限。
