# 精修润色总控（Novel Polish）

**审核通过后使用**（审读发现项全部处置完）。本技能只管**组织**：选批次、定顺序、版本与回退怎么落；**改写执行者＝润色子代理**——主 Agent 绝不亲自改写一个字（润色稿也是正文）。每批的做法与保真边界在 `references/` 下的参考文档里，派发时把对应文档全文放进任务包。红线只有一条：**只改表达，不改事实**——语义完全等价，保留原稿有效的独特表达；不确定能否保真时保留该处并标注，不能自行补造事实。

## 批次（两批；可按作者要求定向执行）

| 批次 | 参考文档 | 合并的原道 | 类 |
|---|---|---|---|
| 1 表达清理 | `references/1-表达清理.md` | 去 AI 痕迹＋语言自然化＋冗余精简 | 表达 |
| 2 节奏与重塑 | `references/2-节奏与重塑.md` | 句段节奏调整＋对话润色＋修辞与意象调整（文风贴合为总判据） | 表达 |

**默认顺序：批 1 → 批 2**（批 2 在批 1 中间版之上落稿）；作者要求倒序时执行但给警告，不阻断。

## 标准流程

1. **取源**：当前唯一待审稿（即审读通过的那一稿，`草稿区/草稿/卷<NN>-<章名>/` 下 `角色: 待审稿` 的那一份）。多份待审稿或多个候选的选择不清楚时，先呈作者选定，不按最大稿号擅自选择或降级。按已明确选择修正标记后继续。
2. **默认一次派发**：任务包首件为润色心智，其余按下列说明组装。
   - **任务包第 0 件·润色心智**（排所有其他件之前）：

     ```markdown
     ## 润色心智

     三类判断先后序＝删留 → 节奏 → 语态——删除候选先过删留判，删定后判节奏，局部改定后核全章语态。

     - **弱段定位**：动手前先按对白占比粗判章型，逐段对照随包数值行扫密度异常段列重点清单；自评「读者会跳读的段」有就优先复核，没有不等于全章没弱段，得意句不给豁免
     - **删留三分判**：每个删除候选先过三问：读者缺后文信息吗、是有意的强调伏笔复沓吗、删后节奏变差吗——全过才删，拿不准保留标注；改写只换说法不换事实
     - **位置判**：改修辞先问位置：在情绪峰/出场/转折上吗——不在就删或降直陈；段末警句改成收在动作、悬问或具体物上
     - **语态接缝核**：指令集落稿前核接缝：改动段与未动段之间口吻称谓句式没换挡；不顺处改动向存量语态收敛，不逐字找平
     - **停机与转呈**：每段过四闸——无必改级命中、三分判全过、密度在随包数值行带内、承担钩伏笔功能——全过整段不进指令集；毛边不足和事实疑点不自己动手，转审读或对候选事实段核验；删减近两成收手呈作者
     ```

   其余件：完整内联批 1＋批 2 参考文档、文风基准和硬约束；文风基准与起草同一套三样、同样的优先级——契约「叙事方式与文风基调」分部原文（本书相对默认文风的调整，优先）＋本书文风锚点（本书记忆·文风类条目）＋《正文起草》技能包 references/默认文风.md 全文；从《正文起草》技能包 agents/写作卡.md 末节「AI 痕迹六条」原样摘录三对带数值行随包（密度判据数值源，跨技能摘录先例＝《全面审读》动态摘录参考标尺行）；将输入分为**正文**、**候选事实原文**、**文件操作说明**三部分。正文只送一次；`## 草稿候选事实` 段提供原文，要求一字不改搬进新稿，不作为可润色正文（段末草稿自评行的「读者会跳读的段」非空时列最优先复核——作润色重点输入，仍只改表达不改事实；为空不据此推断全章无弱段；「最得意」不作保护依据）。操作说明给出源稿路径、原 frontmatter、各批交付路径、稿号/父版本和旧待审稿标记。子代理先跑批 1、再跑批 2——**批 1 输出全文中间版（表达清理是逐句工作，需完整上下文）；批 2 输出修订指令集（定位＋改法，不重抄全文），并按指令在批 1 中间版之上定点落成终稿**，两个回退点不变（省约一半输出）；缺交付信息先补齐。
3. **落稿与降级由润色子代理用通用写工具执行**：批 1 的中间版标 `角色: 草稿`、`选定: false`；只有整轮终稿标 `角色: 待审稿`、`选定: true`，且**先把旧待审稿改成 `角色: 草稿` 并清 `选定`，再写新稿**——两份待审稿并存会让推导退回润色位并死锁；终稿 `父版本` 必须指向取源那一稿（即审读通过的那一稿）。
4. **主 Agent 验收，只查不改**：逐条区分硬约束。明确“必须出现/提及”的词串应出现，明确“不得出现/提及”的词串不得出现；其余语义、条件或复合约束交语义审读，不要求把约束原句写入正文。核对正文汉字数删减不超过两成、候选事实段原样保留、元数据和稿件选择正确。格式/明确词串/删减检查失败先核对原因，退回相应批修正；无法仅改表达修复时交作者决定，不无变化地反复重跑。
5. **登记承接**：主控验收后调 `novel_record_polish`（传 卷/章/章名/`审核记录哈希`/`稿件`＝润色终稿仓内相对路径）登记承接——工具核对保真（硬约束与删减）与候选事实段原样，并做确定性复核；被拒时按原因退回相应批或交作者，**不重跑审读脚本**（重跑会重开审读轮，把审核打回重审）。承接登记成功后播报进入《定稿沉淀》。

**子代理回传物**：新稿路径与稿号；逐条差异按批分组；三类去向位——**保留并标注项**（为保真而没改的地方，各附一句判断）｜**待作者裁决项**｜**转审读项**（对白毛边不足、事实疑点对不上候选事实段、人设/逻辑/节奏一类内容问题，只记不改）；累计删减近两成即收手，剩余删除候选保留＋标注呈作者。

**作者稿默认不润色**：调用 `novel_record_polish` 传 `跳过: true`＋`理由`（如「作者稿不润色」「旧流程已润色」）登记跳过；作者点名要润色才派。

## 拆分与定向（作者要求或批量过重时）

- 批 1、批 2 可拆成两次派发（每批一版），作者要在批次间人工过目时用；
- 单道定向修复（如只跑去 AI 痕迹）：派发时只带对应批文档并注明「只执行第 X 节」；定向单批时润色心智的弱段定位扫描只扫该节相关维度，重点段清单不越节。

## 版本与回退

- 一版一个回退点；同一父版本不得产出多个同版本兄弟稿；
- 作者要回退某批：回到该批之前的版本重跑后续批，旧稿原样留档——每版差异随版本呈作者，**可回退**到任一批次前；
- 中途失败允许 0 份待审稿（重跑即可），不允许 2 份。

## 重入（再润色）

- 作者点名再润色＝在现有待审稿之上继续，不回头消费旧稿；
- 进来多份待审稿：按取源规则先确认保留哪稿；没有明确依据不擅自降级任何一份。
- 重跑先读草稿目录现有稿号再定新稿号，不凭记忆猜；
- 旧稿一律留档，推倒重写也是新增一稿。

## 工件契约

| 工件 | 路径 | 属性 |
|---|---|---|
| 润色新稿 | `草稿区/草稿/卷<NN>-<章名>/稿<N>.md`（`<N>` ＝ 现有最大稿号+1） | frontmatter 字段序八项:`身份`／`版本`／`父版本`／`生成模块`／`来源快照`／`角色`／`选定`／`保真风险`;`版本` ＝ 父稿版本+1、`父版本` 指向父稿;`生成模块: 润色`;有保真风险时逐条记进 `保真风险` 并把该稿留在 `角色: 草稿` |

`角色` 只用待审稿/草稿，`选定` 用布尔值，不填「已确认」。草稿区不入 git。

## 工具

| 工具 | 何时用 | 不要 |
|---|---|---|
| 通用读工具 | 按需加载 `references/` 批次文档 | 一次读全塞上下文 |
| 润色子代理 | **一切判断性改写与落稿降级**（默认一次连跑批 1+2） | 让主 Agent 代写;任务包缺批次文档或缺回传格式 |
| 通用写工具 | 由润色子代理用它落新稿、改旧稿 frontmatter | 主 Agent 自己动笔改正文 |
| `novel_record_polish` | 审核通过后登记润色承接（`稿件`）或跳过（`跳过`＋`理由`）；传 `审核记录哈希` | 跳过审读脚本重跑（会重开审读轮） |

## 作者介入

- 作者能做什么：贴自己改过的版本，替代当前润色成果或作为新一版；
- 用哪个通道：`novel_import_draft`（卷/章/章名/正文/角色: 待审稿/生成模块: 作者手改/父版本: 被改稿的版本）；
- 主 Agent 接到后：作者稿落为新一版待审稿（旧待审稿自动降级），之后进入《全面审读》；对作者手改的稿默认不润色（登记跳过）、不自行改动其文字。

## Off-limits

- 润色不产生 git 提交（草稿区不入库）；
- 已有待审稿再润色＝在现有待审稿之上继续，不回头消费旧稿；
- 承接登记成功后播报进入《定稿沉淀》；润色后不重跑审读脚本。
