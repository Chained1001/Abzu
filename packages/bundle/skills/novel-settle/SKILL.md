# 定稿沉淀（Novel Settle）

向作者呈报字数时，读取本次待定稿包（`草稿区/定稿准备/卷<NN>-<NNNN>-<章名>/`）的 `正文.md` 的 `字数统计.汉字数`；字符数须另标口径。不得沿用起草、润色或旧稿审读报告中的估数。该统计与审读共用计数规则；换稿须重算。

本章的收束节点，次序不可颠倒：**先完整呈报，再作者裁决，后原子沉淀**。未完整呈报、未获作者明确批准，严禁调用 `novel_settle_chapter`——调用即弹作者裁决弹窗，裁决记录由裁决通道生成、不经你手，你没有任何参数可以替作者答。

## 标准流程

事实沉淀汇报若发现人物选择或结果改变上层前提，可按《工作台总控》说明证据并提出少量候选，先复用已有待裁决提案。未采纳候选不使旧计划失效。

1. **派沉淀子代理**（审核完成后、组包前；审读子代理仍在跑时可先做候选事实段的写时发现分拣与对账准备——见《工作台总控》审读沉淀并行句）：按「沉淀子代理派发模板」节组装任务包——包内 `agents/沉淀对账.md` 全文＋待审稿正文与候选事实段＋确认细纲定位段＋材料包「当前事实与连续性」「故事线承诺线索」两段＋计划时间线本卷条目，材料全部内联；子代理返回六段 Markdown（五段时间线变更/账本变更/本书层记忆候选/章摘要/事实变更＋第六节「入档后回写候选」——不进待定稿包七件、只供主控呈报与入档后回写，空节写「无」）；章摘要两固定行——`语态样本：`（定稿沉淀时从本章正文挑一句子代理自认最佳的原句，置章末状态行之前；跨章语态基准，防语态漂移）＋`章末状态：`（末行——《工作台总控》回归简报与《细纲备料》技能包 agents/写前十查.md ④接钩预检的末行读取位，语态样本不得占末行）；
2. **组包**（前置：唯一待审稿＋审核完成＋润色已承接或已登记跳过；后两项由工具真校验，不满足则 `novel_prepare_pack` 被拒并给解法，无审核记录的老书不误拦）：
   - **先组包再逐件审阅**：调 `novel_prepare_pack`（卷/章/章名＋沉淀候选五个字段）落盘七件到 `草稿区/定稿准备/卷<NN>-<NNNN>-<章名>/`——正文 / 事实变更 / 时间线变更 / 账本变更 / 章摘要 / 卷对账 / 本书层记忆候选。备包脚本 `定稿备包.mjs` 只用于正文/卷对账预检，**不能预览五段候选**；候选逐段预校验，失败返回解析器原话：按原因修正候选后重调，同一原因修正后最多补试一次，仍失败就报告；不无变化地循环重调；**子代理某段整段留空就不传那个字段**，传占位文字会被判「存在未分类正文」整批拒；
3. **呈报裁决**：向作者呈报「**本章只需看这几处**」三行制——①偏离项与处置选项（卷对账偏离项，有偏离讲清楚不掩盖）；②需作者决定点——文风锚点（前五章问一次，照旧）、写时发现去向中的例外、待查项仍未解决的；③风险行——润色确定性复核新增中/低项、保真保留项、建议级处置汇总（编号＋一句）；末尾折叠行：字数、七件变更计数（如「时间线 +2／账本 +1／事实 +3」）。作者一次表态。作者对偏离项表态后，把处置结论作为 `## 决策` 下的一个条目补进沉淀候选的本书层记忆段（`# 本书层记忆候选` 下 `## 决策`／`### <条目名>`，条目名或正文里逐字带上偏离项名——进度卡按名匹配扣减未决偏离），重调 `novel_prepare_pack` 组包再入档（与下述文风锚点同一机制，走沉淀服务原子写入）。明确请求裁决：批准入档，或退回修改；本书前五章（第 1–5 章）定稿呈报时各问一次「从本章挑一段满意的收进文风锚点吗」，之后作者主动点名时再收——作者点名段落后，把该段以「定稿章来源标识＋引文」标注补进沉淀候选的记忆段（`## 文风` 起新条目），重调 `novel_prepare_pack` 组包再入档；作者不选就跳过，不为填条目编造；
4. **沉淀**：作者明确批准后调 `novel_settle_chapter`（卷/章/章名/summary）——按清单原子写入＋账本/时间线/本书层记忆/世界书事实经沉淀服务同步＋**单次 Git 提交（ch: 前缀）**；写入阶段失败会整体回滚不留半截；提交阶段失败则文件已落位、未形成提交，原样重跑本工具即可补提交（会再弹一次作者裁决；见 Off-limits 末条）。**入档前先完成写时发现分拣并落 pending**；`novel_settle_chapter` 入档成功后自动清理本章草稿区五处（草稿/材料包/审核记录/待定稿包/候选细纲），快照留痕；审核记录计数摘要已存 `定稿/卷<NN>/审读摘要/`，跨章统计不断源；清理后原文不可读，分拣依据只剩 pending 记录与第六节候选，不能再等清理后补分拣。存量旧书可跑 `node <resourceBase>/scripts/草稿清理.mjs --book <bookRoot> [--卷 N] [--执行 true]`（默认只算不写，`--执行 true` 逐章补清＋快照）。近期窗口的「已消费」标记不在这一步，另调 `novel_roll_window`（自带 `design:` 提交）。**按作者在定稿呈报里的表态逐件回写**（素材＝沉淀第六节「入档后回写候选」）：人物认知增量/金手指代价经 `novel_confirm_worldbook_entry` 写入（每件一笔 `design:` 提交，不再另行呈报；作者未点名否决的默认执行；认知增量＝世界书人物条目带 `### 认知` 节的，对照本章核对——该人物新知道、称呼变化、新隐瞒逐项改入条目正文，无变化跳过不为填节编造；金手指代价按对账底本对账方法 5 判使用型（子代理只核对不落账）——在 `世界书/力量体系/` 对应条目金手指轨道位追加「G 代价已结·第N章」行；持有型代价不逐章落账（持有即持续状态），状态变化时才记）；常量已随事实变更段（模块=世界常量）随入档自动追加，不重复回写；**写时发现分拣**：按第六节分拣建议落处执行——尚未写进正文的新伏笔经 `novel_note_pending` 记到本卷卷纲「线索推进」节（标「写时发现」来源），作者确认后在后续细纲排期——正文里已写下的线索走候选事实段「线索埋设」，随本次沉淀入账本；人物/设定新发现经 `novel_note_pending` 记在对应工件（标工件名），作者确认后改世界书；改窗口/改卷纲先记待改，走影响分析前置呈报流程（照旧）；分拣结果呈报作者，不自动落盘。正文自创的程序细则（规则细则/程序条款——正文层生长出的程序性规则）复现 ≥2 次的细则必须回写：在对应局规则条目或世界规则条目的「程序细则（正文生长）」行登记（行式单源在《定调设计》技能包 templates/世界书/ 对应条目模板；防设定漂移——跨章复用靠条目单源，不靠章摘要记忆），经 `novel_confirm_worldbook_entry` 落盘（`design:` 提交）；复现不足两次的留审核记录备查，不回写。`<工作范围>/书房/信息释放/<书名>.md` 存在时同步更新信息释放台账——按本章实际揭示流转清单「状态」（未知→部分→已释）、「释放章」落本章章号，实际载体与知情圈变化随同次更新（「载体」/「知情圈」列），正文追加本章揭示登记行 `第N章｜释放条目（清单序号）｜累计已释 x/y＝z%｜新问号一句`（登记素材取本章定稿与沉淀对账结果；台账结构单源在《卷幕规划》SKILL「信息释放台账建账」段；通用写工具写，书房资产非真源）；无账跳过不开新账。模板新增结构节不强制回填旧条目——只按本章增量改动；旧条目缺新节时趁本次写入按《定调设计》技能包 templates/世界书/ 对应条目模板补齐缺节，留白合法，不为回填重写未变动内容。完成后播报入档清单与新近况；本章入档后停止；本次委托已包含的窗口已消费标记可完成，补充新窗口或开启下一章等待作者委托。

## 作者介入

组包前主控须做一次独立语义核对：逐条确认「主体／时点／原文证据／事实或证言或推测或规则」，核对同名账本是不是同一对象、作者已给的例外有没有落实。将这份简短核对结果随候选摘要呈报；不把哈希完整、格式通过或审核正文通过当成沉淀语义通过。未经正文支持的通用规则不入包，没有推进的旧线索不重写。

- 作者能做什么：呈报后改沉淀候选任何一条、补事实、删记忆候选；
- 用哪个通道：直接向你说，你按作者意见改候选后重调 `novel_prepare_pack` 再呈报；入档后的更正走吃书补偿（`retcon:`，`novel_apply_retcon`），不在组包里做。**审读「返回节点＝沉淀（账本更正）」**同此分界：本章未入档账本→改候选「账本变更」段重组包；已落在已定稿章→走吃书补偿。不口头转述。

## 重入（退回后重组包）

- 作者退回：**删掉待定稿包目录**（草稿区可弃可重建），位置随即退回，按根因回对应节点（局部问题→改稿；定位/结构问题→细纲；上游设定问题→按提案回路回上游）；不手写 `清单.json` 的 `裁决` 字段；
- 改完重新调 `novel_prepare_pack`；
- **每次入档都要重新获批**：重新呈报，再调 `novel_settle_chapter` 会重新弹一次裁决，一次调用一份新记录，没有可复用的旧批准。

## 幕末结算（一幕写完时，替代原段级刷新）

已拆出到《卷幕规划》技能包——六步与幕纲未建旧书跳过说明见该技能「幕末结算」节与 templates/步骤卡-幕末结算.md。

## 卷末与卷摘要（当前卷收束后）

已拆出到《卷幕规划》技能包——卷对账→卷摘要→下卷注意事项三件一批见该技能「卷末与卷摘要」节（卷摘要候选脚本仍随本技能包 scripts/ 分发，由该流程调用）。

## 工件契约

| 工件 | 路径 | 属性 |
|---|---|---|
| 待定稿包 | `草稿区/定稿准备/卷<NN>-<NNNN>-<章名>/`（七件＋`清单.json`） | 清单机器态 JSON，`schemaVersion: 1`，逐文件 sha256；另有 `裁决` 字段（`已批准`／`已退回`）是推导读的机器面——**不由你写**；卷对账是轮次工件不入档 |
| 定稿章 | `定稿/卷<NN>/<NNNN>-<章名>.md` | 真源，只增不改 |
| 审读摘要 | `定稿/卷<NN>/审读摘要/<NNNN>-<章名>.json` | 入档时从审核记录派生的计数摘要，只留计数与指纹；跨章查 `novel_review_summary` |
| 章摘要 | `故事剧情/卷规划/卷<NN>/章摘要/<NNNN>-<章名>.md` | 真源，与定稿章同批写入，同样只增不改 |
| 本书层记忆·决策条目 | `本书记忆/<条目名>.md` | 经定稿沉淀写入（沉淀候选记忆段 `## 决策`）：偏离处置结论记这里，条目名或正文逐字带偏离项名（进度卡按名匹配扣减未决偏离）；`名称`／`类`／`来源`／`裁决记录` 由沉淀生成 |

## 工具

| 工具 | 何时用 | 不要 |
|---|---|---|
| `novel_prepare_pack` | 审核完成后组装呈报；作者表态偏离处置或点名锚点段后补进候选重调 | 存在多份待审稿时组包（先裁定唯一） |
| `novel_settle_chapter` | 完整呈报之后一次调用（调用即弹裁决） | 未呈报就调用；想覆盖已入档章（更正走 `novel_apply_retcon`）；把 `裁决记录` 当参数传 |
| `novel_apply_retcon` | 已定稿内容更正：提案回路走完（影响分析已呈报、作者已在对话中批准）后调用，调用即弹裁决 | 未走完提案回路就调用；拿它当退回修改的捷径；当成撤销用（历史经补偿事件留痕，不是撤销） |

## Off-limits

- 定稿区只增不改：写错的事实走「吃书补偿（retcon:）」更正通道，不直接改定稿。吃书补偿是两个裁决点之一，须作者批准，只整条替换既有条目、目标不存在即拒，是「只增不改」的唯一例外；**工具入口是 `novel_apply_retcon`**（前置：影响分析已呈报、作者已在对话中批准；调用即弹作者裁决，作者退回即拒），未走完提案回路不要调；
- `清单.json` 的 `裁决` 字段不由你写：`已批准` 是作者裁决的机器面，手写它等于替作者拍板；
- 账本与本书层记忆只有一条写入路径——沉淀服务，严禁手工编辑账本文件；
- 章号全书连续：与其他卷撞号会被拒绝，换号重报；
- 提交失败返回可读原因时，七件已落位、账本与世界书已同步、未形成提交：**原样重跑 `novel_settle_chapter` 即可补提交**（会再弹一次作者裁决；落盘内容与待写逐字节一致就幂等放行，命中已完成则不重复提交）；若目标已被作者改出不同内容则仍被拒绝，如实把这一状态报给作者，别重写文件也别改定稿。
