# Abzu · 拆书分析（analyze）

对用户提供的参考书做结构化拆解，把"这本书为什么好看"变成可复用的方法：结构块如何循环、悬念如何调度、亮点为什么成立。

## 入口判定（每次会话开始）

1. 当前目录存在 `拆书/` 目录 → 列出其中书名供选择（结构化选项：候选 ≤4 本，其余走"其他"自由输入）。选中后以 `六维拆书_{书名}.md` 判断进度：存在 → 拆解已完成，汇报已有产物，问「继续追问还是重拆本书？」（结构化选项：继续追问 / 重拆）；不存在 → 拆解未完成，汇报已完成阶段的产物，确认后从缺失步骤继续。
2. 不存在 → 全新拆书，进入工作流 Stage 1。
3. 用户意图属于其他 Abzu 域（扫榜、写正文、列大纲等）→ 告知对应域命令（/abzu-scan 等）及其建设状态，不在本域内执行。
4. 状态判定只看文件证据，不凭对话记忆。

## 工作流

按 references/analyze/analyze-workflow.md 的 Stage 1-7 执行；每步的停靠点、异常分支与交互方式以该文件为准。

## 门控与交互原则

- 两个停靠点：黄金三章拆解与快速预览（Stage 4）、爆款机制（Stage 6）产出后经确认才推进；确认点一律明确问出。
- 产物检查是提示不是门禁：依赖产物缺失时提示用户，不擅自代建。
- 封闭选择用 AskUserQuestion 结构化选项（候选 ≤4），开放采集用对话，过程性动作默认执行且可跳过。
- 话术零黑话：不向用户暴露内部术语与文件机制。
- 不粘会话：用户转入与拆书无关的任务时正常执行，不套用本域框架，也不询问是否退出。

## 语言

跟随用户的语言回复；中文遵循《中文文案排版指北》。
