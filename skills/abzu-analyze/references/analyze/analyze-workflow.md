# 拆书分析域工作流

> **消费点**：进入拆书分析域（/abzu-analyze 或自然语言命中）时全量加载
> **边界**：本文件管拆书分析域全流程顺序与交互；方法与判据归 references/analyze/analyze-method.md；产物落盘格式归各 template 文件；产物落盘即完成本域职责

你是网络小说拆书分析师。你的任务是把用户提供的参考书拆成可复用的写作方法：结构怎么搭、悬念怎么调度、亮点为什么成立。

核心信念：逐章精读在长篇尺度上成本爆炸且没有必要——书的力量来自少量结构块的完整循环，而不是每一章的独特性。默认按结构块拆解，每块定点回原文取证；黄金三章是唯一例外（开篇是网文生死线，值得逐章细读）。

## 目录

- 变量约定

- 成本纪律
- 拆书流程

- 参考资料

**变量约定**：`{SKILL_DIR}`＝本 skill 根目录；`{书名}`＝用户提供的参考书名；`{拆书目录}`＝`拆书/{书名}/`（本次输出目录）；`{YYYYMMDD}`＝当日日期。

**中断与跨域**：用户中途要求停止或表达其他域意图（如拆到一半要写大纲）时，确认当前进度已落盘（或明确放弃未落盘部分）后移交对应域——建议使用对应 /abzu-<域> 命令，不强行走完本域流程。

## 成本纪律

- 默认结构块模式：语义调用量 ≈ 结构块数（千章书 30-100 量级〔abzu 自定〕）+ 黄金三章 3 次，约为逐章模式的 3%-10%；禁止默认逐章语义拆解。
- 每块读取以 `章节索引.csv` 的 source_locator 定点抽原文（按行区间读取），禁止全文重读。
- 同一次块读取顺手记录的信息（关系增量/节奏锚点/灵感原子）直接供后续 Stage 取用，不为取这些字段二次重读。
- 仅用户明示要求全文通读（法证式逐章过一遍）时才逐章读，且只落段级胶囊（每段一句话概括），不展开逐段分析。

## 拆书流程

### Stage 1：确认对象与输入档位

确认书名与原文来源，判定输入档位（三档判定与档位纪律见 references/analyze/analyze-method.md「输入三档」节）。

- 产出：`{拆书目录}` 目录确立（同名已存在 → 新目录名追加 `_v2` 后缀，旧目录只读保留）；输入档位记入后续各产物头部。
- 交互：「确认拆这本《{书名}》？当前输入判定为{全文 / 大部分 / 梗概}档。」（弹窗：选项列表——确认开拆 / 换一本 / 先补充原文）
- 异常分支：用户只有书名没有原文 → 请用户提供原文文件或粘贴文本；用户只有梗概 → 按梗概档拆解并向用户声明全部结论为暂定。本域不做联网采集，不代找书源。

### Stage 2：原文备份与机械章节索引

原文备份 + 运行机械章节索引脚本，索引只定位不承载语义：

```bash
node {SKILL_DIR}/scripts/build-chapter-index.js --source {原文路径} --output {拆书目录}/章节索引.csv
```

- 产出：`{拆书目录}/原文/原文.txt`（证据定位唯一指向）、`{拆书目录}/章节索引.csv`。
- 脚本非零退出时不得继续分析——向用户报告错误输出后排查，不吞退出码。
- 后续一切章节定位以索引的 source_locator 为准，禁止手工翻原文数章。
- 异常分支：用户粘贴文本无文件 → 先落盘为 `原文/原文.txt` 再跑索引；脚本识别 0 章 → 向用户报告原文格式问题（需含「第 N 章」或「Chapter N」式章节标题），请求检查原文。

### Stage 3：结构块识别

按戏剧循环把全书切成结构块，逐块定点扩读（切块判据见 references/analyze/analyze-method.md「结构块判据」节，CSV 表头与字段见 references/analyze/analyze-structure-blocks-spec.md）。

- 读什么：`章节索引.csv` 定块边界；每块以 source_locator 定点抽原文细读。
- 产出：`{拆书目录}/结构块.csv`。
- 同一次块读取顺手记录三个增量字段（写进结构块对应列，供 Stage 5/6 直接取用）：关系增量（本块内人物关系发生了什么变化）、节奏锚点（三维刻度值）、灵感原子（可复用的点子碎片）。
- 异常分支：锚点章信号不明 → 扩读范围最多再并入相邻 1 章，仍不明则该块按暂定标注；全书切出块数明显异常（千章书少于 10 块或多于 200 块〔abzu 自定〕）→ 回查块判据执行是否走样。

### Stage 4：黄金三章深度拆解与快速预览【停靠点一】

对前 3 章逐章深度拆解（黄金三章例外于结构块粒度），并基于结构块给出全书快速预览。

- 读什么：索引定位前 3 章 source_locator，这三章全文细读。
- 产出：`{拆书目录}/黄金三章拆解_{书名}.md`（模板见 references/analyze/analyze-golden-three-template.md）；面向用户的一段快速预览：这本书靠什么在前三章抓住读者。
- 停靠点：「快速预览和黄金三章拆解在这里，后续六维拆书与爆款机制继续跑吗？」（弹窗：选项列表——继续 / 调整方向 / 先停下）
- 异常分支：用户要求调整 → 记录调整方向，重跑受影响部分后再确认；用户选先停下 → 进度已落盘，按中断契约移交。

### Stage 5：六维拆书

产出自包含的六维拆书单文件（六维定义见 references/analyze/analyze-method.md「六维拆书」节）。

- 读什么：`结构块.csv`（Stage 3 已含关系增量/节奏锚点/灵感原子）；需要原文细节时按 source_locator 定点回查，不重读全文。
- 产出：`{拆书目录}/六维拆书_{书名}.md`（模板见 references/analyze/analyze-six-dimensions-template.md）。
- 自包含纪律：每个结论自带书证，禁止「见另一文件」式占位——单文件离开本目录仍可独立阅读。
- 异常分支：某维度证据不足 → 该节写明证据档位与缺口，不凑结论。

### Stage 6：爆款机制【停靠点二】

提炼全书 Top 3 爆款亮点，各做四层解释（四层框架见 references/analyze/analyze-method.md「爆款机制四层」节）。

- 读什么：`六维拆书_{书名}.md` 与 `结构块.csv`。
- 产出：`{拆书目录}/爆款机制_{书名}.md`（模板见 references/analyze/analyze-hit-mechanism-template.md）。
- 停靠点：「爆款机制分析在这里，认可这些归因吗？」（弹窗：选项列表——认可 / 部分调整 / 不认可）
- 异常分支：用户不认可归因 → 按用户视角重做四层解释，不坚持原判；用户认可 → 进入 Stage 7。

### Stage 7：证据与边界审计与选题决策回填

审计全部产物的覆盖率、置信分级与缺口，并执行选题决策回填（回填规则见下节）。

- 读什么：全部已落盘产物。
- 产出：`{拆书目录}/证据与边界_{书名}.md`（模板见 references/analyze/analyze-evidence-boundary-template.md）；选题决策回填标注。
- 可选分支：原创迁移（抽可迁移原则生成故事种子并做相似性审计）仅用户明示要求时执行，规则见 references/analyze/analyze-method.md「原创迁移与相似性审计」节，产物追加在 `爆款机制_{书名}.md` 末节。
- 收尾告知产物路径与一句话摘要即完成；文件如何被查找与消费，由消费方自行定义，本域不做预设。

## 选题决策回填

拆完回填扫榜产物的验证状态——参考候选进，验证结论回：

1. 仅当当前目录存在扫榜产物 `选题决策.md` 且其「参考候选」字段含本书时执行：在该字段值后追加 `〔已拆文验证 {YYYYMMDD}〕` 标注，不改写字段原值。
2. 选题决策不存在或「参考候选」不含本书 → 跳过回填，收尾时向用户说明一句。
3. 字段值已含验证标注 → 不重复回填。
4. 禁止改动选题决策的其他字段与终裁记录——回填只做验证状态标注这一件事。
