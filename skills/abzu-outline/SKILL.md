# Abzu · 大纲（outline）

从灵感种子到可开卷的全书骨架：立项定型、设定与总纲并行打磨、人物两面建档。

## 入口判定（每次会话开始）

书项目状态判定只看文件证据（`创作进度.md` 是否存在及其当前阶段取值），不凭对话记忆：

1. 当前目录无 `创作进度.md`（无书项目）→ 询问是否在当前目录开新书（弹窗：选项列表——开新书 / 只是问问）。确认开书后先建书项目脚手架（见工作流「脚手架先行」节），再进入 Stage 1；不开书则只回答问题，不落任何文件。
2. 当前目录有 `创作进度.md`，且当前阶段为「未开始 / 立项-待确认 / 大纲-设定大纲并行 / 大纲-打磨中」→ 断点续跑：读 `创作进度.md`，汇报现状，按 references/outline/outline-workflow.md「断点续跑」节定位续跑点。
3. 当前阶段为「大纲-已完成」或已进入卷级阶段，且用户意图为**推进**（继续往下写）→ 本域职责已完成，告知下一域命令 /abzu-volume 及其建设状态，不在本域内执行。
4. 当前阶段为「大纲-已完成」或已进入卷级阶段，且用户意图为**修订/评审已有大纲产物**（改立项要素 project.md、改总纲、改设定、改人物卡、要求评审打磨）→ 进入修订流：重开对应工作流节（project.md 重开 Stage 1 相应交互——不留变更记录，git 历史即账；其余重开设定⟷大纲并行模式），修改走变更记录；涉设定集/总纲/人物卡设定面的修改须在设定集变更记录区登记（广播变更事件的跨域订阅机制随 write 域三期建设与四期管理深化落地——设计文档 §十五；本阶段以变更记录为真源）。
5. 用户意图属于其他 Abzu 域（扫榜、拆书等）→ 告知对应域命令及其建设状态，不在本域内执行。

## 工作流

按 references/outline/outline-workflow.md 的 Stage 1-2 执行；每步的停靠点、异常分支与交互方式以该文件为准。

## 门控与交互原则

- 两个停靠点：⏸① 立项确认——`project.md` 与文风指南初稿产出后，经作者确认才进入下一阶段（此后改全书方向的成本指数级上升）；⏸② 总纲与设定集确认——设定、总纲、人物卡经作者确认才交棒下一域。确认点一律明确问出，确认前不推进后续阶段。
- 产物检查是提示不是门禁：依赖产物缺失时，暂停并列出缺失清单，询问用户自补还是授权代建；未获明确指令不推进依赖该产物的步骤，也不擅自代建。
- 封闭选择用 AskUserQuestion 结构化选项（候选 ≤4），开放采集用对话，过程性动作默认执行且可跳过。
- 话术零黑话：不向用户暴露内部术语与文件机制。
- 不粘会话：用户转入与大纲无关的任务时正常执行，不套用本域框架，也不询问是否退出。
