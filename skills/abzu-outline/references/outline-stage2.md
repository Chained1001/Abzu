## 流程概述

### 总览图

作用：本阶段的一屏导览——先看图知走法，再进正文执行。

备注：只画分流与调用序，不放话术、字段值与校验规则；改正文须同批回扫此图；与正文不符时，以正文为准。图例：■＝终点（「可续」＝暂停后可续跑）；↺＝回本步重做。

```text
入口          创作进度.md 当前阶段＝「大纲-资料收集中」
（1.3 规格确认后）├ 基本规格.md 的「主要参考」为空 → 回 1.3 补参考（本阶段不开始）  ■ 回上一阶段
                 └ 主要参考在 → 进 2.0 ↓
2.0 采风准备   读参考偏好 → 逐本判稀缺度 → 开工通报 → 静默进 2.1
               └ 无参考（N=0）→ 跳过 2.1 与 2.2 → 进 2.3 默认表分支 ↓
2.1 采风执行   N 本书并行：每本建一份 资料/参考-{书名}.md（13 节采风档模板）
（subagent）   ├ agent 超时／重试仍缺 → 补一轮 → 仍缺 → 回 2.0 降级裁决          ↺ 回 2.0
               └ 全部 N 份「档完」才进 2.2 ↓
2.2 档案审核   脚本核档案 → 全过 → 作者过目 N 份：内核批量确认

               ├ 作者要改某本 → 改完重核＋重审                              ↺ 重审
               ├ 作者要看全档 → 贴出 → 回确认列表                            ↺ 重审
               ├ 先停下 → 状态「待确认·已暂停」＋备注写接点                  ■ 止（可续）
               └ 全部确认 → 进 2.3 ↓
2.3 标尺合成   从已确认的档案合成 参考标尺.md（十二组＋依据强度＋来源）
               ├ 有参考 → 按体量分档 → 逐组合成 → 写标尺 → 准备关键发现（不单独发）
               └ 无参考 → 全组方法论默认表（全推演⚠️）→ 写标尺 → 准备关键发现
2.4 资料确认   脚本核标尺 → 全过 → 一条消息：关键发现＋标尺摘要＋全文＋确认问句
               ├ 脚本有 ✗ → 回 2.3 重合成                                        ↺ 回 2.3
               ├ 确认 → 阶段翻「大纲-草稿中」＋该行「已确认」→ 告知草稿未建    ■ 本阶段止
               ├ 要补采 → 回 2.0（新增参考重跑全链）                           ↺ 回 2.0
               └ 先停下 → 该行「待确认·已暂停」＋备注写续跑接点                ■ 止（可续）
```

### 执行语义

作用：预先裁定各步通用的交互歧义——一条即一条规则，各步引用、不重复写。

备注：本阶段**复用**大纲生成阶段的执行语义（问法两种、同屏即同消息、话术逐字、暂停三级、状态表四值、收到即写、续跑先核对等）——出处 `references/outline-stage1.md`「执行语义」表，本件不重复列。以下仅列资料收集阶段新增条目。

| # | 名字 | 规则 | 备注 |
| --- | --- | --- | --- |
| 1 | 后台静默 | 采风执行期间不发进度消息；作者问进度时读各档案头部「状态」字段如实报（几本档完／几本进行中） | — |
| 2 | 档完门槛 | 档案核心五节齐（基本信息／内核定标／主线结构／人物档案／来源标注）才翻「档完」；书评无提及的字段写「未能采得」亦算档完 | 模板备注同源 |
| 3 | 未档完不进审 | 2.1 产出有「进行中」档案 → **不得进 2.2**——回 2.0 降级（LLM 知识版／换参考／等）由作者裁决 | — |
| 4 | 内核先审后合 | 内核定标的作者确认在 2.2 档案审核完成——**确认后才准合成标尺**（未确认的内核会传染整个标尺） | — |
| 5 | 标尺只合成一次 | 2.3 合成后，2.4 的「要补采」会重跑 2.0→2.1→2.2→2.3 全链（新增参考入统计）；**不增量合并**——重合成比增量可靠 | — |
| 6 | 落成即核 | **每个文件落成后立即机器核验，通过后才停下来给作者确认**——脚本未建成前降级为人工核，并在后续通报中注明「模型自核，未跑脚本」 | 与 stage-spec 的 1.2→1.3 同构 |
| 7 | 暂停必写状态 | 本阶段任何分支暂停（先停下／等／降级）→ `创作进度.md` 该行状态改 `待确认·已暂停`＋备注写续跑接点——**不写状态不算暂停完成** | 复用 stage-spec「暂停三级」③ |

## 二、步骤：资料收集

每一步内部固定四个条目、按执行先后排列：（1）作用（2）具体步骤（3）完成判定（4）异常——（2）按时间顺序编号，每小步一个动作、动词开头，该读哪个文件、哪个字段、该说哪句话（逐字）、该写哪行，都写在那一小步里；本步没有的条目写「无」，不留空。步骤号带阶段前缀（2.x＝本阶段第 x 步；引用其他阶段的步骤写全号如「回 1.2」，不产生歧义）。

### 2.0 采风准备

（1）作用：把参考清单变成采风任务并定预算——控制成本、告诉作者开始了。

（2）具体步骤：

1. 读 `基本规格.md`「参考偏好」节的「主要参考」行与「次要参考」行（0-3 行），取参考清单（主要 1＋次要 ≤3，共 N 本）。
2. **判无参考分支**：N＝0 → 发一条消息（纯文本，逐字）：「没有选参考作品。跳过采风，直接用方法论默认表合成标尺——没问题吧？」[继续（用默认表）／回去补参考（回 1.3）]（选项列表）→ 作者选「继续」→ **跳过第 3-5 小步，直接进 2.3 第 1 小步的「无参考」分支**。
3. 逐本判稀缺度：热门（检索预算 5 次）／常规（10 次）／冷门（15 次）——判法定为：近三年有影视／动画改编或有百万级讨论帖＝热门；百科词条＋豆瓣条目齐全＝常规；百科缺项或书评少于 10 条＝冷门。
4. 发开工通报（纯文本，逐字）：「{N} 本书，{N} 路采风助手，预算按稀缺度分档——{各书名：热门 5 次／常规 10 次／冷门 15 次}，开始了。」
5. 静默进入 2.1——后台执行，不发进度消息（执行语义『后台静默』）。

（3）完成判定：机器核＝无（本步无脚本；产物＝采风任务单，临时不落文件，可从参考清单确定性重推导）；人工核＝开工通报已发、每本的稀缺度已判定（或无参考分支已走）。

（4）异常：断网 → 给作者降级选项（选项列表）：「采风遇阻：网络不可用。走哪条？」[用 LLM 知识版（标 ⚠️）／等（暂停，网络恢复后续跑）]——选「等」→ `创作进度.md` 落行：产物名列 `资料包`、状态列 `待确认·已暂停`、备注列「2.0 断网暂停，网络恢复后从开工通报接」。

### 2.1 采风执行（并行，subagent）

（1）作用：把每本参考拆成可对照的档案——草稿步的燃料。

（2）具体步骤：

1. 对每本参考，派一个 `web-scraper` agent（N 本 N 路，并行）。派发时指定四件事：①模板＝`assets/outline-reference-archive-template.md`；②输出＝`资料/参考-{书名}.md`（新建，可写此一件）；③检索预算＝按 2.0 判定的稀缺度（热门 5／常规 10／冷门 15 次）；④回报格式＝档案路径＋核心五节齐否＋工具往返数。Agent 行为规则（三层调度＋站点清单＋采法纪律）见 `.claude/agents/web-scraper.md`——stage-spec 不重复。
2. Agent 回报后 → 逐份核验「档完」条件：核心五节齐＝翻「档完」；有缺 → 补一轮（同 agent 续跑）。
3. 补一轮后仍有缺 → **不得进 2.2**（执行语义『未档完不进审』）→ 给作者降级选项：「{书名} 采不齐（缺{节名}）。走哪条？」[用 LLM 知识版补齐（标 ⚠️）／换这本参考（回 1.3 改）／先停下]（选项列表）——选「先停下」→ `创作进度.md` 落行：产物名列 `资料包`、状态列 `待确认·已暂停`、备注列「2.1 {书名}采集受阻暂停，续跑从补采裁决接」。

（3）完成判定：机器核＝无（模板字段级核验待 `check_reference_pack.py` 随建设批建，建前降级人工核）；人工核＝全部 N 份档案头部「状态」＝`档完`。

（4）异常：冷门书 LLM 无知 → 联网保底（扩大检索至预算上限）→ 仍不足 → 请作者口述补充（该档标 ⚠️「作者口述」）；agent 超时或限流 → 重试一次 → 仍失败 → 按第 3 小步降级裁决。

### 2.2 档案审核

（1）作用：作者过目全部已档完的档案——**内核批量确认是标尺合成的前置**（内核判错，标尺全歪）。

（2）具体步骤：

1. 跑脚本核验全部档案：`python "<skill 目录>/scripts/check_reference_pack.py" "<书目录>/资料/"`（不可用试 `py -3`；再不可用→**降级明示**：按核验项逐条人工核——①全部档案状态＝`档完`；②核心五节齐且无占位；③来源标注两栏分记非空——降级时在后续通报中注明「模型自核，未跑脚本」）。
2. 脚本全过 → 发一条消息（纯文本，逐字）：「{N} 本书的档案采完了，核验过了。先过一眼每本的核心判断，对了我就去合成标尺。」＋ 每本一行：`{书名}——内核：{类型内核}（{皮核判断}）——对吗？`
3. 按作者回应走分支：
   - 全部点头 → 把每份档案「内核定标·三源记录」的「作者确认」位从 `{待确认}` 改为 `{已确认＋日期}` → 进 2.3。
   - 某本要改 → 作者说什么就改什么 → 改完重跑脚本＋重发第 2 小步的消息请作者重审（只重审改过的那本——**未改的本保持已确认位**，不回退）。
   - 要看某本全档 → 说书名 → 读对应 `资料/参考-{书名}.md` 全文贴出 → 看完回到第 2 小步的确认列表。
   - 先停下 → `创作进度.md` 落行：产物名列 `资料包`、状态列 `待确认·已暂停`、备注列「2.2 档案审核暂停，续跑从内核确认接」 → 「好，档案先搁着。回头喊一声 /abzu-outline，从『内核确认』接着来。」

（3）完成判定：**不过不进 2.3**。机器核＝脚本全过（`check_reference_pack.py` 退出码 0——待随建设批建，建前降级为人工逐条核）；人工核＝全部档案的「内核定标·三源记录·作者确认」位＝`已确认`。

（4）异常：脚本两轮仍不过→把 ✗ 清单原样贴给作者，请作者裁决（默认改档案内容；若判定脚本误报，记录并请作者裁决）；作者答不上来某本的内核对错→建议先停下想清楚——内核判错标尺全歪，宁可多等一轮。

### 2.3 标尺合成

（1）作用：从已确认的档案统计出「这个量级的书长什么样」——治内容匮乏，不是配额考核。

（2）具体步骤：

1. **判分支**：有参考 → 读全部「档完」且「内核已确认」的档案（`资料/参考-{书名}.md`，N 份）；无参考 → 直接用方法论默认表填充十二组（全推演 ⚠️），跳到第 4 小步。
2. 判体量语境：参与档案的体量差异超一档（体量分级＝<30 万／30-80 万／80-200 万／>200 万）→ 分组或剔除，**不得跨体量混算**；剔除须在合成结论中注明（剔了哪本、为什么）。
3. 照 `assets/outline-reference-ruler-template.md` 逐组合成——可数组每格三件（范围值＋依据强度＋来源），范围值取参与档案的最小至最大；依据强度判级（优先级从高到低，命中高级则不再判低级）：
   - **锚定实测**：数值直接数自 ≥1 份档完档案的对应字段；
   - **多源统计**：≥2 份档案交叉一致，或 1 份档案＋≥2 处独立书评佐证；
   - **推演 ⚠️**：以上皆无，取方法论默认值（必带 ⚠️，定稿前复查能否升级）。
4. 写 `参考标尺.md`（书目录下新建，跨阶段资产）——含「合成结论」节。
5. 三条关键发现写进 `参考标尺.md`「合成结论」节末尾（**落文件**，不只在对话里准备——中断可恢复）→ 进 2.4（2.4 第 2 小步①段从此节读出）。

（3）完成判定：机器核＝无（待 `check_reference_pack.py` 随建设批建，建前降级人工核）；人工核＝十二组齐、每格三件全、≥1 组为锚定实测（无参考例外＝全推演 ⚠️＋作者确认视为过）。

（4）异常：单参考 → 范围收窄、强度至多多源；无参考 → 全组方法论默认表（全推演 ⚠️），标尺照写、流程照走。

### 2.4 资料确认

（1）作用：本步是阶段确认点——把资料包与标尺交作者过目确认；确认即本阶段收尾，资料自此作为草稿步的输入。

（2）具体步骤：

1. 跑脚本核验标尺：`python "<skill 目录>/scripts/check_reference_pack.py" "<书目录>/参考标尺.md"`（不可用试 `py -3`；再不可用→降级明示同 2.2 第 1 小步，降级时在本条消息末尾注明「模型自核，未跑脚本」）。
2. 脚本全过 → 发一条消息（纯文本，逐字，四段按序不拆发）——①三条关键发现（照抄 2.3 第 5 小步准备的内容）；②标尺摘要（十二组各一行：{组名} {范围值}（{强度}））；③在对话内贴出 `参考标尺.md` 全文＋可点开的路径；④「资料齐了吗？齐了就开始写草稿。」[确认，进入草稿／要补采（对话说方向）／先停下]（选项列表）。①③为通报非问句，与④同消息合规。
3. 按作者所选走分支：
   - 确认 → `创作进度.md` 翻「大纲-草稿中」、该行产物名列 `参考标尺`、状态列 `已确认`、备注改「草稿未建——建成后续跑接」 → 如实告知：「草稿这步还没做，到此为止——回头建好了接着走。」（未建阶段不模拟、不产出占位内容。）
   - 要补采 → 说方向（新增参考／某本补字段）→ 回 2.0（执行语义『标尺只合成一次』——全链重跑）。
   - 先停下 → 该行状态改 `待确认·已暂停`、备注改「2.4 资料确认已呈现，作者选先停下；续跑从此处接」 → 「好，就停在这儿。进度都记在文件里了——回头喊一声 /abzu-outline，从『资料齐了吗』接着来。」

（3）完成判定：**不过不进确认分支**。机器核＝脚本全过（标尺面：十二组齐、每格三件全、合成结论已写——待 `check_reference_pack.py`，建前降级人工核）；人工核＝作者在确认问句上选「确认」。

（4）异常：脚本不过→贴 ✗ 清单回 2.3 重合成；作者自填——含「确认」「停」等近义词 → 映射到对应分支（「确认」→ 确认分支；「停」→ 先停下分支）；其他自填 → 按作者所说展示或改，改完回 2.3 重合成＋重跑脚本。
