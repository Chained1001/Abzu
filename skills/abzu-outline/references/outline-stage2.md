## 二、步骤：资料收集

每一步内部固定四个条目、按执行先后排列：（1）作用（2）具体步骤（3）完成判定（4）异常——（2）按时间顺序编号，每小步一个动作、动词开头，该读哪个文件、哪个字段、该说哪句话（逐字）、该写哪行，都写在那一小步里；本步没有的条目写「无」，不留空。步骤号带阶段前缀（2.x＝本阶段第 x 步；引用其他阶段的步骤写全号如「回 1.2」，不产生歧义）。

### 2.0 采风检索准备

（1）作用：把参考清单变成采风检索任务并定预算——控制成本、告诉作者开始了。

（2）具体步骤：

1. 读 `基本规格.md`「参考偏好」节的「主要参考」行与「次要参考」行（0-3 行），取参考清单（主要 1＋次要 ≤3，共 N 本；主要参考必填，无参考走不到本阶段——入口与 1.2 脚本第 4 项双重拦）。
2. 逐本判稀缺度与媒介类型：稀缺度——热门（起步 5 次）／常规（10 次）／冷门（15 次），判法（LLM 知识初判即可，不必联网核实——起步档本就可超，停采靠 2.1 的「连续 2 轮无新增」线）：近三年有影视／动画改编或有百万级讨论帖＝热门；百科词条＋豆瓣条目齐全＝常规；百科缺项或书评少于 10 条＝冷门。媒介类型——小说／动漫／影视，按作品常识判（拿不准时一次检索确认），随任务书下发。
3. 发确认弹窗（选项列表，逐字）：「{N} 本书，{N} 路采风检索助手，起步预算按稀缺度分档——{各书名：热门 5 次／常规 10 次／冷门 15 次}，字段未齐可超出（连续 2 轮无新增即止，超支如实回报）。开始吗？」[开始检索／回去改参考（回 1.3）／先停下]。
4. 按作者所选走分支：
   - 开始检索 → 静默进入 2.1——后台执行，不发进度消息（执行语义『后台静默』）。
   - 回去改参考 → 回 1.3（改完重走 Stage 1 的确认流程再进 Stage 2）。
   - 先停下 → `创作进度.md` 落行：产物名列 `采风资料`、状态列 `待确认·已暂停`、备注列「2.0 采风检索开工确认暂停，续跑从此处接」。

（3）完成判定：机器核＝无（本步无脚本；产物＝采风检索任务单，临时不落文件，可从参考清单确定性重推导）；人工核＝开工通报已发、每本的稀缺度与媒介类型已判定。

（4）异常：断网 → 给作者降级选项（选项列表）：「采风检索遇阻：网络不可用。走哪条？」[用 LLM 知识版（标 ⚠️）／等（暂停，网络恢复后续跑）]——选「等」→ `创作进度.md` 落行：产物名列 `采风资料`、状态列 `待确认·已暂停`、备注列「2.0 断网暂停，网络恢复后从开工通报接」。

### 2.1 采风检索执行（并行，subagent）

（1）作用：把每本参考拆成可对照的档案——草稿步的燃料。

（2）具体步骤：

1. 对每本参考，派一个 `web-scraper` agent（N 本 N 路，并行）。派发时指定五件事：①模板＝`assets/outline-reference-archive-template.md`；②输出＝`资料/参考-{书名}.md`（新建，可写此一件）；③检索预算＝按 2.0 判定的起步档（热门 5／常规 10／冷门 15 次）——字段未齐可超出，连续 2 轮无新增即止，超支数回报；④回报格式＝档案路径＋核心五节齐否＋工具往返数＋失败 URL 及原因；⑤作品名＝`基本规格.md`「参考偏好」节「主要参考」「次要参考」行所列（2.0 第 1 小步已读得）；媒介类型＝2.0 第 2 小步所判——两者是 agent 第一层站点优先级与版本取舍的裁定依据。Agent 行为规则（三层调度＋站点清单＋采法纪律）住本域 `references/web-scraper.md`〔维护出处：`web-scraper.md`；运行时不必加载——部署到项目 `.claude/agents/` 后宿主自动加载〕——stage-spec 不重复。
2. 某本 agent 回报后，随即对该份跑机器核：`python "<skill 目录>/scripts/check_reference_pack.py" "<书目录>/资料/参考-{书名}.md"`（档案面八项；不可用试 `py -3`，再不可用→（4）异常的降级）。
   - 回报说核心五节有缺 → 先让同一 agent 补一轮（上下文还热）→ 补完回到本小步重跑脚本。
   - 脚本有 ✗ → 把 ✗ 清单原样发给**同一个 agent**修 → 修完重跑脚本；至多两轮。
   - 脚本过（退出码 0）→ 该本算「档完」，处理下一本——**单本不过只阻塞该本，不拖其他本**。
3. 全部 N 份脚本都过 → 进 2.2。
4. 某本两轮仍不过（或 agent 超时／限流重试一次仍失败）→ **不得进 2.2**（执行语义『未档完不进审』）→ 给作者降级选项：「{书名} 采不齐（缺{节名}）。走哪条？」[用 LLM 知识版补齐（标 ⚠️）／换这本参考（回 1.3 改）／先停下]（选项列表）——选「先停下」→ `创作进度.md` 落行：产物名列 `采风资料`、状态列 `待确认·已暂停`、备注列「2.1 {书名}采集受阻暂停，续跑从补采裁决接」。

（3）完成判定：机器核＝全部 N 份档案面八项全过（第 2 小步逐份跑，退出码 0）；人工核＝全部 N 份档案头部「状态」＝`档完`。

（4）异常：冷门书 LLM 无知 → 联网保底（换检索词与站点扩采，直至字段齐或连续 2 轮无新增）→ 仍不足 → 请作者口述补充（该档标 ⚠️「作者口述」）；脚本与 `py -3` 都不可用 → **降级明示**：对该份按八项逐条人工核，并在后续通报中注明「模型自核，未跑脚本」。

### 2.2 采风资料审查

（1）作用：作者过目全部已档完的档案——**内核批量确认是参考标尺合成的前置**（内核判错，参考标尺全歪）。

（2）具体步骤：

1. 进审前全量终检：`python "<skill 目录>/scripts/check_reference_pack.py" "<书目录>/资料/"`（目录级——2.1 已逐份过，这里防写入文件后被改动、保判定面一致；不可用试 `py -3`；再不可用→**降级明示**：按核验项逐条人工核——①全部档案状态＝`档完`；②核心五节齐且无占位；③来源标注两栏分记非空——降级时在后续通报中注明「模型自核，未跑脚本」）。终检**单份不过只阻塞该本**（回 2.1 补采），其余各本照常进第 2 小步。
2. （通过终检的）各本齐 → 发一条消息（纯文本，逐字）：「{N} 本书的档案采完了，核验过了。先过一眼每本的核心判断，对了我就去合成参考标尺。」（N＝通过终检的本数；终检有阻塞本时，句末加「另有 {X} 本终检未过、已回 2.1 补采。」）＋ 每本一行：`{书名}——内核：{类型内核}（{皮核判断}）——对吗？`
3. 按作者回应走分支：
   - 全部点头 → 把每份档案「内核定标·三源记录」的「作者确认」位从 `{待确认}` 改为 `{已确认＋日期}` → 进 2.3。
   - 某本要改 → 作者说什么就改什么 → 改完重跑脚本＋重发第 2 小步的消息请作者重审（只重审改过的那本——**未改的本保持已确认位**，不回退）。
   - 要看某本全档 → 说书名 → 读对应 `资料/参考-{书名}.md` 全文贴出 → 看完回到第 2 小步的确认列表。
   - 先停下 → `创作进度.md` 落行：产物名列 `采风资料`、状态列 `待确认·已暂停`、备注列「2.2 采风资料审查暂停，续跑从内核确认接」 → 「好，档案先搁着。回头喊一声 /abzu-outline，从『内核确认』接着来。」

（3）完成判定：**不过不进 2.3**。机器核＝脚本全过（`check_reference_pack.py` 退出码 0）；人工核＝全部档案的「内核定标·三源记录·作者确认」位＝`已确认`。

（4）异常：脚本两轮仍不过→把 ✗ 清单原样贴给作者，请作者裁决（默认改档案内容；若判定脚本误报，记录并请作者裁决）；作者答不上来某本的内核对错→建议先停下想清楚——内核判错参考标尺全歪，宁可多等一轮。

### 2.3 参考标尺合成

（1）作用：从已确认的档案统计出「这个量级的书长什么样」——治内容匮乏，不是配额考核。

（2）具体步骤：

1. 读全部「档完」且「内核已确认」的档案（`资料/参考-{书名}.md`，N≥1 份；「内核已确认」＝读各档案「内核定标·三源记录·作者确认」位为 `已确认`）。
2. 判体量语境：体量分级＝<30 万／30-80 万／80-200 万／>200 万（按各档案「热度数据」的总字数定档）。**以服务书目（`基本规格.md` 体量字段）所在档为准**取同档档案合成，跨档的剔除——**不得跨档混算**；剔除须在合成结论中注明（剔了哪本、为什么）。篇幅三选与档的对应：30 万字以内→<30 万、100 万字上下→80-200 万、300 万字以上→>200 万（作者自填值按最近档归入并在合成结论注明）。档案缺总字数 → 以可得体量证据（卷数、单本篇幅）推演定档并标 ⚠️、在合成结论注明；推不出档 → 该档案剔除并注明。
3. 照 `assets/outline-reference-ruler-template.md` 逐组合成——每格三件（值＋依据强度＋来源）。**喂料对照**（哪格吃档案哪个字段——只从表内字段取数；表内无对应字段的格＝无料可喂，走推演默认；**产物照抄此表**进「喂料对照」节，消费方按此核对取数来源）：

   | 组 | 喂料（参考作品档案的节·字段） | 取数法 |
   | --- | --- | --- |
   | ① 节奏目标 | 节奏密度：高潮周期、爽点间隔 | 从量级描述折出可数量（每卷场数、间隔量级） |
   | ② 结构要点 | 主线结构：分卷节奏、剧情走向；暗线数另取 名场面与伏笔＋冲突矩阵 | 换图数地图与卷断口；暗线数贯穿性长线 |
   | ③ 人物分层名单 | 人物档案全节 | 盘点名单元得人数 |
   | ④ 反派层级 | 人物档案：反派档案·层级数 | 直读字段 |
   | ⑤ 伏笔量 | 名场面与伏笔：伏笔案例 | 数在空线与埋收跨度 |
   | 派生体量 | 基本信息：热度数据（总字数／卷数／章数） | 换算（式见取数总则·派生换算） |
   | ⑥ 情绪基调 | 基本信息：核心阅读承诺＋读者反馈 | 映射情绪词表取并集 |
   | ⑦ 主角压力 | 一页结论：对手压力阶梯＋主线结构：冲突矩阵 | 归纳阻力类型／层级／递增方式 |
   | ⑧ 读者情绪曲线 | 读者反馈：读者情绪曲线 | 并集归纳 |
   | ⑨ 爽点类型分布 | 读者反馈：爽点类型分布 | 并集并按提及主次排序 |
   | ⑩ 信息揭示节奏 | 读者反馈：信息揭示节奏 | 归纳揭示单位与间隔 |
   | ⑪ 结局形态分布 | 结局与感情线：结局形态 | 按 N 份实际计数得比例 |
   | ⑫ 感情线处理分布 | 结局与感情线：感情线处理 | 归纳线型／浓度／与主线关系 |
   | 主线支线比例（②内） | 无对应字段 | 方法论默认（推演 ⚠️） |

   取数总则：
   - 数值型字段：范围值取参与档案的最小至最大；
   - 描述型字段：先找**可数的量**（每卷几场、跨几卷、几条线、几层），把每份档案的描述折成该量的值再取最小至最大；折不出数的（情绪基调、爽点分布这类）按参与档案**取并集**；比例式组（⑪⑫）按 N 份档案实际计数；
   - ⑥组词汇映射：归纳出的情绪词一律映射至 `references/outline-emotion-words.md` 词表；映射不上的表外词按最近词写入、⑥行内括注原词，2.4 资料确认时随标尺一并过目——作者认可即增词进词表对应轴并把头部版本号 +1（增词须作者认可，词表取值规则同款）；
   - 派生换算：章均字数＝总字数÷总章数（仅同章制可比时——实体出版制与网文章制不可比，走方法论默认）；节点数＝卷数×每卷卷级大高潮数（取 ①）；
   - 依据强度判级（优先级从高到低，命中高级则不再判低级）：
     - **锚定实测**：数值直接数自 ≥1 份档完档案的对应字段；
     - **多源统计**：≥2 份档案交叉一致，或 1 份档案＋≥2 处独立书评佐证；
     - **推演 ⚠️**：以上皆无，取方法论默认值（必带 ⚠️，定稿前复查能否升级）。
4. 写 `参考标尺.md`（书目录下新建，跨阶段资产）——含「合成结论」节；重合成时更新「合成日期」并整体重写（不增量合并，见执行语义『参考标尺只合成一次』）。
5. 三条关键发现写进 `参考标尺.md`「合成结论」节末尾（**落文件**，不只在对话里准备——中断可恢复）。关键发现限三类各取要害：**数据缺口**（缺什么、补什么可升级）、**样本偏差**（如某组值全偏一类）、**适用性限制**（如实体章制不可向网文迁移、量级跨档外推须放大）；不足三条按实数写，无则写「无」。
6. 落成即核（执行语义『落成即核』）：跑 `python "<skill 目录>/scripts/check_reference_pack.py" "<书目录>/参考标尺.md"`（标尺面九项；不可用试 `py -3`，再不可用→（4）异常的降级）→ 脚本有 ✗ → 修参考标尺重跑，至多两轮；两轮仍不过 → 贴 ✗ 清单请作者裁决（判定脚本误报则记录）→ 脚本过（退出码 0）→ 进 2.4（2.4 第 1 小步①段从「合成结论」节读出）。

（3）完成判定：机器核＝标尺面九项全过（第 6 小步跑，退出码 0）；人工核＝≥1 组为锚定实测。

（4）异常：单参考 → 范围收窄、强度至多多源；脚本与 `py -3` 都不可用 → **降级明示**：按九项逐条人工核，并在 2.4 通报中注明「模型自核，未跑脚本」。

### 2.4 资料确认

（1）作用：本步是阶段确认点——把采风资料与参考标尺交作者过目确认；确认即本阶段收尾，资料自此作为草稿步的输入。

（2）具体步骤：

1. 发一条消息（纯文本，逐字，四段按序不拆发）——①三条关键发现（照抄 2.3 写进 `参考标尺.md`「合成结论」节末尾的内容）；②参考标尺摘要（十二组各一行：{组名} {值}（{强度}））；③在对话内贴出 `参考标尺.md` 全文＋可点开的路径；④「资料齐了吗？齐了就开始写草稿。」[确认，进入草稿／要补采（对话说方向）／先停下]（选项列表）。①③为通报非问句，与④同消息合规。
2. 按作者所选走分支：
   - 确认 → `创作进度.md` 翻「大纲-草稿中」、该行产物名列 `参考标尺`、状态列 `已确认`、备注改「草稿未建——建成后续跑接」 → 如实告知：「草稿这步还没做，到此为止——回头建好了接着走。」（未建阶段不模拟、不产出占位内容。）
   - 要补采 → 说方向（新增参考／某本补字段）→ 回 2.0（执行语义『参考标尺只合成一次』——全链重跑）。
   - 先停下 → 该行状态改 `待确认·已暂停`、备注改「2.4 资料确认已呈现，作者选先停下；续跑从此处接」 → 「好，就停在这儿。进度都记在文件里了——回头喊一声 /abzu-outline，从『资料齐了吗』接着来。」

（3）完成判定：机器核＝2.3 第 6 小步标尺面九项全过（**承接 2.3 结果，本步不重跑**）；人工核＝作者在确认问句上选「确认」。

（4）异常：续跑接本步时发现 `参考标尺.md` 疑被改动 → 回 2.3 第 6 小步重核（执行语义『续跑先核对』）；作者自填——含「确认」「停」等近义词 → 映射到对应分支（「确认」→ 确认分支；「停」→ 先停下分支）；其他自填 → 按作者所说展示或改，改完回 2.3 重合成＋重核。
