## 选题四步

每个推荐选题都走完这四步，缺一不可。每步标注其**产出的模板字段**——字段必须有生产步骤，否则禁止入模板：

1. **能爆的原因（先当假设）**：从榜上**重复出现的样本**（排除单本个例）+ 新元素提取，推出"这个方向能爆，依靠 X 结构/梗/人设吃这波读者"。单本上榜只是个例（扫榜原则 1：多本重复才算信号）。这里只写假设，标 `待验证`。（产出：能爆的原因、题材组合、**开篇钩子公式**——从榜上重复的开篇卖点归纳公式化结构、**参考候选**——榜上代表作 1-3 本，供拆书验证与大纲参考）
2. **市场验证**：榜上同方向有几本 + 趋势（↑/→/↓）+ 反例（同方向有没有扑街/烂尾的）。样本越多、趋势越稳，越可信。（产出：市场风险——大盘是否走弱/读者疲劳、**题材雷区**——从反例/评论提取或按题材归纳、可行性-市场面）
3. **差异化定位与读者定位**：作者优势 × 市场缺口 = "你的版本和榜上现有的不同在哪"，同时锁定目标读者与其代偿心理。没有差异化 = 同质化挤不进去。（产出：差异化定位、目标读者、**读者代偿心理**——对照 references/scan/scan-reader-profiling.md 九维画像与平台速查、**技术难点**——作者优势的反面即写作难点）
4. **可行性 + 风险 + 验证动作**：给出可行性高/中/低（下节规则）、最可能的失败点、开写前怎么低成本验证。（产出：可行性、**长期追读动力**——判断该方向能否承载百万字的核心悬念/成长线，找不到即冲榜短打信号、**内容风险点**——对照 references/scan/scan-genre-trends.md 各题材审核约束、**验证动作**——对照 references/scan/scan-publishing-guide.md「数据指标解读」绑定平台可测指标、**篇幅/平台**——卷数由榜上字数分布按卷均 20-40 万字〔abzu 自定〕折算）

## 可行性判断

分三档；样本不够时禁止给"高"，别让几条数据撑出假信心：

| 可行性 | 含义 | 条件 |
| --- | --- | --- |
| 高 | 可放心写 | 同方向榜上样本够（≥15，小平台≥10）+ 趋势↑或→ + 作者素材能撑 + 有差异化空间 |
| 中 | 可写但先验证 | 样本够但趋势↓ / 或差异化不清 / 或作者素材半撑 |
| 低 | 不建议 | 同方向已饱和（扑街反例多）/ 或作者素材撑不住 / 或平台调性不符 |

**硬规则**：某方向背靠的榜单若标了 `[数据稀疏]`（有效条目 < 15，小平台 < 10，即扫榜采集质量检查标的稀疏阈值），该方向**禁止给"高"**，强制降到"中" + 写明"样本不足，先扫够样本或试水再定"。

**内置知识模式**：无榜单、纯凭知识库趋势时，**所有方向一律给"中"**，理由写"基于通用认知，无榜单验证，开写前必须先扫榜或小成本试水"。禁止给"高"。

## 交付

1. 写到本次扫榜的输出目录（和榜单文件同一个目录）：`扫榜/{平台}{方向}_{YYYYMMDD}/选题决策.md`（输出目录约定见 references/scan/scan-collection-guide.md；扫榜常在还没有小说项目的目录下跑，所以产物落在这里，不直接写进项目）。
2. **落盘即完成职责**：产物落在扫榜输出目录即为本域全部义务；文件如何被查找与消费，由消费方自行定义，本域不做预设。
3. **收尾交互收敛成单步决策**：展示 3 个选题（对比表：方向/核心卖点/差异化/可行性/验证动作）后，只问一个决策——「你倾向哪个选题？或都不满意？」
   - 都不满意 → 换方向重扫 / 换平台 / 用户给新方向
   - 选定 → 针对**该选题**问一次素材匹配：「这个题材你能写吗（素材储备/擅长点）？」——答案直接决定可行性是否上调；只问选中题，不泛问"擅长什么"
   - 不问计划字数：平台+方向已定则市场已定义篇幅（写进选题的「篇幅/平台」字段）；用户主动提计划篇幅时采纳，不主动问
4. 收尾只告知产物路径与内容摘要，不引导任何后续动作；文件如何被查找、读取与使用，由消费方自行定义（本域不预设）。
