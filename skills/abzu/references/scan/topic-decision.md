## 选题四步

每个推荐选题都走完这四步，缺一不可：

1. **能爆的原因（先当假设）**：从榜上**重复出现的样本**（排除单本个例）+ 新元素提取，推出"这个方向能爆，依靠 X 结构/梗/人设吃这波读者"。单本上榜只是个例（扫榜原则 1：多本重复才算信号）。这里只写假设，标 `待拆文验证`；要坐实得靠拆文回填。
2. **市场验证**：榜上同方向有几本 + 趋势（↑/→/↓）+ 反例（同方向有没有扑街/烂尾的）。样本越多、趋势越稳，越可信。
3. **差异化定位**：作者优势 × 市场缺口 = "你的版本和榜上现有的不同在哪"。没有差异化 = 同质化挤不进去。
4. **可行性 + 风险 + 验证动作**：给出可行性高/中/低（下节规则）、最可能的失败点、开写前怎么低成本验证（通常："先写黄金三章测追读，不行就换"）。

---

## 可行性判断

分三档；样本不够时不许给"高"，别让几条数据撑出假信心：

| 可行性 | 含义 | 条件 |
| --- | --- | --- |
| 高 | 可放心写 | 同方向榜上样本够（≥15，小平台≥10）+ 趋势↑或→ + 作者素材能撑 + 有差异化空间 |
| 中 | 可写但先验证 | 样本够但趋势↓ / 或差异化不清 / 或作者素材半撑 |
| 低 | 不建议 | 同方向已饱和（扑街反例多）/ 或作者素材撑不住 / 或平台调性不符 |

**硬规则**：某方向背靠的榜单若标了 `[数据稀疏]`（有效条目 < 15，小平台 < 10，即扫榜采集质量检查标的稀疏阈值），该方向**不许给"高"**，强制降到"中" + 写明"样本不足，先扫够样本或试水再定"。

**内置知识模式**：无榜单、纯凭知识库趋势时，**所有方向一律给"中"**，理由写"基于通用认知，无榜单验证，开写前必须先扫榜或小成本试水"。不许给"高"。

## 选题决策.md 模板

```
# 选题决策：{平台/方向}

- 扫榜日期：{YYYYMMDD}     # 数据新鲜度；写作读取时若过期会提示复扫
- 数据来源：{榜单文件名 / 内置知识}

## 推荐选题

### 选题 1：{一句话方向}

- 题材组合：{主类型 + 副类型/梗}
- 题材库覆盖：{已命中卡{名} / 未命中（库外题材——可考虑补卡，作者裁决）}——对照题材卡索引（agent-references 副本）的别名匹配词列，纯描述引用不跨技能（B71）；未命中只呈报候选，不自动生成卡
- 目标读者：{画像}
- 核心卖点：{读者为什么追}
- 能爆的原因：{X 结构/梗为什么吃这波}（假设，`待拆文验证`）
- 差异化定位：{和榜上现有的不同在哪}
- 可行性：高/中/低 — {理由，写清同方向几本 + 趋势}
- 失败风险：{最可能崩在哪}
- 验证动作：{开写前怎么低成本验证}
- 篇幅/平台：{建议字数区间 + 目标平台}

### 选题 2 ...
### 选题 3 ...
```

2-3 个选题为宜，按可行性排序（高的在前）。

## 交付

1. 写到本次扫榜的输出目录（和榜单文件同一个目录）：`扫榜/{平台}{方向}_{YYYYMMDD}/选题决策.md`（输出目录约定见 SKILL.md；扫榜常在还没有小说项目的目录下跑，所以产物落在这里，不直接写进项目）。
2. **落盘即完成职责**：产物落在扫榜输出目录即为本域全部义务；文件如何被查找与消费，由消费方（立项/大纲域）自行定义，本域不做预设。
3. **收尾交互收敛成单步决策**：展示 3 个选题（对比表：方向/核心卖点/差异化/可行性/验证动作）后，只问一个决策——「你倾向哪个选题？或都不满意？」
   - 都不满意 → 换方向重扫 / 换平台 / 用户给新方向
   - 选定 → 针对**该选题**问一次素材匹配：「这个题材你能写吗（素材储备/擅长点）？」——答案直接决定可行性是否上调；只问选中题，不泛问"擅长什么"
   - 不问计划字数：平台+方向已定则市场已定义篇幅（写进选题的「篇幅/平台」字段）；用户主动提计划篇幅时采纳，不主动问
4. **拆文保持独立，不自动衔接**：提示一句「想坐实'能爆的原因'可自行 analyze 域拆 {对标书}，拆完回填」即可——拆不拆、何时拆由用户决定，选定选题不代表进入拆文。
5. 告知用户产物路径即可；对文件后续如何被使用不做承诺或预定义（消费方规则由各域自行定义、自行告知）。
6. 本产物定位为立项/开书的参考输入；各消费方如何读取与使用，由各域自行定义（本文件不预设）。
